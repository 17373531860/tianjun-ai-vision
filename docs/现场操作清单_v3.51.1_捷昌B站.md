# 捷昌 B 站双工位 · v3.51.1 升级后现场操作清单（超详细版）

> **装这个版本，不用再打任何补丁。** v3.51.1 = v3.51.0 全部内容 + 虚拟双工位战役修复的 6 个 bug。
> 覆盖安装即可（项目/数据/扫码器配置全保留），装完在"系统设置"页底部确认版本号 **v3.51.1**。
>
> v3.51.1 相比 v3.51.0 修了什么（都是升级即生效，无需配置）：
> 1. **扫新码后旧箱账收不掉**（旧账一直"检测中"、新箱出不了结果）→ 已修
> 2. **扫了已合格的码被拒后扫码枪灯永灭**（产线卡死要重启扫码）→ 已修：全部工位都拒绝该码时枪自动重新亮灯
> 3. **工位组超时"强制NG"档还给先合格的工位报"已合格"** → 已修：改为全组统一报一次整体不合格
> 4. **偶发无关周期被之前的组内 NG 拖累改判** → 已修（残留覆盖 60 秒自动作废）
> 5. **旧件拿走后几秒内同位置放"另一种"新件不计数**（账凑不齐下一箱被误判 NG）→ 已修
> 6. **两个工位都合格时弹的是红色"不合格"提示**（实际是合格）→ 已修：弹绿色合格

## 第 0 步：装软件

1. 把 5 个分片和 `merge_installer.bat` 放同一目录，双击 `merge_installer.bat` 合并出 `TianJun-AI-Vision-3.51.1-Setup.exe`；
2. 双击安装，路径保持上次的安装目录（覆盖升级）；
3. 装完启动，系统设置页底部版本号应为 **v3.51.1**。

## 第 1 步：把工位 0 的项目绑定改回来（必做，一次性）

历史 bug 把工位 0 的项目绑定写坏成了小件项目（"删个标签两个工位都变小件"的病根之一）。升级后**先修数据**：

1. 进 **源设置** 页，切到 **工位 0**；
2. "绑定项目"下拉选回 **大件项目**，保存；
3. 切到 **工位 1** 确认绑定仍是 **小件项目**。

## 第 2 步：关掉「自动接管未绑定工位」（必做，防复发）

**系统设置 → 显示设置 → 「启用项目时自动接管未绑定工位」→ 关**。

关掉后，任何一次"启用项目"（包括删标签后保存项目触发的重载）都**只影响明确绑定该项目的工位**，两个工位不再互踩。

## 第 3 步：两个项目都开「扫码后才计数」（要"扫码前检测不算数"必开）

A 站能"扫码前不算数"是因为 A 站项目开了这个开关，B 站两个项目要照做：

1. **项目管理 → 大件项目 → 逻辑设置 → 跟踪模式配置 → 「扫码后才计数」开**，保存；
2. **小件项目**同样操作，保存；
3. 每个项目改完后**重新激活**（或重启检测）生效。

## 第 4 步：扫码器（一把广播枪管两个工位）

**MES管理 → 扫码器 → 设备管理 → 编辑那把广播枪**：

| UI 项 | 设定值 | 说明 |
|---|---|---|
| 通讯协议 | 55256 LON/LOFF（保持现状） | — |
| **扫描模式** | **E 码-合格-码** | 扫到码灭灯；**两个工位都合格**当场亮灯放行下一码；NG 保持灭灯等人工。E 档自动强制"先扫后检"和"仅合格才亮灯"，不存在漏配 |
| 绑定工位 | **广播到 0 和 1** | 一把枪两个工位。若面板上还有一台 192.168.0.2 的旧设备且现场并不存在这台枪，删掉它（它连不上会一直报连接超时日志） |
| 绑定时机 | 中途绑定（默认） | 不要选"码-码闭环"（与齐件即结算互斥） |
| 重复扫码 | 拒绝 | 在检期间扫新码 → 弹黄色警告拒绝 |
| **强制去重（strict_ok_dedup）** | 开 | 已合格的码永久拒绝再次进站。**v3.51.1 起拒绝后枪会自动重新亮灯**，可继续扫下一箱；如果确实要重做某个码：数据中心删除该码相关记录（清理会自动解锁该码，见第 6 步验收 4） |

## 第 5 步：建工位组 + 开「统一播报」（"两个都合格才一起报"）

**系统设置 → 工位组互通 → 新建工位组**：

| 配置项 | 填什么 | 说明 |
|---|---|---|
| 组名 | B站双工位 | — |
| 成员工位 | 0, 1 | — |
| 联动策略 | **全部工位 OK 才算合格**（synchronized_all_ok） | — |
| **统一播报** | **开** | 选上面策略后才出现。先合格的工位不亮灯不语音不弹框（计数/记录/MES 照常），两个都合格**一起报一次绿色合格**；任一 NG 立即报永不等待 |
| 等待超时 | **120000 毫秒（2 分钟）起步**，跑顺再收紧 | ≥ 单件最长检测时长，宁大勿小 |
| 超时处理 | 二选一，见下 | — |
| 启用 | 开 | — |

**超时处理两档怎么选**：

- **退化独立**（推荐先用这档）：超时后已合格的工位补报自己的合格，慢工位继续等——不会"永远没反馈"；
- **强制 NG**（绑死档）：超时 = 全组统一报一次**整体不合格**（v3.51.1 起不会再给先合格的工位报"已合格"），慢工位的账也记 NG。要求"两个必须一起过，过不了就整箱判废"选这档。

## 第 6 步：验收（15 分钟走一遍，照做必过）

1. **重启工控机** → 软件自动起 → 监控页**两个工位都有画面**（黑屏兜底验证；个别工位慢 10 秒内自动补拉）；
2. **不扫码**，往两个工位视野里放东西 → 两边**物品清单都不动、不计数**（第 3 步验证）；
3. **扫一个新码** → 两个工位开始计数；先凑齐的工位**安静**（不亮灯不弹框），第二个也凑齐时**两边一起弹绿色合格 + 扫码枪重新亮灯**（第 4/5 步验证；v3.51.1 修复点 6：弹的必须是绿色合格不是红色）；
4. **重扫刚才那个已合格的码** → 两边弹黄色警告"已合格拒绝"，**几秒内扫码枪重新亮灯**（v3.51.1 修复点 2 验证），能直接扫下一箱；
5. **数据中心 → 按日期清掉刚才的记录** → 再扫同一个码 → 正常进站不再提示"已合格/已登记"（v3.51.0 解锁 + v3.51.1 状态一致验证）；
6. **只给工位 0 上料、工位 1 不放满** → 等到超时：选"退化独立"= 工位 0 补报自己的合格；选"强制 NG"= 两边一起报整体不合格（v3.51.1 修复点 3 验证）；
7. **超时那箱之后扫下一个码** → 工位 1 挂着的旧账被自动收成 NG，新码正常开始（v3.51.1 修复点 1 验证）；
8. **合格后不收走物品，直接扫下一个码** → 旧物品不计数不弹框；把旧物品拿走、换上新一箱的料（可以放在同样位置）→ 正常计数（v3.51.1 修复点 5 验证）。

任何一步不符 → 拍下监控页 + 导出当天日志发回来。
