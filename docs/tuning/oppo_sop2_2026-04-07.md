## 调优过程

### 第1轮: 粗粒度时序分析（0.5s间隔）
- 观察: 用脚本逐帧推理，以 0.5s 间隔统计出现/消失模式。发现撕璃形纸每 5~7 秒出现一次（符合周期预期），共识别出 46 个周期
- 调整: 无（纯分析轮）
- 依据: 需要先摸清原始检测质量
- 结果: 序列匹配率极低——43/46 个周期实际顺序 `撕璃形纸→翻手机→翻电池→安装电池`，而非预期 `撕璃形纸→翻电池→安装电池→翻手机`。翻手机在步骤切换间有 0.00~0.15s 闪现误检
- 状态: 需继续调整

### 第2轮: 错误假设——max_interval 跨周期
- 观察: 撕璃形纸的 max_interval=5.0s ≥ 周期间隔 5~7s，初步判断状态机可能认为撕璃形纸"一直在"而无法触发第一步结算
- 调整: 建议降低撕璃形纸 max_interval 到 1.5~2.0s
- 依据: max_interval 超过周期间隔会导致步骤"不消失"
- 结果: **用户纠正**——消失处理器会在 disappear_delay 后删除 step_last_seen，之后 max_interval 不参与判定。去重间隔不影响消失确认
- 状态: 假设错误，需重新分析

### 第3轮: 代码审计——消失处理器机制
- 观察: 用户说"去重间隔下一个步骤出现就直接终止了"，审查 source.py 消失处理代码（line 3183-3219）
- 调整: 无（代码审计轮）
- 依据: 追踪 `step_last_seen` 的生命周期——在消失处理器中被 `del`（line 3219），在 `_process_single_step` 中被设置（line 2923）
- 结果: 确认消失处理器只用 `disappear_delay`（默认0），不用 `max_interval`。**执行顺序**：① 消失处理器 disappear_delay=0 → 0.03s 后删除 step_last_seen → ② 出现处理器检查 max_interval → old_last_seen=None → max_interval 永远不被检查
- 状态: 找到根因——disappear_delay=0 使 max_interval 形同虚设

### 第4轮: 逐帧 debug 日志分析
- 观察: 将分析粒度从 0.5s 改为逐帧（每 3 帧取 1 帧），加 debug 日志追踪每个步骤的加入/移出
- 调整: 无（诊断轮）
- 依据: 需要看到状态机内部的步骤进出过程
- 结果: 发现撕璃形纸的检测不连续——一次 2.6s 出现被帧间抖动切碎。典型案例：
  ```
  11.83s  结算后撕璃形纸重新出现
  12.18s  消失 dur=0.30s < 1.0s → 移出周期
  12.23s  重新加入
  13.23s  消失 dur=0.95s < 1.0s → 移出周期（差 0.05s）
  13.28s  重新加入
  13.43s  消失 dur=0.10s → 移出
  ...反复5次，全部不够1秒
  ```
  本来 11.83~14.53s 是一次完整出现（~2.7s），被切成5段后没有一段能过 1.0s 门槛
- 状态: 确认问题模式，需要测试 disappear_delay 修复效果

### 第5轮: 测试 min_duration 调整（disappear_delay=0 下）
- 观察: 在不改 disappear_delay 的前提下，尝试通过调 翻手机 min_duration 改善序列
- 调整: 翻手机 min_duration 分别测试 0.05s / 0.20s / 0.30s / 0.40s
- 依据: 翻手机闪现持续 0.00~0.15s，提高 min_duration 应能过滤
- 结果:

| 翻手机 min_dur | 周期数 | OK | 合格率 |
|----------------|--------|-----|--------|
| 0.05s（原始）  | 15     | 1   | 7%     |
| 0.20s          | 14     | 0   | 0%     |
| 0.30s          | 14     | 0   | 0%     |
| 0.40s          | 14     | 0   | 0%     |

  提高翻手机 min_duration 后合格率反而降到 0%——翻手机的有效出现（周期末尾）也被过滤了。且周期数依然只有 14~15 个（应为 44），说明 **根本问题不是翻手机闪现，而是 disappear_delay=0 导致步骤反复进出**
- 状态: 确认单纯调 min_duration 无法解决

### 第6轮: 测试 disappear_delay 梯度
- 观察: 确认 disappear_delay=0 是根因后，梯度测试不同值
- 调整: disappear_delay = 0 / 0.3 / 0.5 / 1.0s（全部步骤统一值）
- 依据: 需要找到"远大于帧间抖动（0.03~0.3s）、远小于周期间隔（3~5s）"的平衡点
- 结果:

| disappear_delay | 周期数 | OK | 合格率 | 主要 NG 类型 |
|-----------------|--------|-----|--------|-------------|
| 0s（原始）      | 15     | 1   | 7%     | 周期数严重不足 |
| 0.3s            | 44     | 17  | 39%    | 缺翻电池/翻手机 |
| 0.5s            | 44     | 26  | 59%    | 缺翻电池 |
| 1.0s            | 44     | 37  | 84%    | 缺翻电池(4次) |

- 状态: disappear_delay=1.0s 效果最佳，通过

### 第7轮: 分析剩余 NG 原因
- 观察: disappear_delay=1.0s 时仍有 7 个 NG 周期，主要为 `撕璃形纸→安装电池→翻手机`（4次，缺翻电池）
- 调整: 未执行（分析阶段，等待用户实测）
- 依据: 翻电池检测也存在帧间抖动，0.15s 的 min_duration 在边界上
- 结果: 可选微调方向——翻电池 min_duration 降到 0.10s 或翻手机 min_duration 提到 0.15s
- 状态: 建议用户实测后决定是否继续

### 关键发现: 去重间隔失效机制
- 观察: 用户配置的去重间隔（max_interval）= 5.0s 应该能合并帧间抖动，但实际无效
- 根因: 代码中消失处理器只使用 `disappear_delay`，不使用 `max_interval`。执行顺序为：① 消失处理器用 disappear_delay（=0）确认消失并删除 step_last_seen → ② 出现处理器用 max_interval 判定 is_new_appearance，但此时 step_last_seen 已被删除，old_last_seen=None，max_interval 永远不会被检查
- 影响: 任何 disappear_delay=0 的项目，去重间隔都不起作用
- 建议: 后续版本考虑让消失处理器也参考 max_interval，或将 disappear_delay 默认值改为 1.0s

## 调优总结
- 关键发现: disappear_delay=0 使 max_interval 完全失效，检测帧间抖动导致步骤反复进出周期，是周期判定异常的根本原因
- 推荐参数范围: disappear_delay 建议 0.5~1.5s（远大于帧间抖动 0.03~0.3s，远小于周期间隔 3~5s）
- 注意事项:
  - disappear_delay 不能超过周期间最短步骤间隔，否则消失确认会延迟到下一步骤出现后
  - 翻手机的 0.05s min_duration 处于边界，0.03s 的单帧检测刚好通过，建议后续观察是否需要提到 0.15s
  - 翻电池 0.15s min_duration 偏紧，部分有效检测卡在 0.10~0.15s 边界
