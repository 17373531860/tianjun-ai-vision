# v3.35.0 (2026-07-12)

> 主题：**萍乡百斯特胶装水泥称重项目 · 视觉 SOP × 秤门控融合架构**——周期主线回归视觉顺序 SOP，电子秤降级为步骤完成门控（去皮门控/称重判定），配套前置选择有效期、视觉料源防错、USB 报警确认按钮、MES 数据库直写适配器（达梦等 5 库）；包装线扫码健壮性（复合条码取段/工单号识别规则/放工单=尾箱收尾动作）；步骤消失等待不被打断开关。全部默认关或零差异。

## 功能变更

- [FEAT-001] 视觉 SOP × 秤门控融合架构（drive_mode='step_gate'）
  - 需求: 百斯特现场周期节奏由人操作视觉步骤决定，v3.31 纯秤驱动模式（logic_mode='weighing'）无法继承顺序模式的违序/缺步/超时报警；需要"视觉顺序 SOP 为周期主线，秤数据只做步骤完成门控"的融合形态
  - 实现: 称重引擎新增 StepGate 门控状态机（纯逻辑可单测）——视觉步骤确认后先"武装"门控，秤读数满足条件才放行入周期。两种门控: 去皮门控 tare（毛重超阈值且稳定→自动发去皮指令→放行）/ 称重判定 weigh（净重稳定→按型号×料别对比标准量→合格放行，缺料/超量报警拦截）。接线点在结算 mixin 的单步骤处理: 新出现步骤先查门控，未放行不写入周期（下帧重查），引擎未登记通道时直接放行绝不卡产线。steps_config[].device_gate 配置，默认无配置零开销早退；启停/强制结算统一清残留门控。前端: 步骤设置表新增「外设门控」列（弹层配类型/阈值/事件），称重配置页签在融合模式下复用出现（logic_mode 仍为 sequential）
  - 影响文件: backend/services/weighing_engine.py, backend/api/source_settlement_mixin.py, backend/api/source_project_config_apply.py, backend/api/source_state_init.py, backend/api/source.py, frontend/src/views/Project/StepsConfigTab.vue, frontend/src/views/Project/index.vue, tests/test_weighing_fusion.py

- [FEAT-002] 称重前置选择有效期 context_expiry（默认 never 零差异）
  - 需求: 客户诉求"上班没重新选型号要报警"——操作员/型号选一次永久有效会导致换班后沿用昨天的型号投料
  - 实现: 纯函数 context_expired 判定四种策略: never（默认，现行为）/ daily（每天 reset_time 后旧选择失效）/ shift（按班次表跨班次失效，支持跨午夜班次）/ hours（选择后 N 小时失效）；expire_fields 可配失效清哪些字段（默认只清型号）。选择时刻随 set_context 记录。前端称重配置页新增有效期策略区块
  - 影响文件: backend/services/weighing_engine.py, frontend/src/views/Project/WeighingConfigTab.vue, tests/test_weighing_fusion.py

- [FEAT-003] 视觉料源防错 visual_guard（动作×固定区域→料别/限区判定，默认关零差异）
  - 需求: 6.3 物料防错的 visual 档需要料别标签来源——百斯特现场料桶外观无差异，只能靠"舀料动作命中哪个盆的固定区域"推断料别
  - 实现: VisualGuardMatcher 纯逻辑判定器（射线法点在多边形内，不依赖 cv2）: mode=map 动作命中区域→上报料别标签走投错校验；mode=restrict 动作限区，区域外出现即报警；连续帧确认防单帧误检 + 规则级报警冷却。source=direct_label 支持料桶可视觉区分的客户（标签直接映射不画区域）。推理热路径每帧喂检测结果（flag 守门，未启用一次 getattr 早退零开销）。前端: 称重配置页规则表 + 复用主 ROI 编辑器画判定区域
  - 影响文件: backend/services/weighing_engine.py, backend/api/source_step_stats_mixin.py, backend/api/source_project_config_apply.py, frontend/src/views/Project/WeighingConfigTab.vue, frontend/src/views/Project/index.vue, tests/test_weighing_fusion.py

- [FEAT-004] MES 数据库直写适配器（第 6 种推送协议: database）
  - 需求: 客户 IT 不开 HTTP 接口，直接给一张关系库中间表（达梦）；要求事件数据直接 INSERT
  - 实现: DatabaseAdapter 注册进适配器注册表，支持达梦 DM/MySQL/PostgreSQL/SQL Server/SQLite；与 HTTP 适配器共用模板体系（template 顶层键名=目标表列名，_array_source 按数组逐行 INSERT 同一事务）；表名/列名白名单校验防注入；驱动按库型懒加载，未安装时报错直接写清要装哪个包；短连接不池化。前端网关面板新增「数据库直写」适配器类型及连接表单（库型/主机/端口/账号/库名/表名），HTTP 语义字段（URL/鉴权/健康探测等）对其隐藏
  - 影响文件: backend/services/mes_adapters/database_adapter.py (新增), backend/services/mes_adapters/__init__.py, frontend/src/views/MES/GatewayPanel.vue, tests/test_mes_database_adapter.py

- [FEAT-005] USB 报警确认按钮（扫码枪第 4 种用途 ack）
  - 需求: 称重缺料/超量/投错等 require_ack 报警定格后，现场需要一个物理按钮解除定格（操作员戴手套不便碰屏）
  - 实现: USB 扫码枪用途新增 ack——本质是只发固定码的 HID 按键，按一下走事件人工确认接口解除本工位定格；路由判定纯函数扩展（usage='ack' 短路，不进包装/拉单/绑定链路）；无待确认事件时温和提示不当故障。配套《按钮及配件选型》采购文档
  - 影响文件: frontend/src/composables/useScanGun.js, frontend/src/views/MES/UsbScanGunDialog.vue, docs/百斯特萍乡_按钮及配件选型.md

- [FEAT-006] 步骤消失等待不被打断 disappear_uninterruptible（步骤级布尔，默认关零差异）
  - 需求: 工具驻留画面的产线（滤网清洁: 吹枪插在工件上时并行做敲击/检查），"其他步骤一出现就掐掉消失等待"的规则 B 会把驻留步骤的闪断误判成消失→重现→首步提前结算
  - 实现: steps_config 步骤级开关，开启后该步骤消失等待不被其他步骤打断、按配置时长走完；配套守门——首步结算模式下开了此开关的首步持续可见期间重现不触发首步结算，只有真正走完消失结算后的再次出现才算新工件边界。前端步骤表 B 新增「等待不被打断」列
  - 影响文件: backend/api/source_step_stats_mixin.py, backend/api/source_settlement_mixin.py, backend/api/source_project_config_apply.py, frontend/src/views/Project/StepsConfigTab.vue, tests/test_disappear_uninterruptible.py, tests/e2e_browser/test_steps_disappear_uninterruptible.py

- [FEAT-007] 包装线复合条码取段 + 工单号识别规则（默认关/空零差异）
  - 需求: 正式产线箱标签是多段拼接码（订单|工单|数量|校验串），整串与工单号比对必不符；且开机后第一枪误扫数量/物料条码（如 '80.00'）会开出垃圾工单
  - 实现: 复合条码取段——按分隔符拆段，按前缀认段（多段命中取最长）或取第 N 段，取出工单段再走原有归一化；无分隔符的码原样通过，工单纸与箱标签可混扫，取段失败原样返回不吞码。工单号识别规则——归一化后须匹配正则才当工单，仅在无在途工单开第一单时校验，不符则报警忽略。配置 7 个新列（composite_* 6 个 + order_code_pattern），面板新增对应表单 + 取段预览
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/packaging_flows.py, backend/models/mes_models.py, backend/db/migrations/m0000_legacy.py, frontend/src/views/Settings/PackagingFlowPanel.vue, tests/features/packaging_composite_label.feature, tests/step_defs/test_packaging_composite_label.py

- [FEAT-008] 放工单=尾箱收尾动作 tail_paper_as_close_action（挂起快照闭环，子开关默认关）
  - 需求: 尾箱装满但"放工单"动作发生在周期结算之后——老 gate 拦下后无路可走，下个周期结算用新周期的滑块数（≈0）判 NG
  - 实现: gate 拦下时把被拦那次的滑块数/合格性存进运行态挂起快照，四个出口消化: ①后续周期探到放工单→按快照原成绩收尾；②扫码时探到放工单→快照收尾（扫的是新单则接着开新单）；③没放就扫新工单→尾箱判 NG 收尾留痕再开新单；④管理员强制结案→豁免 gate 按快照落账。同号重扫且仍没放只提醒继续等。仅 tail_paper_order_required 开时生效
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/packaging_flows.py, backend/models/mes_models.py, backend/db/migrations/m0000_legacy.py, frontend/src/views/Settings/PackagingFlowPanel.vue, tests/features/packaging_flow_sliders.feature, tests/step_defs/test_packaging_flow_sliders.py, tests/test_packaging_flow_coordinator.py

## Bug 修复

- [BUG-001] 放工单探测被上一周期缓存遮蔽
  - 症状: 尾箱挂起等放工单期间，操作员补放了工单但系统仍报"未检测到放工单"
  - 根因: 探测钩子优先读"上一个已结算周期"的步骤缓存，而补放动作恰恰落在当前还没结算的周期里，被缓存遮蔽
  - 修复: 探测钩子在缓存未命中时补查当前周期实时步骤集
  - 影响文件: backend/services/packaging_flow_coordinator.py
