# v3.49.0 (2026-08-12)

> 主题：**捷昌整改批次**——扫码/结算全链路去延迟（MES 外推并发派发 + 集群上报异步化 + scan_pair 新码先上屏）+ PostgreSQL 数据库支持落地（方言兼容/备份/迁移工具/安装器组件/Settings 数据库卡片）+ 双方言测试体系扩容与双后端可见 UAT。

## 功能变更

- [FEAT-001] MES 网关外推并发派发 + 落盘补发（WS1）
  - 需求: 客户 MES 接口慢/挂时，外推在 hook 队列里内联串行执行，堵住结算热路径（捷昌现场"扫码后卡好几秒"的嫌疑源之一）
  - 实现: 外推按连接甩到独立执行器并发派发，单连接慢死不影响其他连接与主链路；积压超上限落盘 `gateway_spool.jsonl`，恢复后自动补发；每连接可配重试预算 `retry_budget_sec`（存 config JSON，默认 0=不限，GatewayPanel 弹窗可编辑）；开关 `GET/PUT /api/v1/mes/gateway/async-dispatch`（存 SystemConfig `mes_async_dispatch`，默认开，显式关=回退旧内联派发）；box_complete 集群汇总推送同样走异步
  - 影响文件: backend/services/mes_hooks.py, backend/services/mes_gateway.py, backend/api/mes_gateway.py, frontend/src/views/MES/GatewayPanel.vue

- [FEAT-002] 集群副机上报异步化 + 落盘重放（WS2）
  - 需求: 副机→主机上报在结算路径内联 HTTP，主机慢/断网时拖垮副机结算；断网期间数据直接丢
  - 实现: 上报走独立线程 + 内存队列；发送失败落盘 `cluster_report_spool.jsonl`，恢复后按序重放；超时 `report_timeout_sec` 与异步开关 `report_async` 进 `/api/v1/cluster/config` 可配（默认异步开/超时 10s）；新增 `GET /api/v1/cluster/report-status` 暴露队列深度/落盘积压/累计补发；ClusterPanel 增设上报链路状态区（内存队列/落盘积压/已补发）
  - 影响文件: backend/services/cluster_collector.py, backend/api/cluster.py, frontend/src/api/cluster.js, frontend/src/views/MES/ClusterPanel.vue

- [FEAT-003] scan_pair 新码先上屏（WS3）
  - 需求: 捷昌第一工位反馈扫新码后条码迟迟不上屏——旧序是"先结算前一件（含慢 IO）→ 再顶替新码上屏"，前一件结算多慢、新码就多久不上屏
  - 实现: 新序改为"新码先顶替上屏 → 提交扫码状态 → 用显式 `prev_wp_id`/`prev_scanned_at` 异步结算旧窗口"；结算范围用显式身份钳制，杜绝顶替后误结算新工件；开关 `GET/PUT /api/v1/scanner/scan-pair/new-code-first`（存 SystemConfig `scan_pair_new_code_first`，默认开，关=回退旧序）；Settings 显示设置页新增两只开关（MES 并发派发 / 新码先上屏）；Monitor 当前条码 override 适配新序时序
  - 影响文件: backend/services/mes_hooks.py, backend/api/scanner.py, backend/api/source_session_lifecycle_mixin.py, frontend/src/views/Settings/index.vue, frontend/src/views/Monitor/index.vue

- [FEAT-004] 结算耗时埋点进调试日志中心（WS4）
  - 需求: 现场"卡"的口述无法定位到具体环节，需要量化的分段耗时证据
  - 实现: debug_center 新增 `backend.timing` 类目；扫码处理/窗口结算/MES 外推等关键路径打分段耗时点，调试日志中心可直接筛看；默认与既有调试日志开关联动，无额外常驻开销
  - 影响文件: backend/core/debug_center.py, backend/services/mes_hooks.py

- [FEAT-005] PostgreSQL 数据库支持（WS5，P0+P1）
  - 需求: 多工位并发写 SQLite 锁竞争 + 客户 IT 要求集中式数据库，PG 迁移是本批次最大风险项，需按"可回退、可验证"落地
  - 实现:
    - 方言兼容: `backend/db/sql_compat.py` 新增 `hour_minute`/`date_str`/`sum_bool` 方言助手；`export_context`/`external_alarm`（json_extract → SQLAlchemy JSON 索引）/`sessions`（like → ilike）收编
    - 备份链路: `/data/maintenance` 备份在 PG 下走 `pg_dump -Fc`（SQLite 保持文件级备份）
    - 运行时接入: Electron `backend-manager.js` 支持 `DATABASE_URL` 注入（环境变量或 `db_config.json`）；官方 PG 建库路径定论为 `create_all + apply_pending`（alembic 仅做 CI 基线校验），决策记录进 `backend/db/migrations/__init__.py`
    - 可视化: `GET /api/v1/system/db-info`（dialect/脱敏位置/服务端版本/连接池），Settings 性能设置页新增数据库卡片
    - 安装器: installer.iss 增加 PostgreSQL 可选组件（默认不选，选装才铺 PG）
    - 迁移工具: `scripts/db/sqlite_to_pg.py` 支持 `--dry-run`/`--verify`（逐表行数比对）、JSON 字段解码直写、孤儿外键扫描报告、迁移期 `session_replication_role=replica` 关 FK
    - 旁路队列决策: 短信离线队列/互连采样队列保持本地 SQLite（与主库解耦，不随 DATABASE_URL 走），决策注释入码
    - 插件 DDL 方言化: sensor-clean 示例插件建表语句改方言安全写法（AUTOINCREMENT → 方言 identity）
  - 影响文件: backend/db/sql_compat.py, backend/services/export_context.py, backend/services/external_alarm.py, backend/api/sessions.py, backend/api/sessions_maintenance.py, backend/api/system_display.py, backend/db/migrations/__init__.py, backend/services/sms_offline_queue.py, backend/services/interconnect/sample_queue.py, electron/backend-manager.js, electron/build/installer.iss, frontend/src/views/Settings/index.vue, scripts/db/sqlite_to_pg.py, plugins-examples/sensor-clean/backend/hooks.py

## Bug 修复

- [BUG-001] scan_pair 双通道广播下兄弟通道结算串身份
  - 症状: 广播模式（一支扫码器喂多工位）下，兄弟通道超时/停止结算时可能拿主通道的工件 ID 记账，记录归属错工件
  - 根因: 广播结算路径统一读 entry 里主通道的 `wp_id`，未按通道取各自的 `_inspecting_workpiece[channel_id]`
  - 修复: 结算身份改为 `_inspecting_workpiece.get(channel_id) or entry.get("wp_id")`，每通道各归各账；三窗金标准剧本（含双通道广播）回归锁定
  - 影响文件: backend/services/mes_hooks.py

- [BUG-002] 幽灵项目绑定拦住项目激活（PG 外键暴露的历史脏数据路径）
  - 症状: PG 下激活项目报 `detection_sessions_project_id_fkey` 外键违规；SQLite 因不强制 FK 一直静默容忍
  - 根因: 工位绑定配置里残留已删除项目的 `project_id`，`_channels_bound_to_other` 把幽灵绑定当作"被占用"参与判定
  - 修复: 绑定判定前查库校验项目存活，已删项目的绑定视为 stale 忽略；多通道有效绑定语义不变
  - 影响文件: backend/api/projects.py
