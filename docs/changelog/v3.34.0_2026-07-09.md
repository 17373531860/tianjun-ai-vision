> 主题：**电机装配线（对角打螺丝）真实模型上线打磨** —— 多轮次拆分/步骤时长门/严格顺序在客户真实 YOLO 模型 + 真实产线视频下暴露的一批误判逐一修复，全部默认关或零差异；同期新增「确认后保留周期（断点补做）」人工确认语义、区域事件秒基确认时长，交付电机装配线标注规范 v1.1 与现场部署指南，sensor-clean 插件 v1.4.2 定稿出厂值。

## 功能变更

- [FEAT-001] 事件人工确认新增「确认后保留周期（断点补做）」（`ack_keep_cycle`，默认关零差异）
  - 需求: 违序警告这类"中途拦截"事件，老语义确认即丢弃在制周期整件重做；现场更常见的诉求是工人确认后**从断点继续补做**（典型：违序定格 → 确认 → 接着打漏掉的那颗螺丝，整件照常判定）。
  - 实现: `events_config[*].ack_keep_cycle` 勾上后，人工确认（含超时自动确认）只解除定格、保留在制周期与全部步骤运行时；确认端点返回 `kept_cycle: true`。不勾走老"确认重做"路径（清运行时），零差异。前端事件卡片勾选框 + 说明文案 + 落库默认值补齐。
  - 影响文件: backend/api/source_event_trigger_mixin.py, backend/api/source_routes.py, backend/api/source_step_stats_mixin.py, frontend/src/views/Project/EventsConfigTab.vue, frontend/src/views/Project/index.vue, tests/test_event_ack_v39.py, tests/e2e_browser/test_events_config_tab.py
  - 关键词: ack_keep_cycle, 断点补做, 确认后保留周期, 人工确认, require_ack, 违序补做, keep cycle
- [FEAT-002] 多轮次拆分真实模型三防护：切换确认时长 + 切换标签置信度下限 + 归零守门（默认 0/零差异）
  - 需求: 电机装配真实模型 UAT 实测三类误判——① 单帧误检闪现（2 帧假"盖罩"）把轮次多推一拍；② 非切换阶段零星低置信度误检不停刷新"最近在场时刻"，真正切换永远凑不满离场 gap、轮次卡死；③ 工件刚开工、切换标签已离场而首颗螺丝还没进周期的空窗被误判"工件下线"，轮次刚推到 1 就被打回 0。
  - 实现: `rounds` 新增 `trigger_min_seconds`（切换标签重新出现后需持续在场满该秒数才确认切换，0=见帧即切）与 `trigger_conf`（切换标签专用置信度下限，低于按不在场，0=不过滤）；轮次归零加"本轮次内周期确实装载过步骤"守门。前端拆分编辑器补两个输入框 + 老规则缺省回填 0；多轮次开启时放行"区域名与原始标签同名"校验（最终名带轮次前缀不会自我映射，"力矩/标记只按轮次拆"场景的自然写法）。
  - 影响文件: backend/api/source_label_split.py, frontend/src/views/Project/LabelSplitDialog.vue, frontend/src/views/Project/labelSplit.js, frontend/src/views/Project/index.vue, tests/test_label_split.py
  - 关键词: trigger_min_seconds, trigger_conf, 轮次切换, 单帧误检, 轮次卡死, saw_cycle, 多轮次, label_splits, rounds, 切换确认时长
- [FEAT-003] 区域事件模式：确认时长秒基门槛 `min_seconds`（默认 0=老帧数语义）
  - 需求: `min_frames` 的实际时长 = 帧数/推理帧率，而现场相机帧率（24/30fps）和推理帧率（随 GPU 负载 15~30fps）都会漂，同一份配置在不同机器上门槛松紧不一致。
  - 实现: overlap/enter 规则可配 `min_seconds`，>0 时确认改按"episode 命中跨度 ≥ 该秒数"判定、与帧率解耦，`min_frames` 退化为 3 帧硬下限防杂散框蒙混。前端逻辑设置规则卡新增「确认时长（秒，0=按帧数）」输入框，0 值不落库不污染老配置。
  - 影响文件: backend/api/source_region_events.py, frontend/src/views/Project/LogicConfigTab.vue, frontend/src/views/Project/index.vue, tests/test_region_events.py, tests/e2e_browser/test_region_events_tab.py, tests/uat/uat_20260709_region_events_min_seconds.py
  - 关键词: min_seconds, 秒基门槛, 帧率解耦, region_events, 确认时长, min_frames, episode
- [FEAT-004] 结算调试可观测性三处加点（`backend.settlement` 开关守门，默认零开销）
  - 需求: 真实模型排障时缺"拆分层出口的唯一真相"——上游看模型、下游看状态机，中间改写层黑箱。
  - 实现: ① 拆分层出口 SplitOut 逐帧改写轨迹（仅标签集合变化的帧打点，防刷爆环形缓冲）；② 轮次切换标签每次在场留痕（conf + 是否低于下限 + 当前轮次，5s 节流）；③ 「步骤检出被拒」节流键带原因前缀，同一步骤的"时长门"与"离场清理"两条线索互不遮蔽；轮次切换/工件下线归零补 print 落日志。
  - 影响文件: backend/api/source_inference_loop_mixin.py, backend/api/source_label_split.py, backend/api/source_step_stats_mixin.py
  - 关键词: SplitOut, debug_center, backend.settlement, 步骤检出被拒, 调试打点, 轮次日志

## Bug 修复

- [BUG-001] 步骤时长门"幽灵起点"借尸还魂：0.24s 滑过被当成"已持续 135s"触发第一步重现结算
  - 症状: 真实模型 UAT 中某标签短暂滑过（0.24s，未过 min_duration 时长门）后，下一次真实出现瞬间越过时长门，甚至直接触发第一步重现结算，周期莫名切断。
  - 根因: "已确认但从未进入周期逻辑"的检出消失时不清理——确认态与原始起始时刻永久残留，该标签下次出现带着陈旧起点计算持续时长。
  - 修复: 时长门内的确认态标签离场超过本步骤"消失等待时间"后清理确认态/连续帧计数/原始起点（立即清会把时长门内的正常检测闪烁一并清掉、连续在场时长永远攒不满，故必须等离场确认）。
  - 影响文件: backend/api/source_step_stats_mixin.py
  - 关键词: 幽灵起点, min_duration, 时长门, 短暂滑过, step_raw_start, 借尸还魂, 第一步重现
- [BUG-002] 视频源帧号差耗时被时长门双重扣除：1.0s 真实步骤被量成 0.38s 判无效
  - 症状: 视频源回放（按帧号差算步骤耗时）配了 min_duration 后，真实持续 1.0s 的步骤耗时被量成 0.38s，低于门槛被判无效步骤。
  - 根因: wall 时钟起点取"首次出现的原始时刻"，帧位起点却在"过完时长门才正式处理"时才盖章——耗时先被扣掉整个门槛时长，结算时再对比 min_duration，双重惩罚。
  - 修复: 帧位起点与 wall 起点同刻记录（首次出现即存 `_step_raw_start_frame_pos`），结算两处取用点全部改走原始帧位，两种时钟口径一致。
  - 影响文件: backend/api/source_step_stats_mixin.py, backend/api/source_settlement_mixin.py
  - 关键词: 帧号差, min_duration, 双重惩罚, step_start_frame_pos, 视频源耗时, 步骤时长
- [BUG-003] 已完成步骤的余像重现被误报违序：严格+单次守门只对"提前出现"报警
  - 症状: 真实视频验证中，收尾标记笔迹持续在画面、工件横放中途被调整等"已完成步骤再次出现"的现场常态动作，被当场报违序警告，误报刷屏。
  - 根因: v3.32 严格+单次守门对一切错位出现都触发违序事件，未区分"提前出现"（真违规）与"已完成步骤余像重现"（补拧/笔迹残留/摆位调整）。
  - 修复: 只对"该步骤本周期还没做过"的提前出现报违序；已完成步骤的重现维持静默拦截不入周期（原防护语义不变），不再报警。
  - 影响文件: backend/api/source_settlement_mixin.py
  - 关键词: 违序误报, 严格顺序, 余像重现, strict_order_violation, 提前出现, accept_once
