## 重大变更（高层视角）

- **插件系统 (Plugin System) 落地**：从 `feat/plugin-config` 分支整合一套完整的"白标 / 客户定制"能力，
  支持 Tier 1 (主题) / Tier 2 (UI 扩展) / Tier 3 (全栈) 三层粒度，所有插件包必须经过
  RSA-PSS-SHA256 签名 + HMAC-SHA256 客户码绑定才能被后端加载。
- **数据库主线切到 PostgreSQL**：保留 SQLite 作为单机回退，同时完成 dialect-aware 引擎、
  Alembic 迁移、docker-compose 一键起 PG、SQLite→PG 数据搬迁脚本与多客户 schema 隔离方案。
- **GitHub Actions 双 workflow** 守护以上两块新基建：plugin-tooling（签名往返 + BDD）+
  db-matrix（SQLite + PG 双库矩阵），任一回归都会立刻在 PR 上拦截。

## 兼容性

- **数据库**：
  - 不设 `DATABASE_URL` 时仍回落到 SQLite，老用户单机部署零迁移
  - SQLite 数据可通过 `scripts/db/sqlite_to_pg.py` 一键搬到 PG，源文件不动
  - Alembic baseline = v3.7.0，老 SQLite 部署如想接入 alembic 管控，需先 `alembic stamp head`
    把当前状态打成 baseline
- **API**：
  - `/api/v1/plugins/*` 全部新增；不影响现有 18 组 API 路由
  - 测试态兼容路由 `RUNTIME_MODE=test` 才挂载，生产环境不暴露
- **前端**：
  - `usePluginStore` 是新增 store，老 Settings tab 行为完全保留
  - `licenseMismatch` getter 仅在"激活了插件 且 license 缓存有 customer 字段 且 二者不等"时为 true，
    UI 是新增 tag 警告，不影响其他流程
- **打包/分发**：
  - 现有 Inno Setup 安装包流程不变
  - 客户机如使用 PG 模式，需额外起 docker compose 容器或外接 PG 服务，
    详见 `docs/database-migration/README.md` 第 11 节
