# v3.37.0 (2026-07-14)

> 川南火工 v3.33 现场反馈整改版（对客户答复文档: `docs/川南火工问题答复_2026-07-13.md`）

## 功能变更

- [FEAT-001] 外部开工切项目后, 前端界面自动跟随（川南问题 1a）
  - 需求: 客户用 Postman 发开工请求, 后端项目实际已切换成功, 但检测中心/导航栏
    界面不刷新就一直显示旧项目, 现场误以为切换失败。
  - 实现: 导航栏每 5s 轻量轮询一次后端当前激活项目, 发现与前端不一致时把项目
    加载进前端各 store 并弹"项目已由外部系统切换"提示。跟随路径只对齐显示,
    不回调激活接口（后端已激活, 再调会无谓重载模型）; 与手动切换共用同一段
    项目装载逻辑（抽出 applyProjectToStores）。项目列表里没有的新项目会顺带
    刷新下拉。
  - 验证: 可见浏览器 UAT（uat_20260713_chuannan_fixes.py B 段 + prod_loop 全链路:
    mock 中控 → 后端 → 真浏览器不刷新 ≤10s 跟上）。
  - 影响文件: frontend/src/layout/Navbar.vue, frontend/src/api/project.js

- [FEAT-002] 工单接收新增「开工后自动开始检测」开关（川南问题 1b）
  - 需求: 客户希望开工指令直接把设备带进推理状态; 默认行为（只切项目+建任务,
    检测由现场控制）保持不变。
  - 实现: 入站配置新增键 start_detection_on_task（默认关）。开工任务处理成功后,
    对"视频源在跑 + 未在检测"的工位自动拉起检测, 模型就绪校验交给检测启动
    自身（与手动点"开始检测"同款）; 任何失败只记调试日志中心, 不影响开工响应。
    ⚠️ 拉检测前必须先提交本请求的 DB 事务——检测启动内部另开会话写检测记录,
    与未提交的工单写事务互斥, 会撞满 SQLite busy_timeout(15s) 导致上游中控
    误判超时（2026-07-13 UAT 逼出的真锁）。前端 MES 工单接收面板加开关 + 说明。
  - 验证: BDD 场景 15/16（开关开→拉起 / 默认关→不触碰）+ 单测 + 生产级 UAT
    三端联动（mock 中控 9100 → 后端 → 浏览器）。
  - 影响文件: backend/services/mes_inbound.py,
    frontend/src/views/MES/OrderInboundPanel.vue,
    tests/features/chuannan_mes_integration.feature,
    tests/step_defs/test_chuannan_mes_integration.py, tests/test_mes_inbound_unit.py

## Bug 修复

- [BUG-001] 推理链路"框卡死"自愈防线（川南问题 6）
  - 症状: 识别某类别后检测框冻结在画面上, 后续类别全不识别, 周期照样超时 NG;
    现场极易误判为模型问题（客户说 3.19 没有）。
  - 根因: 推理循环每帧异常时, 发布点永远走不到, 上一次发布的检测结果被反复
    重发布, 前端框永久定格。根因待客户提供调试日志/录屏后定位（答复文档已列
    取证清单）。
  - 修复: 推理线程连续 30 帧异常时主动发布空检测结果（清空画面残留框, 一眼
    看出是链路故障而非模型不识别）+ 调试中心留证（含最后一次异常详情）。
    走通一轮即计数归零, 单帧偶发异常行为与老版完全一致。
  - 验证: tests/test_inference_error_clear.py 用 synthetic 源真跑推理线程,
    注入"每帧必炸"验证 框出现→清空→计数达阈值。
  - 影响文件: backend/api/source_inference_loop_mixin.py

- [BUG-002] 新建项目弹窗"图像分割"被误禁用且误标"语义分割"（川南问题 5）
  - 症状: 新建项目时任务类型第二项显示"语义分割"且不可选, 客户以为分割能力
    没了。软件分割能力（YOLO-seg 实例分割）本身一直正常, 只是新建入口被封。
  - 根因: 下拉选项写死 disabled + 命名错误（实际是实例分割不是语义分割）。
  - 修复: 恢复可选, 文案改为"图像分割 (Instance Segmentation)"。
  - 验证: UAT C 段（弹窗下拉真点开、选项可选）。
  - 影响文件: frontend/src/views/Project/CreateProjectDialog.vue

- [BUG-003] 导航栏右上角 Logo 内置回退在打包版失效（v3.36.0 回归）
  - 症状: v3.36.0 上"Logo 自定义上传"后, 未上传过自定义 Logo 的打包版右上角
    图标消失（开发环境正常, 所以当时 UAT 没拦住）。
  - 根因: 右上角图标从静态地址改成运行时表达式 `logoDataUrl || '/app-icon.png'`
    后, 字符串字面量 Vite 构建期改写不到; 打包版页面走 file:// + 相对 base,
    以 / 开头的地址解析到系统盘根目录 → 内置图标 404 → 空白。改动前的静态
    src 会被 Vite 编译成 `new URL(..., import.meta.url)` 所以没这个问题。
  - 修复: 回退地址改用 `import.meta.env.BASE_URL + 'app-icon.png'` 构建期注入
    （dev 下 '/'、打包后 './'）, Navbar 与设置页 Logo 预览两处同修。
  - 验证: 可见浏览器 UAT 6/6（dev 下内置图标真实加载 naturalWidth=256 /
    自定义 data URL 优先 / 清空后回退）; `npm run build` 后用 file:// 直开
    dist 复刻 Electron 语义, 图标加载成功; 新增 CI E2E 2 用例锁回归。
  - 影响文件: frontend/src/layout/Navbar.vue, frontend/src/views/Settings/index.vue,
    tests/e2e_browser/test_navbar_logo.py, tests/uat/uat_20260714_navbar_logo_fallback.py
