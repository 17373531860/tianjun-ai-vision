# v3.51.5 (2026-08-17)

> 捷昌 B 站现场补丁收编版：v3.51.3a / 3.51.3b / 3.51.3c 三个现场热补丁全量收编进主线 + 详细调试日志体系 + 捷昌三通道打包线标注规范交付。全部为 bug 修复与可观测性增强，无新功能开关，升级零配置差异。

## Bug 修复

- [BUG-001] 双工位重启后相机/模型串位（v3.51.3a 收编）
  - 症状: 双工位各绑各的相机+模型，关软件重开后左工位显示的是右工位的视频流和模型，右工位黑屏；切页再回来也不对
  - 根因: 前端 Monitor `autoRestoreSource()` 的单工位 localStorage 兜底逻辑在多工位模式下照跑，拿着**上次单工位时代缓存的 device_index** 抢先 `camera/start`，与后端权威的多通道恢复赛跑，把工位 0 的相机抢成了别人的
  - 修复: `autoRestoreSource()` 先查后端 `channel_count`，多工位模式直接跳过 localStorage 兜底（单工位行为不变）；后端 `auto_restore_video_sources` 对"通道已跑但相机 index 与落盘配置不符"打警告日志
  - 影响文件: frontend/src/views/Monitor/index.vue, backend/main.py

- [BUG-002] 启动恢复慢、画面要切页才出、模型双重加载（v3.51.3b 收编）
  - 症状: 重启后视频源加载 30 秒+，加载完监控页仍黑屏，必须切走再切回才出画面
  - 根因: 三处叠加——① 后端开机自动加载先载原始 `.pt`、项目激活又重载转换后的 TensorRT 引擎，模型双重加载+双重预热；② 前端进页时后端未就绪，`fetchChannelCount` 一次失败就把 UI 锁死在单工位模式；③ 通道 `is_running` 迟到变 true 时前端不重连 MJPEG 流
  - 修复: ① `_resolve_startup_model_path` 按 `model_format` 直接解析转换引擎（GPU 架构匹配才用），`_load_channel_model_with_fallback` 引擎加载失败自动回退 `.pt`；② `fetchChannelCount` 失败后 3 秒重试；③ `processChannelResult` 检测到 `is_running` false→true 跳变即重置零帧计数、断开旧连接、`syncMultiStreams()` 强制重连
  - 影响文件: backend/main.py, frontend/src/views/Monitor/index.vue

- [BUG-003] 自动恢复反复覆盖用户的停止/待机操作（v3.51.3b 收编）
  - 症状: 现场点"停止"或"待机"后，几秒内软件又自动点回"开始"，反复几轮很难把检测停下来
  - 根因: 开机恢复的多轮重试 `_restore_detection_pass` 只认"检测没在跑就拉起"，分不清"源没就绪"和"用户手动停了"
  - 修复: 记录本函数自动拉起过的通道及其 capture 线程 id；下轮发现检测停了**而线程没换**（说明源没重启过、是人停的）→ 记入 `user_vetoed`，后续轮次不再碰该通道；源真正重启（线程换了）仍正常恢复
  - 影响文件: backend/main.py

- [BUG-004] 绑定项目等部分更新会整写抹掉工位相机配置（v3.51.3c 收编）
  - 症状: 配好双工位相机后在源设置绑定项目，重启后 `workstation_config.json` 里 `source_type`/`device_index`/`resolution` 全没了，相机不自动恢复、黑屏
  - 根因: `PUT /workstations/channel-config` 固定 `merge=False` 整写语义，只带 `project_id` 的部分更新也把该工位源配置段整段覆盖
  - 修复: `save_channel_config` 按请求体有无 `source_type` 判定：有 = 完整源配置写入保持整写；没有 = 部分更新转 `merge=True` 只更新给的键
  - 影响文件: backend/api/channel_manager.py

- [BUG-005] 多工位下"记录全删了还被强制去重拒码"（v3.51.3c 收编）
  - 症状: 广播扫码一拒一收；操作员把 MES 工件追溯"全选批量删除"后重扫同码仍被拒，找不到挡在哪
  - 根因: 工件追溯页默认开"仅当前项目"过滤，而"当前项目"只是最后激活的项目——多工位各绑各的项目时，其它工位项目的 ok 工件被藏在列表外，批量删除删不到它们，`strict_ok_dedup` 查库仍能查到 → 持续拒码
  - 修复: `WorkpiecePanel` 挂载时查工位数，`channel_count > 1` 时默认关闭"仅当前项目"过滤，所有项目工件默认可见可删；单工位保持原默认
  - 影响文件: frontend/src/views/MES/WorkpiecePanel.vue

## 功能变更

- [FEAT-001] 详细调试日志体系（现场问题定位留痕）
  - 需求: 现场反复出现"配置被抹/拒码找不到原因/枚举回退无感知"类问题，日志不够定位
  - 实现: ① 工位配置每次写盘打 `[ChannelCfg]` 日志（整写/合并写模式 + 写入键 + 整写丢弃的旧键）；② `strict_ok_dedup` 拒码日志带全量依据（项目号/工件号/登记与最后检测时间/两条解除方法）；③ 相机 ffmpeg 枚举解析为空时留 stderr 头部、走试开法兜底时明示；④ 工件追溯页过滤决策进调试日志中心（`mes.workpiece` 标签）
  - 影响文件: backend/api/channel_manager.py, backend/services/mes_hooks.py, backend/api/source_routes.py, frontend/src/views/MES/WorkpiecePanel.vue

- [FEAT-002] 捷昌 B 站三通道打包线标注规范交付（文档，不影响软件行为）
  - 需求: 捷昌 B 站扩为三通道（一工位/二工位大件/二工位小件），黑款模型已有、白款待训；现役黑款小件模型在实拍视频上实测螺钉包 0 检出、螺钉位满判空、水杯架检出闪烁，需重训补数据
  - 实现: 产线总规范 + 二工位小件独立规范 v1.0（9 类 id 对齐现役模型 / 状态互斥对规则 / 按实测弱点定向配重 / 12 张实拍示例图含正误对照）+ 通用 MD→带图 PDF 生成器
  - 影响文件: docs/customers/捷昌/标注规范_捷昌B站打包线.md, docs/customers/捷昌/标注规范_捷昌B站_二工位小件.md(+.pdf), docs/customers/捷昌/标注规范assets_二工位小件/(12图), scripts/docgen/gen_jc_annotation_spec_pdf.py
