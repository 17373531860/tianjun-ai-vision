# v3.39.0 (2026-07-16)

> 主题：**萍乡百斯特两阶段流水线称重 + 川南在途报警出口与显示定制**——称重投料模式新增 `drive_mode='pipeline'`（秤上称重结算 + 秤下收尾动作结案，两件并行，秤指令严格重量驱动）；川南反馈三件套：在途报警软件内消除出口、开工自动开始检测"暂停源复活+原因回带"、监控页任务信息条显示定制（工单徽标可隐/两行表格布局/扫码按钮可隐）。

## 功能变更

- [FEAT-001] 两阶段流水线称重模式（萍乡百斯特，drive_mode='pipeline'）
  - 需求: 萍乡百斯特产线事实是"工件坐秤装料的同时，上一件在压机侧加钢脚水泥收尾"——同时最多两件在制，经典逐道投料状态机（放件→去皮→投料→判定逐道推进）套不上；且现场要求秤指令（去皮 T / 清零 Z）全自动发出、模型漏检不能影响称重主链路。对应《萍乡百斯特称重×视觉联动完整方案 v1.5》。
  - 实现: 称重引擎新增流水线工位状态机（空秤→装料→离秤确认三相位）：上秤自重进皮重合法范围且稳定→自动发去皮指令进装料相位（视觉"工件上秤"标签作加速/双确认佐证，可配秤台区多边形过滤别处拿件误报）；离秤瞬间冻结重量事实并判 OK/NG（record 落库 + 合格件借主程序 OK 事件响应面亮绿灯），随后进"待收尾队列"（FIFO）；视觉识别到收尾动作（加钢脚水泥）时结案队头件并推 MES（结案状态 confirmed），超时未见收尾按"收尾未确认"结案+报警。清零调度/归零验证/自动重发/残留报警、快手兜底（Z 未发新件已上秤→取消清零皮重差值折算；Z 已发→正读数直接确认零点绝不重发）、两种作业习惯（秤上装料/拿下装料）兼容、装料超时与队列超深节拍报警齐全。秤指令时序 15 项参数全部现场可调（去皮触发源三档/稳定窗/离秤确认/清零延迟与重发/标签连续帧与冷却期等）。配置重载保留待收尾队列（已冻结的事实不丢）。逐件记录人员归属未显式选人时自动落当前登录用户。
  - 前端: 项目称重配置页新增"驱动模式"选择 + "流水线参数"卡（三标签绑定/判定料别/皮重范围/队列深度/秤台区 ROI 复用统一编辑器）+ "秤指令时序"卡（15 项）；监控页称重面板流水线看板（秤上件/有效读数/待收尾队列/最近结算，隐藏扫码开始入口，件号自动生成）。
  - 影响文件: backend/services/weighing_engine.py, backend/api/source_project_config_apply.py, frontend/src/views/Project/WeighingConfigTab.vue, frontend/src/views/Project/index.vue, frontend/src/views/Monitor/WeighingPanel.vue, tests/test_weighing_pipeline.py, tests/features/weighing_pipeline_baist.feature, tests/step_defs/test_weighing_pipeline_baist.py, tests/e2e_browser/test_weighing_pipeline_tab.py, tests/uat/uat_weighing_pipeline.py

- [FEAT-002] 在途报警软件内消除出口（川南反馈）
  - 需求: 川南范式下报警只能由外部生产管控系统回推消除；上游不回推时报警横幅一直挂着，软件内没有任何出口，联调/现场运维被卡死。
  - 实现: 两个出口都默认关（保持"只能外部消除"的对接契约），入站配置页按需打开：① `alarm_banner.allow_manual_clear` 开时监控页报警横幅出现"手动消除"按钮（带确认弹窗，前端配置开关 + 后端 403 守门 + 权限对齐监控页清零三重闸）；② `alarm_banner.clear_on_counter_reset` 开时监控页"清零"顺带消除全部在途报警。服务层新增"一键清空在途报警"入口（与按键匹配消除语义刻意分开，留消除来源字段审计）。
  - 影响文件: backend/services/external_alarm.py, backend/api/mes_inbound.py, backend/api/source_routes.py, backend/services/mes_inbound.py, frontend/src/api/gateway.js, frontend/src/views/Monitor/ExternalAlarmBanner.vue, frontend/src/views/MES/OrderInboundPanel.vue, tests/test_alarm_manual_clear.py, tests/uat/uat_20260715_alarm_manual_clear.py

- [FEAT-003] 开工自动开始检测：暂停源复活 + 未拉起原因回带响应（川南反馈）
  - 症状: 现场点过一次"停止"后视频源暂停，之后每次外部开工都拉不起检测；且开关开了没拉起时上游只看到 ok，完全无从排查（原因只进调试日志）。
  - 根因: 老逻辑把"源未运行"一律当不满足门槛跳过，而手动点"开始"走的 start_detection 本就有暂停续播/相机重连的复活路径；未拉起原因不回传。
  - 修复: 只要配置过视频源就放行交给 start_detection 复活（与手动行为完全一致），仅"从没配置过源"才跳过；模型未就绪给出指路原因（提示到项目管理配默认模型）；全部未拉起原因附在开工成功响应文案后（业务码不变，上游按 code 判成败不受影响），一次请求即可自诊。
  - 影响文件: backend/services/mes_inbound.py, tests/test_mes_inbound_unit.py, tests/test_alarm_manual_clear.py

- [FEAT-004] 监控页任务信息条显示定制（川南反馈"信息显示不全"）
  - 需求: 开工四要素 + 工单徽标挤在信息条一行里被截断，客户要求只留任务要素且字段多也不截断。
  - 实现: 入站配置任务信息条新增两个显示层开关（默认值均 = 原界面，其他客户零感知）：`show_order_chip` 关 = 信息条不显示"工单 单号 进度 良率"块；`two_line_layout` 开 = 任务要素改为"表头一行+信息一行"表格布局。
  - 影响文件: backend/services/mes_inbound.py, frontend/src/views/Monitor/index.vue, frontend/src/views/MES/OrderInboundPanel.vue, tests/e2e_browser/test_task_info_layout.py, tests/uat/uat_20260715_task_info_layout.py, tests/uat/uat_20260715_cn_real_video_display.py

- [FEAT-005] 监控页扫码操作按钮可隐藏（川南反馈）
  - 需求: 现场操作员不碰软件的部署，"清除本次扫码/禁用扫码"按钮容易误触。
  - 实现: 系统设置显示项新增"扫码操作按钮"开关（默认显示 = 原界面），关闭后监控页单/多工位视图的扫码操作按钮全部隐藏。
  - 影响文件: frontend/src/store/useSystemStore.js, frontend/src/views/Settings/index.vue, frontend/src/views/Monitor/index.vue, tests/e2e_browser/test_task_info_layout.py
