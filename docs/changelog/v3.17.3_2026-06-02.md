# v3.17.3 (2026-06-02)

## Bug 修复

- [BUG-001] 插件前端资源被 Electron 打包环境 HTTP 缓存焊死，换包/升级永不生效
  - 症状: 客户机金龙插件升到 1.3.0 后「步骤设置表三档耗时配置列」始终不出现；卸载、重装、重启软件、换不同版本的包反复折腾都没用；开发机一切正常。客户机日志 `register()` 只注册出 `monitor.layout.body` 一个槽，没有 `project.step-cell.durations` 三档槽。
  - 根因: 前端插件加载器拉 ESM 的 `fetch(url, { credentials: "omit" })` 未禁用缓存，后端发资源的 `FileResponse` 也未设禁缓存响应头。打包后主窗口走 `file://`、跨源拉 `http://localhost:8001` 资源，Chromium 缓存策略激进，把第一次装上的旧 ESM 焊死；之后磁盘文件确实被换成新版（PowerShell 实测磁盘文件 53039 字节、含三档代码），但 fetch 始终命中缓存返回最早那份旧文件（字符数 39104、不含三档注册），于是三档槽永远注册不上。开发机走 vite 开发服务器默认不缓存，故无法复现——典型「开发机好、客户机坏」的打包环境专属陷阱。
  - 附带澄清: 加载日志 `ESM 文本已拉到 {"bytes": N}` 的 `N` 实为 `text.length`（字符数，中文按 1 算），并非字节数；本次排查初期被该误导性字段名带偏，已在日志注释标清。
  - 修复: 前端 `fetch` 加 `cache: "no-store"`，后端 `FileResponse` 加 `Cache-Control: no-store, no-cache, must-revalidate, max-age=0` + `Pragma`/`Expires`。每次回源读磁盘最新文件，彻底消除缓存焊死。现场止血办法=完全退出软件后删 Electron 缓存目录（`%APPDATA%\tianjun-ai-vision\{Cache,Code Cache,GPUCache}`）再启动，已验证清缓存后字符数 39104→真实值、三档槽注册成功。
  - 影响文件: frontend/src/composables/usePluginLoader.js, backend/api/plugins.py

## 已知问题

- 插件安装/卸载仍用「整目录 rename」替换，Windows 上若插件后端模块已被进程 import 持有，文件操作可能失败；本版未触及该路径（本次问题实为缓存、非文件锁，磁盘文件已成功替换）。后续可改为「下次启动、加载插件前」切换 + 失败显式报错。
