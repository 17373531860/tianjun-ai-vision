# v3.48.0 (2026-08-10)

> 本版是一次**三分支汇合发版**：吸收 `SY9`（上银包装线记账精度整改）、`feat/tianyong`（RFC 13 通用 PLC 连接器 + RFC 14 统一触发中心 + 计数组合判定表）、`dev-qing`（Modbus 完成脉冲 + 短信汇总形态）三个并行分支，逐分支合并逐分支回归。SY9 迁移因与主线撞号由 m0006 改编号 m0009。

## 功能变更

- [FEAT-001] RFC 13 通用 PLC 连接器（8 协议驱动 + 点位/规则全可配 + 方案模板）
  - 需求: 客户产线 PLC 对接需求百花齐放（读产品号绑码、完成信号触发、结果码回写、心跳握手），此前只能逐客户写死代码
  - 实现: `/api/v1/plc/*` + `plc_connections` 表整表 JSON 配置化——8 种驱动（modbus/s7/mc/fins/enip/opcua/mock，依赖懒加载缺库不炸主程序）；点位引擎（536 行）按点位表批量读 → 编解码（int16/32/float/string × 4 种字节序 × scale）→ 值变化沿评估规则（防抖/min_interval）→ 动作（bind_sn 绑码建工件 / trigger_event / manual_settle 等）；事件写回 `dispatch_plc_event`（mes_hooks 触点 enqueue 级非阻塞、内部全兜底永不抛）；s7_db_handshake V0.2 方案模板一键套用。MES 页新 PlcPanel 面板（连接卡片/点位实时值/IO 日志/试读试写）。默认无连接零开销
  - 影响文件: backend/services/plc/*（14 个新文件）, backend/api/plc.py, backend/schemas/plc.py, backend/models/plc_models.py, backend/services/mes_hooks.py, backend/main.py, backend/api/router_manifest.py, frontend/src/views/MES/PlcPanel.vue, frontend/src/api/plc.js, backend/requirements.txt

- [FEAT-002] RFC 14 统一触发中心（6 种触发源 × 全局动作注册表）
  - 需求: 现场"人工确认/手动结算"的物理入口五花八门（手遮画面、脚踏板、中控调接口、串口报文、定时清零），此前各自为战
  - 实现: `/api/v1/triggers/*` + `trigger_channels` 表——6 种触发源（pixel_region 画面像素区域遮挡带参考帧缓漂 / hid_key 脚踏板 / http 带 IP 白名单+变量提取 / serial_pattern 串口正则 / timer 间隔+每日定点 / mock）× 全局动作注册表（manual_settle/trigger_event/ack_alarm 等，与 PLC 规则共用）；规则层防抖/min_interval/生效时间窗。系统设置新 TriggerPanel 面板（类型化参数表单 + 模板 + 触发历史）。工位裁撤挂 `on_channel_removed` 第 5 处配套清理。默认无实例零开销
  - 影响文件: backend/services/triggers/*（13 个新文件）, backend/api/triggers.py, backend/schemas/triggers.py, backend/models/trigger_models.py, backend/api/channel_manager.py, backend/main.py, frontend/src/views/Settings/TriggerPanel.vue, frontend/src/api/triggers.js, frontend/src/store/usePollingStore.js

- [FEAT-003] 计数组合判定表（检测模式纯视觉判型）+ positional 位置去重计数口径
  - 需求: 缸体判型类场景——同一工位混流多种型号，按"各标签计数组合"判 OK/NG 并打型号 tag（如 5+5+0=4缸、7+7+6=6缸含挺柱）
  - 实现: `pipeline_config.combo_table`（labels × rows[counts, verdict, tag]）结算时匹配计数组合出判型；计数口径二选一——steps（按步骤账本）/ positional（新增 `source_combo_positional.py` 位置去重追踪器：IoU 匹配已知位置 + EMA 平滑 + 连续 N 帧确认，治同一位置反复计数），positional 六追踪参数 UI 全可配；推理循环喂帧 None 早退零开销
  - 影响文件: backend/api/source_combo_positional.py（新）, backend/api/source_project_config_apply.py, backend/api/source_settlement_mixin.py, backend/api/source_inference_loop_mixin.py, frontend/src/views/Project/LogicConfigTab.vue, frontend/src/views/Project/index.vue, tests/test_combo_table.py

- [FEAT-004] 容器装箱清点：槽位完整性门 + 物品/托盘去重 IoU 阈值可配 + 预计进箱数字（上银 SY9）
  - 需求: 上银现场滑块密排遮挡残数/模型重复框，需要更细的记账精度工具
  - 实现: ①槽位完整性门（默认关）——本帧"货数+空槽数=槽位数"才采信，影子峰值兜底绝不漏账、两盘同框空槽按中心归属不串盘（UI 带 2026-08-05 实测警示：空槽召回不足时反而更差，慎开）②物品框/托盘框去重从硬编码改 IoU 阈值可配（缺省 0.45/0 = 双边客户零差异）③监控页容器卡新增预计进箱数字（结账同源口径）
  - 影响文件: backend/api/source_custom_mix.py, frontend/src/views/Project/LogicConfigTab.vue, frontend/src/views/Project/index.vue, frontend/src/views/Monitor/CustomMixItemPanel.vue, tests/test_custom_mix_unit.py

- [FEAT-005] 放工单只认"等收尾之后"的出现（tail_paper_only_after_awaiting，默认关）
  - 症状: 尾箱周期里"放工单"误检一次，工单当场收尾，工人其实没放也没人提醒
  - 实现: 开关开时尾箱落账一律先挂「等放工单收尾」，历史检出一概不算、非等待态检出整条丢弃（连提前放工单报警也不报）；代价是工人必须封箱后再放工单。默认关 = 老行为零差异。迁移 m0009（SY9 分支原编号 m0006，吸收时与主线 m0006_sms_report_content_template 撞号改号）
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/packaging_flows.py, backend/models/mes_models.py, backend/db/migrations/m0009_pkg_tail_paper_only_after_awaiting.py, frontend/src/views/Settings/PackagingFlowPanel.vue

- [FEAT-006] Modbus 完成脉冲外设协议 + 逐件覆盖联动（modbus_pulse，dev-qing）
  - 需求: 打螺丝现场打完最后一颗要 PLC 立刻吹气/放行，等周期结算太慢
  - 实现: 外设新协议 `modbus_pulse`（400 行）——设备线程持 Modbus TCP/RTU 连接，脉冲=写线圈 ON→pulse_ms→OFF，cooldown_ms 冷却窗丢重复，断线自动重连；per_item 两触发点（all_covered 首次全覆盖那一帧带同周期边沿锁 / cycle_ok 判 OK 落账），推理线程只入队不阻塞；面板可配置/手动试发。附台达 ES3 对接文档（含 PLC 侧程序附录）
  - 影响文件: backend/services/external_device_pulse.py（新）, backend/services/external_device.py, backend/services/external_device_models.py, backend/services/external_device_protocols.py, backend/api/source_per_item_mixin.py, backend/api/external_device.py, frontend/src/views/MES/ExternalDevicePanel.vue, docs/PLC完成脉冲对接指南_台达ES3.md, tests/test_external_device_modbus_pulse.py

- [FEAT-007] 短信汇总发送形态：合并分列 / 逐工位 + 参与工位筛选（dev-qing）
  - 需求: 多工位现场 12h 汇总短信要么全挤一条看不清工位，要么想按工位发给不同负责人；部分工位不值得发短信
  - 实现: `summary_form` 二选一——merged_detail（默认，一条内按工位分列明细）/ per_channel（逐工位逐条）；`summary_channel_ids` 限定参与汇总的工位（空=全部）。Alarm 页配置卡同步
  - 影响文件: backend/services/sms_service.py, backend/services/sms_config.py, backend/services/sms_summary.py, backend/schemas/sms.py, frontend/src/views/Alarm/index.vue
