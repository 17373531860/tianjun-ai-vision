# v2.7.12 (2026-04-23)

## Bug 修复

- [BUG-001] 工单"新建工单"对话框输入框全部看不见
  - 症状: 打开工单管理 → 新建工单, 产品名称/工单号/产品编码/规格/计划数量/优先级/备注 7 个字段的输入框完全消失, 只剩标签, 无法输入
  - 根因: `DynamicFieldInput` 函数式组件使用 `h('el-input', ...)` 字符串组件名写法. 在 Vite + ElementPlus auto-import 组合下, 字符串组件名不会被运行时解析, 结果渲染出空节点 (之前 GatewayPanel/ScannerPanel 类似 bug 修过, 这里漏了一处)
  - 修复: 显式 `import { ElInput, ElInputNumber, ElDatePicker, ElTimePicker, ElSwitch, ElSelect, ElOption } from 'element-plus'`, 把 `h('el-input', ...)` 全部改成 `h(ElInput, ...)` 等对象引用
  - 影响文件: `frontend/src/views/MES/OrderPanel.vue`
  - 关键词: DynamicFieldInput, 新建工单, 输入框隐形, h 渲染函数, el-input 字符串, ElementPlus auto-import, functional component

- [BUG-002] 计划数量字段显示 0.00 两位小数
  - 症状: 新建工单中"计划数量"默认显示 `0.00`, 整数也被强制带小数
  - 根因: `DynamicFieldInput` 对所有 `type: 'number'` 字段固定设 `precision: 2`
  - 修复: `planned_qty` 单独判分支, 走 `precision: 0` + `step: 1`
  - 影响文件: `frontend/src/views/MES/OrderPanel.vue`
  - 关键词: planned_qty, 计划数量, precision, 小数, ElInputNumber

- [BUG-003] 集群"目标明细"同一条码出现多条同通道、OK/NG 同时并存
  - 症状: 工位 B/C 下"通道 3"出现多行, 同一条码 sub_reports 里既有"缺东西"又有"已完成"
  - 根因: `cluster_collector._receive_station_report_locked` 每次把新 sub_reports 直接追加, 没按 (channel_id, source_address) 去重, 导致同一物理通道多次推送全部累积
  - 修复: 按 (channel_id, source_address) 去重, 保留最后一条覆盖旧条目
  - 影响文件: `backend/services/cluster_collector.py`
  - 关键词: 集群汇总, 目标明细, sub_reports, BoxAggregation, 去重覆盖, 串扰

- [BUG-004] 扫码器重复扫码导致 A 物品占位不消费, 产生脏记录
  - 症状: A 扫码 → A 完成 OK → 移走 A 途中再次扫到 A → 新物品 B 进来被判成 A 的延续, A 在 DB 里留"queued 但不会消费"的垃圾记录
  - 根因: `mes_hooks._handle_scan` 无冷却窗口, 已 OK 的工件被重扫时会被重新置 queued, 占位位被 B 的检测结果填入
  - 修复: `ScannerConnection` 新增 `ok_rescan_cooldown_sec` 字段 (int, 默认 0 = 不开启), 在冷却窗口内对同条码重复扫码静默忽略; NG 不受影响以便纠错重扫
  - 影响文件: `backend/services/scanner.py`, `backend/services/mes_hooks.py`, `backend/api/scanner.py`, `backend/models/mes_models.py`, `frontend/src/views/MES/ScannerPanel.vue`
  - 关键词: 扫码器, 重复扫码, 冷却时间, ok_rescan_cooldown_sec, 脏记录, queued workpiece, 去重

- [BUG-005] Monitor 页面检测结果一闪而过 (1.2 秒就回"等待扫码...")
  - 症状: 工件检测完成后, 步骤结果图标和"动作合格"状态 1200ms 就被清空, 肉眼看不清
  - 根因: 原逻辑在 cycle 完成后固定 1200ms 清理 `workpieceOverride`
  - 修复: 延长到 3.5s; 期间若新条码到达直接覆盖, 不会卡死下一轮
  - 影响文件: `frontend/src/views/Monitor/index.vue`
  - 关键词: Monitor, 结果显示时长, 3.5s, workpieceOverride, 等待扫码

## 功能变更

- [FEAT-001] 外部 MES 适配器新增 2 种参数形式 (共 4 选 1)
  - 需求: 客户答复 "POST body + param" 已被现有 Form-Data 覆盖; 但新客户可能说"字段平铺不要打包"或"参数放 URL 里", 需要前端直接切换无需改代码
  - 实现:
    - `FormUrlencodedAdapter`: 把 payload 每个字段平铺成 `order_no=xxx&result=NG&missing_items=A,B`, 自动 url-encode; 数组支持逗号/JSON 串两种拼接模式
    - `QueryStringAdapter`: 把 payload 全部塞到 URL query, body 为空, POST/GET 都支持
    - 在 `mes_adapters/__init__.py` 注册为 `form-urlencoded` / `query-string`
    - 前端 GatewayPanel 适配器选项从 3 个扩到 5 个 (REST/JSON · Form-Data · Form 平铺 · URL 参数 · Modbus), 对应 HTTP 请求在客户界面有一句话说明 + 例子
  - 影响文件: `backend/services/mes_adapters/form_urlencoded_adapter.py` (新增), `backend/services/mes_adapters/query_string_adapter.py` (新增), `backend/services/mes_adapters/__init__.py`, `frontend/src/views/MES/GatewayPanel.vue`
  - 关键词: MES, 适配器, form-urlencoded, query-string, 4 种参数形式, 适配器注册表, POST body param

- [FEAT-002] 集群箱数据管理: 按条码删除 + 批量清理
  - 需求: 用户要求"一个条码当新条码重扫" (删除所有历史记录) 和"批量清理" (按 scope 清)
  - 实现:
    - `DELETE /cluster/box/{barcode}` - 删除指定条码的 BoxAggregation + BoxSummary
    - `POST /cluster/boxes/clear` - scope=all/pending/recent/older, `older` 支持 `before_days`
    - ClusterPanel 前端加"清理"按钮 + 批量清理对话框
  - 影响文件: `backend/api/cluster.py`, `frontend/src/api/cluster.js`, `frontend/src/views/MES/ClusterPanel.vue`
  - 关键词: 集群汇总, 批量清理, BoxAggregation, BoxSummary, 按条码删除, scope
