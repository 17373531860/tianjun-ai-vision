# v3.5.0 (2026-05-06)

## 功能变更

- [FEAT-001] 自定义导出 / 客户模板系统
  - 需求: 客户要求"从固定文件夹提取 SN.txt → 检测后改写测试结果/各项检测值/程序版本号"，
    并希望通用化为"在数据中心可选输入文件、输出格式、自由编辑输出内容"。
  - 实现:
    - 新增 ORM: `ExportTemplate` (模板)、`ExportRealtimeRule` (实时规则)、
      `ExportRunLog` (落盘日志)、`SystemConfig` (KV 显示字段)，含手动 migration。
    - 新增 API 模块 `backend/api/export_custom.py`：
      - `POST /api/v1/export/preview` - Jinja2 渲染预览
      - `POST /api/v1/export/render` - 二进制返回 (txt/csv/docx/xlsx/pdf)
      - CRUD `/api/v1/export/templates` + 路线 B 占位符模板上传
      - CRUD `/api/v1/export/realtime-rules` + test-run + run-logs
    - 新增渲染层: `services/export_context.py` (cycle/range/system 三种上下文构造)、
      `export_field_registry.py` (308 字段中央仓库)、`export_renderer.py` 主入口、
      `export_renderer_docx.py` / `_xlsx.py` / `_pdf.py` 三种二进制渲染。
    - 路线 A: Jinja2 模板字符串自动渲染样式；路线 B: docx/xlsx 占位符模板上传后填充。
    - input_file_mode 三种: none/read_template/append (支持基于客户原 SN.txt 改写)。
    - 前端: `frontend/src/views/Data/components/CustomExportDialog.vue` +
      `RealtimeRulesDialog.vue` 拖拽式编辑器，左侧字段树右侧模板编辑器。
    - Data 页"数据导出"tab 加 "自定义导出 / 客户模板" + "实时规则（扫码自动写入）" 按钮。
    - License 信息从 Electron IPC 推送到后端，可在模板渲染时引用 `{{ license.* }}`。
  - 影响文件:
    - 新增: `backend/api/export_custom.py`, `backend/api/export_realtime.py`,
      `backend/api/system_display.py`, `backend/models/export_models.py`,
      `backend/services/export_*.py` (8 个文件), `backend/services/export_seed.py`
    - 新增: `frontend/src/api/export.js`,
      `frontend/src/views/Data/components/CustomExportDialog.vue`,
      `frontend/src/views/Data/components/RealtimeRulesDialog.vue`
    - 修改: `backend/main.py` (注册新路由 + migration),
      `backend/api/__init__.py`, `frontend/src/views/Data/index.vue`

- [FEAT-002] 实时规则 (cycle 结束自动渲染落盘)
  - 需求: 客户希望扫码完成检测后，按规则自动写入文件夹（不需手动点导出）。
  - 实现:
    - `services/export_realtime.py` 提供 `dispatch_cycle_end_export(db, channel, cycle_id, project_id)`
      入口，扫描启用规则、按 channel_filter / project_filter 匹配后渲染落盘。
    - `services/mes_hooks.py` 的 `_handle_cycle_end` 末尾调用 dispatch，
      与 MES Hook / Scanner / Container 清理独立 try/except，互不影响。
    - `ExportRunLog` 记录每次执行 (success/failed/skipped) + 错误堆栈，
      支持前端日志面板查询。
    - 规则 CRUD UI 含 test-run 按钮 (用最近 cycle 干跑)。
  - 影响文件:
    - 新增: `backend/services/export_realtime.py`, `backend/api/export_realtime.py`
    - 修改: `backend/services/mes_hooks.py`

- [FEAT-003] 周期性强制动作 (Periodic Required Actions)
  - 需求: 客户场景"动作 A-B-C-D 每做完 20 轮必须做动作 E，超期触发事件"。
    希望通用可配置: count_basis / reset_policy / overdue_repeat 三个维度都可选。
  - 实现:
    - 新增 mixin `backend/api/source_periodic_actions_mixin.py` (PeriodicActionsMixin)
      含: `_apply_periodic_actions` / `_check_periodic_actions` / `_should_trigger_overdue` /
      `_emit_periodic_notification` / `get_periodic_actions_status`。
    - VSM MRO 加 `PeriodicActionsMixin`，配置应用入口
      `source_project_config_apply.py` 末尾调用 `_apply_periodic_actions(config)`。
    - `source_session_lifecycle_mixin.py::end_cycle()` 在 commit + MES Hook 后调用
      `_check_periodic_actions(cycle.step_sequence, is_good)`，独立 try/except。
    - `source_routes.py::get_detection_results` 暴露 `periodic_actions` 字段
      (含每条规则的 counter / interval / state=ok|due|overdue)。
    - 计数器 JSON 持久化: `backend/data/counters/project_{id}_ch{ch}.json`。
    - 配置项:
      - `count_basis` ∈ {all, good_only, ng_only}
      - `reset_policy` ∈ {always, only_when_due}
      - `overdue_repeat` ∈ {every_cycle, once, cooldown:N}
      - `interval` 任意正整数, `due_warning_event_id` / `overdue_event_id` 可选
    - 前端: Project 页"逻辑设置"加独立卡片，含规则增删 + 4 维度选择器。
      Monitor 页加进度区块 (counter 进度条 + 状态色 ok/due/overdue)。
  - 影响文件:
    - 新增: `backend/api/source_periodic_actions_mixin.py`
    - 修改: `backend/api/source.py` (MRO),
      `backend/api/source_project_config_apply.py`,
      `backend/api/source_session_lifecycle_mixin.py`,
      `backend/api/source_routes.py`,
      `frontend/src/views/Project/index.vue`,
      `frontend/src/views/Monitor/index.vue`

- [FEAT-004] System 显示字段 + License 缓存
  - 需求: 自定义导出模板需引用品牌名 / 厂名 / 工位号等"系统显示字段"。
  - 实现:
    - 新增 `backend/api/system_display.py` 暴露 `/api/v1/system/display` 读写接口。
    - SystemConfig KV 表存储: brand_name / app_name / inspector_name /
      device_number / factory_name / line_name 等。
    - 前端在 IPC 接收 license 后 POST 给后端 `/api/v1/system/license-cache`，
      模板渲染时可用 `{{ license.customer }}`。
  - 影响文件:
    - 新增: `backend/api/system_display.py`
    - 修改: `backend/main.py`

- [FEAT-005] Step 置信度聚合 + 内部跟踪状态暴露
  - 需求: 自定义导出模板需要 step.avg_confidence / max_confidence 等聚合字段。
    同时跟踪模式的 `_stack_state` / `max_recognized` 也希望前端能显示。
  - 实现:
    - `sessions_stats.py` 在 step 维度增加 avg/min/max_confidence 聚合。
    - `source_routes.py::get_detection_results` 始终返回完整 `tracking` 子树，
      含 `_stack_state` / `max_recognized` 等内部状态。
  - 影响文件:
    - 修改: `backend/api/sessions_stats.py`, `backend/api/source_routes.py`,
      `backend/api/source_tracking_mixin.py`

  - 实现 (4 层 86 个测试，1 分 9 秒跑完):

      - `test_pairwise_export.py`: 5 fmt × 3 context × 2 route = 30 → 9 pairwise。
      - `test_pairwise_input_modes.py`: input_file_mode × 格式 = 9 全跑 + 3 个负向。
    - L3 集成链路: `test_integration_cycle_end_chain.py`
      真 DB + 真 Jinja2 + 真磁盘 IO，验证 cycle_end → dispatch → 文件落地。

    - L4 Playwright 浏览器 E2E: `tests/e2e_browser/`

  - 工具链: pytest + pytest-bdd + allpairspy + playwright + chromium。
  - conftest 隔离: 临时 DATA_DIR + in-memory DB；e2e_browser 用真生产 DB
    但用 `__e2e_` 前缀清理保证不留垃圾。
  - 影响文件:
    - 新增: `tests/conftest.py`, `pytest.ini`, `tests/__init__.py`,
      `tests/features/*.feature` (4 个), `tests/step_defs/*.py` (4 个),
