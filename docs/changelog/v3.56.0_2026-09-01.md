# v3.56.0 (2026-09-01)

> 主题：**周期多码采集（一工件多码分类/去重/数量门/收尾结算）主程序原生落地** + 并行收编逐件覆盖五件套、装箱清点取值重设计、缺步提前发现、监控清零二选一、MPS 读写锁并发提速。
> 多码采集面向六和焊接组装工位现场确认单（母排 1 + 芯子 6/9 + 工装收尾）交付，**全部新能力默认关 = 存量客户升级零配置差异**。

## 功能变更

- [FEAT-001] 周期多码采集子系统（scan_collect，v3.56 新子系统）
  - 需求: 焊接组装工位一个工件周期内要扫 8~11 个码（母排码 M 开头 32 位 ×1、芯子码 13 位纯数字 ×6/9、工装码 H-C 开头 ×1 收尾），按类归档、重复/少扫/多扫报 NG、逐工件落 txt、主页实时进度、历史可追溯；两种作业（6/9 芯）切项目即切换。
  - 实现: `ScanCollectEngine` 单例（槽位制正则分类优先 + 顺序兜底、本组去重 + 跨工件历史去重、收尾码结算 OK/NG、超时结算、切项目作废防串账）；借 VSM `fire_external_event_response` 事件响应面（灯/Toast/语音/计数器）不动检测周期；新表 `scan_collect_configs`（项目级配置）+ `scan_collect_records`（逐码留痕，纠错删码 status=deleted 只审计不进追溯）；`mes_hooks._handle_scan` 顶部优先路径（互斥于单码绑定）；`channel_manager` 裁撤清理挂 `on_channel_removed`（不变量 #4）；`/api/v1/scan-collect/*` 8 端点（config CRUD / scan / state / remove-code / clear / resolve-ng / records）。
  - 影响文件: backend/services/scan_collect.py, backend/models/scan_collect_models.py, backend/api/scan_collect.py, backend/api/router_manifest.py, backend/services/mes_hooks.py, backend/api/channel_manager.py, backend/api/source_routes.py, backend/main.py, alembic/env.py

- [FEAT-002] 多码采集现场确认单增补（v3.56.1 语义，随本版一并出）
  - 需求: 现场确认单回传后新增三项——①循环工装码跨工件必然重复不能拦；②芯子多扫直接判 NG 但多扫母排（=忘扫收尾开新件）只拦提示；③少扫收尾后操作员要"补扫缺码"救回而不是立即作废。
  - 实现: 槽位级策略覆盖（`dedup_cross_group` / `on_overflow` 每槽可选"跟随全局/豁免/拒收/判 NG"）；`ng_pending` NG 挂起——少扫收尾不关组、报警后等补扫，补齐转 OK 结算，或人工「按 NG 放行」（`POST /scan-collect/resolve-ng`，挂 `monitor.detection.ack` 权限）；挂起期间已响过 NG 铃放行不二次响。

- [FEAT-003] 视觉 + 扫码双重验证（vision_gate，默认关）

## Bug 修复

- [BUG-001] 循环工装码致工件追溯多轮码组混排
  - 症状: 工装码是循环治具跨工件重复，同一序列号名下多轮码组的组件码在追溯详情混在一起。
  - 根因: 引擎以收尾码注册工件，`WorkpieceService.register` 同序列号复用同一工件行，records 全挂同 workpiece_id。
  - 修复: 数据层本有 `group_id` 区分，追溯 UI 按码组分节显示（结算时间抬头 + OK/NG 标，最近一轮在前）。
  - 影响文件: frontend/src/views/MES/WorkpiecePanel.vue

- [BUG-002] 包装「等扫箱标签」态重扫工单裸码误报警
  - 症状: 枪重发/双扫/恢复后再扫工单码被当"标签取量失败"报警。
  - 修复: 无复合分隔符的裸码视为工单重扫静默忽略；复合串数量非法仍报警。
  - 影响文件: backend/services/packaging_flow_coordinator.py

- [BUG-003] 组合位置计数超时强制 NG 后旧件计数污染新件
  - 症状: 盖瓦场景超时 NG 后计数 5→9 乱序恶化。
  - 根因: positional 引擎只在正常结算清池，强制超时/清场路径不清。
  - 修复: `_clear_step_runtime_state` 同步 reset positional 引擎，单测锁回归。
  - 影响文件: backend/api/source_settlement_mixin.py, tests/test_combo_table.py

- [BUG-004] 多工位 SOP 卡串项目 + 定格确认吃掉补做超时窗
  - 症状: 多工位各通道项目不同时 SOP 卡可能吃顶部项目的 sequence 串步骤；定格确认后缺步补做计时已耗尽。
  - 修复: results 瘦快照下发本通道 `sequence_order`/`custom_*` 身份字段，前端 `resolveStepsToShow` 禁止 fallback 顶部项目 sequence；ack 路径仍有 `_settle_hold` 时 `since` 重记。
  - 影响文件: backend/api/source_routes.py, frontend/src/views/Monitor/monitorModes.js, index.vue

- [BUG-005] 工位 GPU 钉选不落盘重启弹回
  - 症状: 监控页钉 mps/cuda 只改内存，激活项目或重启后按旧 `gpu_device` 重载弹回 cpu。
  - 修复: `set_channel_gpu` 走 `save_channel_source(..., merge=True)` 落盘（守不变量 #17 分段写）。
  - 影响文件: backend/api/channel_manager.py

- [BUG-006] per_item 计数器读取对旧测试桩 AttributeError
  - 症状: `test_per_item_ok_no_false_ng_log` 桩对象缺 `_per_item_config` 报错。
  - 修复: `getattr(self, '_per_item_config', None) or {}` 防御取值，与 mixin 既有防御风格一致。
  - 影响文件: backend/api/source_per_item_mixin.py
