# v3.50.0 (2026-08-12)

> 捷昌二期批次：齐件即结算 + 扫码器生命周期"码-合格-码"闭环。
> 现场叙事：操作员扫码 → 放料 → 所有物品放齐并稳定 N 帧后周期**立即**判 OK
> （不等物品离开视野）→ 扫码器只在 OK 后重新亮灯（NG 灭灯等人工恢复），
> 亮灯同时作废旧码，已合格的码永久拒绝 → 一码对应一合格件，不串码不漏码。
> **所有新选项默认关闭，不配置时与 v3.49 行为零差异。**

## 功能变更

- [FEAT-001] 跟踪模式"全部合格立即结算"（齐件即结算）
  - 需求: 捷昌装配线物品放齐后希望立刻出 OK 结果驱动扫码器进入下一循环，
    现状 roi_exit/container 都要等物品/箱子物理离开才结算，节拍被离开动作拖慢
  - 实现:
    - `pipeline_config.tracking_settle_on_complete` 项目级开关（默认关），
      **仅 ROI离开 / 容器模式两种策略可用**——触发标签语义冲突（操作员信号
      即结算指令）、全部消失无空间约束多批场景误结算风险高，二者不开放
    - 步骤级 `steps_config[].settle_confirm_frames`（默认 1）：物品需连续
      在场 N 帧才"确认放入"入账，防手部遮挡/抖动误计；开关开启时才在
      物品设置表露出该列（`settleOnCompleteActive` 条件渲染）
    - ROI 离开：`_tracking_entry_pending` 缓冲未满 N 帧的新目标；凑齐即调
      `_finish_tracking_cycle`；已结算但仍在场的目标进 `_settle_complete_exempt`
      豁免名单（含 ID 漂移 IoU 合并转移），防止残留物品二次入账/幽灵开周期
    - 容器模式：`_container_entry_pending` 同款 N 帧确认；箱内物品凑齐即结
      该箱，箱子转入 `_box_settled_waiting_exit`"已结算等离开"状态机
      （对齐 scan_d"已扫等消失"设计，含 ID 漂移转移 + gone_frames 确认离场
      后清除），期间不重建 ledger、不再入账
    - 互斥守门：scan_pair 码-码闭环通道运行时跳过齐件即结算分支
      （周期节奏由扫码事件主导）；前端 LogicConfigTab 开关 tooltip +
      ScannerPanel scan_pair 提示双向明示互斥
    - 豁免名单/等离开状态**跨周期保留**（`_reset_counting_cycle` 不清），
      仅项目切换（`source_project_config_apply`）时重置
  - 影响文件: backend/api/source_tracking_mixin.py,
    backend/api/source_container_grouping_mixin.py,
    backend/api/source_state_init.py, backend/api/source.py,
    backend/api/source_project_config_apply.py,
    frontend/src/views/Project/LogicConfigTab.vue,
    frontend/src/views/Project/StepsConfigTab.vue,
    frontend/src/views/Project/index.vue

- [FEAT-002] 扫码器生命周期可配置（重新亮灯时机 / 亮灯作废旧码 / 强制去重）
  - 需求: 捷昌二期要求扫码器与判定结果联动——NG 后不能自动亮灯继续扫
    （防止 NG 件未处置就被下一码顶掉），且旧码不得挂到新周期、
    已合格的码不得复用
  - 实现:
    - `scanner_devices` 加 3 列（迁移 m0010，默认值 = 现状零差异）：
      `resume_on`（'cycle_end' 默认 OK/NG 都亮 / 'ok_only' 仅 OK 自动亮，
      NG 保持灭灯等人工恢复）、`rearm_forget_last`（重新亮灯时作废未绑定
      旧码 + 重置物理去重缓存，默认关）、`strict_ok_dedup`（已判 OK 条码
      永久拒绝 = ok_rescan_cooldown 的无限版，默认关）
    - `resume_after_cycle` 接收结算结果 `is_good`（`end_cycle` 传入），
      ok_only 且非 OK 时置 `_resume_blocked` 保持灭灯；人工恢复
      （manual=True）无条件放行并清阻塞
    - 人工出口三通道: `POST /api/v1/scanner/resume`（新端点）、监控页
      "恢复扫码"按钮（`scanner_resume_blocked` 进 MES payload 驱动显示，
      MES 信息条 v-if 补该条件否则 NG 后无工件时整条不渲染按钮出不来）、
      触发中心 `resume_scanner` 动作（脚踏板/PLC 可接）
    - 拒绝路径统一警告 toast: `_emit_scan_warning` 把强制去重拒绝 /
      OK 冷却期拒绝 / duplicate_scan_action=reject 三条静默丢弃路径改为
      `scan_warning` + `warn_reason` 事件；scan_pair 重复码警告并入同一
      字段体系（保留旧 `scan_pair_dup_warning` 兼容）；前端 `handleScanToast`
      统一渲染警告 toast
    - ScannerPanel 新选项区: 仅 text_lon 且扫描模式 C/D 时解锁
      "重新亮灯时机/亮灯作废旧码"（USB 键盘枪无灯控置灰 + 提示），
      "强制去重"不依赖灯控任何设备可用
  - 影响文件: backend/models/mes_models.py,
    backend/db/migrations/m0010_scanner_lifecycle.py,
    backend/db/migrations/__init__.py, backend/api/scanner.py,
    backend/services/scanner.py, backend/services/mes_hooks.py,
    backend/api/source_session_lifecycle_mixin.py,
    backend/api/source_routes.py, backend/services/triggers/actions.py,
    frontend/src/views/MES/ScannerPanel.vue,
    frontend/src/views/Monitor/index.vue
