# v3.46.0 (2026-08-05)

> 主题：**主程序原生短信/微信通知栈**（NG 12h 汇总通知 + 每日短信日报，统一系统级五通道，默认全关 = 存量零差异）**+ 推理设备 auto 档支持 Apple MPS**。
> 短信栈来自 `feat/jinlong` 分支吸收（含 dev-qing NG 通知栈合流），通道层已统一治理（`sms_adapters` 平行实现已删）。

## 新功能

- [FEAT-001] 主程序原生 NG 短信/微信推送通知（12h 汇总，默认关）
  - 需求: 客户管理者不守在产线也想收到 OK/NG 产量汇总；不同客户网络条件不同（有的只能插 USB 短信猫，有的能走公网云短信/微信）。
  - 实现: `SmsService` 门面 + `sms_providers/` 统一通道工厂五选一（`at_modem` USB/AT 短信猫、`generic_http` 通用 HTTP 网关、`wxpusher` 微信推送、`aliyun`、`tencent`）；
    汇总调度二选一——滚动 12h（后端冷启动以启动时刻重锚，配置热替换不重锚）或班次模式（`shift_start_hour`/`shift_end_hour`，夜窗默认不发）；
    **不在 `_trigger_event` 热路径发送**，汇总线程只读已落库结算周期；HTTP 类通道断网走 SQLite 离线队列重试；
    报警页新增「NG 短信/微信推送」配置卡（与灯塔/蜂鸣器完全隔离：独立配置文件 `sms_config.json`、独立 COM、独立线程）；
    启停接线在 `main.py`（启动锚定 + 关机有限收尾，错误全隔离不阻主程序）。默认 `enabled=false`。
  - 影响文件: backend/api/sms.py, backend/schemas/sms.py, backend/services/sms_service.py,
    backend/services/sms_config.py, backend/services/sms_summary.py, backend/services/sms_at_client.py,
    backend/services/sms_modem.py, backend/services/sms_offline_queue.py, backend/services/sms_providers/*,
    backend/services/sms_utils.py, backend/main.py, frontend/src/api/sms.js, frontend/src/views/Alarm/index.vue

- [FEAT-002] 每日短信日报（数据中心配置，cron 定点发当日 KPI 到手机）
  - 需求: 客户希望每天固定时间（如 20:00）把当日产量/合格率/计数器增量摘要发到管理者手机，不用登系统。
  - 实现: 日报规则三表 `sms_report_rules` / `sms_send_logs` / `counter_daily_stats`（`models/notify_models.py`）；
    独立 APScheduler cron 调度（与定时导出同范式，无 enabled 规则零开销）；规则 CRUD/启停/预览（渲染变量不发送）/mock 试发（全链路不发真短信）/逐号发送日志；
    计数器当日增量走 `counter_daily` 内存日桶节流落库（`record_for_host` 挂在事件计数器联动点，只累计正向增量）；
    正文口径双轨——云模板通道（aliyun/tencent）用平台审核模板 + 变量映射（规则 `template_code` 可覆盖），内容式通道（at_modem/generic_http/wxpusher）用规则 `content_template`（`${变量}` 占位）本端渲染（迁移 m0006）；
    前端数据中心「短信日报（每天发到手机）」对话框（规则 tab + 发送通道 tab 只读指路报警页）；
    插件 returnable hook `daily_report_before_send` 可改写变量/收件人/跳过发送。
  - 影响文件: backend/api/sms_report.py, backend/services/sms_report.py, backend/services/counter_daily.py,
    backend/models/notify_models.py, backend/db/migrations/m0006_sms_report_content_template.py,
    backend/plugin_system/hook_dispatch.py, backend/api/source_event_trigger_mixin.py,
    backend/api/source_periodic_actions_mixin.py, backend/services/export_field_registry.py,
    frontend/src/api/smsReport.js, frontend/src/views/Data/components/SmsReportDialog.vue, frontend/src/views/Data/index.vue

- [FEAT-003] 统一短信通道层（消除 sms_adapters 技术债）
  - 需求: NG 通知与日报曾各带一套通道实现（`sms_providers/` vs `sms_adapters/`），双份维护必漂移。
  - 实现: 日报改走 `sms_providers/` 工厂 + 共享 `sms_config.json`（`SmsConfigStore`）；报警页通道扩到五选一（补阿里云/腾讯云）；
    日报对话框通道 tab 改只读展示；中转方案改 `generic_http` 字段映射（`scripts/sms_relay/` 提供中转服务器示例）；删平行适配器。
    **不变量：通道实现只能进 `sms_providers/`，禁止再造第二套适配器。**
  - 影响文件: backend/services/sms_report.py, backend/api/sms_report.py, frontend/src/views/Alarm/index.vue,
    frontend/src/views/Data/components/SmsReportDialog.vue, scripts/sms_relay/relay_server.py

- [FEAT-004] 推理设备 auto 档支持 Apple MPS（cuda > mps > cpu）
  - 需求: Apple Silicon 开发机上 auto 档静默落 CPU，开发/演示帧率被压死。
  - 实现: 新增 `backend/core/torch_device.py` 统一出口（auto 解析 / MPS 缓存清理与同步）；
    模型加载（主+slot）、通道设备解析、MediaPipe 二段检测、GPU reset/停机同步/缓存清理点全部接入；
    MPS 上强制 FP32（half 仍仅 CUDA），预热扩展到 MPS。实测 yolov8n@640: MPS 168 FPS vs CPU 26 FPS（6.4x）。
  - 影响文件: backend/core/torch_device.py, backend/api/channel_manager.py, backend/api/source.py,
    backend/api/source_lifecycle_mixin.py, backend/api/source_mediapipe.py, backend/api/source_model_load_mixin.py

- [FEAT-005] 独立 AT 短信猫调试工具 `tools/sms_4g`
  - 脱离主程序单测 USB 4G 短信模块（AT 指令/GUI/假串口测试），现场排硬件问题不用起整套系统；含 Windows 启动 bat（CRLF）。
  - 影响文件: tools/sms_4g/*
