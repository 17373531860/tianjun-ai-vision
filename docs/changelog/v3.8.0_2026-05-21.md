# v3.8.0 (2026-05-21)

> **基线**：v3.7.6 (2026-05-18)  → v3.8.0 (2026-05-21)
> 主线两条：(1) per_item 逐件覆盖模式上线；(2) 定时导出 + 多格式快捷下载首发；
> 配套大量周期生命周期 / 视觉时序 / 视频鲁棒性方面的修复。

## 功能变更

### [FEAT-001] 定时导出（按 cron 周期性自动出报表）
- **需求**：客户希望"每天凌晨 0 点把昨天一整天的检测数据导出到 D:\日报\"。早晚班 / 跨日截断逻辑必须与现有数据页 4 个手动按钮完全一致。
- **实现**：
  - 新表 `export_scheduled_rules`（含 cron 表达式 / 数据窗口类型 / 输出格式 / 模板来源 / 输出目录 / 编码 / 冲突策略 / 运行状态 / 累计计数）。
  - APScheduler `BackgroundScheduler` 后台单线程，启动 / 关停挂在 `backend/main.py` lifespan 上；CRUD/toggle 后通过 `reload_rule` 动态注册。
  - 数据窗口 7 种预设（昨天 / 今天 / 过去 N 小时 / 过去 N 天 / 昨天白班 / 昨夜班 / 自定义偏移），跨日班次 `start_hour > end_hour` 自动走 `sessions_export._shift_filter_cycles` 原跨日 OR 查询路径，跟手动按钮零差异。
  - 全局默认输出目录 `SystemConfig.export.scheduled.default_dir`，每条规则可单独覆盖。
  - 失败 / 跳过 / no_data 通过 `ExportRunLog` 借表记录，前端按 `skip_reason=scheduled_rule_id={id}` 反查。
- **影响文件**：
  - 后端：`backend/models/export_models.py`、`backend/services/export_scheduled.py` (新建)、`backend/api/export_scheduled.py` (新建)、`backend/api/__init__.py`、`backend/main.py`、`backend/requirements.txt`
  - 前端：`frontend/src/api/export.js`、`frontend/src/views/Data/index.vue`、`frontend/src/views/Data/components/ScheduledRulesDialog.vue` (新建)

### [FEAT-002] 多格式快捷下载（CSV / TXT / XLSX / DOCX / PDF）
- **需求**：数据页 4 个快捷按钮（导出当日 / 某周 / 某月 / 范围）原本只能导 CSV，客户希望可选 txt/docx/xlsx/pdf。
- **实现**：
  - 抽出 `sessions_export.build_csv_string`，让多格式 writer 和 HTTP response 共用一份 CSV 字符串构造逻辑。
  - 新模块 `backend/services/export_scheduled_writers.py` 集中实现 `csv_string_to_format_bytes`，供 4 个手动按钮 + 定时导出共用。
  - DOCX 走 XML fast-path（`tc` 直接拼 `<w:p>/<w:r>/<w:t>`，绕开 `cell.text` 的 O(n²) 性能问题），386 行表从 >2min 优化到 <1s。
  - PDF 用 reportlab 内建 `STSong-Light` CID 字体，免外部字体依赖，中文 100% 可渲染。
  - Data 页 4 个按钮上方加"输出格式"下拉，所有按钮共享一个 `exportOutputFormat`。
- **影响文件**：
  - 后端：`backend/api/sessions_export.py`、`backend/api/sessions.py`、`backend/services/export_scheduled_writers.py` (新建)
  - 前端：`frontend/src/api/data.js`、`frontend/src/views/Data/index.vue`

### [FEAT-003] 自定义计数器显示开关（默认隐藏）
- **需求**：客户用计数器做"事件中间状态"是常见用法，但不希望它们一律堆在监控页右上角的统计板块。
- **实现**：
  - `Project.counters_config[i].show_in_monitor` 字段（默认 `false`），UI 上每条计数器旁加"显示"勾选 + tooltip。
  - 旧项目计数器 `show_in_monitor === undefined` 视为隐藏，符合"默认不显示"语义。
  - Monitor 页统计板块过滤逻辑：系统三计数器（检测 / OK / NG）恒显示，自定义计数器按 `show_in_monitor` 过滤。
- **影响文件**：`frontend/src/views/Project/index.vue`、`frontend/src/views/Monitor/index.vue`

### [FEAT-004] 周期性强制动作 — 多触发频率 / 时间触发 / 自定义事件 / 立即清零
- **需求**：客户原来"周期未做强制动作"只在每周期结束触发一次事件，希望可选"持续不断报警"，触发频率自定义，且强制动作一旦做出立即清零并停止触发。
- **实现**：
  - `pipeline_config.periodic_actions[i]` 加 `notify_mode`（once / every_cycle / interval）、`notify_interval_sec`、`notify_event`（自定义事件名）字段。
  - `source_periodic_actions_mixin.py` 触发器后台定时检测，强制动作命中后立即清零计数 + 取消未触发的间隔通知。
  - 同时支持"按时间触发"（time-based）和"按周期触发"（cycle-count-based）两种模式。
- **影响文件**：`backend/api/source_periodic_actions_mixin.py`、`backend/api/source_routes.py`、`frontend/src/views/Project/index.vue`

## Bug 修复

### [BUG-001] PT/CT 显示时机 + 周期切换视觉残留
- **症状**：
  - 周期结算后，下面 SOP 卡片仍然全绿挂着，直到下一周期 A 步骤到来才清掉，视觉效果差。
  - 部分周期最后一步 PT 时间显示明显滞后，常常要等下一周期第三步做完才显示上一轮第一步的 PT。
  - 极端情况：OK 结果先于 PT 出现，且 PT 数值出现后还在增长（边算边显示）。
- **根因**：
  1. 前端 `step.status` 判定过严，必须等 `cycleSumStepDurations` 写入（authoritative PT）才标 completed，导致已 OK 但 PT 还在落库期间一直挂"detecting"。
  2. 后端 `cycle_sum_step_durations` 在 `end_cycle.finally` 立刻清空，导致周期结束瞬间前端 PT 列丢失。
  3. 前端 `else` 分支 fallback `!step.cycleResult && count > 0` 会把边界清零后的 `pending` 翻回 `completed`，跟周期切换体感冲突。
- **修复**：
  1. 后端 `source_routes.py /detection/results` 透出 `current_cycle_id` / `current_cycle_uuid`，让前端 polling 拿到周期边界信号。
  2. 前端 `Monitor/index.vue` 用 `lastSingleCycleId` 跟踪 cycle_id 变化；仅在"新周期开始"（null → int 或 int → 新 int）时清掉步骤表 status/cycleResult/cycle_sum，周期间隙保留视觉反馈。
  3. 后端 `source_session_lifecycle_mixin.py` 把 `step_cycle_durations` / `step_durations` 的清空从 `end_cycle.finally` 挪到下一周期 `start_cycle`，保留间隙期 PT 显示。
  4. 后端新增 `_flush_active_steps_pt`，结算前把仍在画面里的步骤 PT 主动写入累计字典，避免"最后一步 PT 永远丢"。
  5. 前端 `step.status` 放宽到三态：`detectingLabels.has` 即 active；`thisPosCompleted || isCoveredByBackup` 即 completed；其余 pending。`step.cycleResult` 继续等 authoritative PT，避免 OK/NG 闪烁。
- **影响文件**：`backend/api/source_routes.py`、`backend/api/source_session_lifecycle_mixin.py`、`backend/api/source_settlement_mixin.py`、`frontend/src/views/Monitor/index.vue`

### [BUG-002] 检测框越界 — 三层 clip 防御
- **症状**：极端帧（模型 imgsz 与原图差异大 + 边界目标）下 Drawer 渲染出超出图像边界的检测框，文字外溢黑屏。
- **根因**：YOLO 模型在边界外推出 xyxy 超过 (W, H) 的坐标，Drawer 把这些坐标直接传给 cv2 描点。
- **修复**：在 source_geometry / source_drawer / source_detect_runners 三处分别加 clip：
  1. 模型出框后 `clip_bbox_normalized`
  2. 像素坐标转换后 clip
  3. Drawer 渲染前再 clip 一次（兜底）
- **影响文件**：`backend/api/source_drawer.py`、`backend/api/source_inference_loop_mixin.py`

### [BUG-003] 海康相机 NameError（v3.7.x hotfix 回归）
- **症状**：连接海康工业相机 `start_hikvision_camera` 抛 NameError，相机无法启动。
- **根因**：v3.7.x mixin 拆分时漏 import `MV_CC_DEVICE_INFO_LIST` 等海康 SDK 常量。
- **修复**：在 `source.py` / `source_lifecycle_mixin.py` 补全 import。
- **影响文件**：`backend/api/source.py`、`backend/api/source_lifecycle_mixin.py`

### [BUG-004] 扫码器列表为空时不再报"未绑码"
- **症状**：客户机没装任何扫码器，结算时仍会触发"⚠ 未绑码"事件，干扰报警。
- **根因**：`is_warn_no_barcode()` 没检查 `has_any_scanner_present()`，"没扫码器"被当成"有扫码器但没扫到"。
- **修复**：`source_settlement_mixin.py` 加守门：扫码器列表为空时直接返回 False，静默不报警。
- **影响文件**：`backend/api/source_settlement_mixin.py`

### [BUG-005] 顺序模式新一轮开始时不结算上一轮（A-B-C 没 D 又来 A）
- **症状**：严格 A-B-C-D 顺序模式，前一轮 A-B-C 完成但 D 没检到，紧跟下一轮 A 出现，前一轮没被结算，被静默吞掉。
- **根因**：顺序状态机只在 D 出现时才结算，没考虑"D 没来但新一轮 A 提前到"的边界。
- **修复**：`source_sequential_mixin.py` 加"结算步骤即将到来时新一轮第一步出现 → 结算上一轮 NG + 启动新一轮"逻辑；行为按钮配置默认关。
- **影响文件**：`backend/api/source_sequential_mixin.py`

### [BUG-006] 检测停止后画面残留 / 重启检测后画面残留
- **症状**：检测启动后停止再去其他页面改配置，回 Monitor 页画面还残留上次的渲染；连续 start/stop/start 也会残留。
- **根因**：`stop_detection` 没清 Drawer 内部 Kalman/missing 缓存 + last_frame 缓存。
- **修复**：`source_lifecycle_mixin.py` stop 路径加 `clear_filters()` + `last_annotated_frame = None`。
- **影响文件**：`backend/api/source_lifecycle_mixin.py`、`backend/api/source.py`

## 依赖变更

## 配置/迁移变更
- 新表 `export_scheduled_rules` 由 `Base.metadata.create_all()` 自动建，无需 ALTER TABLE。
- 新增 `SystemConfig` key `export.scheduled.default_dir`（不存在时回落到 `DATA_DIR/exports/scheduled`）。
- `.gitignore` 新增 `backend/exports/`（定时导出运行时产物，不入版本库）。

## 已知问题
- 自定义模板渲染上下文是"单 cycle 字段"，定时导出场景目前只走"标准日报列"模式；如客户要求自定义日报模板，需要在 `export_field_registry` 加聚合层字段，待后续版本。
- DOCX / PDF 渲染对超大量行（>5000 行）仍可能在客户机上偏慢，建议日报场景按"日"或"班次"切分。
