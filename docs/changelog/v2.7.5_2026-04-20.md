# v2.7.5 (2026-04-20)

## Bug 修复

### [BUG-001] 外部设备「清空日志」返回 `int_parsing` / `[object Object]`
- **症状**: 在 MES → 外部设备面板点「清空」报"清空失败"，前端只显示 `[object Object]`。
- **根因**:
  1. `backend/api/external_device.py` 的路由顺序是 `@router.delete("/{device_id}")` 出现在 `@router.delete("/logs")` 之前，FastAPI 先按动态路径匹配，`/logs` 被解析成 `device_id="logs"` 直接 422。
  2. 前端 `handleClearLogs` / `handleSave` 把 axios 的 `error.response.data.detail`（可能是 list/dict）直接丢给 `ElMessage.error`，导致显示 `[object Object]`。
  3. SQLite 在并发写入时会抛 `OperationalError: database is locked`，但没有重试。
- **修复**:
  - 将所有 `/{device_id}` 动态路径端点移至文件末尾，确保 `/logs`、`/scan` 等静态路径先命中
  - `clear_logs` 改用 `q.delete(synchronize_session=False)`，增加 3 次重试，失败时还会回退到原生 SQL `DELETE`
  - 前端把 `detail` 规范化为字符串再展示（list → 逐条 `msg` 拼接，dict → JSON）
- **影响文件**: `backend/api/external_device.py`, `frontend/src/views/MES/ExternalDevicePanel.vue`, `frontend/src/views/MES/ScannerPanel.vue`

### [BUG-002] 新建/编辑外部设备时串口路径含前后空格导致 `[Errno 2] No such file or directory: ' /dev/ttyUSB0'`
- **症状**: 复制粘贴串口路径时带了首尾空格，保存立刻 400。
- **根因**: 前端直接把 `v-model` 的原值送后端；后端也没 `strip()`。
- **修复**:
  - 前端 `buildFormData` 对 `name/serial_port/ip/station_id` 统一 `.trim()`
  - 后端新增 `_sanitize_device_payload` 助手，在 `create_device/update_device` 入口处 strip 相同字段
  - 另外：保存时如果串口暂时打不开（未插线/占用），后端不再 400，而是返回 200 + `warning` 字段，前端以 warning Toast 提示，记录仍会入库
- **影响文件**: `backend/api/external_device.py`, `frontend/src/views/MES/ExternalDevicePanel.vue`

### [BUG-003] 称重器 Modbus ASCII 粘包导致「串口有响应但解析失败」
- **症状**: 点『测试』按钮，日志显示 RX 有数据但解析失败。
- **根因**: `_parse_modbus_ascii_response` 只按单帧逻辑处理，当串口缓冲里堆了两帧（`:...CRLF:...CRLF`）时 LRC 校验全部失败。
- **修复**: 按 `:` 分段 + `\r\n` 或下一个 `:` 作结束，逐段 LRC 校验，任一段有效即返回解析结果。
- **影响文件**: `backend/services/external_device.py`

## 功能变更

### [FEAT-001] 画面旋转 / 镜像（按通道独立配置）
- **需求**: 客户现场摄像头安装方向不一致，希望能 0/90/180/270° 旋转，并支持左右/上下镜像。检测框要和画面一起转，Monitor / 录像 / MJPEG 都要同步生效。多工位每个通道可独立设置。
- **实现**:
  - 后端 `VideoSourceManager`：
    - 新增字段 `video_rotation (0/90/180/270)` / `video_flip_h` / `video_flip_v`
    - 新增 `_apply_frame_transform(frame)`：`cv2.rotate` + `cv2.flip` 组合
    - 在 `_capture_loop` 里紧跟 `frame.copy()` 后应用，后续推理 / MJPEG / 录像拿到的都是变换后帧，**检测框坐标天然对齐，无需二次映射**
    - `_load_device_config` / `_save_device_config` 引入 `per_channel` 子结构（`{"0":{...},"1":{...}}`），保存时不会覆盖其它通道
  - 新增 REST API：`GET /source/transform/config?channel=N` / `POST /source/transform/config?channel=N`
  - 前端 `Settings/index.vue` 的「显示设置」已有变换 UI，保持不变
- **影响文件**: `backend/api/source.py`
- **测试**: `test_video_transform.py` 11 用例全过（含各角度、组合、per_channel 持久化、非法角度回退）

### [FEAT-002] MES 工单表单模板编辑器
- **需求**: 「新建工单」弹窗里的字段客户各不相同，希望能改名、删除、重排系统预设字段，还能加自定义字段（文本/多行/数字/日期/时间/日期时间/下拉/开关）。模板全局生效、浏览器持久化，不走后端。
- **实现**: 完全重写 `frontend/src/views/MES/OrderPanel.vue`
  - 工具栏新增「字段配置」按钮，打开模板编辑器弹窗
    - 上下按钮调顺序、删除按钮、新增自定义字段、恢复系统预设、恢复默认
    - 预设字段（`order_no` / `product_name` / `product_code` / `product_spec` / `planned_qty` / `priority` / `remark`）可改名、必填切换、删除
    - 自定义字段 key 必须是合法标识符（`^[A-Za-z_][A-Za-z0-9_]*$`）且唯一
    - `select` 类型选项支持 `标签=值,标签=值` 或 `选项A,选项B` 两种格式
  - 新建/编辑弹窗按模板动态渲染：`DynamicFieldInput` 组件根据 `type` 选择对应控件
  - 保存时：预设字段 → 后端标准字段；其它字段 → `extra_data`；编辑时模板外的原 `extra_data` 字段保留不丢
  - 必填字段兜底：模板删除 `order_no` 时新建自动补 `ORD-{时间戳}`；删 `product_name` 时补『未命名』
  - 模板存储在 `localStorage[mes_order_form_template_v1]`
- **影响文件**: `frontend/src/views/MES/OrderPanel.vue`

### [FEAT-003] MES 推送上下文新增 `ng_steps` / `missing_step_count` 便利字段
- **需求**: 客户集成 MES 时希望在 JSON / 表单模板里直接拿到"漏做 / 做错的步骤列表"和"缺了几步"，不想自己写 Jinja 过滤器。
- **实现**: `MESGateway.build_context_from_cycle`
  - `context["ng_steps"] = [步骤 for 步骤 in steps if is_good=False]`
  - `context["cycle"]["missing_step_count"]`:
    - 优先用 `total_steps - completed_steps`（若均为 int）
    - 否则回退到 `len(ng_steps)`
  - OK 周期 → `ng_steps=[]`, `missing_step_count=0`
- **影响文件**: `backend/services/mes_gateway.py`
- **测试**: `test_mes_ng_steps.py` 3 用例全过（NG 有数据、OK 无漏、total/completed 缺失时回退）
- **使用示例**（MES Gateway JSON 模板配置）：
  ```json
  {
    "order_no": "{{ order.order_no }}",
    "result": "{{ cycle.result }}",
    "missing_count": {{ cycle.missing_step_count }},
    "ng_step_names": [{% for s in ng_steps %}"{{ s.label }}"{% if not loop.last %},{% endif %}{% endfor %}]
  }
  ```
