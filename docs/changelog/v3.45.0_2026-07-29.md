## 新功能

- [FEAT-001] 箱标签扫码授权 + 标签取本箱数量（包装配置 组⑧，全可选默认关 = 存量零差异）
  - 需求: 上银现场每箱有标签（二维码 `ORD|JOB|数量|哈希` + 一维条码裸工单号），要求扫完工单后
    每箱开做前必须扫二维码确认本箱滑块数量，数量逐箱可不同。
  - 实现: 每箱进「等扫箱标签」态，扫到本工单标签才放行开做；扫标签解析数量段（段序/正则可配）
    动态设本箱视觉目标；未扫开做当场报警（周期开始通知钩子）；裸一维条码/取不出数量拒收+报警
    提示重扫二维码；已授权重扫同号忽略/更新可配；工单收尾对账 Σ标签数量 ≠ 排产量报警（只提醒
    留痕不改成绩）；未授权箱完成周期挂账等人工/照记可配。事件一律走既有事件响应面。迁移 m0004。
  - 影响文件: backend/models/mes_models.py, backend/db/migrations/m0004_pkg_box_label_scan.py,
    backend/services/packaging_flow_coordinator.py, backend/api/packaging_flows.py,
    backend/api/source_custom_mix.py, frontend/src/views/Settings/PackagingFlowPanel.vue,
    frontend/src/views/Monitor/PackagingFlowCard.vue

- [FEAT-002] 包装工单同步进工单管理（默认开）

  - 实现: 扫码开工/收尾/中止时把包装单镜像到工单管理（来源标"包装扫码"绿标签），重启作废的
    在途包装单镜像同步推"已取消"；镜像失败隔离不阻断包装状态机。默认开（老库 NULL 视为开），
    关 = 老行为。迁移 m0005。
  - 影响文件: backend/models/mes_models.py, backend/db/migrations/m0005_pkg_sync_work_orders.py,
    backend/services/packaging_flow_coordinator.py, backend/api/packaging_flows.py,
    frontend/src/views/Settings/PackagingFlowPanel.vue, frontend/src/views/MES/OrderPanel.vue

  - 实现: 数量门升级放行步骤（SY 设 ['封箱']）弹琥珀色人工确认后放行进周期，触发少装挂起，

    放工单移出周期序列（工单级完结动作）；包装卡完成态横幅改"本单已结束，扫码开始下一张工单"。

## Bug 修复

- [BUG-001] 上银连放托盘滑块记账体系重做（0c/0d/0e 三批收编，7-23/7-27/7-28 现场视频驱动）
  - 症状: 连放托盘（~3 秒/盘）末盘漏记、下一箱错位补记；备盘全程无人计数末盘少记 1-2 个
    （95/96 误 NG）；快节奏时几盘合并成一盘入账；桌边备用盘残影折进箱账误报"超出"。
  - 根因: 每帧只数一个计数目标（主位/动作期新生身份），峰值记账依赖"身份消失"驱动——
    堆顶检测框无缝衔接时身份永不消失；唯一可入账视角是"在途飞行拍"（手挡少记）。
  - 修复: 所有在位托盘身份各自按自框累计峰值（中心归属天然不串账）；结算挂账等真账
    （爬满立即结/满窗兜底/到期清幽灵）；新增"动作前稳定计数"快照记账（滚动窗口计数众数
    ±2 摆动容忍 + 4 秒回看 + 位置过滤，与工人快慢解耦）；救账候选按动作时间窗限定取峰值最大者。
  - 影响文件: backend/api/source_custom_mix.py
  - 验收: 7-23 正常视频 4 箱全部 96/96 合格；7-27 快节奏少装视频 4 箱全部 NG、
    逐盘入账与人工核对真值一致（13 盘中 12 盘完全一致、1 盘 ±1 为模型重复框噪声）。

- [BUG-002] 收尾数量门竞态：末盘记账延迟窗内放油嘴包被静默误拦（0c 收编）

  - 修复: 门口径改为"已记账 + 在途主盘峰值"，真少装凑不满照拦。
  - 影响文件: backend/api/source_custom_mix.py, backend/api/source_settlement_mixin.py

- [BUG-003] 模型瞬时重复框把 24 数成 25/26 → 整箱误报"超出"NG（0d/0e 收编）

- [BUG-007] 台秤清零指令被量程限制静默拒绝，秤面卡负值 / 件重被吞（萍乡百斯特现场）
  - 症状: 离秤后秤面显示负值（-皮重-净重），清零不生效；后续新件自重被算错，
    水泥加到皮重区间才误去皮把已加的水泥吞掉。
  - 根因: 置零指令有硬件量程限制（仅零点附近 ±4% 量程有效），偏离远被秤静默拒绝；
    旧实现对"清零后正读数"盲判为"新件已上秤"，不识别"清零被拒 + 新件"的负基线场景。
  - 修复: 清秤指令智能选择——读数在零点附近才用置零（顺带校正真零漂移），偏离远改用去皮
    （任何读数下都有效，阈值可配默认 0.5kg）；正读数用皮重合法区间做双解释合理性核对
    （哪种解释算出的自重合法就信哪种）；重发前守门——新件疑似已上秤绝不再发清秤指令
    （防止把件重吞进秤内皮重寄存器）。
  - 影响文件: backend/services/weighing_engine.py

- [BUG-008] MES 网关推送在推理热路径同步等网络，达梦不可达时画面冻结 15 秒 + 误判 NG
  - 症状: 萍乡现场日志抓到现行——数据库直写适配器不可达时同步重试 3×5s 卡死推理线程，
    画面冻结、收尾步骤耗时被灌成 15s 误判 NG。
  - 修复: 称重侧网关推送全部出让到后台守护线程串行投递（队列有界 256，满挤最旧，
    网关自有通讯日志兜底），检测/称重热路径绝不等网络（不变量 15）。
  - 影响文件: backend/services/weighing_engine.py

- [BUG-009] 达梦数据库直写毫秒时间戳绑定溢出 + 端口配置错误不可诊断（萍乡现场）
  - 症状: 称重成品结案推达梦失败，报错 "int too large to convert to C unsigned long"
    完全看不出原因；另有端口框误粘贴出超长数字（UI 被挤到 25px 宽看不见）把连接搞炸。
  - 根因: dmPython 在 Windows 把 Python int 绑成 C 32 位 unsigned long，毫秒级时间戳必踩；
    网关面板全局 label 120px 把端口输入框挤瘪。
  - 修复: 超 32 位整数降级为字符串交给达梦库端隐式转换；连接前端口合法性守门（1~65535，
    报错点名端口框）；端口输入框独立窄 label + 禁压缩 + 去步进钮 + 限位。
  - 影响文件: backend/services/mes_adapters/database_adapter.py,
    frontend/src/views/MES/GatewayPanel.vue

- [BUG-010] 逐件模式整板微移丢逻辑 ID + 防重复打误报（dev-qing 合入，commit 9973d4c）
  - 修复: 锁定数量下用跨步骤位移估计同步预测框，一对一关联并打关联标记；监控页不显示
    未关联预测编号、未关联检测框禁止回退默认绿色；防重复打改为"抬枪正证据"（已打螺丝
    重新清晰出现或电枪明确移到另一颗）后再判返回，纯漏检不累计。
  - 影响文件: backend/api/source_per_item_mixin.py, backend/api/source_custom_mix.py,
    frontend/src/views/Monitor/index.vue, frontend/src/views/Project/LogicConfigTab.vue
