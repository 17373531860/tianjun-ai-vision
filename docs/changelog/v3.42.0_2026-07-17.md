# v3.42.0 (2026-07-17)

> 主题：**两处现场"死环"打通**——(1) 电机装配线部署时「从当前画面抓取锚点框」在打包版里无路可走（检测中锁菜单切不进项目页，停止/待机后实时结果又被清空），新增标定用单帧推理兜底；(2) 川南同任务号工单被结案成终态后再开工永远静默挂不上单，新增终态工单再开工策略（默认自动复活）+ 开工响应透明化。

## 功能变更

- [FEAT-001] 「抓取锚点框」支持停止/待机状态——标定用单帧推理兜底
  - 需求: 客户现场（电机装配线部署）配「打螺丝」拆分规则时点「从当前画面抓取锚点框」，顶部弹红"当前画面没有检测到工件"。根因是两条老约束叠加成死环：检测运行中侧边栏锁菜单（切不进项目页）×停止/待机时实时检测结果被清空（切进去了也抓不到）——打包版里标定流程无路可走。
  - 实现: 新端点 `POST /api/v1/source/detection/infer-once`（summary+response_model 四件套齐）→ VSM 新方法「标定用单帧推理」：停止（定格帧）/待机（画面继续）状态下模型仍在显存，对当前显示帧现推一帧，毫秒级、无任何状态机副作用（不发布实时结果、不触碰拆分引擎/就位提示）。与常规检测的**刻意差异**：跑在显示帧上（坐标天然是编辑器画布坐标系）、**不过**步骤过滤/步骤阈值/box 尺寸/ROI——锚点标签（如「工件」）通常不是步骤，过滤了就永远抓不到；无模型但在检测（synthetic 剧本）时透传实时结果。前端两处抓取入口（拆分规则编辑器 + 区域事件规则）实时结果为空时自动走兜底，标定流程文案同步改为"停止/待机后抓取"。
  - 影响文件: backend/api/source_detect_runners_mixin.py, backend/api/source_routes.py, frontend/src/api/detection.js, frontend/src/views/Project/LabelSplitDialog.vue, frontend/src/views/Project/LogicConfigTab.vue
  - 关键词: 抓取锚点框, 单帧推理, infer-once, infer_once_for_calibration, 标定, 锚点跟随, 拆分规则, 区域事件, 停止, 待机, standby, 检测中锁菜单, 打包版死环, 电机装配, one shot inference

- [FEAT-002] 终态工单再开工策略（terminal_order_policy，默认自动复活）+ 开工响应透明化
  - 需求: 川南 07-17 现场钉死的第二层陷阱：同任务号的工单被顶替/手工结案/完工报文收掉成"已完工/已取消"后，再收到开工报文——老代码"终态不复活"+ 响应仍回"已就绪"= 静默死路，该工位从此永远挂不上单（信息条四要素不显示、推送里任务字段全 null），现场无从察觉。
  - 实现: 入站配置新键「终态工单再开工」两档——`revive`（默认）：外部开工报文是权威指令，视为同一任务新一轮生产，绕过状态机直接复活为"生产中"（清完工时间；UI 手工路径仍受状态机约束不受影响），响应文案追加"已从完结状态重新开工"；`reject`：回"重复任务"码拒收并提示换任务号。配套响应透明化：工单最终没进"生产中"时不再谎报"已就绪"，回"状态异常，检测数据将不会计入该任务"；正常在产复用响应保持原文案不打扰。前端入站面板加对应下拉。
  - 影响文件: backend/services/mes_inbound.py, frontend/src/views/MES/OrderInboundPanel.vue
  - 关键词: 终态工单, 复活, revive, reject, terminal_order_policy, completed, cancelled, 再开工, 已就绪谎报, 响应透明化, 挂不上单, 川南, mes_inbound, _ensure_in_progress
