## Bug 修复

- [BUG-001] 检测模式首步重现结算无视「消失等待不被打断」——扫码抬离回位被切成新周期
  - 症状: 六和芯子装配工位（9 步检测模式：下层母排 + 芯子×6 + 盖母排 + 模具盖板）：
    员工放下层母排 → 拿起整件扫母排码 2~4s → 放回，系统把回位判成"新周期开始"，
    一次装配被拆成两个 NG 周期（缺少步骤 + 重复步骤报警）。现场已把消失确认时间
    设到 5s 仍复现——v3.9 规则 B（等待期间出现其他步骤立即按消失处理）把等待
    掐成 0；而即使开了 v3.34 的「消失等待不被打断」，检测模式依然切周期。
  - 根因: 两处检测模式路径漏掉了 v3.34 顺序模式已有的豁免：
    1. `source_settlement_mixin.py` 检测模式"首步重现结算"块没有 `_held_visible`
       豁免——首步开了 `disappear_uninterruptible` 且上一次出现尚未走完消失结算
       （`old_last_seen` 非 None，等待桥接中）时，重现仍触发 `_settle_detection_cycle`
       把周期切开（顺序模式 first_step 结算在 v3.34 就修了，检测模式漏了）；
    2. 检测模式"步骤交替即新出现"信号（`last_added_step != label`）同样无视该
       开关——桥接中的回位被当成新出现重复入账，产出"重复步骤"NG。
  - 修复: 两处接入同源豁免——开了「不被打断」且等待桥接中：首步重现不触发结算、
    交替回位不算新出现（不重复入账）；真正走完消失结算后的再次出现（`old_last_seen`
    为 None）仍正常切周期。开关默认 False → 恒不生效，存量行为零差异。
  - 参数配套（现场整改）: 下层母排 消失等待时间 5s（> 扫码抬离 2~4s，< 工件间隔
    7s+，过长会吞掉真实工件边界——真视频实测 8s 时边界 held 7.92s 险些误桥接）+
    「等待不被打断」开。真视频 UAT：旧参数复现 2 个碎片周期/母排入账 5 次/重复步骤
    NG；新参数+修复后母排全程入账 1 次、扫码抬离回位桥接为一次 9.7s 连续出现、
    零碎片周期。
  - 影响文件: backend/api/source_settlement_mixin.py
  - 测试: tests/test_detection_first_step_reappear_uninterruptible.py（先红后绿 3 例）
    + tests/uat/uat_20260919_liuhe_first_step_rescan.py（真模型+真视频双阶段对照 7/7，
    含现场同源扫码流注入，业务真值断言 1NG+1OK）

- [BUG-002] 多码采集启用时每次结算仍弹「未绑定工件码」警告
  - 症状: 工位走 v3.56 周期多码采集（母排×1/芯子×6/工装收尾×1），码全部正常
    入槽，但每次周期结算都弹"未绑定工件码"警告 toast。
  - 根因: v3.56 多码采集是互斥路径——`ScanCollectEngine.on_scan` 独占消费扫码，
    不走单码绑定（`_pending_workpiece`）；而结算侧 `should_warn_no_barcode` 只看
    "有扫码器在册 + 不在豁免窗口"，不知道多码采集已接管，永远等不到单码绑定
    → 每次结算误报。
  - 修复: `source_event_trigger_mixin.py` 结算警告判定前查
    `ScanCollectEngine.get_config(None, project_id)`，该项目启用多码采集即豁免
    未绑码警告（多码完备性由采集引擎自身的少扫 NG/催扫链路守护，不归这个警告管）。
  - 影响文件: backend/api/source_event_trigger_mixin.py
  - 测试: tests/test_scan_collect_no_barcode_warn.py（先红后绿 4 例）

## 现场定案参数（六和工位一，真视频回放收敛）

按工程师业务真值（录像半中间开始、一个半周期 → 应判 1NG + 1OK）实测收敛：

- 视觉侧: 结算方式=**末步完成结算**（FEAT-001 入口）+ 下层母排 5s「不被打断」+
  全步骤单次接受（治芯子阶段框抖动重复入账）+ 模具盖板 最少帧数2/消失等待2s +
  空闲超时保持 0（放完母排到装芯子中间有 ~10s 扫码空窗，空闲超时设小会把
  一件从中间切断——实测踩过）。
- 扫码侧（多码采集）: 收尾码结算/少扫NG挂起/待机静默/结算不计数 全部保持现场
  原值；**「视觉+扫码双重验证」(vision_gate) 建议关**——末步消失结算（拿件后
  ~2s）天然晚于工人扫收尾码，gate 只能消费到**上一件**的视觉结果，上件 NG 会
  连坐本件误判 ng_vision（真视频实测复现）。关掉后两条线独立把关能力不打折。
- 回放验证: 视觉落库 1 周期 OK（第二件 9 步全齐）+ 扫码组1 少扫 NG（挂起→
  放行）+ 组2 码齐 OK = 1NG + 1OK，与工程师预判一致。

## 已知问题 / 设计约束

- 「消失等待不被打断」+ 长消失等待会推迟首步的消失结算：等待时长必须小于
  工件间隔（上一件首步最后可见 → 下一件首步放置的空窗），否则真实周期边界
  会被桥接吞掉。六和工位一实测：扫码抬离 2~4s / 工件间隔 7s+ → 推荐 5s。
- 检测模式"非首步不开周期"是既有语义：录像/开机接班时已装到一半的工件
  （缺首步）不会进视觉周期账，其 NG 由多码采集少扫链路兜住（挂起→补扫或
  人工 NG 放行）。
- 检测模式 last_step 下末步（结算步）不会像顺序模式那样被自动剥「单次接受」，
  建议结算步配「最少帧数 ≥2 + 消失等待」防抖，避免闪断重复结算（六和形态
  下模具盖板每件只出现一次，风险低；东莞"容器常驻"形态请走 v3.59 容器定界）。
