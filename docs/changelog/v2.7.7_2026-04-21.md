# v2.7.7 (2026-04-21)

## Bug 修复

- [BUG-001] WMax 扫码器无法识别（三端口协议对齐）
  - 症状: 扫码器连接显示"已连接"但扫任何条码都没反应，前端无条码到达
  - 根因:
    1. 之前按 ASCII `LON/LOFF` 文本协议实现，而真实 WMax 扫码器走二进制 Protobuf 协议 + 三端口（55266 CMD / 55276 IMG / 55286 RPT）
    2. `protocol.py` 的 `DataLen` 默认 4 字节，现场设备实际是 3 字节变体，发 4B 设备静默丢弃所有命令
    3. `encode_get_config_opt` 在 `config_id=-1` 时仍写 `field1=-1`，真机只接受省略 `field1` 的变体
    4. `activate_rpt_reporting` 发了 `HandShake`（CmdType=3），抓包证实 IDManager 从来不发这个，设备对其无响应只会 3 秒超时
  - 修复:
    - `wmax/device.py::WMaxDevice.__init__`: `_data_len_size` 默认从 4 改为 3，匹配真机 (receiver 侧仍保留 4B 自动探测)
    - `wmax/messages.py::encode_get_config_opt`: `config_id<0` 时省略 `field1`
    - `wmax/device.py::activate_rpt_reporting`: 删除 `HandShake`，改为 `GetConfigOpt + TurnOnOffVideo` 序列（和 IDManager 抓包一致）
    - `wmax/manager.py::auto_discover_and_connect`: 删除 `HandShake` 调用
  - 影响文件: `backend/services/wmax/messages.py`, `backend/services/wmax/device.py`, `backend/services/wmax/manager.py`
  - 关键词: WMax, 扫码器, 三端口, 55266, 55276, 55286, Protobuf, DataLen, HandShake, GetConfigOpt, TurnOnOffVideo, 二进制协议

- [BUG-002] `scanner.py` `device_type='auto'` 被错误降级为 `text_lon`
  - 症状: 用户在前端配置扫码器选"自动"，启动后仍走老文本 LON 路径，完全不识别 WMax 设备
  - 根因: `_start_device` 第 440-441 行：`raw_type = ... or 'text_lon'`，当数据库 `device_type='auto'` 时被当作"无值"降级
  - 修复: 保留原值，`auto`/`wmax` 都走 `WMaxDeviceManager` 三端口逻辑
  - 影响文件: `backend/services/scanner.py`
  - 关键词: device_type, auto, text_lon, scanner, 降级

- [BUG-003] `_listen_loop` 为 auto/wmax 类型建本地 TCP 抢占 WMax CMD 端口
  - 症状: scanner 启动时本地建一条到 55266 的 TCP，WMaxDeviceManager 再连时端口已被占导致失败
  - 根因: `_listen_loop` 对所有 `device_type` 都跑统一流程，和 `_auto_discover_wmax_bg` 并发冲突
  - 修复: `device_type in ("auto", "wmax")` 时进入 `pending_wmax` 等待循环，完全交给 `WMaxDeviceManager` 管理三端口
  - 影响文件: `backend/services/scanner.py`
  - 关键词: listen_loop, 端口抢占, pending_wmax, 三端口

- [BUG-004] UDP 自动发现到的 IP 未更新 `conn.status=connected`
  - 症状: 前端扫码器卡片一直显示"未连接"，即便后台 WMaxDeviceManager 已连上
  - 根因: `_auto_discover_wmax_bg` 只在"UDP 未发现 → 降级直连"路径更新 `status`，UDP 发现成功的路径忘了更新
  - 修复: 在 `connected_mgmt_ips` 集合处理完后统一把对应 scanner conn 标记 `connected`
  - 影响文件: `backend/services/scanner.py`
  - 关键词: UDP 发现, status, 前端状态不同步

- [BUG-005] "测试"按钮对 WMax 扫码器无效
  - 症状: 点扫码器测试按钮，直接 `socket.connect + sendall(b"LON\r\n")`，WMax 不响应
  - 根因: `test_connection` 当年为文本模式写的，不走 WMax 协议
  - 修复: 改为优先调 `WMaxDevice.flash_and_scan(duration=5.0)`，同时同步收集扫到的条码；失败时再降级到老文本 LON 路径
  - 影响文件: `backend/services/scanner.py`, `backend/services/wmax/device.py`
  - 关键词: test_connection, 测试按钮, flash_and_scan

## 功能变更

- [FEAT-001] 扫码器切换为触发式 (ondemand) 工作模式
  - 需求: 现场反馈扫码器持续扫描灯一直闪，希望改成"检测周期内才扫，周期外灯灭"
  - 实现:
    - `_auto_discover_wmax_bg` 启动时只建三端口 TCP，不再自动 `activate_rpt_reporting`
    - `manager.auto_discover_and_connect` 同样不激活 RPT
    - `start_scanning(channel_id)` 通过新增的 `_wmax_trigger` 发 `TurnOnOffVideo(on=True) + Trigger + LON` 三命令兜底
    - `stop_scanning(channel_id)` 发对应 off 命令
    - `trigger_scan` 新增 `_do_trigger_once_wmax` 分支：触发后最多等 10s 收条码，超时自动 off
  - 影响文件: `backend/services/scanner.py`, `backend/services/wmax/device.py`, `backend/services/wmax/manager.py`
  - 关键词: ondemand, 触发式, LON, LOFF, TurnOnOffVideo, Trigger, start_scanning, stop_scanning

- [FEAT-002] 测试按钮：闪光 5 秒 + 同步采集条码
  - 需求: 用户点测试要能实际看到扫码器闪光，并在 5 秒窗口内扫到条码直接返回，方便现场验收
  - 实现:
    - `WMaxDevice.flash_and_scan(duration=5.0)`: 临时接管 `on_code_received`，5 秒内去重收集条码后恢复回调，结束发三命令关灯
    - `scanner.test_connection`: 优先走 WMax 路径，返回 `{success, message, scanned: [...]}`
  - 影响文件: `backend/services/scanner.py`, `backend/services/wmax/device.py`
  - 关键词: flash_and_scan, 测试闪光, 5秒, 同步采集

## 已知问题

- **扫码器 LOFF 后灯不熄灭**：`trigger_off` 已发 `TurnOnOffVideo(off) + Trigger(off) + SendTermCmd(LOFF)` 三种命令，但扫码器固件仍保持扫描状态。需要进一步抓包 IDManager 看它关灯发什么命令才能对齐。当前不影响扫码功能，只影响"视觉体感"（灯常闪）。
- scanner.py 网络层 `192.168.0.100` 需要物理网卡在 `192.168.0.x` 网段，若被 Clash/Mihomo 代理劫持会 "connect 成功但无响应"，现场部署前先 `ping 192.168.0.100` 验证。

## 部署说明

客户机只需覆盖 4 个后端文件（其他无变动）：

```
backend/services/scanner.py
backend/services/wmax/device.py
backend/services/wmax/manager.py
backend/services/wmax/messages.py
```

扫码器前端配置不变（保持 `port=55256`，`device_type=auto`）。WMax 走硬编码 55266/55276/55286 三端口，`port` 字段只是登记用。
