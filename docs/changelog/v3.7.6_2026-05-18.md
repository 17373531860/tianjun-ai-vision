## Bug 修复

### [BUG-001] 顺序模式 cycle 末尾步骤"OK 已出 PT 仍 `--`"修复
- **症状**：客户看到「步骤详情」表里某一步状态=已检测、结果=OK，但 PT/s 列一直是 `--`。最典型出现在 cycle 末尾那一步（如顺序 A → B → C → D 里的 D 步）。
- **根因**：顺序模式 / 自定义顺序模式 在 cycle 判定结尾有一段"补计"逻辑，专门处理还在 `step_last_seen` 里、没经过 disappear_delay 主路径的步骤。这段代码只写了 `step_counts` 和 `step_durations` / `step_durations_history`，**漏写了 `step_cycle_durations`**：
  - 前端 `step_counts` +1 → `actualPosByLabel` 含该 label → 标 OK
  - 前端取 `cycleSumStepDurations` / `avgCycleSumStepDurations` / `lastCycleSumStepDurations` 任何 PT 合并档都没该 label 的 key → PT 列永远 `--`
  - **客户视觉感受**："OK 先出，时间没出来"
- **修复**：在两处补计路径补齐 `step_cycle_durations` 写入，跟主路径（`source_step_stats_mixin.py:298-303`）完全对齐：
  ```python
  prev_sum = self.step_cycle_durations.get(label, 0.0)
  self.step_cycle_durations[label] = round(prev_sum + rounded_dur, 2)
  ```
- **影响文件**：
  - `backend/api/source_sequential_mixin.py`（两处补计：顺序模式 + 自定义顺序模式）

### [BUG-002] PT 时间周期结束不归零修复（"当前周期内 + 最后一次"组合）
- **症状**：客户切到「PT 显示口径 = 当前周期内 + PT 计算方式 = 最后一次」时，周期结束后 PT 列**停在上一周期的值**，没归零。
- **根因**：双端不对齐
  - **后端**：`step_durations` 字段（语义"按 label 持续覆盖式的最近一次耗时"）只在 `reset_stats()`（手动清零按钮）里清空，**cycle 结束时不清**。`step_cycle_durations`（合并 SUM 档）则在 `end_cycle` / `_discard_empty_cycle` 的 finally 里清空。两个字段的清零行为不对齐。
  - **前端**：`Monitor/index.vue` 第 3663 行用 `Object.assign(stepDurations.value, data.step_durations)` 把后端推过来的字典 merge 而非替换。即便后端清空了，老 label 在前端字典里也清不掉。
- **修复**：双端同时对齐 — 后端清，前端整体替换
  - **后端**（`source_session_lifecycle_mixin.py`）：
    - `end_cycle` finally 块：在原有 `step_cycle_durations = {}` 之后追加 `self.step_durations = {}`
    - `_discard_empty_cycle` finally 块：同步追加，避免作废周期里的 label 串到下一周期
    - 注：清空位置在 finally 里、`end_cycle` 主体 629/661 行的兜底引用之后，安全
  - **前端**（`Monitor/index.vue`）：把第 3663 行的 `Object.assign(stepDurations.value, ...)` 改成整体替换 `stepDurations.value = data.step_durations || {}`，跟 `cycle_sum_step_durations` 第 3672 行的行为对齐
- **副作用兼容**：`last_step_durations` / `avg_step_durations`（历史档）保持 merge 行为不动，跟"累积式可读"语义对齐
- **影响文件**：
  - `backend/api/source_session_lifecycle_mixin.py`
  - `frontend/src/views/Monitor/index.vue`

## 功能变更

### [FEAT-001] 步骤详情表"列顺序调整 + 结果列硬性守门"
- **需求**：客户提出「步骤详情板块希望先出时间再显示 OK/NG 的结果」。
- **实现**：分两步
  1. **列顺序调整**：表头从 `No / 步骤 / 状态 / PT/s / 结果` 改为 `No / 步骤 / **PT/s** / 状态 / 结果`，PT 列前移到状态列之前。视觉叙事变成「第几步 → 用了多久 → 查没查过 → 结果如何」。
  2. **结果列硬性守门**（客户反馈"没区别"后追加）：在 td 模板里加 `v-if` 守门，**非跟踪模式下** PT 必须有真实数值（`formatStepPT(row.label) !== '--'`）才允许显示 OK/NG，否则也显示 `--`。
     - 这道守门是为了堵 BUG-001 之外另一类场景：accept_once / 跟踪类逻辑下，step_counts 已 +1 但 duration 还没写后端字典的"中间窗口期"。
     - 跟踪模式跳过守门（保持原 `counted > 0 → OK` 语义，因为跟踪模式底层就不写 step_durations）：
       ```vue
       <template v-if="isTrackingMode || formatStepPT(row.label) !== '--'">
         <span v-if="row.cycleResult === 'ok'">OK</span>
         ...
       </template>
       ```
- **影响文件**：
  - `frontend/src/views/Monitor/index.vue`

### [FEAT-002] PT 显示口径默认值从「平均」改为「当前周期内」
- **需求**：客户希望"周期结束 PT 时间默认归零"。出厂默认走"历史平均"，归零是"永不"，跟客户直觉不符。
- **实现**：
  - `frontend/src/store/useSystemStore.js`：`monitor.ptMode` 默认值 `'avg'` → `'current'`
  - `frontend/src/views/Monitor/index.vue: formatStepPT` 内部兜底默认 `|| 'avg'` → `|| 'current'`（跟 store 默认值对齐，store 未初始化时也能正确兜底）
  - `ptAggregate` 默认仍为 `'sum'`（合并），所以最终默认组合是「当前周期内 + 合并」→ 数据源 `cycleSumStepDurations` → cycle 结束自动归零
- **兼容性**：
  - 全新装机 / 没在 Settings 改过 PT 显示口径的客户：升级后默认归零生效
  - 已在 Settings 手动改过 PT 显示口径的老客户：localStorage 里存的选择**保留不动**，需要客户自行去设置切到「当前周期内」才能体验归零
  - 视觉冲击提示：默认 avg 时 PT 列显示的是历史平均（稳定数字），改成 current 后变成实时累加值（周期内增长 + 结束归零），有客户可能误以为"以前的数据没了" — 解释清楚：3 种口径并存在 Settings → PT 显示口径 里可切
- **影响文件**：
  - `frontend/src/store/useSystemStore.js`
  - `frontend/src/views/Monitor/index.vue`
