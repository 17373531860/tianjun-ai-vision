## 功能变更

- [FEAT-001] 逐件覆盖模式：重复打同一颗螺丝防护（默认关，老项目零差异）
  - 需求: 打螺丝场景工人回头对已打过的螺丝再打一枪，现有逻辑覆盖状态单调不变，既不报警也不留痕，漏检真实工艺违规。
  - 实现: `pipeline_config.per_item.duplicate_screw_alarm` 开启后，螺丝已覆盖 → 动作框"连续离开足够帧数（duplicate_release_frames，默认 8）算真正移开" → 又压回来并持续 duplicate_sustain_frames（默认 2）帧 → 判"重复打"：复用 NG 事件点报警灯 + PerItemPanel 黄条提示（duplicate_warning_display_sec 控制显示时长，duplicate_alarm_interval_sec 控制报警间隔），不落账 / 不结束周期 / 不动覆盖状态。单帧闪断 / 拔枪卡顿因"离开不够久不开门"从根上防误报；待补态里回头重打已打螺丝照样报，补打漏掉的螺丝合法不报。
  - 影响文件: backend/api/source_per_item_mixin.py, frontend/src/views/Monitor/PerItemPanel.vue, frontend/src/views/Project/LogicConfigTab.vue, tests/test_per_item_duplicate_screw.py
- [FEAT-002] 逐件覆盖模式：换板兜底结算（工件整体消失确认，默认关）
  - 需求（也是修 bug）: finish_label 单一结算的项目，若"换板/拿板"动作没被模型检出，上一板周期永不结算，其逐颗覆盖状态会按位置泄漏到新板——新板没打却显示已打（变绿）、计数为 0。
  - 实现: `pipeline_config.per_item.workpiece_absent_settle_frames` > 0 时，周期进行中所有 item 标签连续消失该帧数 → 视为工件被拿走/换板 → 按真实覆盖状态自动兜底结算（OK/NG）并复位，新板从零重锁。只在"全部件都不见"才累计，手拧单颗不会误触发；离场判定模式（judge_on_workpiece_leave）自带离场结算不走此兜底。
  - 影响文件: backend/api/source_per_item_mixin.py, frontend/src/views/Project/LogicConfigTab.vue, frontend/src/views/Project/index.vue, tests/test_per_item_board_swap.py
- [FEAT-003] 安装器：安装目录可选 + 升级"搬家"自动迁移（Windows Inno Setup）
  - 需求: 客户要求安装时能自己选目录；此前升级时静默沿用上次目录不给选，客户若想换盘符只能装出两份。
  - 实现: 升级也永远显示"选择安装位置"页（DisableDirPage=no + UsePreviousAppDir=yes，默认值仍是上次目录）；[Code] 段新增搬家逻辑——从卸载注册表读上次安装目录，本次选了不同目录时：先抢救旧目录内可能残留的用户数据库到用户数据目录，安装完成后确认旧目录确实躺着我们的主程序 exe 才整目录清除（防注册表脏值误删无关目录），并把开机自启快捷方式重指到新位置。同目录覆盖安装行为不变。
  - 影响文件: electron/build/installer.iss

## Bug 修复

- [BUG-001] 项目"显示启用"与"工位实际使用"重启后错位（显示与使用必须一致）
  - 症状: 项目页显示启用 A 项目，工位实际跑的却是 B 项目的模型与配置；重启电脑后必现复发，用户无法调试（"显示的和用的不是同一个"）。
  - 根因: 两套互不同步的持久化——项目页"启用"写数据库 is_active，工位各自的"绑定项目"写 workstation_config.json；开机自恢复优先级是绑定 > 全局启用。而运行时把项目推到工位（/source/detection/set-project，前端每次"开始检测"必经）和播放新视频（/source/video/start）都只改运行时状态、从不回写绑定，重启后旧绑定复活恢复另一个项目+另一个模型。启用项目（activate）对"已绑定其它项目"的工位又整体豁免，单工位部署时用户眼里的"启用"根本落不到那唯一的工位上。
  - 修复: ① set-project 成功后把该工位持久化绑定同步写成同一个项目（merge 只动 project_id 键）；② video/start 成功后落盘实际播放的视频路径；③ 启用项目时单工位部署（仅 1 个工位）不再被旧绑定豁免——配置、模型、持久化绑定一起切；多工位（≥2）保持"各工位绑定优先"原语义。修复后模拟重启验证：开机恢复项目/模型/视频三者一致。
  - 影响文件: backend/api/source_routes.py, backend/api/projects.py
  - 关键词: 显示与使用一致, 重启恢复错位, workstation_config 绑定, auto_load_active_project, set-project 持久化, 单工位激活豁免
