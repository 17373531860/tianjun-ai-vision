# v3.12.0 (2026-05-27)

> 合并 `chore/feature-verify` + `feat/per-item-enhance` 两条主线分支正式发版。无破坏性改动, 老项目 JSON/DB/接口全部兼容; 跳过 v3.11.x 直接到 v3.12.0 (用户决定)。

## 合并主线 — feat/per-item-enhance (per_item 逐件覆盖模式增强)

### [FEAT-001] **per_item 严格等量周期触发**
- **需求**: 客户打螺丝场景, 期望 6 颗螺丝, 不到 6 颗时不能开周期 (避免漏件被算成 NG); 必须 "看到 6 颗稳定 N 帧" 才正式起步。
- **实现**: 项目级 `pipeline_config.per_item.require_exact_count`. True 时 `_per_item_should_start_cycle` 把触发条件改成 "稳定窗口里每帧检出数 == expected_count" + "次步同时刻检出 ≥ 各自 expected_count"。False (默认) 沿用 v3.10.x 老逻辑。
- **影响文件**: `backend/api/source_per_item_mixin.py`, `backend/api/source_project_config_apply.py`, `frontend/src/views/Project/index.vue`
- **关键词**: per_item / require_exact_count / 严格等量 / 漏件 / 稳定窗口

### [FEAT-002] **per_item 手动结算模式**
- **需求**: 部分客户希望"师傅手动按按钮才认这一周期", 软件不能自作主张结算 (避免漏检判定为 OK)。
- **实现**: `pipeline_config.per_item.disable_auto_settle = True` 时, 自动收尾流程 (sustain_frames 满 / cycle_max_seconds 到 / 收尾标签触发) 全部跳过, 只能调 `/api/v1/source/detection/per-item-control` 显式结算。新增手动结算 / 强制开始两个 action。
- **影响文件**: `backend/api/source_per_item_mixin.py`, `backend/api/source_routes.py`, `frontend/src/views/Project/index.vue`, `frontend/src/views/Monitor/PerItemPanel.vue`
- **关键词**: per_item / 手动结算 / disable_auto_settle / per-item-control / force_start

### [FEAT-003] **box 尺寸过滤 (post-YOLO 守门)**
- **需求**: 现场摄像头偶尔把整个料盒 / 工位 / 操作员手臂识别成一颗 "巨型螺丝", 误开周期。
- **实现**: 在 `source_detect_runners_mixin._passes_box_size_limit` 加宽高守门, 任一标签匹配 `steps_config[i].per_item.box_max_width / box_max_height` 时按归一化坐标 (0-1) 过滤掉超大检测框。
- **影响文件**: `backend/api/source_detect_runners_mixin.py`, `backend/api/source_project_config_apply.py`, `frontend/src/views/Project/index.vue`
- **关键词**: per_item / box_max_width / box_max_height / 检测框过滤 / 误检

### [FEAT-004] **per_item 检测短路放行**
- **需求**: per_item 模式有自己的"瞬时累计计数"语义, 不能被 `_get_confirmed_detections` 的"连续帧确认"过滤掉, 否则首次检出永远凑不齐 expected_count。
- **实现**: `source._get_confirmed_detections` 在 logic_mode == "per_item" 时直接 `return list(detections)`, 跟 synthetic 模式同等待遇。
- **影响文件**: `backend/api/source.py`
- **关键词**: per_item / _get_confirmed_detections / 检测短路

## 合并主线 — chore/feature-verify (Monitor SOP 卡片增强)

### [FEAT-005] **SOP 卡片"图永不空"策略**
- **需求**: 客户 Monitor 视图里步骤缩略图在新周期开始那一瞬间被清空 → 灰白闪一下再填新图, 视觉跳变明显。

- **影响文件**: `frontend/src/views/Monitor/index.vue`
- **关键词**: SOP 卡片 / 步骤缩略图 / 图永不空 / 跨周期继承

## Bug 修复 (验收测试期间发现)

### [BUG-001] **`tests/conftest.py` 漏 import `auth_models`**
- **症状**: `pytest` 启动后 `Base.metadata.create_all` 直接报 `sqlalchemy.exc.NoReferencedTableError: users`, 全套测试无法跑。
- **根因**: v3.10.0 `feat/user-system` 引入 `backend/models/auth_models.py` (含 users 表), 业务代码会 import, 但 conftest.py 没显式 import → 调 `create_all` 时 SQLAlchemy 还不知道 users 表存在, 解析 ForeignKey 时炸。
- **修复**: 在 conftest.py 跟其他 ORM 模块一起加一行 `from backend.models import auth_models as _auth_models  # noqa`。
- **影响文件**: `tests/conftest.py`
- **关键词**: conftest / auth_models / NoReferencedTableError / 测试基础设施

### [BUG-002] **`test_pt_ct_modes_exposure` MagicMock 自动属性导致路由走错路径**
- **症状**: `test_current_cycle_time_在跑时大致正确` 报 `TypeError: '<' not supported between instances of 'float' and 'dict'`。
- **根因**: 路由 `current_cycle_time` 计算分支用 `_compute_dur = getattr(mgr, '_compute_duration_sec', None)` 判走 fallback。MagicMock 默认对未显式设置的属性返新 MagicMock 实例 → `is not None` 误为真 → `round(MagicMock, 2)` 返 dict → 测试 assert "<" 报 TypeError。
- **修复**: `_make_mock_mgr` 显式设 `mgr._compute_duration_sec = None` 让路由走 wall-clock fallback (测试模式期望的契约), 同时补 `cycle_start_frame_pos / video_current_frame` 两个帧号字段。
- **影响文件**: `tests/test_pt_ct_modes_exposure.py`
- **关键词**: pt_ct / MagicMock / 自动属性 / _compute_duration_sec / 测试 fixture

### [BUG-003] **`test_periodic_actions_v352` 字段名 `trigger_labels` 与生产代码 `trigger_step_labels` 不一致**
- **症状**: `TestPeriodicTriggerObservedBypassesSequentialFilter` 6 个测试全 fail, `_periodic_triggers_observed` 集合永远空。
- **根因**: 测试 fixture `_rule()` 给的是 `trigger_labels: [trigger]`, 但 `_apply_periodic_actions` 读的是 `trigger_step_ids` 或 `trigger_step_labels` (没 _step 前缀的不读) → rule 解析后 trigger_labels 集合为空 → "规则 'xx' 无有效 trigger 步骤，跳过" → `_periodic_actions = []` → `_observe_periodic_trigger` 短路返回不写账本。
- **修复**: 测试 fixture 补一个 `trigger_step_labels: [trigger]` (跟生产代码字段名对齐), 保留 `trigger_labels` 兼容老调用点。
- **影响文件**: `tests/test_periodic_actions_v352.py`
- **关键词**: periodic_actions / trigger_step_labels / 测试 fixture / 旁路账本

### [BUG-004] **`test_integration_scanner_bypass_*` 测试没跟上 v3.7.3 模板英文化**
- **症状**: 5 个 scanner_bypass 集成测试 fail, 内容含 "Pass / Fail" 但测试断言 "合格 / 不合格"; 第 4 行步骤时长格式从 "取件: 2.34s" 变成 "2.34s | 5.67s | 1.89s"。
- **根因**: v3.7.3 按客户固定英文要求把内置扫码器旁路模板从中文改成 Pass/Fail, 第 4 行步骤时长去掉了步骤名标签。集成测试断言没跟上模板演化。
- **修复**: 5 个断言统一改 Pass/Fail + 第 4 行只断言时长数值 ("2.34s" 等), 不再断言步骤名标签。
- **影响文件**: `tests/test_integration_scanner_bypass_export.py`, `tests/test_integration_scanner_bypass_strategies.py`
- **关键词**: 扫码器旁路 / 内置模板 / Pass/Fail / 模板英文化

### [BUG-005] **测试环境缺 `jsonschema` 依赖, plugin_system 校验测试集体降级**
- **症状**: `tests/plugin_system/test_validate_manifest.py` 7 个细节断言 fail, 错误统一为 "DID NOT RAISE ManifestValidationError"。
- **根因**: `_plugin_common.validate_manifest` 用 jsonschema 库做 schema 严格校验, 测试环境没装 → 走 fallback 模式只校验 required 字段 / customer_code / plugin_version 三个粗粒度字段 → stores prefix / table prefix / adapter prefix / hook enum 等细粒度规则全部不校验 → 测试期望抛错的 invalid manifest 都"通过"了。
- **修复**: `pip install jsonschema` (4.26.0 + 依赖)。装好后 81/81 plugin_system 测试全 PASS (包含被 fallback 屏蔽的 67 个细粒度测试)。
- **影响文件**: 无代码改动, 仅环境补依赖 (建议后续在 `requirements-dev.txt` 显式声明)。
- **关键词**: jsonschema / plugin_system / ManifestValidationError / 测试环境依赖
