# v3.25.0 (2026-06-24)

> 主题：**冷启动随机失败根治 + 补齐 v3.24.0 暂缓三项**。根治工控机"重启就不行、重开又好"的冷启动随机失败；把 v3.24.0 暂缓的 B1②(并发外推) / D1(取流背压) / C4(显存监控) 全部落地，新增的高/中风险能力**一律默认关**，关闭状态与旧版字节级一致，发版不影响现有现场；现场可开开关验证。

## 新增能力

### [FEAT-STARTUP-RETRY] 冷启动网络错误自动重试（默认开）

- **症状**：工控机重启后偶发"项目页空白 / USB 扫码枪静默失效"，重开软件又好——典型"重启就不行、重开又好"。
- **根因**：前端 `file://` 页面加载远早于后端就绪（CUDA 预热 + 大模型加载几十秒），落地即发的首屏请求撞上冷启动报 `Network Error`，各调用方 catch 后放弃且不再补。
- **修复**：在 axios 层对"请求没到服务器"的网络错误做退避重试（重发安全）：
  - 仅在 `backendEverReady=false` 的冷启动窗口内生效，**收到首个响应即永久关闸**（运行期不堆积、不请求风暴）；
  - 跳过所有高频轮询端点（监控结果/状态/扫码/调试）与关机端点；
  - 测试环境（vitest）禁用；一处生效自动覆盖所有客户在用接口。
- **影响文件**：frontend/src/api/index.js

### [FEAT-STARTUP-GATE] 加深启动就绪门槛（默认关）

- **能力**：开关开 → Electron 把"放主窗进来"的门槛加深到**后端深度就绪**（`/system/startup-ready` 真查数据库 + 项目表），进来即一切就绪；30s 数据库宽限超时则**降级放行 + 一次性告警**，绝不死等。
- **默认关**：仍探 `/source/status`，与旧版字节级一致（冷启动靠上面的首屏重试兜底）。
- 落盘 `workstation_config.json`，`GET/PUT /workstations/startup-ready-gate` + 设置页开关；下次开机由启动程序读取生效。
- **影响文件**：electron/main.js, electron/backend-manager.js, electron/preload.js, frontend/src/App.vue, backend/api/system_display.py, backend/api/channel_manager.py, frontend/src/views/Settings/index.vue

### [FEAT-C4] 模型加载后显存监控埋点（监控版，零风险）

- 主模型 / slot 加载后报告 VRAM 占用，空闲 < 800MB 告警，全程 `try/except` 不抛错。
- **不改**"每工位各持一份模型"现状（跨通道共享是历史串扰雷区，不动刀）。
- **影响文件**：backend/api/channel_manager.py

### [FEAT-B1②] 外部 MES 推送并发派发（默认关）

- **症状**：客户 MES 慢 / 断连时，`cycle_end` 外推的阻塞式重试把整个 hook 队列（扫码配对 / 绑工件）全堵住。
- **根因**：外推 `gw.dispatch()` 自带 `time.sleep × retry_count` 阻塞重试，跑在单条 `mes-hook-worker` 线程上。
- **修复**：开关开 → 外推甩到"每工位一条"`ThreadPoolExecutor`——**同工位 FIFO 严格保序**，慢工位不拖累 worker / 其它工位，每工位积压 > 200 丢最新 + 告警（MES 长时间不通的背压）；默认关 = 原内联派发字节级一致。
- 存 `SystemConfig(mes_async_dispatch)`，`GET/PUT /mes/gateway/async-dispatch` + 设置页开关即时生效。
- **影响文件**：backend/services/mes_hooks.py, backend/api/mes_gateway.py, frontend/src/views/Settings/index.vue

### [FEAT-D1] 多工位视频解码背压（默认关）

- **症状**：长时间多工位运行内存 / GC 压力升高。
- **根因**：多工位 MJPEG 每帧 `new Image()` 异步解码，解码跟不上到达速率时未完成解码 + blob URL 越堆越多（4 路高帧率叠加）。
- **修复**：开关开 → 改用 `createImageBitmap` + `framePump` 背压（**每工位同时只解一帧，跟不上丢中间帧只留最新**，`bitmap.close()` 即时释放解码像素），在途解码恒 0~1/工位、内存有界；默认关 = 原 `new Image()` 逐帧路径字节级一致。
- 背压逻辑抽成纯模块 `framePump.js`（无 DOM 依赖）+ node 单测（keep-latest / 单帧在途 / 跨工位独立，**红绿已验证**）。
- **影响文件**：frontend/src/views/Monitor/index.vue, frontend/src/views/Monitor/framePump.js, frontend/src/store/useSystemStore.js, frontend/src/views/Settings/index.vue
