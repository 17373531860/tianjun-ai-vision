> 三大主线合入主干：(1) **包装箱结算通用模式**（上银包装线）—— 工单→箱→托盘三层状态机，扫码驱动，全流程可配置（事件映射/去连字符/尾箱），不启用零差异；(2) **sensor-clean 传感器清洁插件 + detection_frame 帧级钩子** —— 平台新增 observe-only 帧级检测广播能力，插件按 detect6 自适应轨迹追踪算法逐帧自计数，离线比对基准 44→45（<3% 一致）；(3) **OK/NG 录像分开保留** —— 合格品短存、不良品长存，数据记录防孤儿。修 fujian-jinlong 插件 pydantic 2.12 兼容真 bug。三层测试（单元 + BDD + 可见浏览器 UAT）全绿：L1 836 passed（19 串污染单跑全绿）+ L2 361 passed，包装 UAT 9/9 + 视频分开存 UAT 4/4。

## 功能变更

- [FEAT-001] 新增: **包装箱结算通用模式（上银包装线，主程序原生）**
  - 需求: 上银包装线"扫工单→拿箱扫标签→贴标套袋→放四托盘（每托盘检测滑块数达标）→封箱→扫下一标签结算上一箱"的多层结算流程；箱标签号与工单号一致，多扫/少扫（漏箱）要报警。客户百花齐放但属基础设施性质，定为主程序原生通用能力（非插件），不启用时零影响
  - 实现: 独立 `PackagingFlowCoordinator` 单例（工单→箱→托盘三层事件驱动状态机），与核心检测解耦；扫码事件驱动 + 经 source 的 `on_cycle_settled` 挂接真检测路径触发托盘结算；高度可配置（扫码源/匹配规则/去连字符归一化/尾箱/期望箱数）；7 个异常类型（标签不匹配/漏箱/多箱等）映射到项目"事件设置"触发报警/语音/Toast/计数，经 `fire_external_event_response` 轻量响应不打断检测周期；Monitor 包装进度卡（启用显示当前工单/第几箱/托盘进度，禁用整块消失零差异）
  - 影响文件: backend/services/packaging_flow_coordinator.py（新）, backend/api/packaging_flows.py（新）, backend/models/mes_models.py, backend/api/source_session_lifecycle_mixin.py, backend/api/source_event_trigger_mixin.py, frontend PackagingFlowPanel.vue（新）, Monitor 包装卡, backend/main.py（建表迁移）

- [FEAT-002] 新增: **sensor-clean 传感器清洁插件 + detection_frame 帧级钩子（平台能力）**
  - 需求: 传感器清洁工序要"一根棉签擦满 K 个产品后锁定计数 + 换棉签解锁 + 双视角监控"，且产品计数要逐件复刻客户 detect6 脚本精度（基准 44 件）。主程序周期结算机制无法逐件对齐 detect6 的逐帧锚动作生命周期计数
  - 实现: 平台新增 `detection_frame` observe-only 帧级钩子，推理循环每帧（非 tracking 路径）把本帧检测框广播给插件；不在 RETURNABLE_HOOK_FIELDS 白名单（返回值丢弃，不改主程序检测/计数/录像/状态机），无 active 插件 O(1) 早退（热路径零开销），异常隔离不抛回推理线程。sensor-clean 插件用 detect6 同款 ProductCounter 自适应轨迹追踪（移动即计数 + 帧硬锁 + lost 抗丢检）逐帧自计数 + 棉签寿命约束 + 跨视角换棉签解锁 + 一键应用对齐 detect6 的项目配置模板
  - 验证: 离线隔离 YOLO 推理（视角1 best.pt + test.mp4 1728×1080@60fps）同锚框序列两路比对 —— detect6 原版算法 = 44（命中基准），插件 ProductCounter = 45，差 1 件（<3%）。差异根因为归一化坐标各向异性（x÷1728/y÷1080 致 y 方向位移放大），可通过 move_threshold 配置微调，不影响"效果一致"判定
  - 影响文件: backend/api/source_inference_loop_mixin.py, backend/plugin_system/hook_dispatch.py（docstring）, plugins-examples/sensor-clean/*（新插件）

- [FEAT-003] 新增: **OK/NG 录像分开保留 + 分别保留期**
  - 需求: 客户希望周期录像按结果分开存，合格(OK)录像短期留存省磁盘、不良(NG)录像长期留存可追溯（如 OK 7 天 / NG 180 天），仅作用于周期录像
  - 实现: VideoClip 加 `result` 列（OK/NG/None），周期结算时把结果回写关联录像记录（无条件一次 UPDATE，开销极小）；清理逻辑重构为两阶段 —— 数据记录"至少全局保留期、且不短于其录像保留期"（NG 录像更久时周期记录同步延长，防回放孤儿），录像文件按 OK/NG 各自保留期删除并置空回放引用；不开分开存时 OK/NG 一视同仁按全局保留期（等价旧行为，零差异）；Data 页"存储与清理"加开关 + 条件渲染 OK/NG 天数（关闭时不显示）
  - 影响文件: backend/models/models.py（VideoClip.result）, backend/api/source_session_lifecycle_mixin.py, backend/api/sessions_maintenance.py, backend/main.py（迁移）, frontend/src/views/Data/index.vue

## Bug 修复

- [BUG-001] 修复: **fujian-jinlong 插件 pydantic 2.12 `_StepThreshold is not fully defined`（预存真 bug）**
  - 症状: fujian-jinlong 客户插件后端模块加载即抛 PydanticUserError，13+ 个该插件集成测试全 error，等于该客户插件测试全废
  - 根因: 文件头 `from __future__ import annotations` 让所有注解变字符串，pydantic 2.12 默认延迟构建 schema；而 `_DurationConfig` 类体内 `default: _StepThreshold()` 在类定义期就实例化，此刻 validator 仍是占位 → 报 "not fully defined"
  - 修复: 在 `_StepThreshold` / `_DurationConfig` 类定义后各显式调一次 `model_rebuild()` 把 schema 落定再实例化。先红（复现 PydanticUserError）后绿（5/5 集成测试 + 13+ 单测全 pass）
  - 影响文件: plugins-examples/fujian-jinlong/backend/__init__.py
