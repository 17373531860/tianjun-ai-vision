## Bug 修复

- [BUG-001] USB 相机关自动曝光在暂停/重开后不保持，技彩现场"锁帧"（画面像卡死）
  - 症状: 技彩现场 USB 相机配置了关自动曝光 + 手动曝光值，正常跑帧率稳定；一旦监控页停止再开始、或相机瞬断重连、或刷新页面自动恢复源，画面帧率骤降到近乎静止（"锁帧"），要重新进设置页手动再设一遍曝光才恢复。
  - 根因: 三层叠加——① 停止会 release 相机，三条重开路径（resume 重开 / 采集线程断线重连 / 前端 localStorage 自动恢复源）都只回放了分辨率/FPS，漏回写曝光 → 驱动自动曝光复活，昏暗场景下 AE 拉长曝光时间压死帧率；② 曝光写入本身不分后端语义，MSMF（AE 关=0）和 DirectShow（AE 关=0.25）两个值都写、后写覆盖先写，撞后端时等于没关；③ Windows MSMF 默认探测硬件颜色变换，技彩 UVC 相机上每次 open/set 分辨率要重协商数秒，加剧"重开即卡"观感。
  - 修复: ① 曝光设置重构——先探测实际后端，按 MSMF/DSHOW/V4L2 各自语义精准写 AE 与曝光值，每次 set 记"请求值/set 返回/回读值"三元日志（`[Camera/Exposure]` 前缀）便于现场判断驱动拒绝还是量化；启动成功后记住后端 id。② 三条重开路径全部回放曝光设置：resume 重开沿用原后端（不再硬编码 DSHOW），采集线程重连分支与前端自动恢复源（补传自动曝光开关 + 手动曝光值两参数）同步配套。③ 后端 bootstrap 在 cv2 import 前增加 Windows 专属环境变量关闭 MSMF 硬件变换探测。
  - 影响文件: backend/api/source_camera_start_mixin.py, backend/api/source_capture_loop_mixin.py, backend/api/source_lifecycle_mixin.py, backend/main.py, frontend/src/views/Monitor/index.vue, tests/test_usb_camera_exposure_reopen.py, tests/e2e_browser/test_usb_camera_exposure_restore.py, tests/uat/uat_20260715_usb_camera_exposure_resume.py
  - 关键词: USB相机, 锁帧, 帧率骤降, 自动曝光, 曝光保持, exposure, CAP_PROP_AUTO_EXPOSURE, MSMF, DSHOW, HW_TRANSFORMS, 暂停恢复, 断线重连, 自动恢复源, 技彩, dev-qing
