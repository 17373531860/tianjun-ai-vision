## Bug 修复

### [BUG-001] "压墨"被误标为结算步骤
- **症状**: custom 模式 + `custom_based_on='sequential'` 的项目，Project 页步骤详情把不在执行顺序里的"压墨"高亮成"结算步骤"，客户困惑为什么压墨能算最后一步。
- **根因**: `isSettlementStep` 和 `watch(settlement_mode)` 硬读 `activeProject.value.sequence_order`，没区分 `logic_mode === 'custom' && custom_based_on === 'sequential'` 时真正生效的是 `custom_sequence_order`，旧 sequence_order 里还残留着压墨。
- **修复**: 加 `_activeSequenceOrder()` 助手按 logic_mode 选对应数组，`isSettlementStep` 与 settlement_mode 监听都走它。
- **影响文件**: `frontend/src/views/Project/index.vue`

### [BUG-002] 副模型 "未加载"
- **症状**: Project 页配好副模型 → Monitor 启动检测 → "副模型未加载" Toast，实际只跑主模型。
- **根因 A**: `syncProjectConfig` 把 `getProjectDetail` 返回值当 project 用，但它实际是 axios response，真 project 在 `.data` 里 — Pinia store 永远不更新 → `extraSlots=[]` → 走单模型路径。
- **根因 B**: 后端启动期 `_reload_model_for_active_project` 自动装主模型 → `model_loaded=true` → Monitor mount 时被识别为 `isPaused`，启动走"resume"分支跳过 `pipeline_config.models` 解析，副模型彻底没机会加载。
- **修复**:
  - `syncProjectConfig`: `const fresh = resp?.data`，store 真正更新到最新 pipeline_config。
  - `startDetection` 检测到 `_hasExtraSlots` 时强制 `apiStopDetection()` 后走完整启动路径（release + load 主+副）。
  - 加诊断日志 `[Monitor/start-detection]` 让 F12 一眼看出 extraSlots 是否触发。
- **影响文件**: `frontend/src/views/Monitor/index.vue`

### [BUG-003] 副模型删除后 step label 残留在步骤详情
- **症状**: 删除副模型后，它对应的 step 仍出现在步骤详情里，sequence_order 也带着它，客户感知"删了等于没删"。
- **根因**: `removeExtraModel` 只 `splice(extra_models)`，不动 `steps_config` / `sequence_order` / `detection_steps` / `custom_*` / `custom_conditions` / `simultaneous_groups`。
- **修复**:
  - `removeExtraModel` 加 `ElMessageBox.confirm` 列出影响的 step，确认后调 `onStepEnabledChange(step,false)` 清掉所有引用，再删 step 本体。
  - `initProjectDefaults` 加孤儿步骤自动清理 — 加载老项目时若 `from_model` 不再有对应 slot，自动剔除 step + 各 sequence/condition 引用，应对历史脏数据。
- **影响文件**: `frontend/src/views/Project/index.vue`

### [BUG-004] 视频拖动后开始检测回到起点
- **症状**: 用视频源调试，拖进度条到中段 → 点开始 → 视频从第 0 帧重新跑，客户感知"拖了等于没拖"。
- **根因**: `start_detection` 无脑 `self.capture.set(cv2.CAP_PROP_POS_FRAMES, 0)`，忽略用户 seek 位置。
- **修复**: 只有 `self.video_ended` 才 reset；否则读 capture 当前 `POS_FRAMES` 同步到 `self.video_current_frame`，让进度反算正确。
- **影响文件**: `backend/api/source.py`

### [BUG-005] 导出模板 `{{ app.version }}` 显示 "0.0.0"
- **症状**: 客户机自定义导出模板渲染出来版本号是 `0.0.0` 而不是真实版本。
- **根因**: `_read_app_info` 用 `BASE_DIR/../electron/package.json` 这条相对路径只在开发机灵；客户机打包后 `electron/package.json` 进了 `resources/app.asar`（electron-builder 默认 `asar: true`），Python `open()` 完全读不出来，fall back 到默认 `"0.0.0"` 还被永久缓存。
- **修复**:
  - `electron/backend-manager.js` 顶部 `require('./package.json')`，spawn 后端时通过 env 注入 `TIANJUN_APP_VERSION` / `TIANJUN_APP_NAME` / `TIANJUN_APP_PRODUCT_NAME` / `TIANJUN_APP_BRAND` / `TIANJUN_APP_BUILD_DATE` / `TIANJUN_APP_COMMIT` 共 6 个变量。
  - `export_context._read_app_info` 改"env 优先 → fs 多候选兜底 → 默认值不缓存"三段式。
- **影响文件**: `backend/services/export_context.py`, `electron/backend-manager.js`

### [BUG-006] 模型转换僵死任务永远卡 'converting'
- **症状**: 客户点转换 → ultralytics/TRT 编译卡 GIL → conversion.status 永远 'converting' → 前端转圈无穷无尽。
- **根因**: worker 内 `t.join(timeout=600)` 在 C 扩展里不一定按时返回；主 worker 不死，但子线程僵死。
- **修复**: 加 `_reap_stale_conversions`，在 `get_conversion_status` / `get_model_conversions` / `convert_model`（重提交）所有查询入口做懒回收，阈值 900s（600s worker 超时 + 5 分钟安全缓冲），落库改 `failed` + 友好错误。worker 开始转换时刷新 `created_at` 防误回收。
- **影响文件**: `backend/api/models.py`

### [BUG-007] 激活项目后阈值改动不生效
- **症状**: 客户在 Project 页改阈值 / `min_duration` / `sequence_order` 后保存 → 切回 Monitor → 跑检测仍用旧配置，必须手动重启检测才有效，客户感知"参数没用"。
- **根因**: `activate_project` 只调 `_reload_model_for_active_project` 重载模型，**不刷新** `mgr.project_config` — VSM 状态机还跑旧值。
- **修复**: 加 `_sync_project_config_to_channels`，把项目配置 push 到所有未绑定其它项目的 channel `mgr.set_project_config`，与启动期 `auto_load_active_project` fallback 分支同源。
- **影响文件**: `backend/api/projects.py`

### [BUG-008] 顺序模式重复 label 误判 NG（0% OK 率）
- **症状**: `sequence_order` 含重复元素（例 `A-B-C-B-D`，B 出现 2 次），客户跑出来 0% OK，全部 NG。
- **根因**: 旧 settle 用 `unique_steps = [...]` 去重后再 `zip(unique_steps, expected_labels)` 截断，与含重复的 expected 怎么也对不上。`_finalize_sequential_cycle` 里 `unique_steps.index()` 总返首次位置也是同一坑。
- **修复**:
  - `source_sequential_mixin._check_sequential_completion` 改用 `collections.Counter` 区分多次出现，unexpected / duplicated / missing 分别按 multiset 判定。
  - `source_settlement_mixin._settle_sequential_cycle` / `_finalize_sequential_cycle` 用"multiset 相同 → 逐位比较"判顺序，不再做 unique 去重。
- **影响文件**: `backend/api/source_sequential_mixin.py`, `backend/api/source_settlement_mixin.py`

### [BUG-009] 结算后"鬼周期"启动
- **症状**: 上一周期"放置产品"settle 完后，模型对它仍连续识别 → 下一帧立即启动 ghost cycle（cycle_steps 只含这 1 个 step） → 客户后续动作（拿取配件 1 …）被 `strict_order` 缺前置拦截，"闪一下没反应"，直到下一个"放置产品"再触发 settle → NG。
- **根因**: settle 后 `step_last_seen.clear() / step_frame_confirmed.clear()` 立刻执行，同一 label 下一帧再识别就被当"新出现"启动新 cycle。
- **修复**: 加 `_post_settle_ignore_labels` 集合，settle 时记录"仍处于已确认中"的 label，要求它们必须先彻底 disappear 一次才能再次触发 add-to-cycle。`source_step_stats_mixin` 的 disappear 处理负责清理 ignore set。
- **影响文件**: `backend/api/source_settlement_mixin.py`, `backend/api/source_state_init.py`, `backend/api/source_step_stats_mixin.py`

### [BUG-010] `accept_once` 阻挡周期内同 label N 次
- **症状**: `sequence_order` 含重复 label（例"检查外观×2"），第 2 次识别被 accept_once 拦下 — 框冒蓝色但不变绿。
- **根因**: 旧 accept_once 是硬规则"`label in current_cycle_steps` 即拦"，不看期望次数。
- **修复**: 按 `expected_seq.count(label)` 配额放行 — 已入 cycle 次数 < 期望次数时不拦截，让 add-to-cycle 走"期望重复"分支。
- **影响文件**: `backend/api/source_settlement_mixin.py`

### [BUG-011] MJPEG 旧连接累积导致黑屏
- **症状**: 切换 Monitor 路由 / 浏览器刷新 / 多客户端连同一通道，新页面黑屏几秒才出图。
- **根因**: Chrome keep-alive 不立即关旧 MJPEG socket，旧 generator 仍 hold `frame_lock` + thread-pool worker，新连接抢不到锁。
- **修复**: 每条 generator 分配 `connection_id`，记录每 channel 最新 id，旧 generator 每次 yield 前检测自己是否过期，过期主动 `break` 释放资源。同 channel 同时只保留 1 条 generator。
- **影响文件**: `backend/api/source_streaming_mixin.py`

## 功能变更

### [FEAT-001] 副模型支持 TensorRT / ONNX 格式转换
- **需求**: 主模型已能切换 `.pt → TensorRT FP16 → ONNX` 等加速格式（约提速 3-5x），但副模型 UI 没暴露"切换格式"按钮，且 Monitor 启动时 `_resolveModelPath` 硬编码 `pytorch_fp32` — 副模型即使转换好了也不会被加载。
- **实现**:
  - `Project/index.vue`: 副模型卡片加"切换格式"按钮 + 格式 tag 显示；`model_format` 字段进入序列化 / 反序列化；`formatSelectingExtraIdx` 跟踪当前在选的是哪个副模型 slot；对话框标题、当前格式标记按上下文切换；conversion polling 写到正确 slot。
  - `Monitor/index.vue`: 单通道 / 多通道分支的 `_resolveModelPath` 调用都改读 `e.model_format || 'pytorch_fp32'`，老项目无此字段时兜底。
- **影响文件**: `frontend/src/views/Project/index.vue`, `frontend/src/views/Monitor/index.vue`

### [FEAT-002] Project 页副模型参数 UX 简化
- **需求**: 副模型卡片把 `conf` / `IoU` / `优先级` / `FP16` 全部一字排开，客户分不清哪些是常用、哪些是高级；多数客户只调 conf 一个，其它默认即可。
- **实现**:
  - 主行只留 `置信度`（90% 客户只调这个）+"高级参数 ▾"折叠按钮。
  - 折叠区放 `IoU` / `优先级` / `FP16`，给四个参数都加详细中文 tooltip（人话解释，不是术语）。
  - 非 `pytorch_fp32` 格式时 `FP16` 自动 disable，hover 出 tooltip 解释"格式已固化精度，此开关无效"。
- **影响文件**: `frontend/src/views/Project/index.vue`

### [FEAT-003] 周期性强制动作手动重置
- **需求**: 客户中途想清零周期性动作计数器（例上一班产量已统计完，新班开始想从 0 算），但 `reset_stats` 会一并清空产量统计、cycle 状态、events_log，太重。
- **实现**:
  - `PeriodicActionsMixin.reset_periodic_counter(rule_id=None)` — `None` 重置所有规则，传具体 id 只重置一条；只动 counter / `last_overdue_count` / `run_on_start_pending`，不动其它。允许检测运行中调用。
  - 新增 `POST /api/v1/source/detection/reset-periodic?channel=...&rule_id=...` 路由。
  - 前端 `detection.js` 加 `resetPeriodicAction` 封装。
  - 测试 `test_periodic_actions_v352.py` 锁定行为。
- **影响文件**: `backend/api/source_periodic_actions_mixin.py`, `backend/api/source_routes.py`, `frontend/src/api/detection.js`, `tests/test_periodic_actions_v352.py`

### [FEAT-004] 预设模板"扫码器旁路三行 TXT"客户文案微调
- **需求**: 客户固定要求结果文件用英文 Pass/Fail，且步骤时长行不要 label 名字（客户固定 5 步产线，看耗时就够，不需要冗余描述）。
- **实现**:
  - 第 3 行 `合格/不合格` → `Pass/Fail`。
  - 第 4 行去掉 `step.label`，按 `step_order` 顺序只输出耗时，`" | "` 分隔。
  - description 同步更新版面说明 + Pass 完整 5 列示例 + Fail 截断 3 列示例 + Fail 不补 0 占位的注意事项 + app.version env 注入修复说明。
  - `seed_builtin_templates()` 启动时按 `builtin_id` 匹配刷新内容，**不动**客户已复制出的自建副本。
- **影响文件**: `backend/services/export_seed.py`

## 已知问题 / 后续
