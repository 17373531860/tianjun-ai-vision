# v2.7.2 (2026-04-18)

本次发版聚焦于**工位切换残留清理**和**数据中心 CSV 导出按项目/工位区分**两条主线，附带两套离线单元测试脚本（18 个用例）用于 CI/回归。

## Bug 修复

- [BUG-001] 切换工位后 Toast 重复弹出（合格+不合格+两个未扫码同时冒出）
  - 症状: 双工位→单工位（或单→多）切换、重新启动检测后，Monitor 同时弹出"合格 / 不合格 / 两个未扫码"Toast，但数据中心只记录一条结果（比如只一条合格）
  - 根因:
    1. `VideoSourceManager.events_log` 在 `stop_detection()` 里没有清空，只在 500 条截断或 reset_stats 清；`_event_seq` 也没有重置。`get_detection_results` 默认返回最近 30 秒内事件，老 NG 被带回前端当成新事件。
    2. 前端 `initMultiChannelData()` 对已存在的通道不重新初始化，导致切工位后 `multiLastSeenSeq[i]` 保留旧基线，新事件被判定成"已处理"或老事件被判定成"新"。
  - 修复:
    - 后端 `stop_detection()` 追加 `self.events_log = []; self._event_seq = 0`
    - 前端 `initMultiChannelData(count)` 先清理超出 count 的 key，再对 0..count-1 每个通道**强制重置** `multiChannelData`、`multiLastSeenSeq`、`multiFrameNaturalSize`
  - 影响文件: `backend/api/source.py`, `frontend/src/views/Monitor/index.vue`

- [BUG-002] 降工位时 MESHook 残留工单/扫码状态
  - 症状: 从 4 工位降到 1 工位再升回 2 工位时，新 ch1 的第一个周期可能被老的 `_pending_workpiece` / `_last_scan_event` 干扰，表现为"未扫码告警不弹"或"自动绑定到了老工件"
  - 根因: `MESHookManager` 有 6 个按 `channel_id` 存的 dict（`_pending_workpiece` / `_pending_queue` / `_active_orders` / `_inspecting_workpiece` / `_last_scan_event` / `_rebind_prompt`），从未在降工位时清理
  - 修复:
    - `mes_hooks.py` 新增 `on_channel_removed(channel_id)` 方法，集中 pop 6 个 dict
    - `channel_manager.py` 的 `set_channel_count()` 降工位循环里调用该方法
  - 影响文件: `backend/services/mes_hooks.py`, `backend/api/channel_manager.py`

- [BUG-003] 降工位时 AlarmRouter 串口/蜂鸣器残留
  - 症状: 降工位前某通道正在 NG 报警，降工位后蜂鸣器/灯塔仍在响，串口也被占用，再升回同通道无法重连
  - 根因: `AlarmRouter.managers` 按 `channel_id` 持有 `AlarmManager`，无任何清理路径；每个 AlarmManager 自己启后台报警线程 + 持有串口
  - 修复:
    - `alarm.py` 新增 `AlarmRouter.on_channel_removed(channel_id)`：`stop_alarm()` + `_idle_light_active=False` + `all_off()` + `disconnect()` + 从 managers pop
    - `channel_manager.py` 的 `set_channel_count()` 降工位循环里调用
  - 影响文件: `backend/api/alarm.py`, `backend/api/channel_manager.py`

- [BUG-004] 数据中心 CSV 导出不区分项目和工位
  - 症状: 在"项目A + 双工位"下点"导出当日数据 / 某周 / 某月 / 日期范围"，CSV 里混入了**所有项目 + 所有工位**的会话；表头也没有工位列，工厂场景下交付给客户的报表可能串项目
  - 根因:
    1. 后端 `/data/export/csv` 接口签名缺 `project_id` 和 `channel_id` 参数，`all` 分支 query 只按日期过滤
    2. 前端 `exportDateRangeCsv / exportWeekCsv / exportMonthCsv` 三个函数也从未传这两个参数
    3. CSV 表头里有"项目"列但没有"工位"列
  - 修复（一次到位）:
    - 后端 `export_csv` 加 `project_id: Optional[int]` / `channel_id: Optional[int]`（`Query(None)` 向后兼容）
    - `all` 分支追加两个 filter；元数据增加"项目/工位"两行；"会话列表"表头加"工位"列；周期/步骤分组标题改成 `[项目名 / 工位N] 会话 XXX`
    - `session` 分支会话信息表头也加"项目 / 工位"列
    - 前端三个 API 增加 `projectId` / `channelId` 参数
    - 前端 Data 页新增 `exportAllProjects` 开关（默认关）、"导出范围"提示条、多工位未选工位时的橙色提醒
    - 文件名编码 `proj{id|ALL}_ch{N|ALL}_{date}.csv`，避免不同导出互相覆盖
  - 影响文件: `backend/api/sessions.py`, `frontend/src/api/data.js`, `frontend/src/views/Data/index.vue`

## 功能变更

- [FEAT-001] 数据中心导出范围可见化
  - 需求: 解决 BUG-004 的同时让用户在导出前就能一眼确认"这次要导出的项目/工位/日期"
  - 实现: Data 页导出操作区顶部新增提示条，实时显示 `项目【X】 · 工位【Y|全部】 · 日期【Z】`；多工位模式下 `channelFilter=null` 时给出橙色建议；底部有一个"导出全部项目"开关用于跨项目审计场景
  - 影响文件: `frontend/src/views/Data/index.vue`

- [FEAT-002] 降工位清理钩子公共接口
  - 需求: 为后续子系统（外设、扫码、集群）按同样模式接入降工位清理做铺垫
  - 实现: MESHook 和 AlarmRouter 两个单例都暴露 `on_channel_removed(channel_id)` 公共方法，ChannelManager 统一调用
  - 影响文件: `backend/services/mes_hooks.py`, `backend/api/alarm.py`, `backend/api/channel_manager.py`

## 验证步骤（供 QA/用户自测）

1. 启动双工位，让 ch0、ch1 各跑几个周期（含 NG）后停止 → 切单工位保存 → 再切双工位
   - 期望：ch1 的 Toast、计数器、检测框从零开始，不弹出历史 NG/未扫码
2. 双工位场景 ch1 触发蜂鸣器报警后立即切单工位
   - 期望：蜂鸣器立刻停止；ch1 对应串口释放（`ls -l /dev/ttyUSB*` 或设备管理器）
3. 数据中心 → 切到项目 A → 导出当日
   - 期望：CSV 文件名含 `proj{A的id}_chALL`；CSV 顶部元数据写"项目 【A】"；会话列表有"工位"列，不混入项目 B 的 session
4. 打开"导出全部项目"开关 → 再导出当日
   - 期望：文件名含 `projALL`；CSV 含 A 和 B 两项目的 session
5. 选具体工位后再导出
   - 期望：文件名含 `ch{N}`；CSV 元数据写"工位 N"；仅该工位 session
