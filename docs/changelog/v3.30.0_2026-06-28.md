# v3.30.0 (2026-06-28)

> 主题：**规格→检测项目自动切换升级为「位置/分隔符无关」的统一匹配器（入站与包装共用）+ custom_mix 容器进箱确认多方式增强 + 频闪根因修复与诊断**。
> 把"按规格/产品码自动切项目"从死的精确匹配，升级成「对照表精确 → 通配符 → 自动同名子串」三级兜底，天然吃下前缀变/后缀变/中间固定/任意或无分隔符；MES 入站与上银包装线复用同一匹配器，为后期合并铺路。按名匹配默认改为关，存量客户零差异。

## 功能变更

- [FEAT-001] 规格→项目统一匹配器（入站与包装共用，与位置/分隔符解耦）
  - 需求: 现场规格命名千变万化——`xxxx-xxx` 后缀天天变、也可能前缀变/中间固定/分隔符非 `-`/根本无分隔符；旧的"项目名==规格"精确匹配只能命中固定写法
  - 实现: 新增共享函数 `resolve_project_id_by_spec`，取项目三级兜底——① 对照表精确 ② 对照表通配符（键支持 `*`/`?`，取最长键=最具体）③ 自动同名子串（项目名是规格的一段，取最长命中）。MES 入站 `_switch_project` 与包装 `_real_project_activator` 都改调它，口径完全一致
  - 影响文件: backend/services/project_match.py, backend/services/mes_inbound.py, backend/services/packaging_flow_coordinator.py

- [FEAT-002] 自动同名匹配新增"严格边界"可选档（默认关）
  - 需求: 自动子串匹配存在短名误吞风险（如 `HG` 命中 `HGH20-001`）
  - 实现: 开启后要求项目名命中处贴串首/尾或分隔符，防误吞；关（默认）则仅靠"取最长命中"压歧义，但能覆盖无分隔符场景。包装侧新增 `name_match_strict_boundary` 列 + 迁移；入站存 SystemConfig JSON 自动带默认
  - 影响文件: backend/models/mes_models.py, backend/main.py, backend/api/packaging_flows.py, backend/services/mes_inbound.py, frontend/src/views/MES/OrderInboundPanel.vue, frontend/src/views/Settings/PackagingFlowPanel.vue

- [FEAT-003] custom_mix 容器进箱确认多方式增强（上银包装线）
  - 需求: 只靠"托盘消失满 N 帧"判定进箱不可靠（工人拿托盘有快有慢）；需要"识别放托盘动作"作为另一种确认，并支持二选一/组合
  - 实现: 容器累加器支持四种进箱确认（仅帧/仅动作/OR/AND）+ 放托盘动作状态机 + 屏蔽窗口（动作进行中锁主托盘、不数下一盘滑块防串算）。默认"仅消失满帧"=老行为零差异；前端"标签动作确认"通用命名 + "消失确认帧"仅勾选"消失满帧"时显示
  - 影响文件: backend/api/source_custom_mix.py, frontend/src/views/Project/index.vue

- [FEAT-004] 频闪诊断系统（环形快照 + 原始置信度侧信道 + 自动转储）
  - 需求: 现场偶发标签频闪/步骤反复刷"完成"，需在复现时抓到真实根因（是漏帧还是阈值过滤）
  - 实现: 每帧采样标签在场态/置信度/原始置信度写环形缓冲；某标签 2 秒内在场态翻转 ≥8 次时自动转储 JSON 到 `DATA_DIR/diag_flicker/`；runner 在阈值过滤前记录原始置信度侧信道，区分"被低置信过滤"与"真没检出"
  - 影响文件: backend/api/source_step_stats_mixin.py, backend/api/source_detect_runners_mixin.py, backend/api/source_inference_loop_mixin.py

## Bug 修复

- [BUG-001] 包装自动切项目函数缩进语法错导致整模块 import 失败
  - 症状: 上银包装线"按规格自动切项目"实际不生效
  - 根因: `_real_project_activator` 内 `if proj is None:` 与其 body 同级缩进（IndentationError），`packaging_flow_coordinator` 整模块无法 import
  - 修复: 重写该函数改调共享匹配器，缩进修正；新增护栏测试断言模块可正常 import
  - 影响文件: backend/services/packaging_flow_coordinator.py

- [BUG-002] custom_mix 容器/动作标签被当普通步骤反复刷"完成"导致频闪刷屏
  - 症状: 检测中心托盘/滑块标签频闪，终端不停打印"步骤完成: 托盘"
  - 根因: '托盘' 既是容器标签又被配成普通步骤，模型短暂漏检即触发步骤完成事件
  - 修复: 步骤机剥离集由 `item_labels` 扩成 `strip_labels`（物品+容器+动作标签），容器/动作标签由累加器独占消费，不再驱动普通步骤完成
  - 影响文件: backend/api/source_custom_mix.py, backend/api/source_step_stats_mixin.py
