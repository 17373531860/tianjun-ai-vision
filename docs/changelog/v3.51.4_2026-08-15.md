# v3.51.4 (2026-08-15)

> 交付补全补丁版：v3.51.3 发出后做成品安装包解剖审计，发现 PG 组件的**配套迁移工具
> `sqlite_to_pg.py` 从 v3.49 设计之日起就没进过打包清单**——客户勾选 PG 组件装出来
> 只能用全新空库，要保留旧 SQLite 数据无工具可用。本版把工具收进安装包 + CI 存在性
> 硬校验，并把这轮"代码全绿但安装包丢件"的教训沉淀进测试/打包 skill。无任何代码行为变更。

## 功能变更

- [FEAT-001] 安装包收编 SQLite→PG 迁移工具 `sqlite_to_pg.py`
  - 需求: v3.49~v3.51.3 的安装包里从未带过迁移工具（electron-builder extraResources
    只收 backend/前端/插件文档，`scripts/` 整目录不在清单）；v3.51.3 把 PG 组件本体
    交付后，"保留旧数据切 PG"仍然要靠人工拷脚本到现场。
  - 实现: `electron/package.json` extraResources 新增 `scripts/db/sqlite_to_pg.py` →
    客户机落位 `安装目录\resources\scripts\db\sqlite_to_pg.py`。脚本自带"向上三级找
    项目根"的 sys.path 逻辑，在该落位下正好指到 `resources\`（backend 可导入），
    打包 Python 环境里 psycopg2 齐备，零改动直接可跑：
    `resources> python\python.exe scripts\db\sqlite_to_pg.py --sqlite "%APPDATA%\tianjun-ai-vision\sql_app.db" --pg "<db_config.json 的 database_url>" --truncate-first --verify`
  - 防复发: CI "Verify packaged resources" 步骤（v3.15.1 建）的必检清单加入该文件，
    缺失红灯阻断发版——与 PG staging 的硬红同族，不允许交付物再次静默缺失。
  - 影响文件: electron/package.json, .github/workflows/build.yml
