## 功能变更

- [FEAT-001] 区域事件「序列校验三件套」：严格模式 / 无序组（组内按序）/ 监控页展示序列
  - 需求: 雷鸟拿料装盘工位（拿5→检→放→拿6→放→拿4→检→放→拿2→检→放→收盘）——"放入"类动作完成后条件残留恒真（已放入的料一直在盘内），互斥打断后残留重新累计产出假确认搅乱序列；四个拿料动作实际由双手流水交错完成，写死顺序会误 NG
  - 实现: ① `sequence_check.strict` 严格模式——非结算动作型规则确认时不等于期望序列下一位 → 静默吸收（不进序列/不计步骤/不触发事件/不打断其他 episode），吸收后同一动作可再确认，真缺步靠结算 exact 不匹配暴露；结算规则永不吸收，周期未开时非首位确认也吸收（防幽灵开周期）② `sequence_check.groups` 无序组——组成员是并行轨道（不受严格守门/互不打断），每周期每成员须恰好 `count` 次，超额产出 `group_repeat` 留痕不静默；`ordered: true` 组内按序（确认时点可与主序列交错，结算时校验组成员子序列==成员表顺序）；配套 `complete` 结算 = 抽掉组成员后子序列逐字节比对 + 逐组数量完备，一条收口少拿/多拿/缺步/乱序 ③ `display_order` 监控页展示序列——纯前端展示模板（如「拿料4号(第2次)」按物理工位顺序铺卡），引擎零消费
  - 前端: LogicConfigTab「顺序校验」区块三扩展（严格模式开关/无序组编辑器含 ordered/展示序列），Project 保存 `_sanitizeRegionEvents` 兜底，monitorModes `regionEventRuleSteps` 消费 display_order 建卡
  - 默认态: strict/groups/display_order 全部默认无配置零差异，依附 `sequence_check.enabled`
  - 影响文件: backend/api/source_region_events.py, backend/api/source_region_events_mixin.py, frontend/src/views/Project/LogicConfigTab.vue, frontend/src/views/Project/index.vue, frontend/src/views/Monitor/monitorModes.js
  - 测试: tests/test_region_events.py 125 项（严格模式/无序组/ordered 专段）+ BDD region_events_matrix.feature + e2e test_region_events_tab.py + vitest monitorModes 49 项
