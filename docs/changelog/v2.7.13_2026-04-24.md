# v2.7.13 (2026-04-24)

## Bug 修复

- [BUG-001] 跟踪模式"秒/帧"阈值延迟 5 倍
  - 症状: 用户在跟踪模式下把"遮挡容忍"、"消失确认"等秒数类阈值设成 1 秒, 实际生效却要 5 秒以上, 全部"秒"类参数都表现为"按设定值放大 5 倍才结算"
  - 根因: 阈值"秒→帧"换算一直用 `self.fps_actual` (采集线程 FPS, 常见 25~37); 但计帧数 `+=1` 发生在 `_inference_loop` 里, 推理线程受 GPU/模型影响常只有 5~8 FPS. 采集 30 / 推理 6 = 帧数阈值被放大 5 倍. 此外 `min_cycle_age = max(max_lost_sec, 1.0)` 的 1 秒兜底会把 < 1 秒的阈值卡住
  - 修复: 新增 `self.fps_inference` 并在 `_inference_loop` 里每秒统计一次; `_generate_custom_tracker_yaml` 的 `track_buffer`、`_update_tracking_stats` 的 `item_lost_frames`、`_update_step_stats` 的 tolerance 三处换算全部改用 `max(self.fps_inference, 10)`; 去掉 min_cycle_age 的 1 秒兜底, 只保留 max_lost_sec 业务门槛. `get_detection_results` / `get_source_status` 等 API 同时把 `fps_inference` 透出给前端观察
  - 影响文件: backend/api/source.py
  - 验证: 新增 tools/test_tracking_fps.py 在"推理 150ms/帧"模拟弱 GPU 下实测, 采集 37/推理 7, 比值 5.3x; 旧公式下"1 秒"实际生效 5.29s, 新公式 1.43s; "0.2 秒"旧公式 1.00s, 新公式 0.29s. GPU 充足场景 (推理≈采集) 新旧一致, 零回归

- [BUG-002] 集群"待汇总"和"最近完成"显示同一条码结果不一致
  - 症状: 一个箱子左下角"待汇总"里显示为 OK/缺 XX 件、右下角"最近完成"里却显示 NG, 明显是同一个工件但结果互相矛盾; 工人把 NG 工位重扫后, BoxAggregation 数据已刷新但 BoxSummary 仍停留在首次 NG 状态
  - 根因: `_check_and_dispatch` 只查 `status='received'` 的 BoxAggregation, 首次齐发后所有工位 status 变成 `dispatched`; 再扫某一工位只会产生一条新的 `received` 记录, 此时判齐全时只能看到这一条, 整箱误判为缺齐, 不会走到 BoxSummary 更新分支. 另一边 `get_pending_boxes` 的 missing 判定也只看 received 记录, 导致已 dispatched 的工位被误算作"缺失"显示在"待汇总"里(假未齐)
  - 修复: 方案 B — `_check_and_dispatch` 改用 `all_records` (含 dispatched) 判齐全, 但只有至少一条 `received` 才触发逻辑(防止定时器空转); 二次齐发时对比 `_key_fields` (overall_result + ng_items 排序后 tuple): 有变化就回退 status 到 complete 并重推 MES, 无变化只刷 BoxSummary 字段不骚扰 MES. `get_pending_boxes` 的 missing/received 集合都换成 all_records, 齐全则直接从"待汇总"列表里剔除, 避免假未齐
  - 影响文件: backend/services/cluster_collector.py
  - 验证: tools/test_cluster_recovery.py 覆盖"首发 NG → 重扫纠正为 OK → 再次齐发无变化"三轮场景, 断言 BoxSummary 字段随 BoxAggregation 同步、MES 仅在实质变化时重推、"待汇总"在齐全后消失

## 功能变更

  - 影响文件: backend/api/source.py

## 兼容性/升级说明

- 跟踪模式 FPS 修复会让之前"靠旧代码 5 倍放大误打误撞凑对"的参数失配: 如果客户此前把"遮挡容忍"手动缩小 5 倍来绕过旧 bug, 升级后会生效得更快. 建议升级后重新核对一次"遮挡容忍 / 消失确认 / tolerance" 等秒数类参数, 按实际业务需要的秒数填, 不要再"提前缩 5 倍"
- 集群方案 B 的二次校正仅在 BoxAggregation 有新的 `received` 数据时触发. 结果一致时只更新 summary 不重推 MES, 客户 MES 不会收到重复同值骚扰; 结果变化时必然重推, 建议客户 MES 做好幂等(用 `box_serial` / `workpiece_id` 去重)
