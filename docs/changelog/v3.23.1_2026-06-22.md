# v3.23.1 (2026-06-22)

> 完成 v3.23.0 已宣告但尚未真正落地的「NG 补做」核心闭环：把「延迟落账」模型从包装专属的补滑块，
> 推广到任意检测模式的**缺步骤**场景，并补齐操作员侧的人工确认三态处置入口。
> 未开「NG 补做策略」的客户行为零差异。

## 功能变更

- [FEAT-001] 任意模式「缺步骤」NG 延迟落账（通用补做核心）
  - 需求: v3.23.0 FEAT-005 宣告了「可补做的 NG 不先记账，待人工定结果再写终值」的延迟落账模型，
    但只在包装补滑块（FEAT-006）落地。客户要求顺序 / 检测模式下「漏某个步骤」导致的 NG 也能
    人工就地补做判合格，而不重置整个周期。
  - 实现: 在事件中心收口点 `_trigger_event` 加唯一守门——本周期判 NG 且原因是「缺步骤」、
    且项目开了 `ng_remediation.allow_step` 时，**不** end_cycle / 不计数 / 不推 MES，改为挂起
    （报警提示工人），写 `_pending_remediation` 快照（缺项清单 / 原因 / 事件 / cycle）。
    人工三态处置 `resolve_step_remediation`：
    - `supplement_step` 补做缺步 → 信任补做直接判 OK 落账；
    - `confirm_ng` 认 NG → 经一次性旁路标志 `_remediation_bypass` 重发 NG，此刻才落账（防自锁）；
    - `redo`（缺省）丢弃在制周期重检。
    缺步骤解析 `_parse_missing_steps` 兼容「缺少:」/「缺少步骤:」两种文案，正则失配时回退用
    `steps_config` 对比 `current_cycle_steps` 推算缺项，保证缺项清单始终可填。
    默认 `ng_remediation.enabled=False` → 守门不触发，行为与改前严格一致。
  - 影响文件: backend/api/source_event_trigger_mixin.py, backend/api/source_state_init.py,
    backend/api/source_routes.py

- [FEAT-002] 人工确认弹窗扩展三态处置（缺步骤补做）
  - 需求: 缺步骤挂起后操作员需要在监控页就地选「补步骤判合格 / 认 NG / 重做本件」，
    而不只是老的「确认重做」单一动作。
  - 实现: 检测结果新增 `pending_remediation` 字段（None=无挂起；含缺项明细）；前端全局人工确认
    遮罩在挂起态展示缺步骤清单 + 三按钮（补步骤—判合格 / 认 NG / 重做本件），普通确认与提权确认
    （借管理员密码）两条路径都透传 `action` 参数。无挂起时弹窗维持老「确认重做」语义不变。
    后端 `_do_ack_pending` 检测到挂起态时路由到 `resolve_step_remediation`，缺省动作 = redo，
    既保留老按钮语义又避免清掉 `_pending_ack` 却漏清挂起快照 / 留孤儿在制行。
  - 影响文件: backend/api/source_routes.py, frontend/src/api/detection.js,
    frontend/src/views/Monitor/index.vue

## 配置建议

- 操作员要在监控页看到包装结算卡片（客户名 / 工单号 / 箱进度），其角色需含
  `system.packaging_flow.view` 权限。内置 `operator` 角色默认不含此权限，按客户需要在
  「账号鉴权」里给操作员角色补这一项（本版未改默认角色种子，避免影响其他客户）。
