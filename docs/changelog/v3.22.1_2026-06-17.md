# v3.22.1 (2026-06-17)

> 补全 v3.22.0 上银包装/MES 闭环在「系统设置 → 调试设置」里的缺失分类与埋点，并修复一处导致包装结算调试日志全程失效的导入 bug。纯调试可观测性增强 + bugfix，不动任何业务逻辑；未开调试开关时零开销、零差异。

## Bug 修复

- [BUG-001] 包装结算调试埋点导入写错，开关打开也永远不出日志
  - 症状: 系统设置→调试设置里即便打开包装相关开关，实时日志流里一条 `backend.packaging` 都不出；看代码"埋点都在"，实际全是哑的。
  - 根因: 埋点处写成 `from backend.core.debug_center import debug_center`（想从模块里导一个名为 `debug_center` 的对象，但该对象不存在；全项目正确写法是 `from backend.core import debug_center`，把模块本身当 `debug_center` 用）。导入每次抛 ImportError，被埋点外层 `try/except` 静默吞掉 → 一条日志都不落。v3.22.0 里原有的那处包装报警埋点也是同样错误写法，自发版起从未生效。
  - 修复: 5 处统一改为 `from backend.core import debug_center`；加运行时自检（开关打开后驱动一个滑块闭环，确认 15 条关键日志真正落入调试缓冲；关态零开销验证不落任何日志）。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/source_custom_mix.py, backend/api/packaging_flows.py

## 功能变更

- [FEAT-001] 补全包装箱结算调试分类 + 全链路埋点
  - 需求: v3.22.0 上银包装/MES 闭环的核心环节（扫码开单、条码补连字符、MES 拉单、算箱/尾箱、按型号切项目、逐箱滑块结算、尾箱塞工单 gate、漏箱/多箱报警）没进调试中心，现场排查"为什么算成 3 箱尾箱 58 / 为什么尾箱没收尾 / 为什么没自动切项目"时调试设置里开什么都看不到。
  - 实现:
    - 后端注册调试分类 `backend.packaging`（MES 组），前端注册 `mes.packaging`（MES 组），调试设置开关矩阵据此渲染。
    - 协调器加统一埋点助手 `_pkg_dbg`（先 `is_on` 守门再拼字符串，关态一次 dict 查询即返回，零开销）；埋点覆盖：条码正常化(insert_char 补 `-`)、扫码入口、MES 拉单成功/阻断、按规格切项目、开工单(滑块总数/每箱/箱数/尾箱目标)、设当前箱滑块目标(含尾箱动态切)、逐箱周期结算(滑块数/目标/是否尾箱)、尾箱塞工单 gate 过/未过、开下一箱/工单收尾、工单完成/作废、各类报警；trays 口径开箱/结箱也补对称埋点。
    - 容器累加器(托盘当容器、计滑块)埋点：设箱目标、托盘进箱记账(峰值)、封箱周期进箱滑块总数(交给包装结算的那个数)，均带 `is_on` 守门，仅在进箱/封箱等非每帧节点触发。
    - 扫码 API `/packaging-flows/scan` 记一条带工单/箱进度的入口日志。
    - 前端埋点：包装配置创建/更新/启停(`mes.packaging`)、USB 扫码命中包装结算分支、Monitor 包装卡状态变化(仅状态变化才打，避免 1.5s 轮询刷屏)。
  - 影响文件: backend/core/debug_center.py, backend/services/packaging_flow_coordinator.py, backend/api/source_custom_mix.py, backend/api/packaging_flows.py, frontend/src/utils/debug.js, frontend/src/composables/useScanGun.js, frontend/src/views/Settings/PackagingFlowPanel.vue, frontend/src/views/Monitor/index.vue

## 关键不变量

- 仅新增可观测性与一处导入修复，不改任何包装结算业务逻辑；全量 packaging 测试 116 passed 零回归。
