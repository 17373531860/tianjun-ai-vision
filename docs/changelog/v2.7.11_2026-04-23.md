# v2.7.11 (2026-04-23)

## 功能变更

- [FEAT-001] 外部 MES 对接: 新增统一鉴权 (bearer / api_key / custom_header)
  - 需求: 不同客户 MES 要求的鉴权方式不一样, 过去只支持 Basic 和 none, 现代云 MES 常要 Bearer Token 或 API Key Header, 老式客户要自定义 Header
  - 实现: `MESGateway._apply_auth_to_headers()` 静态方法把 `auth.type=bearer/api_key/custom_header` 合并进 `config.headers`, `basic` 仍走 `requests.auth`; 同时支持顶层 `custom_headers` 列表作为"鉴权之外的额外固定 headers"
  - 影响文件: `backend/services/mes_gateway.py`, `frontend/src/views/MES/GatewayPanel.vue`

- [FEAT-002] 外部 MES 对接: 按结果过滤推送 (push_on_result)
  - 需求: 有客户只关心 NG 箱 (不合格才通知), OK 箱不必推; 反过来也有只关心 OK 确认入库的场景
  - 实现: `MESConnection.config.push_on_result` = `["NG"]` / `["OK"]` / `["OK","NG"]`. `_send_to_connection` 在鉴权前先按 `overall_result` / `result` 过滤, 不符合就只写一条 skip 日志不调 adapter
  - 影响文件: `backend/services/mes_gateway.py`, `frontend/src/views/MES/GatewayPanel.vue`

- [FEAT-003] 外部 MES 对接: 物料名称映射 (label_mapping)
  - 需求: 天竣内部步骤名是中文 (如"螺丝A"), 客户 MES 用物料代码 (如 `PART-001`), 过去只能在推送模板里逐字段写死
  - 实现: `MESConnection.config.label_mapping` = `{"螺丝A": "PART-001", ...}` 自动对 `ng_items` 做替换; 两种模式: `replace` 直接换 / `keep_both` 原字段保留再加 `ng_items_mapped`
  - 影响文件: `backend/services/mes_gateway.py`, `frontend/src/views/MES/GatewayPanel.vue`

- [FEAT-004] 集群汇总: aggregated 增加顶层便利字段 (order_no / workpiece_id / ng_items / result)
  - 需求: 过去 MES 模板取工单号要写 `{stations[0].order.order_no}` 嵌套取值, 写模板非常痛; 多个客户都反馈一样的字段取不方便
  - 实现: `_check_and_dispatch` 和 `_push_timeout_result` 两个分支都从 `stations_data` 里扫出第一份 `order` / `workpiece` / 所有 NG 步骤的 `label`, 塞到 aggregated 顶层. 超时分支 `missing_stations` 自动转 `MISSING-<工位>` 合进 `ng_items`
  - 影响文件: `backend/services/cluster_collector.py`

- [FEAT-005] 前端 MES Gateway 配置页: 全面图形化
  - 需求: 过去客户配置要改 JSON, 运维不会改; 这一轮要求"客户怎么回答都不改代码, 前端点点就能配"
  - 实现: GatewayPanel.vue 新增 [鉴权方式下拉 + 对应动态表单] / [额外请求头编辑] / [按结果过滤] / [物料映射表 + replace/keep_both 模式] / [一键填入预设模板 (4 个模板: box_complete·4字段 / box_complete·完整 / cycle_end·简化 / cycle_end·含步骤)] / [工具栏测试用事件下拉]; `openCreate` / `openEdit` / `buildConfig` / `doTest` 全链路适配新字段
  - 影响文件: `frontend/src/views/MES/GatewayPanel.vue`

- [FEAT-006] 后端 /test API: 按 event_type 生成对应 context + 走和实时推送一致的预处理链
  - 需求: 过去 /test 永远用 `cycle_end` context, 测 `box_complete` 模板时字段对不上, 客户看到"测试通过但实际推送字段全空"
  - 实现: `TestPayload` 加 `event_type`; `_build_test_context_cycle_end` / `_build_test_context_box_complete` / `_build_test_context_box_timeout` 三路各生成结构化的真实 context; 测试请求走 `label_mapping + _apply_auth_to_headers`, 但**故意不走 push_on_result** (保证点"测试"一定能看到请求)
  - 影响文件: `backend/api/mes_gateway.py`
