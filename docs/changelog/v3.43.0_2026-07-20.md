# v3.43.0 (2026-07-20)

> 主题：**上银包装线现场仿真联调整改批次**——「放工单=工单收尾」语义重构（箱归周期结算、放工单归工单收尾，缺工单判定扫新单/时限二选一）+ 已完成(OK)工单重扫拦截 + 放工单 gate 永不放行修复（序列外步骤旁路账本）+ 提前放工单报警；**实时NG（违规即时结算）**新项目级开关；人工确认弹窗体验两升级（原因固化 + 处置方式明示）；称重模式监控页被 SOP 卡片抢占修复（萍乡百斯特现场）。

## 功能变更

- [FEAT-001] 包装结算「放工单=工单收尾」语义重构（箱归周期结算、放工单归工单收尾）
  - 需求: 上银 SY 线现场节奏是"封箱周期先结、工单纸随后才塞进尾箱"。v3.34.1 的"挂起快照"方案把尾箱结算悬在半空（不落账、每周期报警），现场体验是尾箱明明装满了却一直红——箱的好坏本该归检测周期，放工单只是工单层的收尾动作。
  - 实现: 尾箱照常按自身成绩当场落账（不报警不弹 NG）；各箱全落账但放工单没探到 → 工单挂「等放工单收尾」等待态（监控页包装卡新增横幅 + 状态色，强制结案按钮对该状态可用），**检测到放工单动作的瞬间即时完成工单**（新入口 on_step_detected，不必等下一次扫码/周期结算）。缺工单判定二选一互斥（迁移 m0003 两列）：扫新单判定（默认）= 下一单扫码进来发现没放 → 报警 + 旧单判 NG 收尾再开新单，无时限；时限判定 = 挂等待态时布防一次性 Timer，到点终局判定（最后探一次，到位 OK / 没到位报警+NG），时限内扫新单被拒收提示稍候。工单层判 NG 不回改箱成绩（final=NG + 强制原因留痕）。重启后等待态一并作废防幽灵在途（内存 Timer 已丢）。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/models/mes_models.py, backend/db/migrations/m0003_pkg_tail_paper_order_settle.py, backend/api/packaging_flows.py, frontend/src/views/Settings/PackagingFlowPanel.vue, frontend/src/views/Monitor/PackagingFlowCard.vue
  - 关键词: 放工单, 工单收尾, awaiting_paper, 等放工单收尾, tail_paper_as_close_action, tail_paper_scan_alarm, tail_paper_timeout_s, 缺工单判定, 扫新单判定, 时限判定, Timer, 尾箱, 上银, 包装结算, m0003

- [FEAT-002] 实时NG（违规即时结算，项目级开关 instant_ng_on_violation，默认关零差异）
  - 需求: 客户要求更硬的口径——违规动作一经确认这一件当场判 NG，不等周期收尾（v3.32 违序即时事件只提示不结算）。
  - 实现: 逻辑设置页新开关（顺序型非 last_first / 检测模式 / 自定义-基于顺序可见）。三类违规触发：违序/缺前置（严格顺序守门拦下的最早可证明时刻）、步骤回退重复（仅顺序型，基于检测的自定义不看回退标记不误杀）、重复超次（纯检测模式，期望次数口径与结算同源，配时长门的步骤交结算兜底）。统一收口 `_fire_instant_ng`：当场触发 NG 事件(2) 走完整结算链路（end_cycle/计数/报警/MES）；提示档/斩立决由事件2自身「需人工确认」配置分流（定格时不清运行时，清理交确认端点，与 ack_keep_cycle 语义一致）；节流与违序提示事件共用一本账（同标签+周期进度 5 秒一次）；周期未开时不触发（退回提示事件）。
  - 影响文件: backend/api/source_settlement_mixin.py, backend/api/source_project_config_apply.py, backend/api/source_state_init.py, frontend/src/views/Project/LogicConfigTab.vue, frontend/src/views/Project/index.vue
  - 关键词: 实时NG, 违规即时结算, instant_ng_on_violation, 斩立决, 提示档, 违序, 缺前置, 步骤回退, 重复超次, 严格顺序, _fire_instant_ng, 节流

- [FEAT-003] 已完成(OK)工单重扫拦截（block_completed_order_rescan，默认关）
  - 需求: 上银现场诉求——做完的单不允许误扫再录入（重扫会重新开单再做一轮）。
  - 实现: 扫码总入口单点守门：扫到"最近一次运行已完成且结果 OK"的工单号 → 报警提示且不重新录入；在途同号刷新不受影响；完成但 NG 的单不拦（允许重扫补做，以 id 最大一条为准）；查库异常按不拦处理不卡产线。可单独指定提示事件。迁移 m0002 两列。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/models/mes_models.py, backend/db/migrations/m0002_pkg_completed_order_rescan.py, backend/api/packaging_flows.py, frontend/src/views/Settings/PackagingFlowPanel.vue
  - 关键词: 重扫拦截, block_completed_order_rescan, event_completed_order_rescan, 已完成工单, 误扫, m0002

- [FEAT-004] 提前放工单报警（自动，随尾箱塞工单 gate 生效）
  - 需求: 用户手测发现的两个错误时机漏报——"第一箱就放工单""上一箱落账后尾箱还一件没装就放"，工单纸只该在尾箱装完时放入，此前全程静默。
  - 实现: 检测层探到序列外"放工单"步骤即时通知协调器：非尾箱作业期间（或名义已翻到尾箱但实时进箱数=0——新注入进箱数探测钩子读容器已结算件数，区分"尾箱正做着/还没开始"，拿不到保守放行宁漏报不误报）→ 当场报警提醒取出纠正，每箱只报一次防轰炸；不改箱成绩不拦结算（位置错是操作提醒，箱好坏仍归检测周期）。复用缺工单事件档。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/source_settlement_mixin.py
  - 关键词: 提前放工单, early_paper, on_step_detected, box_progress, container_settled_item_total, 空尾箱, 动作×状态矩阵

## Bug 修复

- [FIX-001] 放工单 gate 永不放行——序列外步骤旁路账本（v3.42.1 级根因修复）
  - 症状: 顺序/自定义-基于顺序模式下，尾箱塞工单 gate 永远探不到"放工单"动作，尾箱永远收不了尾。
  - 根因: "放工单"是**序列外**启用步骤，FIX-381 把它拦在周期外（正确，不该影响判定）——但 gate 探测只查周期步骤集（当前周期 + 上周期缓存），序列外步骤永远进不了这两处，gate 因此永不放行。
  - 修复: 新增序列外步骤旁路账本（拦截点记账，随周期结算轮转只留最近两代防陈旧残影跨启停放行；停止/切项目/强制结算两代一起清）；gate 探测扩成查四处（周期两代 + 旁路账本两代）；拦截点同时即时通知包装协调器（错误隔离）。
  - 影响文件: backend/api/source.py, backend/api/source_settlement_mixin.py, backend/api/source_custom_mix.py
  - 关键词: is_packaging_paper_order_covered, _oos_steps_seen, 序列外步骤, FIX-381, 旁路账本, gate 永不放行

- [FIX-002] 人工确认框闪退——扫码链路两个子系统副作用互噬（v3.43.1 级）
  - 症状: 扫新单触发"缺工单报警→人工确认定格"，确认框闪一下就消失；同项目还白白重载模型卡几秒。
  - 根因: 同一次扫码链路里，报警定格刚立起，紧接着"按规格切项目→重载模型→重置检测运行时"把定格抹掉——即使命中的项目就是当前激活项目也照样重激活。
  - 修复: ① 切项目命中已激活项目原地不动直接返回成功（不重载模型不重置运行时）；② 扫新单判定路径的缺工单报警延后到开新单（含切项目）之后再触发，定格立在切换之后。
  - 影响文件: backend/services/packaging_flow_coordinator.py
  - 关键词: 确认框闪退, 定格被抹, _real_project_activator, 已激活跳过, defer_alarm, 副作用互噬

- [FIX-003] 称重投料项目监控页看不到专属看板（萍乡百斯特现场撞出）
  - 症状: 称重项目在检测中心永远显示普通 SOP 流程卡片，称重专属看板一次都不出现；底栏「模式」显示"未定义"。
  - 根因: SOP 卡片与称重看板同链互斥且 SOP 在前，其显示条件未排除称重模式——称重项目必配步骤 + SOP 显示开关出厂默认开，永远抢占；开发库里被调教过的显示设置（SOP 开关被关过）骗过了自动化验证十几个版本。底栏模式文案表漏 weighing/region_events 两键。
  - 修复: SOP 卡片显示条件补排除称重模式（融合模式 logic_mode 是 sequential 不受影响）；底栏/导航模式表 + 五语言包补齐「称重投料/区域事件」文案。
  - 影响文件: frontend/src/views/Monitor/index.vue, frontend/src/layout/BottomBar.vue, frontend/src/layout/Navbar.vue, frontend/src/locales/*.js
  - 关键词: 称重看板, SOP 抢占, isWeighingMode, mode.weighing, mode.region_events, 出厂默认态, 萍乡百斯特
