# v2.7.4 (2026-04-20)

## 功能变更

### [FEAT-001] 物品标注框可视化隐藏
- **需求**: 包装项目里有些物品（箱子、泡沫槽等）不属于检测清单的核心目标，但模型依然会检测到。在 Monitor 页实时画面上画出框反而干扰视觉。希望能逐个步骤配置：是否在视觉层（实时画面、SOP 卡片、步骤详情）隐藏，但完全不影响检测逻辑、计数、报警、上报、数据统计。
- **实现**:
  - 前端 Project 页的步骤表新增「隐藏标注框」开关列（`step.hide_in_view`），默认关
  - Monitor 页：
    - 多通道 / 单通道实时画面：在 `drawMultiDetections` / `drawDetections` 中按 label 过滤，跳过被标记隐藏的检测的画框与标签
    - SOP 卡片 / 步骤详情表：`stepsToShow` 与 `tableData` 过滤掉 `hide_in_view=true` 的步骤
  - 仅前端可视化变更，后端 detection_results、计数器、cycle、报警、CSV 导出全部不受影响
- **影响文件**: `frontend/src/views/Project/index.vue`, `frontend/src/views/Monitor/index.vue`

### [FEAT-002] 堆叠模式（同物品多次放置计数）
- **需求**: 跟踪计数模式下，部分物品需要堆叠放置（如干燥剂、泡沫片）：实际放了 2-3 个，但画面始终只能看到最上面那一个。ByteTrack 看不到"被堆下面"的物品，所以只算 1 个。希望能配置：当某 label 消失 N 秒后再次出现，算作"放下了下一个"。
- **实现**:
  - 前端 Project 页跟踪模式表新增 3 列：「堆叠模式」开关 / 「重现间隔(秒)」 / 「堆叠层数」
    - `stack_enabled`: bool，默认 false
    - `stack_reappear_seconds`: float，默认 1.0
    - `stack_required_count`: int，最小 2，默认 2
  - 后端 source.py：
    - `_init_inference_vars` 新增状态：`_stack_state / _stack_counters / _stack_disappeared_at / _stack_visible_frames`
    - `_update_tracking_stats` 解析 stack_steps 配置（仅 count_mode=track 生效）
    - 状态机逻辑：
      - `idle → visible`: 第一次出现就算第 1 层
      - `visible → disappeared`: 物品消失，记录消失时间
      - `disappeared → visible`: 重新出现时若消失时长 ≥ `stack_reappear_seconds`，计数 +1
    - `_rebuild_checklist` 用 `max(tracking_class_counters, stack_counters)` 合并，避免与 ByteTrack 计数双算
    - `_reset_counting_cycle` 同步清理 stack 状态
  - 仅 logic_mode=tracking + count_mode=track 时生效
- **影响文件**: `backend/api/source.py`, `frontend/src/views/Project/index.vue`

### [FEAT-003] 最大识别数（同物品 ID 合并）
- **需求**: 跟踪计数模式下，部分物品概念上是一个但物理上分开（如手套是一双但分左右两只放）。ByteTrack 会给出 2 个 track_id，结果计数为 2，与实际语义不符。希望能配置：某物品同时最多识别为 N 个 ID，超过部分按"最近距离"合并到置信度最高的那 N 个。
- **实现**:
  - 前端 Project 页跟踪模式表新增「最大识别数」列（`step.max_recognized`），默认 0=无上限
  - 后端 source.py：
    - `_update_tracking_stats` 入口处对 detections 做后处理：按 label 分组，超过 N 个时按置信度降序保留 Top-N 的 track_id，其余 detection 的 track_id 改写为最近 keeper 的 track_id
    - 不修改 ByteTrack 内部状态，仅改输出 track_id，下一帧仍正常跟踪
    - 仅 count_mode=track 生效，不影响 event 模式
    - track_id<0 的 detection 跳过（未跟踪上的不参与合并）
  - 与堆叠模式可叠加使用（如手套配置 max_recognized=1 + stack 模式表示"成对手套堆叠场景"）
- **影响文件**: `backend/api/source.py`, `frontend/src/views/Project/index.vue`
