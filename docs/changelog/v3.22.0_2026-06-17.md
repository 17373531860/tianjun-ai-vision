# v3.22.0 (2026-06-17)

> 上银 HIWIN 包装线 MES 对接闭环 —— 在 v3.21「包装箱结算协调器」之上扩展「按滑块总数判满 + 尾箱算法 + 规格自动切项目 + 尾箱塞工单视觉 gate + USB 扫码枪接入」，全部做成**默认关闭的可配置开关**，未开此功能的客户字节级零差异。

## 功能变更

- [FEAT-001] 包装结算新增「按每箱滑块总数」判满口径（count_unit=sliders）
  - 需求: 上银场景不再计托盘数，而是计「进箱滑块总数」(如每箱 96)，托盘只是容器；满箱用检测周期(封箱动作)驱动结算，扫码只管工单/箱编排。
  - 实现: PackagingFlowConfig 加 `count_unit`(trays 默认/sliders)；`on_cycle_settled` 带 `slider_count`；sliders 模式下一个检测周期=一个箱完成，进箱滑块数与「当前箱目标」双重核对判 OK/NG；每箱滑块数来源可选「读激活项目容器目标」或「配置固定值」。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/source_session_lifecycle_mixin.py, backend/api/source_custom_mix.py, backend/models/mes_models.py

- [FEAT-002] 尾箱算法 + 运行时动态切目标
  - 需求: 滑块总数除以每箱数不一定整除，最后一箱(尾箱)可能是余数；整除时最后一箱也算尾箱。
  - 实现: 纯函数 `compute_box_plan(slider_total, items_per_box)` → (box_total, tail_target)，box_total=ceil(总数/每箱)，尾箱目标=余数(整除时=每箱数但仍标记尾箱)；每开一箱把「当前箱目标」反向设回检测层容器累加器(`set_item_target`)，保证普通箱与尾箱的合格判定都用对的目标；PackagingFlowRun 加 `count_unit/slider_total/items_per_box/tail_target/current_box_sliders/paper_order_done` 字段，main.py migrate_database 补 ALTER TABLE。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/models/mes_models.py, backend/main.py, backend/api/source_custom_mix.py

- [FEAT-003] 规格→自动激活项目开关（auto_switch_project，默认关）
  - 需求: 扫工单查 MES 拿到产品规格后，按规格自动切到以型号命名的对应项目(每箱滑块数预配在项目里)。
  - 实现: 配置加「规格→项目 id」映射；`_open_order_sliders` 拿到规格后经注入式钩子激活对应项目，切换失败兜底为报警 + 用当前激活项目继续。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/packaging_flows.py

- [FEAT-004] 尾箱塞工单视觉 gate 开关（tail_paper_order_required，默认关）
  - 需求: 工单纸需放进最后的尾箱，AI 检测到「放工单」动作才算尾箱完成。
  - 实现: 尾箱结算前经注入式探测钩子查「放工单」步骤本周期是否 covered，未做则不收尾 + 报警(missing_paper)，等补做；无探测器时 gate 退化为不阻断(避免误卡)。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/source.py

- [FEAT-005] USB 扫码枪接入包装结算
  - 需求: 现场用 USB 扫码枪扫工单/箱标签驱动包装流程。
  - 实现: useScanGun 扫码先尝试 `POST /packaging-flows/scan`，命中(handled=true)则接管，未命中回退原有 pull/bind 逻辑(零差异)。
  - 影响文件: frontend/src/composables/useScanGun.js, frontend/src/api/packaging_flow.js

- [FEAT-006] 异常对齐 + 报警事件映射
  - 需求: 缺料(漏油嘴步骤 NG)、进箱数量错、漏箱/多箱、标签错、MES 失败、尾箱缺工单各类异常要能触发项目里配的特定事件。
  - 实现: 协调器异常类型→项目事件字段映射(含 box_ng/over_box/short_box/label_mismatch/label_len/mes_fail/missing_paper)；数量错复用现有报警，托盘取出重放不阻断状态机。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/packaging_flows.py

- [FEAT-007] 前端配置面板 + Monitor 卡按滑块口径展示
  - 需求: 配置上述开关，Monitor 实时看本箱滑块进度与尾箱。
  - 实现: PackagingFlowPanel 加组⑦(计数单位/每箱滑块来源/滑块总数字段/规格→项目映射/尾箱塞工单开关/自动切项目开关)；运行状态对话框 sliders 口径显示滑块总数/每箱/尾箱目标/各箱滑块明细；Monitor PackagingFlowCard 按 count_unit 切「滑块 N/目标」与尾箱标记，trays 口径保持原样。
  - 影响文件: frontend/src/views/Settings/PackagingFlowPanel.vue, frontend/src/views/Monitor/PackagingFlowCard.vue

## CI

- [CI-001] TensorRT 版本锁 <11
  - 根因: TRT 11.x 删除 EXPLICIT_BATCH 标志, 与 ultralytics<=8.4.16 导出代码不兼容, 客户机转换必崩。
  - 修复: build.yml 安装 `tensorrt>=10.0,<11` + 启动自检断言主版本==10。
  - 影响文件: .github/workflows/build.yml
