# v3.40.0 (2026-07-17)

> 主题：**川南顺序检测两处现场反馈修复**——(1) 周期跑偏后末步"余像"被误判合法重复，前端末步结果列 OK/NG 来回闪、结算多报"重复步骤"；(2) 中控开工报文把后端检测自动拉起后，空闲中的检测中心页面毫无感知（开始按钮不灰、FPS 0、信息条不出），必须切页再切回才恢复。

## Bug 修复

- [BUG-001] 顺序模式周期跑偏后，滞留画面的末步成品被误判"合法重复"反复入周期
  - 症状: 期望序列 [A,B,C,D] 漏做 B（实际 [A,C,D]）后，做完的成品 D 留在画面里反复闪现，前端末步结果列 OK/NG 来回闪烁；结算时在"缺少 B"之外又多报"重复步骤 D"，NG 账挂到末步头上。全 OK 周期无此现象（与客户反馈吻合）。
  - 根因: 连续重复步骤的"位置索引判定"以 `len(current_cycle_steps)` 为位置指针查 `expected_labels[pos]`，隐含前提是"当前周期是期望序列的严格前缀"。周期一旦跑偏（漏做/乱序），实际长度 3 会把指针错位指到 expected[3]='D'，末步 D 的每次余像闪现都被认成"合法重复"重新入周期。
  - 修复: `SequenceLabels._is_expected_repeat_position` 增加严格前缀守门——`current_cycle_steps != expected[:len(current)]` 时位置指针失效，一律走常规去重；期望内的合法重复（干净前缀）行为不变。
  - 影响文件: backend/api/source_sequence_labels.py, tests/test_sequential_repeat_steps.py
  - 关键词: 顺序模式, 重复步骤, 位置指针, 跑偏周期, 末步闪烁, OK/NG 闪, 余像, deviated cycle, false repeat, prefix guard, 川南

- [BUG-002] 后端被开工报文自动拉起检测时，空闲中的监控页前端毫无感知
  - 症状: 检测中心处于"已停止"（无轮询无取流），中控 POST 开工（开工即自动开始检测），后端确实在推理，但前端开始按钮可点、FPS 显示 0、四要素信息条不出；切到项目管理再切回才正常。
  - 根因: 前端检测/运行状态只在用户点按钮的乐观更新和轮询循环里维护；页面空闲时轮询根本没启动，后端自行拉起的状态变化无人接收。轮询循环本身也不回读后端检测态。
  - 修复: 双保险。(1) 空闲看门狗——监控页空闲时每 2s 探一次源状态，发现后端已在跑就自动接管（同步运行/检测态 + 起轮询 + 重连画面），等价一次页面重进；(2) 轮询循环以后端为真相源同步检测/运行态（用户操作进行中不抢，乐观更新优先）。
  - 影响文件: frontend/src/views/Monitor/index.vue, tests/e2e_browser/test_idle_watchdog_adopt.py, tests/uat/uat_20260716_cn_idle_autostart_adopt.py
  - 关键词: 空闲看门狗, idle watchdog, 开工报文, 自动开始检测, 按钮不灰, FPS 0, 信息条不显示, 状态同步, 轮询, 川南

- [BUG-003] 末步结果列随成品余像闪烁回退为 '--'
  - 症状: 末步已判定出 OK/NG 后，成品滞留画面再次被识别，前端步骤表末步结果列被打回 '--' 再变回，肉眼看是持续闪烁。
  - 根因: 末步"完成"判定只认"已离开画面"（_leftFrame），余像重新出现时该条件翻回 false，结果列跟着回退。
  - 修复: 末步已有权威 PT（完成过一次完整出现）后结果锁定，不随余像回退（_leftFrame || _posAuthoritative）。
  - 影响文件: frontend/src/views/Monitor/index.vue, tests/uat/uat_20260716_cn_last_step_flicker.py
  - 关键词: 末步结果列, 闪烁, 权威 PT, 结果锁定, 余像, 川南
