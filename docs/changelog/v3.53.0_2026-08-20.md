# v3.53.0 (2026-08-20)

> 主题：**录像归档与媒体证据体系（一~四期一次落地）** + 监控页无扫码器时扫码 UI 整组守门。
> 全部新功能默认关（无归档规则时零帧不抽、零文件不搬、零开销），升级零配置差异。

## 功能变更

- [FEAT-001] 录像归档引擎一期：规则驱动的周期录像自动归档
  - 需求: NG 录像散落在本地 recordings 里，客户质量部要"出事的录像自动搬到网盘/指定目录、按工件号命名、有台账可查"。
  - 实现: 新增 `video_archive_rules` / `video_archive_logs` 两表 + `services/video_archive.py` 归档引擎——录像收尾 (`stop_cycle_recording` → `_delayed_release`) 后入队，独立 worker 线程消费；结果筛选 (全部/仅NG/仅OK) × 工位 × 项目三重过滤；文件名 Jinja2 模板 (`build_cycle_context` 全字段可引用)；`.tmp+rename` 原子落位 + 重名策略 (加序号/覆盖/跳过)；瞬态失败落 `video_archive_spool.jsonl` 断点重放 (重试预算 8 次)，永久失败记台账；目标目录黑名单护栏 (系统目录/DATA_DIR 内拒绝)。API 挂 `/api/v1/export/video-archive/*` (rules CRUD / status / logs / test-run)，权限 `data.export`。前端 Data 页「存储与清理」新增录像归档卡 + 配置弹窗 (规则表格/编辑器/状态条/台账)。
  - 影响文件: backend/models/archive_models.py, backend/services/video_archive.py, backend/api/video_archive.py, backend/api/router_manifest.py, backend/api/source_recording_api_mixin.py, backend/main.py, alembic/env.py, frontend/src/api/videoArchive.js, frontend/src/views/Data/components/VideoArchiveDialog.vue, frontend/src/views/Data/index.vue

- [FEAT-002] 归档二期：证据能力（NG 关键帧 / sidecar 报告 / 证据包 zip / 事件切片）
  - 需求: 光有录像不够——客户对账要"出事那一瞬的带框截图 + 数据报告 + 一个包甩给质量部"。
  - 实现: ① NG 关键帧——`end_cycle` NG 定案后置 `_archive_ng_frame_pending`，推理循环同帧消费 (与 interconnect 采样同时序)，画框+水印 (时间戳/工位/SN) +JPEG 编码在独立线程做，落 `recordings/keyframes/<date>/cycle_<uuid>.jpg`；`keyframe_wanted()` 守门，无规则启用时零帧不抽。② sidecar——规则可绑自定义导出模板 (export_templates)，归档时与录像同 basename 成对渲染。③ 证据包——规则级 `bundle_zip` 把录像+关键帧+sidecar+meta.json 打成一个 zip 落位；另有手动批量出口 `POST /video-archive/evidence-pack` (按周期/会话/日期 + 仅NG)，Data 页弹窗一键下载。④ 事件切片——`transform=clip_tail` 用 FFmpeg `-sseof -N -c copy` 秒切结算前最后 N 秒，切片失败回退整段 (证据宁全勿缺)。
  - 影响文件: backend/services/archive_media.py, backend/services/video_archive.py, backend/api/source_session_lifecycle_mixin.py, backend/api/source_inference_loop_mixin.py, backend/api/video_archive.py, frontend/src/views/Data/components/VideoArchiveDialog.vue

- [FEAT-003] 归档三期：生态联动（字段库 / MES 网关事件 / 短信参数）
  - 需求: 归档地址要能进报表、推 MES、进短信——证据链闭环到客户自己的系统。
  - 实现: 字段中央仓库新增 `cycle.archived_video_path` / `cycle.archived_at` / `cycle.archive_status` + `aggregations.archive_success/archive_failed/archive_last_dest` (314 字段)，`build_cycle_context` / `build_range_context` 从归档台账反查填充；新增 MES 网关事件 `video_archived` (归档成功推最终地址，走 dispatch_gateway 异步执行器 + spool，不阻塞归档 worker)；插件 hook `video_archived` (observe 型)；短信汇总模板新增 `{archive_success}` / `{archive_failed}` 命名变量 (默认文案不变，老客户零差异)。
  - 影响文件: backend/services/export_field_registry.py, backend/services/export_context.py, backend/services/archive_ecosystem.py, backend/services/sms_service.py, frontend/src/views/MES/GatewayPanel.vue

- [FEAT-004] 归档四期：远端目的地与治理（FTP/SFTP/S3/HTTP + 凭据加密 + 插件 adapter + 时间窗/限速/回补/删源）
  - 需求: 客户网盘不总是能挂载成盘符——要原生推 FTP/SFTP/S3/MinIO/HTTP；夜间搬运不抢产线带宽；存量录像可回补；归档后本地可分层瘦身。
  - 实现: `services/archive_adapters.py` 统一 deliver 契约 (5 内置 adapter + `register_archive_adapter` 插件注册口，`PermanentDeliveryError` 区分配置类错误不重试)；`services/archive_secrets.py` Fernet 凭据加密 (机器本地密钥 0600，dest_config 敏感字段 `enc:` 前缀落库，API 回显 `******` 打码、回传打码值保留旧值)；带宽限速 (256KB 块间 sleep 的 ThrottledReader)；归档时间窗 `HH:MM-HH:MM` (跨午夜支持，窗外 defer 不消耗重试预算)；历史回补 `POST /video-archive/backfill` (按规则批量补归档存量周期)；`delete_source_after` 归档即分层 (全部命中规则成功 + 字节数校验一致才删本地源并回写 `cycle.video_path=None`)。PluginHost 新增 `register_archive_adapter` API (capability `runtime.archive_adapter`)。
  - 影响文件: backend/services/archive_adapters.py, backend/services/archive_secrets.py, backend/services/video_archive.py, backend/api/video_archive.py, backend/plugin_system/registry.py, frontend/src/views/Data/components/VideoArchiveDialog.vue

## Bug 修复

- [BUG-001] 监控页无扫码器时「等待扫码/清除/禁用扫码」整组 UI 未守门
  - 症状: 没配任何扫码器的产线，多工位监控页信息条仍画「等待扫码...」和「清除/禁用扫码」按钮，误导操作员以为要扫码。
  - 根因: v3.5.2 只挡了「⚠ 未绑码」，v3.47 布局重构把占位守门弄丢——`shouldShowMesBarFor` 的"工位在跑就显示"兜底、4 处「等待扫码」占位、3 组扫码按钮都没检查 `mes.scanner_present`。
  - 修复: 全部渲染点挂 `hasScannerFor()` 守门；`hasScannerFor` 同时认 `scanner_resume_blocked` 为"扫码器在场"证据 (码-合格-码灭灯态不能把人工恢复按钮藏掉)。老后端无 `scanner_present` 字段时行为不变。CI e2e `test_mes_bar_no_scanner.py` 双向钉死。
  - 影响文件: frontend/src/views/Monitor/index.vue, tests/e2e_browser/test_mes_bar_no_scanner.py

- [BUG-002] 归档关键帧 JPEG 原子写 tmp 扩展名致 imwrite 必败（开发期拦下）
  - 症状: (未流出) 关键帧永远存不下来，日志见 "could not find a writer for the specified extension"。
  - 根因: `cv2.imwrite` 按文件扩展名选编码器，`.tmp` 结尾的临时名没有对应编码器。
  - 修复: 临时名改 `.tmp.jpg` 结尾再 `os.replace` 原子落位。单测 `TestKeyframe` 守住。
  - 影响文件: backend/services/archive_media.py

- [BUG-003] 归档两表未在 conftest/main.py 显式注册，测试库建表漏表
  - 症状: 单测报 `no such table: video_archive_rules`；生产端靠 router import 链兜住才没事。
  - 根因: `Base.metadata.create_all` 只建"已 import 的模型"，archive_models 没进 main.py / tests/conftest.py 的显式注册清单 (alembic/env.py 已有)。
  - 修复: 两处补 `from backend.models import archive_models` (与 notify_models 等同风格)。
  - 影响文件: backend/main.py, tests/conftest.py
