> 主题：**川南 MES 对接两处现场反馈修复 + 萍乡手册勘误配套**——(1) 客户固定任务号反复开工，复用工单的项目绑定停留在第一次创建时，监控页四要素不显示、完工/报警推送里工单字段全 null；(2) 报警连接勾了"仅推 NG"，合格周期照样推给中控（WarningText="顺序正确完成"）。另配套网关事件下拉露出"称重成品结案"、模拟秤脚本墙钟计时、百斯特手册 v2.1 达梦推送时机勘误。

## Bug 修复

- [BUG-001] 同任务号重复开工时复用工单不刷新绑定，四要素不上屏、推送工单字段全 null
  - 症状: 客户每次测试都发同一个任务号开工。第二次起走"复用已有工单"分支，工单绑定的项目还是第一次创建时的（甚至为空）→ 工位挂单按"工单绑定项目==工位当前项目"匹配永远落空 → 监控页信息条四要素不显示；完工/报警出站报文里 TaskNo/ProductCode/StepCode/Operator 全 null。
  - 根因: `_ensure_work_order` 的复用分支只打日志不动工单——项目绑定、四要素留痕、产品码、操作员全部停留在建单时刻，后续开工报文的内容被丢弃。
  - 修复: 新增 `_refresh_reused_order`，复用时按"最新开工为准"刷新——重绑当前激活项目（工位路由则重绑本次报文工位）+ 覆盖 extra_data.inbound 四要素留痕 + 产品码/操作员。JSON 列整体重赋值（原地改 dict 不触发 SQLAlchemy 变更追踪）；任何失败只记调试日志不阻断开工；终态单是否复活仍归 `_ensure_in_progress` 决定。
  - 影响文件: backend/services/mes_inbound.py, tests/test_cn_fixes_20260717.py, tests/uat/uat_20260717_cn_order_reuse_null.py
  - 关键词: 复用工单, 重复开工, 同任务号, 四要素不显示, 推送字段 null, 工单绑定过期, order reuse, rebind, task_no, 川南, mes_inbound

- [BUG-002] 网关"仅推 NG"对周期结束事件从未生效，合格周期照样推报警接口
  - 症状: 报警连接结果过滤勾了"仅 NG"，合格周期照样从该连接推给中控，中控报警台账收到 WarningText="顺序正确完成"的假报警。
  - 根因: cycle_end 事件的结果在上下文嵌套层 cycle.result，`push_on_result` 过滤只读顶层 overall_result/result → 周期事件取到空串，按"无结果不过滤"无条件放行——该过滤对周期推送从未生效过。
  - 修复: 结果取值加第三级嵌套兜底：overall_result → result → cycle.result；取到空仍保持放行（行为兜底不变），取到值才按白名单过滤。
  - 影响文件: backend/services/mes_gateway.py, tests/test_cn_fixes_20260717.py, tests/uat/uat_20260717_cn_order_reuse_null.py
  - 关键词: push_on_result, 仅NG, 结果过滤, 周期事件, cycle.result, 嵌套, 合格周期误推, 报警连接, 川南, mes_gateway

- [BUG-003] 模拟秤脚本播放越播越慢，与视频时间轴对齐的仿真整体错位
  - 症状: 全链路仿真里秤读数脚本与真视频时间轴对齐播放，长脚本后段动作时刻越来越滞后（实测 4 分钟漂约 20 秒），称重状态机与视觉步骤对不上。
  - 根因: 模拟协议播放循环按"睡眠次数×轮询间隔"累计段时长，不含每次读数分发的处理耗时，误差随时长线性累积。
  - 修复: 段时长改按墙钟计时（time.time() 差值判段结束）。仅影响模拟协议，真秤硬件无此问题。
  - 影响文件: backend/services/external_device_protocols.py, tests/uat/sim_bst_20260717.py
  - 关键词: 模拟秤, mock scale, 墙钟, 计时漂移, 仿真错位, 时间轴, external_device_protocols
