# v3.4.0 (2026-04-30)

## 功能

- [FEAT-340-001] 扫码模式 D — 容器跨线 / 进区域触发 LON, 扫到码自动 LOFF
  - 复现痛点: 客户场景下容器装件工位的扫码器 (text_lon 协议) 默认 A/B/C 三种模式
    都不能精确匹配产线节奏 — A/B 是持续扫码灯一直闪 (扫到一个码就立刻能扫下一个,
    工件码与箱码混杂时容易串台); C 是扫到码立即 LOFF 等周期结束才再开扫, 但一个
    箱子可能要装多件中间还要扫多个工件码, C 模式只能扫一次。客户希望以"箱子物理
    位置"作为扫码窗口的唯一触发源 — 箱子从产线上画的某条触发线 / 进入某个区域才
    允许扫码灯亮 (LON), 扫到对应箱码后立刻 LOFF 灯灭, 等箱子真正离开 (gone-confirm)
    才允许下一个箱子触发, 实现一箱一灯一码闭环。
  - 已审计上游层: 现有 scan_mode 三种 (continuous / throttled / once_per_cycle) 都基于
    cycle 节拍, 不能感知 box 的物理位置变化; LON/LOFF 只在 start_scanning /
    stop_scanning (检测整体启动 / 停止) 时一次性发, 帧循环里没有"按 box 位置脉冲式
    发" 的入口。需要给 scanner 服务加新的 send_lon_for_channel /
    send_loff_for_channel helper, 并在 source 检测帧循环里加一个状态机, 由
    box 跨线 / 进区域事件主动驱动。
  - 实现 (后端):
    - `mes_models.py / api/scanner.py / services/scanner.py` 新增 4 个字段
      `scan_d_geometry VARCHAR(8) DEFAULT 'line'` (line / zone),
      `scan_d_line JSON` (`{x1,y1,x2,y2,side_a_to_b}` 归一化 [0,1]),
      `scan_d_zone JSON` (`[[x,y], ...]` 归一化 polygon, ≥3 点),
      `scan_d_gone_confirm_frames INTEGER DEFAULT 30` (D 模式专属, 0 = 沿用项目)。
      `main.py` 加自动 migration。
    - `services/scanner.py` 新增 helper:
      - `send_lon_for_channel(ch, reason)` — 主动给绑定该工位的所有 text_lon
        扫码器发 LON (与 start_scanning 不同, 不动 _scanning 状态, 仅脉冲式发)
      - `send_loff_for_channel(ch, reason)` — 主动发 LOFF
      - `is_scan_d_for_channel(ch)` / `get_scan_d_config_for_channel(ch)` —
        供 source 帧循环查询当前 channel 是否启用 D 模式以及拿几何配置
    - `source_container_grouping_mixin.py` 新增 `_scan_d_update()` 状态机:
      - 仅在 `_container_mode=True` 时执行
      - 每帧调 scanner.is_scan_d_for_channel + get_scan_d_config_for_channel
        拿配置, 把归一化 [0,1] 几何乘以当前帧 `width / height` 转像素
      - 对每个 _box_objects 维护 `_scan_d_box_states[box_did]` =
        `{side, in_zone, armed, scanned, gone_frames}`:
        - line 模式: 叉积符号判 box 中心点位于线哪一侧, 跨方向匹配
          (`side_a_to_b=True` 即 A 侧 +1 → B 侧 -1) 触发
        - zone 模式: 中心点从外 (`prev_in=False`) 到内 (`cur_in=True`) 触发
      - 触发时若 `_scan_d_armed_box is None` 则 set armed_box + 调
        `scanner.send_lon_for_channel`; 已 armed 则 log warning 不重发
        (产线节奏串行假设, 异常并发不重入)
      - box 不在画面 → `gone_frames += 1`, 超阈值 (默认 30 帧) reset 状态;
        若 reset 的是 armed 但未 scanned 的 box → 主动 `send_loff_for_channel`
        防 LON 残留
    - `source_container_grouping_mixin.py` 还新增 `scan_d_on_scan_received()`:
      由 `mes_hooks._handle_scan` 在收到任意码后调用, 把当前 armed_box 切到
      scanned 状态 + 调 send_loff_for_channel + 清 armed_box, 等 box 真正
      gone-confirm 后 reset 才允下一个
    - `source_tracking_mixin.py._update_tracking_stats` 在 _update_container_grouping
      之后调一次 `_scan_d_update()`, 异常 try/except 不影响主流程
    - `mes_hooks.py._handle_scan` 头部加 scan_d_on_scan_received 调用
      (与 bind_timing 完全正交, 调完 LOFF 再走老 bind_timing 分支)
    - `source_state_init.py` 加 `_scan_d_armed_box=None` / `_scan_d_box_states={}`
  - 实现 (API):
    - `GET /scanner/check-container-mode?channel_id=N` — 通过 channel_manager
      拿 mgr.project_config 判 logic_mode='tracking' && tracking_container_label
      非空, 返回 `is_container_mode + project_id + project_name`, 供前端切换
      D 模式时校验是否容器项目, 否则弹警告自动回退
  - 实现 (前端):
    - `ScannerPanel.vue` 扫描模式下拉新增 "D 容器跨线/区域触发 (容器模式专用)"
    - `onScanModeChange(val)`: 切到 D 时 GET /scanner/check-container-mode 校验,
      不是容器模式就弹 ElMessageBox + 自动回退到上一次的非 D 模式 (默认 continuous)
    - D 模式露出 3 个表单项: 触发几何 (line / zone radio) + 几何配置按钮 (绘制 +
      已配置时显示状态/方向) + 离开判定帧数 input
    - 新增 TriggerGeometryEditor 弹窗:
      - 加载摄像头 snapshot 做底图, canvas 大小按 snapshot naturalWidth/Height
      - line 模式: 单击 2 次添加起点+终点, 画完后按法向偏移把两侧染色
        (蓝=A 叉积+, 橙=B 叉积-) + 标 "A" / "B" 字, 用户在 radio 选触发方向
        [A→B] / [B→A]; 已画线再单击重新开始
      - zone 模式: 复用 ROI polygon 画法 (单击加点, 点击第一个点闭合, 双击也闭合)
      - 保存时把 canvas 像素坐标除以 width/height 归一化 [0,1] 写回
        `form.scan_d_line / form.scan_d_zone`
    - `frontend/src/api/scanner.js` 加 `checkContainerMode(channelId)` helper
  - 与 v3.3.0 scan_pair 关系: D 模式控扫码灯 (LON/LOFF 何时发, 由 box 物理位置驱动),
    scan_pair 控结算节拍 (cycle 何时结算, 由扫码事件驱动); 同一扫码器可同时启用 D
    模式 + scan_pair, 互不干扰 — D 决定灯什么时候亮 / 什么时候灭, scan_pair 决定
    扫到第几个码触发结算上一周期。
  - 默认值: 老项目升级后 `scan_mode` 仍是 'continuous', 行为完全不变 (兼容承诺)。
    客户需要时手动切到 D 启用。

## 客户现场操作建议

1. **默认行为不变**: 升级后所有现有扫码器仍是 `continuous (A 持续扫描)`,
   行为完全不变; 不主动切到 D 则零影响。
2. **启用前提**: 工位绑定的项目必须是容器模式 (步骤里至少有一个步骤标签设为
   "容器", 即 logic_mode='tracking' 且 tracking_container_label 非空)。在 MES
   → 扫码器 → 编辑里把扫描模式切到 D 时, 系统会自动校验, 不是容器模式直接弹
   警告并回退到原模式。
3. **几何配置**:
   - 线模式 (推荐, 适合大多数产线): 在弹窗里单击 2 次添加起点+终点, 画完后
     画面会按法向把两侧染色 (蓝=A, 橙=B), 在 radio 选"A→B"还是"B→A"为触发
     方向。例如产线从左到右走, 线竖直从上到下画, 选 "A→B" (蓝色在线左, 橙色
     在线右, 箱子从左跨到右触发)。
   - 区域模式 (适合特殊形状的 ROI 触发, 比如 L 形装配工位): 单击多边形顶点,
     点击第一个点 (橙色) 闭合, 至少 3 点。箱子中心点从外进入区域触发。
4. **离开判定帧数**: 默认 30 (= 1 秒@30fps, 推荐); 节拍快可调 15 (0.5 秒);
   节拍慢调 60-90 (2-3 秒)。设 0 沿用项目 pipeline_config.gone_confirm_frames。
5. **多箱并发约定**: 同一时刻只允许一个 armed box 等扫码; 异常情况
   (产线节奏失控同时来 2+ 箱) 第二个 box 跨线被忽略 + log 警告, 不重复发 LON,
   保证扫码器一次只对一个箱码响应。客户产线必须保证"前一个箱扫完离开后, 下一个
   才跨线"才能正常工作 (与产线物理节奏一致)。
6. **与 v3.3.0 scan_pair 关系**: 完全正交 — D 控制扫码灯什么时候亮/灭 (按
   box 物理位置驱动), scan_pair 控制结算节拍 (扫到第二个码触发结算前一周期)。
   高级用法: 同一扫码器可同时启用 D + scan_pair, 流程变成 "箱跨线 → LON → 工人
   扫码 → LOFF → 工人离开箱子开始装件 → 箱跨线下一条线 → LON → 工人扫码 → LOFF
   + 上箱按 sticky was_complete 判 OK/NG"。
7. **异常处理**: armed 但箱子离开画面未扫到码 → 系统主动发 LOFF 防灯一直亮; log
   会有 "armed 但离开未扫到码, 已强制 LOFF" 提示。频繁出现说明产线节奏与触发线
   不匹配, 需要调整线位置或 gone_confirm_frames。
