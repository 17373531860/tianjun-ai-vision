# v3.4.1 (2026-04-30) — D 模式 hotfix

v3.4.0 上客户机首次实测发现两个直接影响 D 模式可用性的 bug, 紧急 hotfix.

## Bug 修复

### [BUG-341-001] D 模式扫码器灯一直闪 (像 continuous)

**症状**: 客户切到 scan_mode='D', 设了划线方向, 启动检测后扫码器灯**像 A 模式
持续扫码那样一直闪**, box 跨没跨线都一直亮; 终端日志整段刷屏:

```
[Scanner/text_lon] 收到 ERROR (本轮无码, 将自动续发 LON, mode=D)
[Scanner/text_lon] LON 续发 (mode=D)
[Scanner/text_lon] 收到 ERROR (本轮无码, 将自动续发 LON, mode=D)
[Scanner/text_lon] LON 续发 (mode=D)
... (每 80ms 一对, 持续不断)
```

**根因**: v3.4.0 实现 D 模式时, `services/scanner.py` 的两处 LON 续发路径
**只把日志加了个 `mode=D` 标签, 实际续发逻辑根本没排除 D 模式**:

1. `_text_lon_recv` 收到 ERROR (扫码器本轮无码超时) 时:
   ```python
   if text.upper() == "ERROR":
       conn._next_lon_after = 0.0
       conn._lon_sent = False  # ← D 模式照样清, 主循环立刻续 LON
       print(f"... mode={mode}")  # 只是日志多了 mode=D
       return
   ```

2. listen loop 主循环按 `_lon_sent=False` 自动续 LON:
   ```python
   while not conn._stop_event.is_set():
       if (conn._scanning
               and not conn._lon_sent     # D 模式被 ERROR 清成 False
               and ...):
           sock.sendall(b"LON\r\n")  # ← 照样续发
   ```

3. `start_scanning` 在检测启动时一次性发 LON, set `_lon_sent=True`. D 模式
   也走这条路径, 灯启动就亮了, 跟"按 box 跨线触发"完全相反.

**修复 (3 处)**:

1. `start_scanning` D 模式不发 LON:
   ```python
   if (conn.scan_mode or 'continuous') == 'D':
       print(f"... D 模式 start_scanning: 不发 LON (等 box 跨线触发)")
       conn._lon_sent = False
       continue  # 跳过 LON 发送
   ```
   灯一开始保持灭, 等 `_scan_d_update` 主动调 `send_lon_for_channel` 才亮.

2. ERROR 处理 D 模式只 return:
   ```python
   if text.upper() == "ERROR":
       mode = ...
       if mode == 'D':
           # D 模式 ERROR 不续 LON, 灯自然进入"未亮"等下次 box 跨线
           return  # 不动 _lon_sent / _next_lon_after
       ...
   ```

3. listen 主循环 D 模式跳过续 LON:
   ```python
   _mode_now = getattr(conn, 'scan_mode', 'continuous') or 'continuous'
   if (conn._scanning
           and _mode_now != 'D'   # ← NEW: D 模式不自动续
           and not conn._lon_sent
           and ...):
       sock.sendall(b"LON\r\n")
   ```

修复后 D 模式 LON 唯一发送源是 `source._scan_d_update.send_lon_for_channel`,
按 box 跨线/进区域脉冲式发, 跟设计一致.

**影响文件**: `backend/services/scanner.py`

### [BUG-341-002] 前端 D 模式校验工位拿错

**症状**: 客户场景"绑定工位=工位2, 广播工位=[工位1, 工位2]", 切到 D 模式时
弹警告 "工位 1 当前绑定的项目不是容器模式" 被自动回退到 continuous;
但用户其实**绑定工位是工位2** (容器模式项目), 校验应该过.

**根因**: v3.4.0 前端 `onScanModeChange` 取错了校验工位号:
```js
// 错误: 取广播列表第一个 (工位1, 不是容器模式)
const broadcast = form.value.broadcast_channels || []
const checkCh = broadcast.length > 0 ? broadcast[0] : (form.value.channel_id ?? 0)
const { data } = await checkContainerMode(checkCh)
```

`broadcast_channels` 是"扫到码后这个码同步通知给哪些工位"的事件分发列表,
跟 D 模式触发判定无关. D 模式状态机跑在扫码器**绑定工位** (channel_id) 的
检测帧循环里 — 用那个工位的摄像头看 box 跨线/进区域.

几何编辑器 `loadTriggerGeoSnapshot` 同样的错误: 用 broadcast[0] 拿 snapshot
也会拿错工位的摄像头画面.

**修复**: 两处都改成只看 `channel_id`:
```js
const checkCh = form.value.channel_id ?? 0
```

**影响文件**: `frontend/src/views/MES/ScannerPanel.vue`

### [FEAT-341-001] D 模式诊断日志增强

v3.4.0 客户首次实测画线后 LON 没触发, 我们对着日志只能看到 `[ScanD] xxx
gone-confirm 完成` 一行, 不知道是: (a) box 没跨过线 / (b) 用户配的方向反了
/ (c) box 一直在线同侧抖动. 增强 `_scan_d_update` 日志:

1. 新 box 首次进入状态机 → log 它的初始几何关系:
   ```
   [ScanD] ch0 箱子1 首次出现 (cx=640,cy=360) side=A(蓝),
           配置方向=A→B, 等待跨线...
   ```
   或 zone 模式:
   ```
   [ScanD] ch0 箱子1 首次出现 (cx=640,cy=360) in_zone=False,
           等待进入区域...
   ```

2. box 跨线但方向反 → 直接提示用户:
   ```
   [ScanD] ch0 箱子1 跨线方向=A(蓝)→B(橙), 但配置要求=B→A,
           未触发 (是不是把方向选反了?)
   ```

这两类日志频率很低 (每 box 出现/跨线各打一次), 不会刷屏.

**影响文件**: `backend/api/source_container_grouping_mixin.py`

## 客户使用提示

升级到 v3.4.1 后, 切到 D 模式重新启动检测:

1. 灯**默认是灭的** (与 v3.4.0 灯启动就亮不一样); 这是设计行为.
2. box 跨过你画的线 / 进入你画的区域时, 灯亮 (LON), 扫码器开始扫码.
3. 扫到码后灯灭 (LOFF), 等当前箱子离开 (gone-confirm 默认 30 帧 ≈ 1 秒)
   再允许下一箱触发.
4. 如果灯一直不亮:
   - 看终端 log 是否有 `[ScanD] xxx 首次出现 ... 配置方向=X` 输出
   - 如果有 `跨线方向=A→B, 但配置要求=B→A` 提示, 去 ScannerPanel
     重新画线把方向选反过来
   - 如果只有 "首次出现", 说明 box 一直没跨过你画的线 (位置不对或线画在
     画面外了)
