# v3.27.0 (2026-06-25)

> 主题：**插件平台新增「插件主动触发主程序事件」桥接能力 + 传感器清洁插件 v1.1.0 三判定接入主程序事件体系**。
> 给插件平台补 `PluginHost.trigger_event`（`runtime.event_trigger` 能力），让插件能借用主程序某个事件的「响应面」（报警 + 计数器 + Toast/语音 + 主页显示）而**不结算检测周期**——专治"过程告警类判定"（如假擦拭 / 操作员离开 / 耗材超限），不污染 OK/NG 良率统计。基于此，sensor-clean 插件升级 v1.1.0：把三个客户判定做成可配置事件，用户全程用主程序原生 UI（项目页配事件/计数器、报警页配灯柱、插件 Tab 选判定→事件）。

## 功能变更

- [FEAT-001] 插件平台新增 `PluginHost.trigger_event(channel_id, event_id, reason)` 主动 API
  - 需求: 插件平台此前只有 `trigger_alarm`（仅报警），缺一个"借用主程序完整事件响应面"的口子。客户过程判定（假擦拭/离岗/超限）需要联动报警+计数器+Toast+主页，但又不能当成"一个产品检完合不合格"去结算周期、污染良率。
  - 实现: 仿 `trigger_alarm` 新增 `trigger_event`，内部调目标通道 `VideoSourceManager.fire_external_event_response`（v3.21 既有，不结算周期）。能力守门 `runtime.event_trigger` + audit log + 错误隔离（通道未注册/事件未找到/异常均返 False 不抛）。`event_id` 是主程序级（项目配置），不强制 `plugin_` 前缀（插件只能复用用户配好的事件）。
  - 影响文件: backend/plugin_system/registry.py, docs/plugin-system/design/01_manifest_schema.md, docs/plugin-system/plugin.schema.json, tests/plugin_system/test_active_apis.py, tests/plugin_system/test_trigger_event_integration.py

- [FEAT-002] sensor-clean 插件 v1.1.0：三判定接入主程序事件体系
  - 需求: 客户在 detect7(1) 版本新增两条过程判定（假擦拭、操作员离开），连同既有"棉签寿命超限"，希望都做成可配置事件——用户自己选每个判定连哪个事件，事件连报警、连计数器，新计数器在检测主页显示。明确不做"假换棉签"（棉签框静止那条）。
  - 实现:
    - 判定器（`counter.py`）: 新增 `StillFakeActionDetector`（复刻 detect7(1) dirty_tracker：框停留超 still_time 秒但累计位移 < still_disp 归一化 → 命中；位移够大视为正常销毁追踪）+ `AbsentCountdown`（复刻周期性强制动作：纯帧级倒计时无后台线程，检测到人重置、持续无人超 timeout 命中一次）。
    - 三判定（`hooks.py on_detection_frame`）: ① 假擦拭（视角1 追踪"擦拭产品"框）② 棉签寿命超限（既有计数达 K，由原 `trigger_alarm` 改为 `host.trigger_event`，兼容老 `alarm_event`）③ 操作员离开超时（视角2 空帧倒计时，默认关）。命中均调 `host.trigger_event(channel, event_id, reason)`。
    - 配置: 新增 `swab_over_limit_event_id` / `fake_wipe_event_id` / `fake_wipe_still_time` / `fake_wipe_still_disp` / `operator_absent_enabled` / `operator_absent_event_id` / `operator_absent_timeout_sec`，默认事件 id=2（系统 NG）；新增 `GET/POST /swab/config` 读写端点（前端配置 Tab 保存走它）。
    - 项目模板（`preset.py`）: 两个视角项目默认带标准 OK/NG 事件 + show_in_monitor 工艺/离岗告警计数器，开箱即可联动主页显示。
    - 前端（`frontend/dist/index.esm.js`）: 配置 Tab 新增三判定→事件下拉（事件选项从 `host.api` 拉激活项目 events_config，默认 NG）+ 阈值/开关输入；网络全面改 `host.api`（已鉴权 axios，file:// 兼容）兜底 fetch。
    - manifest: capabilities 加 `runtime.event_trigger`；`plugin_version` 1.0.0→1.1.0；`main_version_min` 3.27.0。
  - 影响文件: plugins-examples/sensor-clean/backend/{counter,hooks,routes,preset}.py, plugins-examples/sensor-clean/frontend/dist/index.esm.js, plugins-examples/sensor-clean/plugin.json, tests/plugin_system/test_sensor_clean_judgments.py

- [FEAT-003] sensor-clean 插件 v1.1.0：拿 detect7(1) QT demo 用真实模型+视频做离线对账并收正参数
  - 背景: 客户要求插件默认参数/效果对齐 detect7(1).py（基准 QT demo），用同样模型（视角1 best.pt、视角2 更换棉签.pt）跑同样视频对比，直到一致。逐行比对确认插件与 detect7(1) 算法同构（cls0 移动即计数+帧硬锁、cls1 静止假动作、视角2 周期性离岗倒计时）。
  - 收正:
    - **IOU 0.40→0.45**（preset 两个视角项目），对齐 detect7(1) DEFAULT_IOU。
    - **参数照搬 detect7(1)、不引入 demo 里没有的坐标校正**: 主程序给插件的是 `x/宽、y/高` 归一化坐标（宽1728≠高1080），与 detect7(1) 像素欧氏度量在宽≠高时严格说有方向性差异（竖向略敏感）。曾评估加 `frame_aspect`（高/宽）做各向同性校正使视角1 精确等于 detect7（44），但按客户「照搬代码参数、参数全可调让现场自调」诉求**回退该校正**：`_dist` 保持纯归一化欧氏，阈值按 @1728 归一化（detect7 的 20/25/10px ÷ 1728）。视角1 离线计数 **插件 45 ≈ detect7 44（差 1 件**，差异来自归一化竖向略敏感，在现场调参噪声内、参数全可调由现场收敛）、假擦拭 0=0。
    - **视角2 换棉签解锁不对齐 detect7、加可选防抖**: 真值统计（全程 32753 帧逐帧）显示 detect7(1) 工位2 复用「移动即计数」对小幅换棉签动作**严重漏检**——只算 5 次，漏掉 11 次真实换棉签（含第508秒持续1.3秒/80帧的明显动作），根因是换棉签框基本不移动、达不到 20px 阈值。真实换棉签约 16 次。故视角2 保留「出现稳定」解锁，并新增**可选**防抖 gate（`SwabChangeWindow` 加 `min_sustain_sec` 持续时长 + `gap_sec` 丢框容忍，**用秒不用帧、跨帧率鲁棒**，i5+3060 现场低帧率同样可靠）；视角2 解锁参数独立（不再借用视角1 `lock_time`）。**默认 `min_sustain_sec=0` 照搬 demo 不防抖（17 次），现场要滤瞬时误检自行调大（如 0.12→16 次≈真值）**。无论是否防抖都远优于 detect7 的 5 次。
  - 现场提示: `force_lock_frames` 等帧数类阈值按 60fps 定，现场低帧率需等比例调；视角2 大图 2448×2048 实时建议降源帧率或推理 imgsz=1280 减负。
  - 影响文件: plugins-examples/sensor-clean/backend/{counter,hooks,preset}.py, tests/plugin_system/test_sensor_clean_judgments.py
