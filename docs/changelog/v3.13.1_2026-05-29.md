## 主线 1 — RFC 10 工位组 (主程序原生功能, 闭环客户需求 #4)

### [FEAT-001] **工位组 ChannelGroup ORM + CRUD API**
- **需求**: 双工位同时检测同一物件不同角度, A 工位判 NG 时 B 工位也要同步判 NG (单工位无法解决的"组级结算")。
- **实现**:
  - 新表 `channel_groups` (id / name / member_channel_ids: JSON / settle_strategy / timeout_ms / timeout_action / enabled / plugin_data)
  - `detection_cycles` 加 3 列 `channel_group_id / group_settled_with: JSON / group_settle_result`
  - 5 个 CRUD endpoint: `GET POST /api/v1/channel-groups`, `GET PUT DELETE /api/v1/channel-groups/{id}`, `GET /api/v1/channel-groups/{id}/state`
  - 启动迁移自动 ALTER TABLE
- **影响文件**: `backend/models/models.py`, `backend/api/channel_groups.py`, `backend/api/__init__.py`, `backend/main.py: migrate_database`, `backend/core/permissions.py` (`system.channel_group.view / manage`)
- **关键词**: ChannelGroup / 工位组 / 同步结算 / channel_groups 表

### [FEAT-002] **ChannelGroupCoordinator 单例 + 4 种结算策略**
- **需求**: 客户实际生产线节奏不规则, 单一"同步等齐"策略不够用。
- **实现**:
  - 进程内单例 `ChannelGroupCoordinator`, 内部 `_groups / _channel_to_group / _pending_override / _pending_aggregations` 由 `threading.Lock` 保护
  - `synchronized_any_ng`: A NG → 立即给 B 设 `pending_override="NG"` + 直驱 `alarm_router.trigger_alarm("event2", channel_id=B)` 联动报警灯
  - `synchronized_all_ok`: 所有成员等齐后 fire `channel_group_settle_done` hook, 任一 NG 即广播; 用 `threading.Timer` 做超时
  - `timeout_action=fallback_independent`: 超时未齐 → done hook 标 `group_result="PARTIAL"`, 已结算的不动
  - `timeout_action=force_ng`: 超时未齐 → 给没到的成员设 `NG_BY_TIMEOUT` override + done hook 标
  - VSM `end_cycle` 调 `get_pending_override(channel_id)` (take-once 语义) 强制改写 `is_good`
- **影响文件**: `backend/services/channel_group_coordinator.py` (新建), `backend/api/source_session_lifecycle_mixin.py`, `backend/api/channel_manager.py: set_channel_count` (调 `on_channel_removed`)
- **关键词**: 工位组 / synchronized_any_ng / synchronized_all_ok / timeout / pending_override / take-once

### [FEAT-003] **工位组与 cluster (跨机) 互操作**
- **需求**: 单机内工位组 + 跨机集群两个维度都用上时, MES box-level 推送要能看到"该 box 是不是组级 NG"。
- **实现**:
  - `MESGateway.build_context_from_cycle` 输出加顶层 `channel_group: { id, settle_result, settled_with }` + cycle 子树便利字段 `cycle.channel_group_id / group_settle_result / group_settled_with`
  - cycle_context 通过 `BoxAggregation.cycle_context` 跨机透传, `cluster_collector` 聚 box 时自动落到 `BoxSummary.aggregated_context.stations[i].channel_group`
  - 客户 MES 模板可直接引用 `{channel_group.settle_result}` 或 `{stations[0].channel_group.id}`
- **影响文件**: `backend/services/mes_gateway.py`
- **关键词**: cluster / box_summary / channel_group / MES 模板透传

### [BUG-001] **SQLite `JSON.contains` substring match 误报**
- **现象**: 添加成员 channel 0 时, 已有组 `member_channel_ids=[10, 11]` 被误报"冲突" — `JSON.contains(0)` 在 SQLite 内是文本子串匹配 (字符串 "10" 包含 "0")。
- **修复**: 改用 Python 应用层校验 `_check_member_uniqueness` (拉所有 enabled 组用 `cid in other_members` 真正数组成员检查)
- **影响文件**: `backend/api/channel_groups.py`

### [BUG-002] **PUT 端点漏 cross-group 唯一性校验**
- **现象**: 更新组成员或启用组时未重做跨组唯一性校验, 可能造成同一 channel 同时活跃在多个组。
- **修复**: `update_channel_group` 在 `member_channel_ids` 或 `enabled` 改变时调 `_check_member_uniqueness(..., exclude_group_id=group_id)`
- **影响文件**: `backend/api/channel_groups.py`

## 主线 2 — RFC 09 插件平台 v3.13 升级 (M1 业务流程 / M2 UI / M3 配置)

### [FEAT-004] **M1 业务流程双向打通**
- **新增 hook 点 (10 个)**: `pre_cycle_end` (returnable, 可改写 is_good / event_name), `session_end`, `cycle_start`, `step_change` (returnable, 可加 warn_label), `event_fire` (returnable, 可 suppress_alarm), `box_complete`, `scan_received`, `project_activated`, `source_status_change`, `channel_group_settle_start`, `channel_group_settle_done`
- **PluginHost 主动 API (10 个)**: `trigger_alarm`, `mes_push`, `read_system_config`, `write_system_config`, `write_plugin_step_field`, `list_channel_groups`, `query_channel_group`, `broadcast_to_channel_group`, 各带 capability 守门 + audit log
- **Returnable hook 契约**: `fire_plugin_hook` 升级返回 dict, `RETURNABLE_HOOK_FIELDS` 白名单封闭, 多插件优先级竞争记录 audit
- **影响文件**: `backend/plugin_system/{registry,manager,hook_dispatch}.py`, `backend/plugin_system/version_check.py`, `backend/api/source_*_mixin.py` (多文件), `backend/_version.py`
- **关键词**: 插件 / hook / returnable / PluginHost / capabilities / audit

### [FEAT-005] **M2 UI 扩展平台化 — TjSlot + 7 个主程序 slot 全接入**
- **基础设施 (M2.2a)**: `<TjSlot name="...">` 全局组件 + `usePluginThemeStore` (`pluginSlots / uiHidden / settingsTabs / projectTabs` state) + `usePluginLoader` registry (`slots.register / tabs.register`)
- **主程序 7 个 slot 位 (M2.2b)**:
  - `settings.tab.*` / `project.tab.*` — Settings 页 / Project 页 v-for + el-tab-pane 包装, 客户插件可注入自家 Tab
  - `cycle-result.indicator` — Monitor 每个 toast 渲染体可被插件替换 (含 :toast :channel-id)
  - `monitor.step-cell.duration` — 步骤表"耗时"列 (含 :step :label :status :pt-text :is-tracking-mode) — 闭环客户需求 #1 三档颜色
  - `monitor.step-cell.status` — 步骤表"结果"列 — 闭环客户需求 #2 隐藏步骤级红色 (用 `frontend.ui_hidden` 整列隐藏)
  - `monitor.layout.body` — 整体 layout 完全覆盖 (`<component v-if=layoutBodyOverride>` + 原 DOM `v-else-if=channelCount===2` 链式守门) — 闭环客户需求 #3 双工位左右半屏
  - `monitor.layout.footer` — 视频区底部全局状态条 slot, 默认不渲染
- **零差异默认**: 没插件时 `layoutBodyOverride === null` / `settingsTabs === []` / `pluginSlots === {}`, 主程序行为字节级零差异
- **影响文件**: `frontend/src/components/TjSlot.vue` (新建), `frontend/src/store/usePluginThemeStore.js`, `frontend/src/composables/usePluginLoader.js`, `frontend/src/main.js`, `frontend/src/views/{Monitor,Settings,Project}/index.vue`
- **关键词**: TjSlot / 插件 UI / slotification / ui_hidden / layout 重排
