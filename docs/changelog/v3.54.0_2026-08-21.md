  - 需求: 客户反馈 C 盘容易满，且无法实时指定录像路径——录像死写安装盘 `recordings/`，只能靠归档复制一份。

- [FEAT-003] 长录像治理三件套：fMP4 录制 + 条件转码直出 + 会话按小时分段
  - 需求: 24 小时长录像"视频加载失败"高发。根因两条：① 老管线 `+faststart` 要在录制收尾时整文件重写 moov 索引，大文件远超 10s 收尾超时被强杀，moov 残缺=整段不可播；② 回放端不管源编码一律转码，大文件转码 300s 超时必败。
  - 实现: ① 录制改 **fragmented MP4**（`+frag_keyframe+empty_moov+default_base_moof` + `-flush_packets 1` + `-g 125` 五秒 GOP）——每个 fragment 自带索引，进程被杀/断电文件仍可解码；release 后台 daemon 线程 `remux_to_faststart` 流拷贝（不转码）出常规 faststart MP4（秒级 seek+全兼容），失败保留 fMP4 原件仍可播。② 回放端 `_is_browser_compatible_h264` 编码探测（`ffmpeg -i` stderr 解析 h264+yuv420p，带缓存）命中直出原文件**免转码**，老 mp4v 录像照旧转码。③ 会话录像按小时自动分段（`SESSION_SEGMENT_SECONDS` 默认 3600，env `TJ_SESSION_SEGMENT_SECONDS` 可调）——到点先起新 writer 再换旧（新段打不开延用旧 writer 下轮重试不丢帧），每段独立 `VideoClip` 行；新端点 `GET /data/sessions/{id}/videos` 返回分段列表；Data 页播放器多段会话显示分段切换条（第N段+时间标签，缺文件段禁用）。会话清理按 related_id 天然管到全部分段。
  - 影响文件: backend/api/source_recorder.py, backend/api/source_recording_api_mixin.py, backend/api/source_recording_thread_mixin.py, backend/api/sessions.py, frontend/src/api/data.js, frontend/src/views/Data/index.vue, frontend/src/views/Data/components/VideoPlayerDialog.vue
