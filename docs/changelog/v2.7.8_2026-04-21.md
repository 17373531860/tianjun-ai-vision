# v2.7.8 (2026-04-21)

## Bug 修复

### [BUG-001] v2.7.6 传动杆误判过滤两个开关从未生效
- **症状**：v2.7.6 上线「空间共现过滤 + 软时序状态门」后，客户机上即使手动在 DB 的 `project_config` 里加顶层 `rod_companion_filter` / `rod_session_gate` 字段，日志也没有 `[RodFilter] companion_filter enabled` 输出，过滤效果与未启用一致。
- **根因**：`backend/api/rod_filter.py::read_rod_filter_config` 只从 `project_config` 顶层读这两个 key。但 `backend/main.py::_build_project_config` 构造传给 `set_project_config` 的 dict 时，只把字段放进 `pipeline_config / data_config / steps_config / events_config / counters_config`，**没有把这两个 key 抬到顶层**。结果：无论写到 DB 的哪个字段（JSON 顶层根本不存在），运行时都读到 `{}`，两个开关永远为 `False`。
- **修复**：改 `read_rod_filter_config` 兼容两种写法——**优先读 `project_config["pipeline_config"]["rod_companion_filter"]`**，再回退到顶层；配套前端把 UI 输入写到 `pipeline_config` 里，彻底打通数据流。
- **影响文件**：`backend/api/rod_filter.py`, `test_rod_filter.py`

## 功能变更

### [FEAT-001] Project 配置页新增「误判过滤（高级）」卡片，两个开关做成通用 UI
- **需求**：v2.7.6 的两层过滤是纯后端逻辑，没 UI，label 写死在默认值里（"传动杆/大框架/小框架/侧板"），客户每次上新项目都要手动改 DB，而且如上面 BUG-001 所述完全不生效。用户要求做成**项目级通用开关**：按 label 字符串匹配，可为任意类别配置，不限于传动杆。
- **实现**：`frontend/src/views/Project/index.vue` 逻辑设置 Tab 底部新增卡片「误判过滤（高级）」：
  - **第 1 层「空间共现过滤」**：enabled 开关 + 目标 label（单选/可输入）+ 伴随 labels（多选/可输入）+ IoU 阈值（0~1，步长 0.05，默认 0.25）
  - **第 2 层「软时序状态门」**：enabled 开关 + 目标 label + 触发 labels（多选/可输入）
  - label 候选用 `availableLabels` computed，从当前项目的 `steps_config.label` 聚合，同时允许 `allow-create` 输入自定义（兼容模型 label 和步骤 label 不一致的场景）
- 新增 `_cleanLabels` / `_sanitizeCompanionFilter` / `_sanitizeSessionGate` 三个清洗辅助：
  - 自动 trim + 去空字符串
  - IoU 裁剪到 `[0, 1]`
  - **关键防呆**：`rod_label` 空或 `labels` 为空时，即使开关 ON 也强制回落为 `enabled: false`，避免配置不全时误启用
- `initProjectDefaults` 从 `pipeline_config.rod_companion_filter` / `rod_session_gate` 读默认值注入到顶层响应式字段；`handleSaveProject` 反向把顶层字段 sanitize 后写回 `pipeline_config`，和后端 `read_rod_filter_config` 的读取路径一致。
- **默认值**：两层开关全关，老项目升级后行为不变。
- **影响文件**：`frontend/src/views/Project/index.vue`, `backend/api/rod_filter.py`
- **测试**：`test_rod_filter.py` 20 用例全过（新增 4 个用例覆盖 pipeline_config 读取、pipeline 优先级、`pipeline_config=None/{}` 安全兜底）
