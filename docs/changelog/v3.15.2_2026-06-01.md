# v3.15.2 (2026-06-01)

> 紧急热修 v3.15.1 现场 P0：所有 Windows 客户装插件报「插件文件摘要不一致」（跨平台路径排序导致摘要漂移）+ 根治手动从 cmd 启动时日志整屏乱码。配套热补丁可让现存 v3.15.1 客户不重装即修插件问题。

## Bug 修复

- [BUG-001] 插件安装失败 PLUGIN_FILES_DIGEST_FAIL（跨平台文件排序导致摘要漂移）— **P0**
  - 症状: 客户 Windows 机 v3.15.1 上传 .tjvplugin 报「插件文件摘要不一致」；任何含大写文件名（`README.md` 几乎必有）的插件在所有 Windows 客户机上必中
  - 根因: files_digest 计算时文件排序用 `sorted(root.rglob("*"))`，即按 Path 对象排序。Windows 的 WindowsPath 排序**大小写不敏感**（把 `README.md` 当 `readme.md` 排到末尾），Linux 的 PosixPath **大小写敏感**（`README.md` 大写 R 排最前），两平台文件顺序不同 → 摘要按文件顺序拼接哈希 → 算出的 files_digest 不同。插件在开发端（Linux/POSIX 顺序）签名，Windows 客户机重算顺序错位 → 摘要比对失败。开发机（Linux）自测永远通过，bug 只在 Windows 客户机暴露。与 v3.15.1 CI 自检的反斜杠误判同根（Windows vs Linux 路径差异）
  - 修复: 排序键改为相对路径 POSIX 字符串 `p.relative_to(root).as_posix()`（大小写敏感、`/` 分隔），与 `calc_files_digest_in_zip` 的 `sorted(namelist())` 字符串排序、打包端顺序完全对齐，平台无关
  - 影响文件: backend/plugin_system/_plugin_common.py
  - 验证: 现场福建金龙插件摘要在 Linux 重算仍匹配（不破坏已签插件）+ 17 项摘要测试通过（含 2 新回归）

- [BUG-002] 手动从 cmd 启动时日志整屏乱码
  - 症状: 用户从 cmd 双击 `.lnk` 启动，控制台日志整屏乱码（`澶╁啗绉戞妧AI瑙嗚妫€娴媊），现场排错无法看日志
  - 根因: Windows cmd 默认 GBK(936) 代码页；Electron 主进程 `console.log` 的中文 + 它转发的后端 UTF-8 日志输出到 GBK 窗口被错误解码。后端侧编码本已做足（`PYTHONUTF8` / `PYTHONIOENCODING` / `setEncoding('utf-8')`），瓶颈在承载输出的控制台显示代码页
  - 修复: Electron 主进程启动最早（首条中文日志之前）执行 `chcp 65001` 把当前控制台输出代码页切 UTF-8；双击桌面图标无附加控制台时在隐藏子控制台执行、静默无副作用，非 Windows 平台跳过
  - 影响文件: electron/main.js

## 测试

- [TEST-001] 加跨平台摘要排序回归测试
  - `tests/plugin_system/test_files_digest.py` 新增 2 个回归：① 用 `PureWindowsPath` 显式模拟两平台排序分裂（Linux 上 `PosixPath` 排序恰好等于字符串序，旧 bug 在 Linux 测永远绿、抓不到），钉死「排序键必须是 POSIX 字符串」不变量；② 含大写文件名（`README.md`）目录算与 ZIP 算（POSIX 字符串序基准）一致契约
  - 影响文件: tests/plugin_system/test_files_digest.py

## 配套热补丁（patch_v3.15.2a）

- 面向现存 v3.15.1 客户：插件系统不在 Nuitka 编译白名单，`_plugin_common.py` 是源码 `.py` 部署，热补丁直接替换该文件即可，重启软件即修插件摘要 bug，**无需重装**
- 仅修 BUG-001（编码修复在 Electron `app.asar` 内，无法热替换，需随完整安装包重装才能生效）
- 文件: `patch_v3.15.2a.bat`（CRLF / 英文提示 / 自动定位安装目录 + 备份旧文件 + 替换）+ `_plugin_common.py`
