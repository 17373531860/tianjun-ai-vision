# v3.23.0 (2026-06-22)

> 上银包装线现场闭环增强 + 通用 NG 补做能力。本版以「现场异常可由人工就地处置、不重置周期」为主线，
> 同时把外部触发的异常也纳入人工确认定格体系。未配置新功能的客户行为零差异。

## 功能变更

- [FEAT-001] 外部触发事件支持「需人工确认」定格整条检测线
  - 需求: 包装漏箱 / 多装 / 缺油嘴 / 缺工单等异常由外部（包装协调器 / 扫码 / 外设）触发，
    此前只报警不阻断，工人可能继续干导致连环错。客户要求这些异常也能像检测层 NG 一样
    «定格整条线，等人确认才放行»。
  - 实现: 事件设置里某事件标 `require_ack=True` 后，外部触发该事件也进入人工确认阻塞态
    (`_pending_ack`)，整线定格直到操作员确认（或借管理员密码提权确认）。已在阻塞态时不重置，
    保留首个触发原因。默认 `require_ack=False` 行为与改前严格一致（只报警不定格）。
  - 影响文件: backend/api/source_event_trigger_mixin.py, backend/api/source_routes.py,
    frontend/src/api/detection.js, frontend/src/views/Monitor/index.vue

- [FEAT-002] 管理员 / 主管「强制结案」进行中工单（必填理由 + 审计留痕）
  - 需求: 现场卡单 / 工单要提前收尾 / 漏箱要硬收时，需有权限者手动收尾，而不靠停止 / 待机。
  - 实现: 新增权限 `system.packaging_flow.force_settle`（admin / engineer 默认有，操作员无 → 403）；
    `PackagingFlowRun` 加 `forced_reason` / `forced_by` 两列落库审计；协调器 `force_settle_manual`
    强制走 settle 收尾（忽略配置 keep/abort）；新端点 `POST /packaging-flows/{id}/force-settle`；
    监控页包装卡片加「强制结案」按钮（弹框必填理由）。
  - 影响文件: backend/core/permissions.py, backend/models/mes_models.py, backend/main.py,
    backend/services/packaging_flow_coordinator.py, backend/api/packaging_flows.py,
    frontend/src/api/packaging_flow.js, frontend/src/views/Monitor/PackagingFlowCard.vue

- [FEAT-003] 待机维持检测、不结算工单（可恢复继续）
  - 需求: 待机时希望保留进行中工单与检测进度，恢复后接着干，而不是一待机就收尾。
  - 实现: 包装配置加 `forced_settle_on_standby`（默认开=待机即收尾，保持老行为）；
    关掉后待机只暂停不结算工单，停止才收尾。
  - 影响文件: backend/services/packaging_flow_coordinator.py,
    frontend/src/views/Settings/PackagingFlowPanel.vue

- [FEAT-004] 每箱「缺油嘴」视觉 gate（封箱前必须检测到放油嘴动作）
  - 需求: 上银包装每箱封箱前要放油嘴，漏放属不良。
  - 实现: 包装配置加 `oil_nozzle_required` / `oil_nozzle_step_label` / `event_missing_nozzle`；
    sliders 口径每箱结算前复用步骤探测钩子判「放油嘴」步骤是否 covered，未过 → 暂不收尾 + 报警等补放；
    未配置时退化为放行（避免每箱 gate 误卡死线）。
  - 影响文件: backend/main.py, backend/services/packaging_flow_coordinator.py,
    frontend/src/views/Settings/PackagingFlowPanel.vue

- [FEAT-005] 通用「NG 补做策略」项目可选项（任意检测模式）
  - 需求: 缺步骤 / 少装数量导致 NG 时，经人工确认后能就地补做修正成合格，不重置整个周期；
    要做成项目设置里任意模式通用的可选项。
  - 实现: 项目管线配置新增 `pipeline_config.ng_remediation`（总开关 enabled + 允许补步骤
    allow_step + 允许补数量 allow_count），后端 apply 解析 + 状态初始化 + 检测结果暴露；
    项目「逻辑设置」Tab 顶部新增「NG 补做策略」卡片（所有模式通用）。默认全关 = 行为零差异。
    采用「延迟落账」模型：可补做的 NG 不先记账，待人工定结果后直接写终值。
  - 影响文件: backend/api/source_project_config_apply.py, backend/api/source_state_init.py,
    backend/api/source_routes.py, frontend/src/views/Project/index.vue

- [FEAT-006] 包装场景「补滑块」落地（NG 补做策略的包装实现）
  - 需求: 包装少装时，人工确认后补齐数量直接判合格，不重置周期。
  - 实现: 协调器仅对「检测步骤齐、仅滑块数不足」的少装箱挂起（`pending_remediation`），不立即记 NG、
    不推进箱号；新增「补滑块」（自动补齐到目标 / 操作员手动指定实际数，封顶不超目标）+「重做本箱」
    （丢弃等下一周期重测）；补做留痕（谁补 / 从几补到几 / 理由）写进箱明细；挂起期间新周期被忽略。
    多装 / 步骤不齐 / 没开策略 → 保持原行为立即判 NG。新端点 `POST /packaging-flows/{id}/supplement-sliders`
    与 `POST /packaging-flows/{id}/remediation-redo`（均需 `monitor.detection.ack` 权限）。监控页挂起态
    显示横幅 + 「补齐 / 手动输入 / 重做」三按钮。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/packaging_flows.py,
    backend/api/source_session_lifecycle_mixin.py, frontend/src/api/packaging_flow.js,
    frontend/src/views/Monitor/PackagingFlowCard.vue

- [FEAT-007] 开机自动恢复检测开关（auto_resume）
  - 需求: 有产线希望工控机开机即接着检测；有产线希望开机停在待机由工人手动点开始。
  - 实现: `workstation_config.json` 顶层加 `auto_resume` 段（默认 enabled=true）；开关开时后端启动
    无条件自动开始检测（门槛仅「源在跑 + 模型就绪」，含 3s 后重试一轮兜模型加载慢）；关时只恢复
    项目 + 视频源，停在待机。设置页加开关 UI。
  - 影响文件: backend/api/channel_manager.py, backend/main.py,
    frontend/src/views/Settings/index.vue

- [FEAT-008] 项目一键复制
  - 需求: 客户做新项目常以现有项目为模板，逐项重配太慢。
  - 实现: 新端点 `POST /projects/{id}/duplicate`，深拷贝 7 个 JSON 配置 + 任务类型 / 逻辑模式 /
    默认模型 + 推理格式克隆成新副本（默认不激活，名称自动加「副本」后缀防重名）。
  - 影响文件: backend/api/projects.py, frontend/src/views/Project/index.vue

- [FEAT-009] 虚拟扫码枪（现场 / 测试用）
  - 需求: 无实体扫码枪时也能驱动包装结算状态机做演示 / 联调。
  - 实现: 监控页虚拟扫码枪组件 + 独立 USB 扫码枪模拟器工具（PySide6 + 键盘注入）。
  - 影响文件: frontend/src/views/Monitor/VirtualScanGun.vue, tools/usb_scanner_sim/
