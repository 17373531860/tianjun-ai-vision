# v3.6.1 (2026-05-09)

## 功能变更

- [FEAT-361-001] 步骤耗时（PT）新增「计算方式」维度：合并 / 最后一次（默认合并）
  - 需求：客户场景中**同一个步骤在一个周期内可能多次连续出现**（运动场景下短暂遮挡、工艺反复进出），
    v3.5.x 的 PT 显示只取「最后那段连续出现」的时长，不直观——
    工艺标准节拍语境下，工程师真正想看的是**这个步骤在这件工件上累计花了多久**（SUM）。
    诉求：保留旧行为可切回（兼容老脚本/老用户认知），新增"合并"档作为默认。
  - 实现：与现有「PT 显示口径」（平均 / 最近一轮 / 当前周期内）**二维正交**，共 6 档可选。
    - **后端状态**：在周期/步骤耗时统计层新增 2 个维护项——
      - 当前周期内每个步骤的累计耗时（cycle 内 SUM，每段消失结算时累加）
      - 历史周期累计耗时清单（按步骤每周期一条，最多保留 100 条，与原段级历史同节奏滚动封顶）
    - **累加 hook**：`source_step_stats_mixin.py` 步骤段消失结算 + `source.py::_supplement_step_durations`
      结算补充路径，两处对应位置同步累加；周期结算 `end_cycle()` 把累加快照入历史并重置；
      `_discard_empty_cycle()` 仅重置不入历史（作废周期不污染统计）；`reset_stats()` 全清。
    - **后端接口**：`GET /api/v1/source/detection/results` 新增 3 个字段：
      `cycle_sum_step_durations`（当前周期累计）/ `last_cycle_sum_step_durations`（最近一周期累计）
      / `avg_cycle_sum_step_durations`（历史周期累计的算术平均）。老字段保持不变，向下兼容。
    - **前端配置**：`useSystemStore.display.monitor` 新增 `ptAggregate` 字段，
      取值 `'sum'`（默认）/ `'last'`，走原有 localStorage `display_settings` 持久化通道；
      `loadSettings` 深度合并保证老用户升级后自动获得默认值。
    - **前端 UI**：系统设置 → 显示设置 → 检测中心显示，在「PT 显示口径」下方增加
      「PT 计算方式」下拉（合并 / 最后一次），与原下拉风格一致。
    - **前端展示**：`Monitor/index.vue::formatStepPT` 改造为
      （计算方式 × 显示口径）二维选数据源；新增 3 个 ref 接收新字段，单工位轮询 + 多工位轮询
      均同步填充；备用步骤 `default_pt` 兜底逻辑同步覆盖新字段。
  - 影响范围（兼容性）：
    - **数据库不变**：`StepRecord` 始终按段记录（每段一行），不受开关影响；
      要做按周期 SUM 报表，仍可在 SQL 端 `SUM(duration) GROUP BY cycle_id, step_label`。
    - **CSV 导出「耗时(平均/秒)」列暂不联动新开关**，仍按段平均（即"最后一次 × 平均"语义），
      避免破坏老脚本依赖；如客户提需求再扩展。
    - **每周期只出现一次**的步骤场景下，"合并"与"最后一次"在数值上**完全等价**，
      默认值变更对此类项目透明。
  - 影响文件：
    - 后端：`backend/api/source_state_init.py`, `backend/api/source_step_stats_mixin.py`,
      `backend/api/source.py`, `backend/api/source_session_lifecycle_mixin.py`,
      `backend/api/source_lifecycle_mixin.py`, `backend/api/source_routes.py`
    - 前端：`frontend/src/store/useSystemStore.js`,
      `frontend/src/views/Settings/index.vue`, `frontend/src/views/Monitor/index.vue`

## 兼容性

- v3.6.0 所有 API / 数据结构兼容，无需 migration。
- 新增 3 个响应字段属增量扩展，老前端不消费即可，不会引发解析错误。
- `display.monitor.ptAggregate` 缺省值由 store 深度合并注入，老用户 localStorage 没这个键时
  自动取默认 `'sum'`，**首次升级后看到的 PT 数字若变大**，是从"最后段"切到"周期累计"的预期行为；
  想保持旧观感的用户，把"PT 计算方式"切回"最后一次"即可。
- 数据库表结构不变；`StepRecord` 仍按段记录（每段一行）。
