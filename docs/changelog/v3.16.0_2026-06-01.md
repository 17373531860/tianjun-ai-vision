# v3.16.0 (2026-06-01)

> 补齐福建金龙双工位定制需求 R1–R5 中**缺失的配置 UI**。R1–R5 的后端能力在 v3.15.5 已全部具备，但其中两项（步骤耗时三档配置、工位组互通配置）一直**没有前端入口**，客户在界面上找不到、误以为功能没做。本版把这两个配置入口补齐：主程序步骤设置表新增「步骤耗时三档」列并留插件插槽，设置页新增「工位组互通」配置面板；插件升级到 v1.1.9 填充三档配置单元格。R3（双工位布局）/R5（权威 OK/NG 统计）在 v3.15.5 + 插件 v1.1.x 已实现，本版无改动，靠 v3.15.5 的加载抢跑修复重启即显示。

## 功能变更

- [FEAT-001] 步骤设置表「步骤耗时三档」配置 UI（R1/R2）
  - 需求: 客户要在步骤设置里配「最短 / 警告 / 最长」三档秒数——进行中超「警告」档只报警不判 NG；走完未达「最短」或进行中超「最长」则报警 + 判 NG。v3.15.5 插件后端已实现该判定（cycle_start/step_tick/step_change/pre_cycle_end hook）+ `GET/PUT /durations/step-durations` 读写接口，但**始终没有配置入口**，客户无法在界面设阈值。
  - 实现: 主程序 Project 步骤表在「Box 尺寸上限」与「步骤 ROI」之间新增「步骤耗时三档」列，留前端插槽 `project.step-cell.durations`（无插件时显示「需插件」占位，主程序不含业务逻辑）；插件 v1.1.9 注册该插槽的配置单元格组件（最短/警告/最长三个 `el-input-number`，去抖后 PUT 到插件后端 `/durations/step-durations` 落库）。
  - 影响文件: frontend/src/views/Project/index.vue, plugins-examples/fujian-jinlong/frontend/dist/index.esm.js, plugins-examples/fujian-jinlong/plugin.json

- [FEAT-002] 设置页「工位组互通」配置面板（R4）
  - 需求: 双工位作为一道完整检测工序，两个工位的检测逻辑要互通（一起结算）。v3.15.5 后端已落地工位组（`/channel-groups` 路由 + ORM 表 + 协调器 + 结算联动），但**没有前端配置入口**，客户无法创建/编辑工位组、选成员工位与互通策略。
  - 实现: 新增工位组 CRUD 的 axios 封装；新增「工位组互通」管理面板（列表 + 新建/编辑对话框，仿 WorkpieceFlowPanel 风格，可选成员工位、互通策略、启用开关）；设置页集成为「工位组互通」Tab。
  - 影响文件: frontend/src/api/channel_group.js, frontend/src/views/Settings/ChannelGroupPanel.vue, frontend/src/views/Settings/index.vue

## 插件变更

- [PLUGIN-001] 福建金龙双工位检测主页插件 v1.1.8 → v1.1.9
  - 变更内容: 仅前端增量——注册 `project.step-cell.durations` 插槽的三档配置单元格组件（读写 `/durations/step-durations`）。后端、双工位布局、权威统计均不变。
  - 重新打包 + 用主签名私钥重签（指纹 d1f2fcb6，与客户机白名单一致），后端验签器走客户机同款环境（内置白名单 + 内置 HMAC 密钥）验证 5/5 全通过。
  - ⚠️ 插件**不随安装包内置**（`extraResources` 不含 `.tjvplugin`），客户装完 v3.16.0 主程序后需在界面单独上传 v1.1.9 签名包。
