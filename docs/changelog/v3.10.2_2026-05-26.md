# v3.10.2 (2026-05-26)

> **紧急修复版**：v3.10.1 / v3.10.0 / 之前所有版本存在 **machineId 多机撞 ID 漏洞**（已确认现场出现 7-8 台机器同 ID）。本版重做硬件指纹采集逻辑，**不影响老客户在用机器的 license**，但新装机会拿到唯一 ID。

## Bug 修复

### [BUG-001] machineId 多台机器撞 ID

- **症状**：现场 7-8 台不同的工控机生成同一个 machineId（例 `TJ-F64AF21C6DBB`），license 失去机器绑定意义，一份 license 在多台机上都能激活。
- **根因**：`electron/license-manager.js: getStableFingerprint()` 三个指纹源全部不可靠：
  1. `wmic baseboard get product` 取**主板型号**（不是序列号），同型号工控机批量出货时值完全一样（例如全是 `B660M-DS3H`）
  2. `wmic csproduct get uuid` 工控机厂家批量烧 BIOS 时常常忘刷 UUID（全 0 / 全 F / 模板 UUID 是已知问题），同一批机器同一个值
  3. `os.cpus()[0].model` 是 CPU 型号字符串，同款 CPU 必定一样
  - **更糟**：Win11 24H2 起 Microsoft 默认移除 `wmic`，新机器上前两个调用都失败返回空，**最后只剩 CPU 型号一个来源**，同款 CPU 必撞 ID。
  - `execSafe` 失败兜底返回 `''`，`parts.filter(Boolean).join('|')` 把空值过滤掉，**没有任何报错日志**，所以一直没人发现。

- **修复**：重写 `getStableFingerprint()`：
  - **5 个强标识源** + 2 个弱标识源
  - **优先 PowerShell `Get-CimInstance`**（不依赖 wmic，速度也更快），Win10 / Win11 早期版本继续用 wmic 兜底
  - 黑名单过滤 `"To be filled by O.E.M."` / 全 0 UUID / 全 F UUID / `"Default string"` 等工控机厂家常见占位值
  - **强度守门**：强标识源 = 0 时打 ERROR log + 不写缓存 + machineId 标记为 `weak`
  - **老机器零影响**：`machine_id.txt` 缓存还在的话**直接读旧 ID**，不重算，老 license 继续有效

| 来源 | 类别 | 真唯一? | 备注 |
|---|---|---|---|
| 主板序列号 (`Win32_BaseBoard.SerialNumber`) | 强 | 是 | 厂家刷了才有 |
| BIOS UUID (`Win32_ComputerSystemProduct.UUID`) | 强 | 是 | 厂家刷了才有 |
| BIOS 序列号 (`Win32_BIOS.SerialNumber`) | 强 | 是 | 厂家刷了才有 |
| 系统盘序列号 (`Win32_DiskDrive.SerialNumber`) | 强 | **是（最稳）** | 出厂烧的，换硬盘会变 |
| 第一块物理网卡 MAC | 强 | 是 | 每张网卡唯一 |
| 主板型号 | 弱 | 否 | 仅作弱标识，**不计入强标识源数** |
| CPU 型号 | 弱 | 否 | 仅作弱标识，**不计入强标识源数** |

- **影响文件**：
  - `electron/license-manager.js`（核心修复 + 新增 `getMachineIdReport()`）
  - `electron/main.js`（新增 IPC `get-machine-id-report`）
  - `electron/preload.js`（暴露 `getMachineIdReport`）

## 新功能

### [FEAT-001] 现场 machineId 诊断脚本

- **背景**：客户报"license 不对 / 机器码重复" 时缺工具远程看现场到底拿到哪些硬件源
- **实现**：新增 `electron/scripts/diagnose-machine-id.js` + `.bat`
  - 客户机现场双击 `.bat` 即可跑（自动找 Electron 自带 node.exe 或系统 node）
  - 输出每个硬件源的实际返回值 + 哪些被黑名单拒收 + 最终 machineId + 强标识源数量
  - 自动写一份 `machineid-report-<hostname>-<时间戳>.txt` 方便发邮件
- **影响文件**：`electron/scripts/diagnose-machine-id.js`、`electron/scripts/diagnose-machine-id.bat`

### [FEAT-002] machineId 指纹诊断 IPC

- 新 IPC `get-machine-id-report` → 前端可读 `electronAPI.getMachineIdReport()` 拿到详细指纹采集报告
- 后续可在"关于"/"设置"页加诊断面板，省去现场跑 .bat 的步骤
- **影响文件**：`electron/main.js`、`electron/preload.js`

## 现场处置指引（**给客户支持工程师**）

### 老机器（已激活的客户机）
- **完全不需要操作**：升级到 v3.10.2 后 `machine_id.txt` 缓存还在，沿用老 ID，老 license 继续有效。

### 现场已撞 ID 的 7-8 台机器（需要重发 license）
1. 远程让客户**关闭天军软件**
2. 删除 3 个文件：
   - `%APPDATA%\tianjun-ai-vision\machine_id.txt`
   - `%APPDATA%\tianjun-ai-vision\hw_verify.txt`
   - `%APPDATA%\tianjun-ai-vision\license.lic`
3. 重新打开天军软件，会显示"未授权"+ 新 machineId
4. 客户把新 machineId 报回来，用 `generate_license.py` 重发 license

### 新装机
- 安装包带 v3.10.2 后自动用新算法，强标识源 ≥ 1 即可生成稳定唯一 ID。

### 工控机厂家没刷任何 BIOS 字段（极端情况，强标识源 = 0）
- 软件日志会打 `[License] !!!! NO STRONG HARDWARE IDENTIFIER AVAILABLE !!!!`
- `diagnose-machine-id.bat` 会显示"严重警告: 没有任何强标识源!"
- 处理建议：
  1. 联系工控机厂家在 BIOS 写入真实序列号（首选）
  2. 升级到含 TPM 2.0 的硬件
  3. 在 license 里用客户名 + 工位号双重绑定（业务层兜底）
