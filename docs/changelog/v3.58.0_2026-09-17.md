# v3.58.0 (2026-09-17)

> 合并发版：dev-qing 两批次（多显示器工位检测屏跟皮拆参观屏 + 纯自定义条件互斥与空闲超时中断）+ 主线两功能（录像检测框 sidecar 与带框版归档投递 + 头姿全角度模型开关）。新功能全部默认关或零配置差异；**移除 v3.57.0 的参观屏/独立观看槽**（已确认产品决策，旧 visitor 配置字段读取忽略零迁移）。

## 功能变更

- [FEAT-001] 多显示器：工位检测屏跟随总控界面皮 + 拆除参观屏（dev-qing）
  - 需求: 工位检测屏要和总控一致的界面与插件皮（自定义布局同步生效），v3.57.0 的参观屏/独立观看槽确认下线
  - 实现: 总控 layout.body 自定义布局同步到工位 kiosk/station_view 窗口（layoutBodyDisplayRole main/station 双角色）；工位窗沿用主屏导航，只读统一由 multi_monitor.readonly 控制，新增 `readonlyActions.protectMonitorActions` 统一防护写通路（开始/停止/待机/清零/布局编辑）；工位窗 selectedChannel 锁定绑定工位，插件 emit/异步初始化不再能把工位屏切到别的通道；参观屏配置、开窗与 viewer 槽全部删除，旧 visitor 字段读取忽略；channel_manager multi-monitor 配置规范化重构（bounds 归一提为静态方法 + response_model_exclude_unset）；Electron 新增 352 行 vm 沙箱生命周期测试（真跑 main.js：License 守门/三出口退出清理/崩溃熔断/webRequest 工位流隔离），共 37 项
  - 影响文件: electron/main.js, electron/multi-monitor.js, electron/test/main-station-lifecycle.test.js, backend/api/channel_manager.py, frontend/src/views/Monitor/index.vue, frontend/src/views/Monitor/readonlyActions.js, frontend/src/layout/index.vue, frontend/src/layout/Navbar.vue, frontend/src/layout/BottomBar.vue, frontend/src/router/index.js, frontend/src/composables/useDisplayWindow.js, frontend/src/views/Source/MultiMonitorPanel.vue

- [FEAT-002] 纯自定义条件互斥与空闲超时中断（dev-qing）
  - 需求: 纯 custom 模式（custom_based_on 非 sequential/detection）多条件分支并存时，同帧多分支同时推进互相污染；周期开了没下文会永久挂起无出口
  - 实现: 同帧只推进一条条件分支（先完整条件、再按条件顺序优先，无事件的条件不参与同帧竞争）；结算后标签锁存（`_pure_custom_settle_latched_labels`）直到真实离场才能再开新周期，防结算余像立刻误开下一周期；非前缀标签不能开空周期；空闲超时 idle_timeout_seconds>0 时新增可配置中断事件 `idle_timeout_event_id`（未配置回退事件 2，配置的事件不存在归一化回退，中断事件不可用时保持周期不误杀）；完整条件命中仍走原条件结算事件不受中断事件影响；跨周期同现组不能绕过分支前缀守门；based-on sequential/detection 的 custom 保持原行为零差异
  - 配置面: pipeline_config 新键 `idle_timeout_event_id`（仅纯 custom + 超时>0 生效）；LogicConfigTab「超时结算」卡对 custom 模式露出「超时中断事件」下拉
  - 影响文件: backend/api/source_settlement_mixin.py, backend/api/source_step_stats_mixin.py, backend/api/source_project_config_apply.py, backend/api/source_events_check_mixin.py, backend/api/source_state_init.py, backend/api/source.py, backend/api/source_sequence_labels.py, frontend/src/views/Project/LogicConfigTab.vue, frontend/src/views/Project/index.vue

- [FEAT-003] 录像检测框 sidecar 与带框版归档投递
  - 需求: 回放周期录像要能看到当时的检测框；归档到远端的录像希望直接是带框版本便于人工复核——但录像本体必须保持无框原始画面（证据纯净性）
  - 实现: `data_export_settings.record_boxes_data`（默认关）开启后周期录像旁成对写 `<视频名>.boxes.json` sidecar——**帧号对齐**（录制线程写帧成功那一刻的 _frame_count，天然免疫录制队列丢帧导致的时间漂移），run-length 压缩只记检测变化帧，MAX_ENTRIES 20000 护栏，采集线程入队时同拍快照框数据、录制线程单线程写无锁；sidecar 与录像同目录同生命周期（孤儿清理/归档/回放按命名约定找，不加 DB 列）；回放端 `GET /data/videos/{id}/boxes` + VideoPlayerDialog canvas 按帧叠加显示（可开关）；`video_archive_rules.annotated_video`（默认关）归档 worker 烧框渲染 MP4 后投递（渲染失败降级投原片照常归档）；`GET /data/videos/{id}/annotated` 手动下载带框版；迁移 m0012 两列
  - 影响文件: backend/services/detection_boxes_sidecar.py(新), backend/services/annotated_video.py(新), backend/db/migrations/m0012_video_boxes_sidecar.py(新), backend/api/sessions.py, backend/api/source_recording_api_mixin.py, backend/api/source_recording_thread_mixin.py, backend/api/source_session_lifecycle_mixin.py, backend/api/source_state_init.py, backend/api/video_archive.py, backend/models/models.py, backend/models/archive_models.py, backend/services/video_archive.py, frontend/src/api/data.js, frontend/src/views/Data/components/DataSettingsTabs.vue, frontend/src/views/Data/components/VideoArchiveDialog.vue, frontend/src/views/Data/components/VideoPlayerDialog.vue, frontend/src/views/Data/index.vue

- [FEAT-004] 朝向估计头姿全角度模型开关（六和蒸镀现场）
  - 需求: 六和点检常态是背对相机看仪表，正脸头姿模型对背面输出无意义反而把朝向带偏
  - 实现: `/orientation` 新增 GET/PUT `/config`（headpose_full_range，SystemConfig KV 落库 + 推理侧缓存即时刷新，PUT 挂 settings.edit）；默认 False=正脸模型，背对相机跳过头姿精化、用关键点几何身体朝向；绑 6DRepNet360/WHENet 等全角度权重时置 True 背面同样精化；模型仓库试一试抽屉加开关；附六和「排查指引_检测不到人」「整改指引_改区域驻留」PDF 两份
  - 影响文件: backend/api/orientation.py, backend/services/person_orientation.py, frontend/src/api/aitools.js, frontend/src/views/Model/CapabilityTryDrawer.vue, docs/customers/六和蒸镀点检/
