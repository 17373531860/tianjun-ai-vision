# v3.60.2 (2026-09-21)

> 主题：**六和双工位整改合并发版**——工位二（锁付）：混合逐件「开始判定」开账闸门 + 停用配对行三连修复（标签豁免/阈值回填/摆件脉冲/检测框显示）；工位一（芯子装配）：多码采集「随视觉周期结算」（收编 v3.60.1a/b/c 三个现场热补丁）。随版收编 Linux arm64 deb 打包跑道。新功能全部默认关或零配置差异。

## 功能变更

- [FEAT-001] 混合逐件「开始判定」开账闸门（默认全关，零配置差异）
  - 需求: 六和二工位摆螺丝阶段模型误报"已完成"把逐件账本假盖章灌满致假 OK、手挡半盘时锁进幽灵位置；中捷时代独立逐件有"稳定窗口才开周期"语义，混合模式一直缺位（周期主权归步骤侧，引擎从周期第 1 帧就开始锁账）
  - 实现: `_PerItemMixEngine` 新增点火闸门——判定通过前不锁定目标、不记覆盖、不产活动脉冲，通过后本周期内闩锁，随周期复位。两个条件可单选可叠加：①**稳定窗口**（`start_by_stability`）：固定数量行位置检出数连续 N 帧达开周期门槛（复用独立逐件 `stability_window_frames/ratio/tolerance` 同名同义同默认）；②**开始标签**（`start_labels`）：逐标签独立确认（连续 `start_sustain_frames` 帧、置信度 ≥ `start_conf`）、到位过即闩锁不要求同帧齐，全部到位过才通过，支持手输区域拆分虚拟标签（如 就位-左上 四角）。开始标签由闸门独占消费不进步骤序列（与 v3.59 容器标签剥离同构），runner `_get_enabled_labels` 豁免放行。未通过被超时结算时 NG 原因明示「逐件未开始(等待: …)」；`get_state` 透出 `start_gate`（未配置不加键），监控页逐件面板亮「等待开始（缺 …）/已开始」徽标。前端步骤设置配对卡新增「开始判定」区块，两项都不勾时保存 `per_item: {}` 与历史逐字节一致
  - 现场回放证据: 六和二工位真实检测日志（2571 帧）——门关时 t=0 起摆件中途逐颗脏锁账；稳定窗口在 t=32.1s（32 颗位置摆齐瞬间）放行后从干净整板帧一次锁定；「工件就位」标签 t=32.9s 闩锁放行；最终覆盖不劣化。用哪种条件由现场工程师按工况自选（模型未重训→稳定窗口；重训带就位标签→可换/叠加开始标签）
  - 影响文件: backend/api/source_custom_mix.py, backend/api/source.py, frontend/src/views/Project/StepsConfigTab.vue, frontend/src/views/Project/index.vue, frontend/src/views/Monitor/PerItemPanel.vue

- [FEAT-002] 多码采集「随视觉周期结算」`settle_on_vision_cycle`（默认关；收编 v3.60.1a/b/c 现场热补丁）
  - 需求: 六和芯子装配工位一——现场"先扫码后做视觉末步"（先扫工装码再盖模具盖板），少扫时视觉末步照样报 OK、扫码组挂着不翻篇、下一件母排码被旧组以「超出应扫数量（挂起处理中）」拒收（一件两账）
  - 实现: 视觉末步结算瞬间对本件扫码组一刀切——码够本周期 OK、不够直接 NG（缺码类别并入周期 reason），组无条件收口翻篇；closing/all_filled/timeout/ng_pending 挂起全部让位不再自行结算。收口唯一路径在视觉结算点后台线程 `_close_scan_group_async`（**拆除** `_handle_cycle_end` 钩子关组——现场开「须先扫码才开始周期」时周期行不建、钩子不触发，且无锚会误收下一件刚开的组）。组归属锚 = 本周期末步首次出现时间，开于锚点之后的组不碰（治上一件消失确认空档里下一件已开扫的竞态）；视觉周期收口跳过 vision_gate（`_vision_last` 还是上一件）。探针零阻塞纯内存（try-lock + 缓存不碰 DB）。码齐的组同样随周期收口（探针只报缺码不是收口条件）
  - 影响文件: backend/services/scan_collect.py, backend/api/scan_collect.py, backend/api/source_settlement_mixin.py, backend/services/mes_hooks.py, frontend/src/views/MES/ScanCollectConfigCard.vue

## Bug 修复

- [BUG-001] 混合逐件配对标签的步骤行停用时检测被 runner 丢弃，覆盖记账永远 0/N（主线化 v3.60.0a 热补丁）
  - 症状: 现场把「螺丝锁付-已完成」单开一行并停用（避免刷步骤序列噪音）后，逐件覆盖全程 0/32、虚拟步骤永不注入
  - 根因: `_get_enabled_labels` 只收启用步骤行的标签，配对引擎的数据源（item_label/action_label）被 runner 出口直接过滤
  - 修复: 配对个体/动作标签与"步骤行启用与否"解耦，一律豁免放行（与容器标签豁免同构）；开始标签同样豁免
  - 影响文件: backend/api/source.py

- [BUG-002] 停用配对行的置信度阈值随停用一起消失，弱误报直灌覆盖记账（主线化 v3.60.0b 热补丁）
  - 症状: BUG-001 豁免放行后，停用行自己配置的阈值不再生效，置信度守门退化到模型 0.25 下限——摆件期弱误报"已完成"填满账本致假 OK
  - 根因: `_apply_steps_config` 只收启用行的阈值进 `step_conf_thresholds`
  - 修复: `apply_project_config` 末尾对混合逐件 watch_labels 内的停用行回填其显式配置阈值，引擎/画框同一份守门
  - 影响文件: backend/api/source_project_config_apply.py

- [BUG-003] 混合逐件摆件阶段被步骤侧空闲超时误判 NG（主线化 v3.60.0b 热补丁）
  - 症状: 扫码后摆 32 颗螺丝耗时超过空闲超时，覆盖零推进被判"空闲"强杀周期报 NG
  - 根因: 活动脉冲只认覆盖数推进（v3.57 口径），账面个体数推进（摆件入账）不算活动
  - 修复: `_PerItemMixEngine.feed` 增加摆件脉冲——账面个体总数向前推进同样刷新 `last_progress_time`（只认推进，回落只降基线）
  - 影响文件: backend/api/source_custom_mix.py

- [BUG-004] 监控页不画停用配对行的检测框，现场看不到"螺丝已锁付"上屏（主线化 v3.60.0c 热补丁的前端正解版）
  - 症状: 覆盖计数在涨但画面上没有对应检测框，现场无法确认模型在工作
  - 根因: 前端 overlay `enabledLabels` 只收 `s.enabled !== false` 的步骤标签，停用配对行的标签被过滤不画
  - 修复: 新增 `overlayDrawLabels.js`（`collectOverlayDrawLabels`）——配对 item/action 标签无论步骤行启停一律纳入绘制集，`useOverlayDrawing.js` 改用该口径（热补丁包用的 MJPEG 烧框是过渡方案，主线走前端绘制零流量开销）
  - 影响文件: frontend/src/views/Monitor/composables/useOverlayDrawing.js, frontend/src/views/Monitor/overlayDrawLabels.js
