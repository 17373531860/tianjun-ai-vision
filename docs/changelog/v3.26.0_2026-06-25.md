# v3.26.0 (2026-06-25)

> 主题：**主程序原生「外部生产管控系统入站对接」能力 + 后端控制台日志全面 ASCII 化（根治 Windows 控制台中文乱码）**。
> 入站对接让外部 MES/生产管控系统能主动 POST 开工/完工任务进来（配置驱动响应、JSON/XML 双格式、可选来源校验，默认无鉴权走工控内网 M2M），与既有「主动拉取」(v3.20.0 mes_puller) 形成入站/出站完整闭环。同时把后端各模块的中文 print 日志统一改成 ASCII 英文 + 启动强制切 UTF-8 终端，彻底解决手动 cmd / 日志重定向场景下的 GBK 乱码（延续 v3.15.2 控制台编码治理）。

## 功能变更

- [FEAT-001] 外部生产管控系统「入站对接」REST API（主程序原生）
  - 需求: 部分客户的 MES/生产管控系统是「主动推」模型——它来调我们的接口下发开工/完工任务，而不是我们去拉。这是面向所有客户的基础设施，归主程序原生。
  - 实现: 新增 `/api/v1/mes/inbound/*` 一组端点——`POST/GET /task`（外部系统推任务，无鉴权 M2M，配置驱动响应体）、`GET/PUT /config`（前端读写入站配置）、`GET /logs`（最近入站通讯日志）。响应格式按 `response.format` 组装 JSON 或 XML（可配 xml_root / xml_declaration）；来源校验支持共享密钥头 + IP 白名单（默认全关）；落 `MESCommLog` 通讯日志（复用既有表，无新表/无 schema 迁移）。前端新增「入站对接」管理面板 `OrderInboundPanel.vue` 挂进 MES 视图。
  - 影响文件: backend/api/mes_inbound.py（新）, backend/services/mes_inbound.py（新）, backend/main.py（注册路由）, frontend/src/views/MES/OrderInboundPanel.vue（新）, frontend/src/views/MES/index.vue, frontend/src/api/gateway.js

- [HARDEN-001] 后端控制台日志全面 ASCII 化 + 启动强制 UTF-8 终端
  - 需求: 现场手动从 cmd 启动后端 / 日志重定向到文件时，中文 print 在 Windows GBK 控制台上整屏乱码（`澶╁啗...`），定位现场问题困难。Electron 启动路径已 `chcp 65001`，但裸 cmd / 重定向路径没覆盖（延续 v3.15.2 编码治理的兜底）。
  - 实现: (1) `backend/main.py` 启动最早处对 Windows 执行 `chcp 65001` + 对 stdout/stderr `reconfigure(encoding="utf-8")`，作为任意启动路径的底线保障；(2) 把 mes_hooks / scanner / alarm / channel_manager / source 各 mixin / mes_gateway / mes_puller 等模块的 `print()` 日志文案由中文统一改写为 ASCII 英文，避免控制台编码不确定时产生乱码。纯日志文案变更，不改业务逻辑。
  - 影响文件: backend/main.py, backend/services/mes_hooks.py, backend/services/scanner.py, backend/services/mes_gateway.py, backend/services/mes_puller.py, backend/api/alarm.py, backend/api/channel_manager.py, backend/api/source.py, backend/api/source_capture_loop_mixin.py, backend/api/source_event_trigger_mixin.py, backend/api/source_lifecycle_mixin.py, backend/api/source_model_load_mixin.py, backend/api/source_session_lifecycle_mixin.py, backend/api/source_settlement_mixin.py, backend/api/source_streaming_mixin.py, backend/api/projects.py

## Bug 修复

- [BUG-001] 录像按日期分子目录 + 自动清理回收空日期目录
  - 症状: 录像文件全平铺在录像根目录，长跑后目录巨大；自动清理删完当天录像后留下大量空的日期子目录无人回收。
  - 根因: 录像写入未按日期分目录；自动清理只删文件不递归回收空目录。
  - 修复: 录像写入按 `YYYY-MM-DD` 分子目录（`_ensure_dated_dir`）；自动清理递归扫描日期子目录删孤儿文件 + 整天清完后回收空日期目录（`_prune_empty_dated_dirs`），兼容老的平铺录像。
  - 影响文件: backend/api/source_recording_api_mixin.py, backend/api/source_recording_thread_mixin.py, backend/api/sessions_maintenance.py

- [BUG-002] 录像器 DB session 泄漏修复
  - 症状: 长时间运行后数据库连接/会话累积（录像相关写库未及时归还 session）。
  - 根因: 录像线程/接口在写 VideoClip 等记录时 DB session 生命周期管理不严。
  - 修复: 收紧录像相关 DB session 的开闭，停止时统一关闭所有录像器（`[Recording] all recorders closed`）。
  - 影响文件: backend/api/source_recording_thread_mixin.py, backend/api/source_recording_api_mixin.py
