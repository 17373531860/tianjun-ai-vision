# v3.15.1 (2026-05-31)

> 热修 v3.15.0 现场反馈的三个问题（插件装不上 / 启动无动画 / GPU 列表偶发失败），并加 CI 打包资源自检防复发。客户两段现场视频实证。

## Bug 修复

- [BUG-001] 插件安装失败 PLUGIN_MANIFEST_SCHEMA_FAIL（schema 文件未打包）
  - 症状: 客户 Windows 机 v3.15.0 上传 .tjvplugin 插件，后端 500；日志 `FileNotFoundError: plugin.schema.json 不存在: D:\tianjun-ai-vision\resources\docs\plugin-system\plugin.schema.json`
  - 根因: `electron/package.json` 的 backend 打包过滤器只含 `.py/.pyd/.dll` 等扩展名，`docs/` 目录从未在打包清单里；插件清单校验所需的 `plugin.schema.json` + `customer-codes.md` 从未进入安装包
  - 修复: extraResources 新增 `docs/plugin-system → resources/docs/plugin-system` 条目（仅打 schema + customer-codes 两个运行时刚需文件），与代码里 SCHEMA_PATH / CUSTOMER_CODES_PATH 期望的 `resources/docs/plugin-system/` 路径对齐，Python 代码零改动
  - 影响文件: electron/package.json

- [BUG-002] 启动无任何动画（splash.html 未打包，旧版 splash 变透明空窗）
  - 症状: 客户双击启动 v3.15.0，从关机到主界面全程无 splash；空桌面停约 5 秒后主界面突然出现，无任何预加载反馈
  - 根因: `electron/package.json` 的 files 打包白名单只含 `splash/**/*`（手势动画目录）和 `shutdown.html`，漏了根目录的 `splash.html`（旧版简单 loading 动画）；旧版 splash 窗口是 `transparent:true`，loadFile 加载不存在的 splash.html 失败后就是全透明空窗，肉眼完全看不见
  - 修复: files 白名单加入 `splash.html`
  - 影响文件: electron/package.json

- [BUG-003] 启动后偶发"获取GPU列表失败" / CUDA 显示不可用
  - 症状: v3.15.0 进设置页右上角弹"获取GPU列表失败"、CUDA 状态显示不可用（但后端日志显示 GPU 实际加载正常，RTX 3050 / cuda:0）
  - 根因: 后端就绪健康检查只探 `/source/status`（纯对象状态读取，完全不碰 torch），进程一起来就判定就绪并显示主界面；项目未激活时后端启动全程不触碰 GPU，CUDA 上下文一直是冷的；主界面一进来设置页 onMounted 并发打 6+ 个请求，其中 GPU 列表查询首次调 `torch.cuda` 触发 CUDA 上下文冷初始化（本机实测约 5 秒）叠加并发竞争 → 偶发超时失败
  - 修复:
    - 后端：启动时后台线程预热 CUDA，把冷初始化开销移到启动期（splash 期间用户本就在等，无感），幂等（已加载模型则秒返回）+ 异常隔离 + 无 GPU 环境自动跳过
    - 前端：GPU 列表查询在页面自动加载时失败静默重试 2 次（间隔 1.5s）再提示；手动点刷新按钮保持立即提示不变
  - 影响文件: backend/main.py, frontend/src/views/Settings/index.vue

- [BUG-004] 插件安装临时文件清理掩盖真实错误
  - 症状: Windows 文件锁场景下，插件安装收尾删除临时文件抛 `WinError 32`，把真正的 schema 错误掩盖成 500，客户看到的错误信息不准
  - 根因: `install_plugin` 的 finally 中 `tmp_path.unlink` 没有异常保护
  - 修复: unlink 包 try/except，清理失败静默跳过，不掩盖主流程的真实结果
  - 影响文件: backend/api/plugins.py

## 功能变更

- [FEAT-001] CI 打包资源自检（防"新增资源忘加打包白名单"复发）
  - 需求: v3.15.0 连续两个 P0（BUG-001 / BUG-002）同根 —— 新增资源文件忘记加进打包配置（files / extraResources），且开发机无法复现（只在 Windows 打包产物里暴露）
  - 实现: `.github/workflows/build.yml` 在 `electron-builder --dir` 之后、Inno Setup 之前加自检 step：硬验证 `resources/docs/plugin-system/plugin.schema.json` + `customer-codes.md` + `backend/main.py`（extraResources 产物，文件系统直查）以及 `app.asar` 内的 `splash.html` + `splash/index.html` + `main.js`（files，用 asar list 校验），缺任一关键资源红灯阻断发版，残缺安装包不流到客户
  - 影响文件: .github/workflows/build.yml
