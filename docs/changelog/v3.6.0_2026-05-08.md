# v3.6.0 (2026-05-08)

## 功能变更

- [FEAT-360-001] 周期性强制动作（Periodic Actions）能力增强 + 语义修正
  - 需求：客户场景"动作 A→B→C→D 每做完 N 轮要做动作 E"，v3.5.0 只能在 cycle_end 立即触发，
    实测发现 3 个问题：① 重置计数器时把周期性计数器一起清了（不期望）；
    ② 想在"开机首件"也强制触发一次（避免漏检），但只能配 cycle_end；
    ③ 触发的事件只能选 OK/NG，不能用项目自定义事件名。
  - 实现：
    - `pipeline_config.run_on_start` 新开关：开启后，`resume()` / `resume_inference()` 会把
      所有 `run_on_start=true` 的规则的计数器推到 `interval`，并将规则 ID 加入
      `_run_on_start_pending` 集合，**不立即发事件**；
    - 新方法 `_check_periodic_actions_on_first_step(step_label)` 钩入
      `source_step_stats_mixin.py` 步骤完成流程：
      - 第一个完成的 step **是**触发步骤 → 静默清零（合规，无需提醒）
      - 第一个完成的 step **不是**触发步骤 → 立即发提醒事件（漏检告警）
      → 解决"未压墨"等首件抓漏检的真实业务诉求；
    - `reset_stats()` 中**保留** `_periodic_counters` 与 `_run_on_start_pending`，
      操作员清空统计时不会破坏周期性动作进度；
    - `_emit_periodic_notification()` 显式标 `should_warn_no_barcode=False`，
      避免周期性事件被前端误判成"未绑码"toast；
    - 前端 `Project/index.vue`"逻辑设置"卡片加 `run_on_start` `el-switch` +
      事件选择器旁加"+ 新建事件"按钮（直跳事件管理对话框，自定义事件即用即配）。
  - 影响文件：
    - 修改：`backend/api/source.py`, `backend/api/source_lifecycle_mixin.py`,
      `backend/api/source_periodic_actions_mixin.py`, `backend/api/source_step_stats_mixin.py`,
      `frontend/src/views/Project/index.vue`
    - 测试更新：`tests/features/periodic_actions.feature`,
      `tests/step_defs/test_periodic_actions.py`,
      新增 `tests/test_periodic_actions_v352.py`

- [FIX-360-001] 检测框跑出画面边界（偶发幽灵框）三层防御性 clipping
  - 现象：客户实测出现"框跑外面去了"的偶发性 bug——视频画面里检测框被绘制到画面框之外，
    极少数情况下能复现。
  - 根因（多源叠加）：① 后端 YOLO 推理输出的归一化坐标极少数情况轻微 >1.0（浮点误差）；
    ② Kalman 滤波器过预测时 `smoothed_pos` 可能短暂超出 `[0,1]` 区间；
    ③ 前端 Canvas 绘制时缺少最后一道防线，前两层任一漏过就直接画到画面外。
  - 实现（三层防御，任一层都能独立兜底）：
    - **后端推理出口**：新增 `backend/api/source_geometry.py::clip_bbox_normalized(x1,y1,x2,y2,w,h)`
      工具函数，把像素坐标转归一化并强制 clip 到 `[0,1]`；
      `source_detect_runners_mixin.py` 的 `_detect_only / _detect_and_track / _detect_segment`
      三个推理路径全部接入；
    - **后端 Kalman 输出**：`source_drawer.py::apply_kalman_filter` 在卡尔曼更新后
      对 `smoothed_pos` 也做 `[0,1]` clip，避免预测越界；
    - **前端绘制**：`Monitor/index.vue` 新增 `clipNormalizedBox(det)` 助手，
      `drawMultiDetections` / `drawDetections` 在像素坐标计算前再做一次 clip，
      mask polygon 顶点也同样 clip。
  - 影响文件：
    - 修改：`backend/api/source_detect_runners_mixin.py`, `backend/api/source_drawer.py`,
      `backend/api/source_geometry.py`, `frontend/src/views/Monitor/index.vue`

- [FIX-360-002] MES 无扫码器时不再误报"⚠ 未绑码"
  - 现象：用户清空 MES 管理的扫码器列表后，检测中心仍弹"⚠ 未绑码"toast。
  - 根因：前端 toast 触发逻辑没有检查"是否真有扫码器"，且多通道下
    `hasScannerFor(ch - 1)` 存在 0/1-based 索引混淆。
  - 实现（权威决策上提到后端）：
    - `services/mes_hooks.py` 新增 `has_any_scanner_present()`，遍历当前所有 scanner 连接判断；
    - `is_warn_no_barcode()` 中加 early-exit：无任何扫码器（含虚拟）→ 直接 `False`；
    - `source_event_trigger_mixin.py` 在每个 event 写入 `events_log` 时附加
      `should_warn_no_barcode: bool` 字段，前端只消费这个布尔值，不再自己判断。
  - 影响文件：已在 `85c351c` commit 进入 main（v3.5.1 之后），本版本一并发布。

- [FIX-360-003] 海康摄像头 NameError 永久修复
  - 现象：客户端启动时偶发 `NameError: name 'HIK_SDK_AVAILABLE' is not defined` 导致摄像头打不开。
  - 根因：`source_camera_start_mixin.py` 顶部缺失 SDK 与 ctypes 的相关 import，仅在主类作用域可见。
  - 实现：在 mixin 文件顶部补全所有需要的 import（HIK_SDK_AVAILABLE / HCNETSDK / ctypes 类型等）。
  - 影响文件：已在 `df7ce2c` commit 进入 main，本版本一并发布；不再依赖之前下发的临时热补丁。
