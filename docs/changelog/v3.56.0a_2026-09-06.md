# v3.56.0a (2026-09-06) — 热补丁

> 六和焊接组装工位现场反馈：少扫不报警不判定无补救；检测次数比实际产量多、待机扫码也涨数。
> 基础版本 v3.56.0。补丁包 `TianJun-v3.56.0a-补丁`（bat + 后端 3 个 py + 前端 dist + 配置指南 PDF）。

## Bug 修复

- [BUG-001] 少扫组在「数量凑齐即结算」下永远停在采集中：无催扫、无终判、看不到补救按钮
  - 根因: 码序不固定、工装可能中间扫，收尾码没有自然收口点；`idle_remind_sec=0` 且没有人工结算出口。
  - 修复: 催扫提醒（N 秒无新码借 NG 事件 remind_only 催，不计数）+ 面板「本件扫完」(`POST /scan-collect/settle-now`)；挂起分支扩到 manual 触发。
- [BUG-002] 挂起工件被计两次检测次数
  - 根因: 挂起进入时借完整 NG 事件面（总产量+1 / 不良+1），补扫转 OK 再计一次。
  - 修复: 挂起报警改 remind_only；最终结算才完整响一次事件。
- [BUG-004] 视觉+扫码同工位一个工件计两次（视觉周期计一次、扫码结算借同一对事件又计一次）
  - 修复: 新增 `count_on_settle`（默认 True=存量）。关掉后扫码结算走 remind_only 档只借灯/语音/Toast，计数交给视觉周期；纯扫码工位保持计数。配置卡「扫码结算计数」下拉，填入示例预置「不计数（视觉已计）」。
- [BUG-005] 补丁 bat 现场闪退两连（打到 [1/4] 窗口整个消失、pause 兜不住）
  - 根因 1: taskkill 中文进程名以 UTF-8 写出、中文 Windows cmd 按 GBK 解析成乱码；根因 2（真凶）: 工控机安全软件对 cmd 链里 `taskkill /F` 做行为拦截，直接掐死整个 cmd 进程树无报错。
  - 修复: bat 全文件纯 ASCII+CRLF；彻底移除 taskkill/wmic/timeout，关软件改操作员手动确认（pause 守门）+ `ren dist` 失败检查兜底；每步落盘 `patch_log.txt` 留痕。教训已沉淀 create-hotfix skill。
- [BUG-003] 待机扫码仍涨检测次数并落 txt
  - 修复: `standby_silent`（默认关）。通道未检测时结算不发事件、不导出，面板/追溯照常。

## 新功能
