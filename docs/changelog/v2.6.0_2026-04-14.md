# v2.6.0 (2026-04-14)

## 功能新增

- [FEAT-001] 多工位/多通道架构 (1-4 工位)
  - 需求: 客户 SOP 监测场景需要一拖四，包装场景需要三工位两软件协同
  - 实现: ChannelManager 管理 1-4 个 VideoSourceManager 实例，每通道独立视频源、项目、模型、GPU
  - 影响文件: backend/api/channel_manager.py, backend/main.py, frontend/src/views/Source/index.vue, frontend/src/views/Monitor/index.vue

- [FEAT-002] 集群汇总系统 (Master/Slave 多机互联)
  - 需求: 多台机器检测同一箱子不同层，需数据汇总后推送客户 MES
  - 实现: ClusterCollector 服务 + /cluster/report REST API，主机等齐所有工位数据后触发 MES 推送
  - 影响文件: backend/api/cluster.py, backend/services/cluster_collector.py, frontend/src/views/MES/ClusterPanel.vue, frontend/src/api/cluster.js

- [FEAT-003] 外部设备集成框架 (TCP/Modbus TCP/串口/HTTP 轮询)
  - 需求: 第三工位无我们软件，需直接连接称重器等外部设备
  - 实现: 通用外部设备管理，支持 4 种连接协议 + 5 种数据解析模式
  - 影响文件: backend/api/external_device.py, backend/services/external_device.py, frontend/src/views/MES/ExternalDevicePanel.vue, frontend/src/api/external_device.js

- [FEAT-004] MES Gateway 工位绑定
  - 需求: 不同工位推送到不同的 MES 连接
  - 实现: MESConnection 增加 bound_channels 字段，dispatch 按通道过滤连接
  - 影响文件: backend/models/mes_models.py, backend/services/mes_gateway.py, backend/api/mes_gateway.py, frontend/src/views/MES/GatewayPanel.vue

- [FEAT-005] 扫码器广播 (单扫码器触发多通道)
  - 需求: 工位2 一个扫码器服务两个摄像头检测同一箱子
  - 实现: scanner_devices 增加 broadcast_channels 字段，扫码结果分发到多通道
  - 影响文件: backend/api/scanner.py, backend/services/scanner.py, frontend/src/views/MES/ScannerPanel.vue

- [FEAT-006] 多工位通知/报警隔离
  - 需求: 每个工位有独立指示灯、语音、Toast 提示
  - 实现: AlarmRouter 管理多通道报警，每通道独立 Toast 队列和语音播报
  - 影响文件: backend/api/alarm.py, frontend/src/views/Alarm/index.vue, frontend/src/views/Monitor/index.vue

- [FEAT-007] 多工位计数器独立持久化
  - 需求: 每个工位有自己的合格/不良计数，互不影响
  - 实现: 计数器按 project_id + channel_id 保存为独立 JSON 文件
  - 影响文件: backend/api/source.py, backend/counters/

- [FEAT-008] 自动保存/恢复全流程
  - 需求: 重启软件后不用重新配置视频源、项目、GPU、检测状态
  - 实现: workstation_config.json 持久化所有通道配置，启动时自动恢复视频源+项目+模型+GPU+检测状态
  - 影响文件: backend/main.py, backend/api/channel_manager.py, frontend/src/views/Source/index.vue

- [FEAT-009] 每通道独立检测/语音/Toast 设置
  - 需求: 不同工位绑定不同项目，检测设置（语音、Toast）应独立
  - 实现: useSystemStore 增加 channelDetections map，Monitor 页按通道获取检测配置
  - 影响文件: frontend/src/store/useSystemStore.js, frontend/src/views/Monitor/index.vue

## Bug 修复

- [BUG-001] 多工位项目配置被全局覆盖
  - 症状: 4 个工位全显示同一个项目（JC_T1），GPU 工位检测不到任何东西
  - 根因: 前端 startDetectionForChannel 使用全局 currentProject 给所有通道设项目，模型输出的类别名与项目步骤不匹配导致结果全被丢弃
  - 修复: startDetectionForChannel 优先使用 multiChannelData[ch].project（通道绑定项目），syncProjectConfig 增加 explicitProject 参数
  - 影响文件: frontend/src/views/Monitor/index.vue

- [BUG-002] workstation_config channel_count 被热重载覆盖为 1
  - 症状: 配好 4 工位后只显示 1 个工位，其他三个黑屏
  - 根因: ChannelManager 初始化 channel_count=1，_save_config 未保留文件中已有的 count；前端 Source 页在非开发者模式下强制重置为 1
  - 修复: _save_config 和 save_channel_source 用 max(file_count, self.channel_count)；移除前端自动重置逻辑
  - 影响文件: backend/api/channel_manager.py, frontend/src/views/Source/index.vue

- [BUG-003] MJPEG 四通道视频卡顿
  - 症状: 4 工位视频暂停一下开始一下，看着一卡一卡的
  - 根因: generate_mjpeg 在 frame_limit_enabled=False 时无 sleep，4 个线程争抢 CPU；screenshot 每帧每目标都做 imencode
  - 修复: 添加 min_interval sleep（自适应通道数）；screenshot 限频每秒 1 次
  - 影响文件: backend/api/source.py

- [BUG-004] TensorRT 引擎 imgsz 不匹配导致推理静默失败
  - 症状: 模型加载成功但检测结果为 0，AssertionError 被吞掉
  - 根因: TRT 引擎编译为 1024x1024，代码用 640x640 输入，AssertionError 未被正确处理
  - 修复: 增强 load_model TRT 检测逻辑（4 种方式探测 imgsz）；warm-up 捕获 AssertionError 自动修正
  - 影响文件: backend/api/source.py

- [BUG-005] 跟踪模式步骤截图不显示（cv2 未导入）
  - 症状: 跟踪模式下工作流卡片没有检测图片，但画面有检测框
  - 根因: _update_tracking_stats 中 cv2 条件导入导致 UnboundLocalError
  - 修复: 在截图代码块开头显式 import cv2
  - 影响文件: backend/api/source.py

- [BUG-006] 视频文件源不自动恢复
  - 症状: 重启后 video 类型源不恢复，只有 camera/rtsp/hcnetsdk 能恢复
  - 根因: auto_restore_video_sources 缺少 video 类型处理分支
  - 修复: 增加 elif src_type == "video" 分支，调用 mgr.start_video(vf)
  - 影响文件: backend/main.py, frontend/src/views/Source/index.vue

- [BUG-007] 推理连续报错导致 CPU 100%
  - 症状: 模型推理失败时错误日志刷屏，CPU 占满
  - 根因: _detect_only/_detect_and_track 异常后无延迟直接重试
  - 修复: 增加 _consecutive_detect_errors 计数，超过 3 次后 sleep(0.5) + 抑制日志
  - 影响文件: backend/api/source.py

- [BUG-008] 报警串口不自动重连
  - 症状: 重启软件后报警指示灯不亮，需手动重新连接
  - 根因: AlarmRouter._load_all 只加载配置不连接
  - 修复: 加载时检查 enabled + port 自动尝试连接
  - 影响文件: backend/api/alarm.py
