# v3.52.0 (2026-08-18)

> 多显示器一期（dev-qing 分支合入）：工位子窗映射与单通道监控页——Electron 按显示器映射为每个工位开独立 kiosk 子窗，主屏保留总览与操作权，副屏一期只读。默认关闭零配置差异。合并审计发现并修复分支引入的网格总览"整卡点击放大"行为回归（v3.47 存量行为守住）。

## 功能变更

- [FEAT-001] 多显示器一期——工位子窗映射与单通道监控页
  - 需求: 多工位现场希望每个工位有自己的专属显示屏实时监看，主控屏保留总览与全部操作入口
  - 实现: ① Electron 新增 `multi-monitor.js`（配置规范化/显示器解析/主窗 sender 授权/崩溃 60 秒窗口 3 次熔断），`main.js` 按 `display_id`+bounds 在指定显示器开无边框 kiosk 子窗（License 未过不开窗、主窗所在显示器保留不占用、同一显示区域去重、关机三出口统一销毁子窗）；② 后端 `channel_manager.py` 新增 `multi_monitor` 顶层配置段（GET/PUT `/api/v1/workstations/multi-monitor`，PUT 挂 `settings.edit` 权限，规范化丢弃越界工位/非法 bounds）；③ 前端新增 `SingleChannelMonitor` 共用单工位组件（主屏放大态与副屏 kiosk 共用；kiosk 隐藏导航/Toast/人工确认/插件覆盖等全部写通路，只轮询绑定工位）、设置页新增"多屏工位显示（一期）"配置卡（显示器枚举/映射/只读开关/保存并应用热生效）；④ 多屏开启时主屏总览自动改快照轮询为副屏让出 MJPEG 长连接，放大态只拉目标工位一路；⑤ kiosk 子窗路由不读写主窗的路由记忆（`isMultiMonitorRoute` 守门）
  - 默认: `enabled=false`、`readonly=true`，不开启则行为与 v3.51.5 字节级一致
  - 影响文件: electron/multi-monitor.js(新), electron/main.js, electron/preload.js, electron/package.json, backend/api/channel_manager.py, frontend/src/views/Monitor/SingleChannelMonitor.vue(新), frontend/src/views/Monitor/index.vue, frontend/src/views/Settings/index.vue, frontend/src/layout/index.vue, frontend/src/router/index.js, frontend/src/api/detection.js

- [FEAT-002] 良品/不良饼图与合格率仪表盘抽为共用组件
  - 需求: 单工位监控与多屏单通道页需要同一套统计图，消除 Monitor 内联 ECharts 双份维护
  - 实现: 抽出 `GoodBadPieChart` / `YieldRateGauge` 组件（props 驱动，替代原 initCharts/updateCharts 内联 ECharts 与 2 秒节流器），单工位主页与 SingleChannelMonitor 共用
  - 影响文件: frontend/src/views/Monitor/GoodBadPieChart.vue(新), frontend/src/views/Monitor/YieldRateGauge.vue(新), frontend/src/views/Monitor/index.vue

## Bug 修复

- [BUG-001] 网格总览整卡点击放大在多屏关闭时被误改为仅选中（合并审计发现，未流出）
  - 症状: dev-qing 分支原实现里，多屏关闭时 4+ 工位网格总览点击卡片只高亮选中、不再进入放大详情，v3.47 交付的"点击卡片放大单路"入口消失（"放大"按钮仅多屏开启时渲染）
  - 根因: 分支把 2/3 工位的"点击=选中"语义误推广到网格总览，违反"新功能默认关必须零差异"铁律；v3.47 回归测试 `test_grid_overview_pagination_and_zoom` 合并后立即变红暴露
  - 修复: 网格整卡点击恢复恒为 `zoomChannel`（多屏开关不改变此行为），总览提示文案恢复"点击卡片放大单路"；新 e2e `test_disabled_workstations_keep_legacy_selection` 的 4 工位分支改为断言点击进入放大（与 v3.47 回归测试双向守门）
  - 影响文件: frontend/src/views/Monitor/index.vue, tests/e2e_browser/test_multi_monitor_phase1.py, tests/e2e_browser/test_multi_workstation_layout.py

- [BUG-002] `_save_config` 整写 workstation_config.json 抹掉其他顶层段（存量隐患，随分支收编）
  - 症状: 修改工位数时 `workstation_config.json` 被整写为仅 `channel_count`+`channels`，`startup_ready_gate` 等其他顶层段被静默抹掉（多屏 `multi_monitor` 段落地前踩到）
  - 根因: `ChannelManager._save_config` 用新字典整写文件而非 merge 保留既有顶层键，违反不变量 17"各段写入权独占"
  - 修复: 改为读旧文件 merge 更新 `channel_count`/`channels` 两键，其余顶层段原样保留；`set_multi_monitor_config` 同样只替换 `multi_monitor` 段
  - 影响文件: backend/api/channel_manager.py

- [BUG-003] start 接口 HTTP 迟迟不返回时前端操作锁死死等（随分支收编）
  - 症状: 现场网络/壳层异常时点"开始"后后端实际已启动检测，但 HTTP promise 未返回，前端 `isOperating` 锁不释放、按钮一直转圈
  - 根因: 启动达成态只依赖 start API 的 HTTP 响应回来才落，轮询循环不认"后端已 detecting"这个真相
  - 修复: 单工位轮询里加启动达成判定——仅"正处于操作 + 前端未 detecting + 后端 `is_detecting=true`"三条件齐时释放操作锁并对齐运行态（stop/standby 操作因前端 detecting=true 不会误触发）
  - 影响文件: frontend/src/views/Monitor/index.vue

## 已知问题

- 真实多显示器钉屏（display_id 解析/热插拔/DisplayLink 坞）只能在 Windows 多屏现场验收，本版验证覆盖到窗口编排与降级逻辑（Mac + 假 display_id/bounds）
- 主屏放大某工位会抢走该工位副屏的 MJPEG 连接（后端每通道单连接），副屏靠 v3.48.1 零帧检测降级快照模式，主屏退出放大后副屏升回时机待现场确认
- kiosk 子窗不挂 USB 扫码枪键盘监听：现场若焦点落在副屏，扫码输入会丢失——部署时需交代"扫码时主屏持焦"，热键/焦点策略属二期
