# v3.24.0 (2026-06-24)

> 主题：**自动清理可感知 + 长稳健性整治**。围绕客户实锤的"自动清理磁盘没变小 / 只有重启才清 / 保留期外仍有旧数据"问题，连同一轮性能稳定性审计（后端累积、视频/推理/GPU、前端长跑泄漏）做零风险/低风险/中风险分批整治，每项红绿单测，全量回归零回归。

## Bug 修复 — A 组（自动清理，客户实锤）

- [BUG-A1] 自动清理只在重启时触发 / 不知道几点清
  - 症状：客户设了"自动删除 1 天"，但磁盘容量不变、保留期外仍有旧日期数据，且只有重启软件后才清一次。
  - 根因：清理只在启动迁移后跑一次，无定时调度。
  - 修复：新增固定时间每日调度（`cleanup_daily_time`，默认凌晨），启动时算出下一次触发并用定时器调度；并发加锁，避免与手动清理 / 启动清理叠跑。
  - 影响文件：backend/api/sessions_maintenance.py, backend/main.py

- [BUG-A2] 删了数据但 DB 文件不缩小
  - 症状：清理后 `sql_app.db` 文件大小不降。
  - 根因：SQLite 删行后页不归还磁盘；WAL 模式下主库文件不截断。
  - 修复：新增手动"数据库收缩"端点（VACUUM，带锁），VACUUM 前后各做一次 WAL checkpoint(TRUNCATE) 确保主库文件实际缩小。
  - 影响文件：backend/api/sessions_maintenance.py

- [BUG-A3] WAL 文件持续增大
  - 修复：每次自动清理后做 WAL checkpoint，回收 WAL 空间。
  - 影响文件：backend/api/sessions_maintenance.py

- [BUG-A4] 过程日志表无人清
  - 修复：清理纳入扫码日志 / MES 通信日志 / 外设日志三类过程日志（按保留期）。
  - 影响文件：backend/api/sessions_maintenance.py

- [BUG-A5] 导出文件清理可能误删 / 客户改了导出路径就清不到
  - 修复：三层兜底——① 优先按导出运行台账（ExportRunLog）精确清理已知文件；② 支持在数据中心集中登记导出目录，按登记目录清理；③ 黑名单守护的兜底扫描（仅清白名单扩展名的导出产物，绝不碰系统目录）。
  - 影响文件：backend/api/sessions_maintenance.py

- [BUG-A7] 清理无任何可见反馈
  - 症状：客户看不到清理是否执行、释放了多少空间。
  - 修复：记录并暴露上次清理时间 / 各项删除计数 / 释放字节数（`GET /api/v1/data/cleanup/status`）。
  - 影响文件：backend/api/sessions_maintenance.py

## Bug 修复 — B 组（后端累积/阻塞）

- [BUG-B1] MES 回传队列满会阻塞结算线程
  - 根因：关键任务入队用阻塞 `put(timeout)`，外部 MES 慢时反压到结算线程。
  - 修复（第一步）：关键任务改为"立即落盘补偿或丢弃"非阻塞入队，结算线程永不被队列卡住。
  - 影响文件：backend/services/mes_hooks.py
  - 备注：第二步（外部推送/导出并发化）涉及改变推往客户外部 MES 的时序，暂缓待现场真实 MES 验证。

- [BUG-B2] 称重"稳定中"状态日志刷屏
  - 修复：仅对"稳定中"过渡态日志按 ~1/秒节流；"已稳定"态保持不节流（v2.7.9 既定行为，供前端观测）。
  - 影响文件：backend/services/external_device_pipeline.py

- [BUG-B4] 报警定时器可叠加未取消
  - 修复：单路熄灯 / 共享过期定时器在重设前先取消旧的；`stop_alarm` 取消所有挂起定时器。
  - 影响文件：backend/api/alarm.py

- [BUG-B5] 待绑码队列无上限
  - 修复：待绑码队列加上限（500）+ FIFO 淘汰。
  - 影响文件：backend/services/mes_hooks.py

- [BUG-B7] 模型转换队列无上限
  - 修复：转换队列加上限（20）+ 入队前容量校验。
  - 影响文件：backend/api/models.py

- [BUG-B8] 过期登录 token 不清理
  - 修复：每小时 + 启动时清理过期 token（内存池 + 磁盘），不动不过期 token。
  - 影响文件：backend/core/auth.py, backend/main.py

## Bug 修复 — C 组（视频/推理/GPU 稳健性）

- [BUG-C1] 推理超时只在连续超时上限才重建池
  - 修复：抽出统一超时处理，每次超时即重建推理池；连续超时升级到 GPU 紧急重置。
  - 影响文件：backend/api/source_detect_runners_mixin.py

- [BUG-C2] GPU 紧急重置后未重载模型
  - 修复：紧急重置后补一次模型重载，避免重置后推理空转。
  - 影响文件：backend/api/source.py

- [BUG-C3] 推理线程假死无告警
  - 修复：推理线程 join 超时加计数 + 结构化告警埋点。
  - 影响文件：backend/api/source.py, backend/api/source_inference_loop_mixin.py, backend/api/source_capture_loop_mixin.py, backend/core/debug_center.py

- [BUG-C6] 周期录像延迟释放可叠多个 FFmpeg 子进程
  - 修复：并发延迟释放计数 + 超阈值告警（监控版）。
  - 影响文件：backend/api/source_recording_api_mixin.py

- [BUG-C7] 跟踪字典 / 堆叠列表无界增长
  - 修复：track 过期时同步清理跟踪字典；堆叠列表每周期容量限制。
  - 影响文件：backend/api/source_tracking_mixin.py

- [BUG-C8] NVR 停止预览与原生回调竞态
  - 修复：HCNetSDK 包装加 `_alive` 标志，停止预览即置 False，实时数据 / 解码回调进入即检查并提前返回，避免回调访问已释放资源。
  - 影响文件：backend/hcnetsdk/wrapper.py

## Bug 修复 — D 组（前端长跑）

- [BUG-D2] 双工位启动竞态导致画面冻结
  - 症状：双工位机器上偶发画面冻在第一帧。
  - 根因：`onMounted` 中工位数查询与设备状态查询并发；后者在工位数还是默认 1 时误起单工位流，随后多工位流并存抢同一路 MJPEG。
  - 修复：工位数设为唯一真相源——先 await 工位数再决定取流；进多工位前显式停掉单工位流 + 轮询（"起新套前先停旧套"）。
  - 影响文件：frontend/src/views/Monitor/index.vue

- [BUG-D3] 多工位下仍叠一路单工位预览流
  - 修复：单工位取流调用统一加 `channelCount<=1` 守门，多工位不再多占带宽/解码。
  - 影响文件：frontend/src/views/Monitor/index.vue

- [BUG-D4] 多工位结果整对象替换增加 GC 压力
  - 修复（第一步）：改为就地更新多工位数据，减少对象重建。
  - 影响文件：frontend/src/views/Monitor/index.vue

- [BUG-D5] 语音播报队列无界 + 重复播报
  - 修复：语音队列加上限（20）+ 合并相邻相同播报。
  - 影响文件：frontend/src/views/Monitor/index.vue

- [BUG-D6] 工件倒计时定时器卸载/切工位未清
  - 修复：卸载与切工位时清理各通道倒计时定时器。
  - 影响文件：frontend/src/views/Monitor/index.vue

- [BUG-D7] 订单面板自动刷新定时器可叠加
  - 修复：重设刷新定时器前先清除旧的。
  - 影响文件：frontend/src/views/MES/OrderPanel.vue

## 功能变更

- [FEAT-B6] 检测结果轮询截图按内容哈希去重（默认关）
  - 需求：`/detection/results` 每 ~150ms 轮询都重发完全相同的 base64 缩略图大字符串。
  - 实现：前端把已持有指纹（label:md5）经 `known_shots` 上报，后端省略内容未变的截图（前端合并保留旧图），始终回传指纹。开关默认关（前端不带指纹）= 行为与旧版字节级一致。开关位：性能设置 `screenshotDedup`。
  - 影响文件：backend/api/source_routes.py, frontend/src/api/detection.js, frontend/src/store/useSystemStore.js, frontend/src/views/Monitor/index.vue
