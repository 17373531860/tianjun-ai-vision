# v2.2.1 (2026-04-02)

## Bug 修复

- [BUG-001] _just_settled 机制导致 NG 后所有后续周期无法计数
  - 症状: QG-SOP1 项目中，首次 NG 后，后续检测帧虽然出现检测框但步骤不做数、周期不结算
  - 根因: `_just_settled = True` 在周期结算后被设置，只允许第一步（如"拿取"）清除该标志。其他步骤被永久拒绝且 `step_consecutive_frames` 被重置，导致永远无法满足 min_duration/min_frames 条件
  - 修复: 完全移除 `_just_settled` 机制（共 10 处），依靠 `min_duration` 和 `min_frames` 过滤误检
  - 影响文件: backend/api/source.py

- [BUG-002] 替补步骤在新周期开始时被清空导致 NG
  - 症状: oppo_sop1 项目中，撕膜作为顶卡拖的替补，工人先做撕膜再做点亮屏幕，结算时报"缺少顶卡拖"→ NG，但应为 OK
  - 根因: `start_cycle()` 中有 `self.backup_steps_seen_in_cycle = set()` 清空操作。替补步骤（撕膜）在周期正式开始前被检测到并记录，但当点亮屏幕触发 `start_cycle()` 时记录被清空，结算时 `_inject_backup_steps()` 找不到替补记录
  - 修复: 移除 `start_cycle()` 中的 `backup_steps_seen_in_cycle` 清空操作。所有结算函数已在结算时清空该变量，无需在周期开始时重复清空
  - 影响文件: backend/api/source.py

- [BUG-003] 切换项目后点"开始"不加载新模型导致无检测结果
  - 症状: 从 oppo_sop1 切换到 QG-SOP1 后点"开始"，视频正常播放但检测框为 0，后端推理线程运行正常
  - 根因: 前端 `startDetection()` 有三条路径：(1)待机恢复 `resumeInference()`、(2)暂停恢复 `resumeDetection()`、(3)完整启动 `apiStartDetection(modelPath)`。路径1和2不传模型路径。切换项目后 `isPaused`/`isRunning` 仍为旧状态，导致走了恢复路径而非完整启动，后端继续使用旧模型
  - 修复: 在 `watch(currentProject)` 中检测到项目 ID 变化时重置 `isRunning`、`isPaused`、`isDetecting` 为 false，确保下次点"开始"走完整启动路径
  - 影响文件: frontend/src/views/Monitor/index.vue

- [BUG-004] 页面导航离开 Monitor 再返回后视频黑屏
  - 症状: 从 Monitor 页面进入 Project 页面修改参数后返回，视频画面不显示
  - 根因: Monitor 组件无 keep-alive，导航离开时 `onBeforeUnmount` 调用 `disconnectStream()`。返回时 remount，`onMounted` 中 `getSourceStatus()` 返回 `is_running: false` 时不调用 `forceReconnectStream()`，即使后端有视频源配置
  - 修复: 在 `onMounted` 的 `getSourceStatus()` 回调中，暂停状态（有源+模型但未运行）和有源但未运行状态也调用 `forceReconnectStream()`
  - 影响文件: frontend/src/views/Monitor/index.vue
