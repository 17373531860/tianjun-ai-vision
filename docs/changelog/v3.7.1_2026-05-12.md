# v3.7.1 (2026-05-12)

## 1. 核心修复 (BLOCKER — 这就是 v3.7.1 必须发的原因)

- [BLOCKER-371-A] **客户机启动崩溃 `ModuleNotFoundError: No module named '_plugin_common'`**
  - 症状: 客户拿到 v3.7.0 分包安装包, 双击装机后, 启动卡 splash 上,
    BackendManager 报 `[Backend] Process exited (code: 1)`. 软件永远进不去主界面.
  - Traceback: `backend/main.py` line 27 → `backend/api/plugins.py` line 17
    → `backend/plugin_system/verifier.py` line 21
    `from _plugin_common import ...` → `ModuleNotFoundError: No module named '_plugin_common'`
  - 根因: 老 `verifier.py` 用 `sys.path.insert(scripts/plugin)` + 裸 `import _plugin_common`,
    开发机有 `scripts/plugin/` 所以正常. **但 Nuitka 打包不复制 `scripts/`**,
    客户机 `resources/` 只有 `backend/`, sys.path 拼出来的目录根本不存在 → import 失败.
  - 修复 (commit a3ccdc7, 5月11日 23:50 已合入主线, 本版释出):
    权威实现搬到 `backend/plugin_system/_plugin_common.py`,
    `verifier.py` 改 `from backend.plugin_system._plugin_common import ...`.
    `scripts/plugin/_plugin_common.py` 改成 29 行 shim, 用 importlib + sys.modules 替换,
    7 个 CLI 工具 (sign/pack/install/inject-public-key/dev/verify/lint) 不用改一行.
  - 双向验证:
    - 反向 (回滚改动 + 隐藏 scripts/plugin/): `from _plugin_common import` → `ModuleNotFoundError` ✅ 复现现场
    - 正向 (本版 + 隐藏 scripts/plugin/): `from backend.plugin_system.verifier import plugins_root` → 全过 ✅
  - 影响文件: `backend/plugin_system/verifier.py` + `_plugin_common.py` (新) + `scripts/plugin/_plugin_common.py` (改 shim)

## 2. 插件运行时全链路实装 (Phase B: G1 + G1.5 + G2 + G3)

v3.7.0 已发布插件管理 API/UI, 但「装上的插件实际不工作」(后端不挂路由 / 前端不加载),
本版补齐运行时. 详见 `docs/plugin-system/implementation/ISSUES.md`.

- [FEAT-371-G1] **后端 PluginRegistry — 路由 / 钩子 / ORM 表挂载**
  - 需求: 启用插件后, 它的 FastAPI router 要真挂到 app 上 (能 curl 到),
    hooks 要能被业务流程 fire, ORM 表要 create_all 出来.
  - 实现:
    - 新增 `backend/plugin_system/registry.py`: `PluginRegistry` 统管 RoutesRegistry / HooksRegistry / TablesRegistry + PluginHost
    - 改 `PluginManager._load_backend_module`: 把 `register_plugin(app, registry, license_payload, host)` 改成 4 参数标准签名
    - 改 `backend/main.py`: 插件加载从 startup_init 移到 `_load_active_plugin_after_app()`, 在所有内置 router + static mount 之后跑
    - 改 `backend/plugin_system/__init__.py`: 给 `tianjun.plugin` logger 加 StreamHandler, 插件日志直出 uvicorn 控制台
  - 锁定: `tests/plugin_system/test_g1_registry.py` (10 用例, 覆盖 4 个 registry + register_plugin 契约)
  - 影响文件: `backend/plugin_system/{registry.py,manager.py,__init__.py}` + `backend/main.py`

- [FEAT-371-G1.5] **cycle_end 钩子在 source.py 真触发**
  - 需求: Tier 3 插件注册了 `cycle_end` hook, 但没有任何地方 fire 它.
  - 实现: `source_session_lifecycle_mixin.end_cycle()` 在 MES 钩子后、scanner cleanup 前,
    try/except 调 `plugin_manager.registry.hooks.fire("cycle_end", "post_cycle", "post", ctx)`.
    异常被吞, 不影响主检测流程.
  - 调试辅助: `RUNTIME_MODE=test` 下新增 `POST /api/v1/test/synthetic/fire-plugin-cycle-end` 端点,
    可绕过相机/模型直接触发 hook, 用于自动化 UAT.
  - 锁定: `tests/plugin_system/test_g1_5_cycle_end_hook.py` (4 用例: ctx 字段 / demo hook 消费 / 异常吞 / 空 registry 安全)
  - 影响文件: `backend/api/source_session_lifecycle_mixin.py` + `backend/api/test_runtime_routes.py`

- [FEAT-371-G2] **前端 ADR-0002 ESM Loader — Tier 2/3 UI 扩展真加载**
  - 需求: Tier 2/3 插件的前端 ESM 包要被宿主 import 并按 `host` 注入模式 (vue/pinia/router/i18n) 跑起来.
  - 实现:
    - 新增 `frontend/src/composables/usePluginLoader.js`: fetch `.esm.js` → Blob URL → dynamic `import()` → 调 `module.default.register({host, registry})`
    - 改 `frontend/src/main.js`: Pinia + router 就绪后调 `loadActivePluginFrontend(router)`
    - 改 `frontend/src/layout/index.vue`: 菜单动态读 `pluginTheme.sortedPluginMenus`
    - 改 `plugins-examples/tier2-ui/frontend/dist/index.esm.js`: 重写成 host 注入模式 (用 `host.vue.defineComponent` 而非裸 `import 'vue'`)
  - 锁定: `tests/manual_uat/plugin_g2_loader_uat.py` (Playwright 真开浏览器, Phase A 激活 + Phase B 反激活, 10/10 断言)
  - 影响文件: `frontend/src/composables/usePluginLoader.js` + `frontend/src/main.js` + `frontend/src/layout/index.vue` + `plugins-examples/tier2-ui/`

- [FEAT-371-G3] **前端 Tier 1 主题钩子 — 改色 / 改名 / 改 logo / 改 favicon / 改菜单**
  - 需求: 装上 Tier 1 主题插件后, 标题 / 主色 / Logo / Favicon / 隐藏菜单要应用上去.

## 3. 自定义导出预设 — 客户 5 步产线 CSV

- [FEAT-371-PRESET] **新增系统预设「session 5 步产线 CSV (会话信息+计数器+周期明细)」**
  - 需求: 客户老胡照 v3.7.0 changelog 里 FIX-370-C 的字段说明拼模板, 拼出来的 CSV 仍然空白.
    根因: 客户拿的字段名是 README 里**举例**那批 (`good_count` / `total_count` / `avg_duration`),
    跟实际系统字段名 (`good_cycles` / `total_cycles` / `avg_cycle_time`) 对不上;
    `|default('')` 对 Python None 不生效, 出现 `None` 字面量.
  - 修复: 把已经踩平 4 个坑的模板做成系统预设, 客户**下拉一选直接用**, 不用再拼字符串:
    - 4 个坑: 字段名修正 / `or ''` 替代 `|default('')` / `'%.2f' %` 格式化 / 步骤名按位置查表
    - 默认列: 拿取 / 正面涂黑 / 翻转 / 反面涂黑 / 放置 (其他产线复制副本改中文名即可)
  - 实现: `backend/services/export_seed.py` 加 `builtin_session_5step_csv` (csv / scope=batch)
  - 锁定:
    - `tests/manual_uat/customer_export_uat.py` (Playwright 真粘模板, 11/11)
    - `tests/manual_uat/customer_preset_uat.py` (Playwright 下拉选预设, 12/12)
    - `evidence/customer_preset_2026-05-12/` 含「客户操作步骤_预设版.md」
  - 影响文件: `backend/services/export_seed.py`
