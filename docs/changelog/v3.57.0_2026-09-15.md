# v3.57.0 (2026-09-15)

> 汇合发版：v3.56.0 之后并行推进的六大批次一次收口——AI 能力批次（OCR/异常检测逻辑模式 + VLM + 端到端 ONNX 直推 + 朝向驻留）、内置能力模型选用体系、投影光引导 P1~P3、多平台安装包（Ubuntu deb / macOS dmg）、多显示器二期、全系 ROI 多块化；随版收编 v3.56.0a 六和现场补丁。新功能全部默认关或零配置差异。

## 功能变更

- [FEAT-001] AI 能力批次：OCR 读字 / 异常检测升级为正式逻辑模式 + VLM 坐诊 + 端到端 ONNX 直推
  - 需求: 客户场景要"读字判定"（序列号/字符校验）与"免缺陷样本质检"（合格品记忆库比对），且训练平台新形态模型（YOLO26/RF-DETR 无 NMS 端到端）要能直接消费
  - 实现: `source_ai_modes_mixin` 独立节流采样线程（不依赖 YOLO 模型即可起检测），OCR 稳定读数/正则规则/文本变化去重，异常连续超阈值/冷却/恢复 OK 收口，判定走标准 `_trigger_event` 结算链；`ocr_engine`（RapidOCR）/`anomaly_engine`（PatchCore 风格，DINOv2 ViT-S 优先 ResNet18 兜底）；`source_e2e_onnx` 无 NMS 直推 runner，加载层自动切换，其余模型零行为变化；`vlm_service` OpenAI 兼容 HTTP（推荐本地 Ollama + Qwen2.5-VL），默认关零开销；预置模型 `.yvmodel` 启动幂等入库
  - 新端点组: `/api/v1/ocr` `/anomaly` `/vlm`（router_manifest 登记）
  - 影响文件: backend/api/source_ai_modes_mixin.py, backend/api/ocr.py, backend/api/anomaly.py, backend/api/vlm.py, backend/api/source_e2e_onnx.py, backend/services/ocr_engine.py, backend/services/anomaly_engine.py, backend/services/vlm_service.py, backend/services/preset_models.py, frontend/src/views/Monitor/OcrPanel.vue, frontend/src/views/Monitor/AnomalyPanel.vue, frontend/src/views/Project/LogicConfigTab.vue

- [FEAT-002] 内置能力模型入仓与能力选用体系（AI 能力试用页下线）
  - 需求: 主作者方向性反馈——AI 能力不做"试用 tab"孤岛橱窗，模型仓库是唯一模型事实源，YOLO 之外的模型按 capability 有自己的人格与选用价值
  - 实现: `models` 表加 capability/builtin 列（迁移 m0011）+ `builtin_models` 开机幂等 seed 六个出厂行（检人/朝向/头姿/OCR/异常/VLM，缺文件标 missing 不炸）；权重解析 env > 仓内绑定 > 出厂默认，绑定切换热重载；`GET /models/capabilities` 能力目录 + POST bind 换权重 + 内置行禁删 403；`CapabilityAttachmentsMixin` 能力挂件（pose/ocr/anomaly 副通道独立后台线程节流执行，结果透出 `capability_outputs`，无挂件零开销）；前端模型页三分区 + 能力徽标 + 试一试抽屉（传图/读通道画面/记忆库管理/VLM 配置/朝向罗盘/异常热力图）+ 项目基础设置「能力挂件」卡；AI 能力试用独立页删除（路由/菜单/视图）
  - 影响文件: backend/models/models.py, backend/db/migrations/m0011_model_capability.py, backend/services/builtin_models.py, backend/api/models.py, backend/api/source_capability_attachments.py, frontend/src/views/Model/index.vue, frontend/src/views/Model/CapabilityTryDrawer.vue, frontend/src/views/AiTools/index.vue(删), frontend/src/views/Project/BasicSettingsTab.vue

- [FEAT-003] 朝向估计三层后端统一收敛 + facing_dwell 朝向驻留规则（蒸镀点检场景）
  - 需求: 六和蒸镀点检——操作员必须面向仪表点检驻留足够时长，超时无人点检要告警
  - 实现: `person_orientation` 收编 orientation_engine——yolo11_pose/mediapipe_pose 关键点层二选一 + headpose_onnx 头姿精化层（商用授权外置件，可选热生效）+ YawSmoother 平滑，按授权/文件在场自动降级；区域事件引擎新增 facing_dwell 规则（主体朝向与人→仪表点连线夹角判定 + tolerance_deg 容差 + alert_on_absent 取反）；ROI 编辑器新增单点标定模式；新端点组 `/api/v1/orientation/*`；7 段现场真实视频离线验证
  - 影响文件: backend/services/person_orientation.py, backend/api/orientation.py, backend/api/source_region_events.py, backend/api/source_region_events_mixin.py, frontend/src/views/Project/RoiEditorDialog.vue

- [FEAT-004] 区域事件监控型规则四种 + 「只认操作员」蓝工装启发式
  - 需求: 巡检合规类场景（人流计数/区域空置超时）；黄背心外协/便服人员不应计入点检打卡
  - 实现: region_count/region_empty/proximity/cross_count 监控型规则（与动作型规则正交，不参与打断/去重/序列），min_seconds 上限 30→3600s；`tag_operator_uniforms` HSV 蓝/黄工装启发式给检测框打 is_operator（异常隔离不进主链路），规则级 require_operator 开关默认关零差异
