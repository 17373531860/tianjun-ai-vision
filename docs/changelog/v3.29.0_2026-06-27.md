# v3.29.0 (2026-06-27)

> 主题：**外部 MES / 中控「主动推」型双向对接全闭环（川南火工范式）+ 一批"去硬编码 → 可自行配置" + 后端崩溃自愈 / 开机自启 + 调试日志完善**。
> 主线把"中控来推开工、我们把报警与完工推回去"的完整闭环做成主程序原生可配能力（入站开工自动切项目 + 开工四要素上屏 + 在途报警台账闭环 + 最新开工顶替并回推完工 + 健康检查 + 自定义接收路径），全部默认关 = 老项目零差异；同时把"原本写死"的一批参数（集群心跳/离线/扫描间隔、各管理面板刷新间隔与日志条数）改成客户可在系统设置里自行配置；新增桌面壳后端崩溃看门狗自愈与安装时可选开机自启；并给入站/报警/健康新链路补齐"人话"调试埋点。

## 功能变更

- [FEAT-001] 外部 MES / 中控双向对接全闭环（川南火工范式）
  - 需求: 川南火工等"主动推"型中控会来调我们的接口下发开工，并期望我们把检测报警、完工状态推回去，形成一进一出闭环；且各接口路径/字段/话术要能按客户自配，不能写死
  - 实现: 入站对接面板扩展为完整双向闭环——开工按产品代号自动切检测项目（对照表 + "项目名==产品代号"兜底）/ 开工建工单并把任务四要素（任务号·产品代号·工序工步·操作员）落到工单扩展信息留痕 / 最新开工顶替同工位旧任务并自动把被顶替任务的「完工」回推中控 / 完工真值词表可配 / 各结果响应文案可覆盖 / 产品码未知话术可配 / 自定义接收路径（中控按自家 URL 推也能映射到内置处理）/ 健康检查端点
  - 影响文件: backend/api/mes_inbound.py, backend/services/mes_inbound.py

- [FEAT-002] 在途报警闭环（外部报警台账，通用能力）
  - 需求: 报警推给中控后要等中控"消除"才算闭环，期间现场要持续可见、且同一报警不能重复推/重复登记；匹配维度（川南是四要素）要能按客户自定义
  - 实现: 新增在途报警台账（ExternalActiveAlarm 表 + external_alarm 服务）——出站成功推送报警后登记一条在途报警，中控回推消除命令按唯一键匹配撤销，监控页横幅同步消失；支持去重窗口秒数、只登 NG、消除匹配字段可配；匹配维度除 5 个原生列外支持任意自定义维度（存 extra_data.ext，走 json_extract 参与去重/消除），不含任何客户硬编码分支
  - 影响文件: backend/services/external_alarm.py, backend/models/mes_models.py, backend/services/mes_gateway.py, backend/api/mes_inbound.py, backend/main.py

- [FEAT-003] 监控页开工四要素上屏 + 在途报警横幅（逐项可配、默认全关）
  - 需求: 开工后主界面要能常驻显示当前任务四要素，且每项可单独开关；有未消除报警时主界面要醒目持续提醒"等待生产管控系统消除"；不开时维持原界面不追加任何元素
  - 实现: 监控页信息条扩展四要素 chip（任务号/产品代号/工序工步/操作员，逐项勾选，默认全关）；新增外部报警横幅组件（显隐/停靠/主色/刷新间隔/每条显示字段全可配，外部消除后自动撤）
  - 影响文件: frontend/src/views/Monitor/index.vue, frontend/src/views/Monitor/ExternalAlarmBanner.vue, frontend/src/views/MES/OrderInboundPanel.vue

- [FEAT-004] 出站网关：川南字段预设 + 健康定时探测
  - 需求: 报警上报报文要有川南字段一键预设；我们也要能定时探活中控是否在线（协议建议但非强制），且探测频率可配
  - 实现: 网关模板新增川南报警预设（TaskNo/ProductCode/StepCode/Operator/WarningText/Image，开工四要素自动带入）；新增后台健康探测调度器，按连接配置定时探活，只在"在线↔离线"翻转时记日志
  - 影响文件: backend/services/mes_gateway.py, backend/api/mes_gateway.py, backend/services/mes_health_probe.py, backend/services/mes_adapters/rest_adapter.py, frontend/src/views/MES/GatewayPanel.vue, frontend/src/api/gateway.js

- [FEAT-005] 去硬编码：集群计时参数 + 各管理面板刷新间隔/日志条数改为可配
  - 需求: 通用性原则——凡能配置的不写死。集群心跳/离线/box 扫描间隔、各 MES 管理面板的数据刷新频率与"最近日志"显示条数原本是写死的常量
  - 实现: 集群三个计时参数（心跳间隔/离线超时/box 扫描间隔）改存 SystemConfig KV（当前值作默认、免迁移）；系统设置新增「轮询间隔」Tab，集中配置各管理面板刷新间隔（下限 500ms 保护）与日志显示条数（1–500），全部白名单校验、越界回落默认
  - 影响文件: backend/services/cluster_collector.py, backend/api/cluster.py, backend/api/system_display.py, frontend/src/views/Settings/index.vue, frontend/src/store/usePollingStore.js, frontend/src/views/MES/ClusterPanel.vue, frontend/src/views/MES/OrderPanel.vue, frontend/src/views/MES/ScannerPanel.vue, frontend/src/views/MES/ExternalDevicePanel.vue, frontend/src/views/MES/WMaxPanel.vue, frontend/src/views/MES/UsbScanGunDialog.vue

- [FEAT-006] 桌面壳后端崩溃自愈（看门狗）
  - 需求: 现场后端进程偶发崩溃需要有人去重开，应做到自动拉起
  - 实现: backend-manager 内置看门狗——后端"就绪后"意外退出（非主动关机）自动按 1s→2s→4s 退避重启，60 秒内最多 3 次，超限判定为崩溃死循环并提示人工介入；通过 IPC 通知前端重启中/已恢复/失败，恢复后前端弹提示并记入调试中心
  - 影响文件: electron/backend-manager.js, electron/main.js, electron/preload.js, frontend/src/App.vue

- [FEAT-007] 安装时可选开机自启
  - 需求: 部分产线希望"工控机一上电就自动起检测软件"
  - 实现: 安装向导新增「开机自动启动」可选项（写系统启动项），默认不勾；配合既有「开机自动恢复检测」即"通电→起软件→自动开检测"全自动
  - 影响文件: electron/build/installer.iss

- [FEAT-008] 调试日志完善：入站/报警台账/健康探测/看门狗新链路补全埋点
  - 需求: 新增子系统此前只在出错时打日志，现场开调试中心看不到正常决策叙事
  - 实现: 入站补全"收到开工(含四要素)/缺字段/切项目命中或未命中/建单留痕/复用工单/最新顶替/收到消除+命中或未命中"（backend.mes）；报警台账补登记/去重跳过（backend.mes）；健康探测仅在线↔离线翻转打日志（backend.gateway）；前端新增「应用生命周期」类别，后端被看门狗自愈记一条
  - 影响文件: backend/services/mes_inbound.py, backend/services/external_alarm.py, backend/services/mes_health_probe.py, frontend/src/utils/debug.js, frontend/src/App.vue
