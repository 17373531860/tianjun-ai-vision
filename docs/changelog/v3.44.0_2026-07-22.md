# v3.44.0 (2026-07-22)

> 上银 SY3 包装线 NG 处置整改批次：NG 箱账挂起等处置 + 工单收尾快照保留 + 收尾防呆（数量门/缺步挂起，两段现场录像驱动验收）+ NG 处置配置五代散装开关收敛为统一模型（6 张配置卡 → 2 张）；另含放托盘动作不应期（治检测闪断双结算）与秤串口延迟治本。

## Bug 修复

- [BUG-001] 包装 NG 箱当场落账翻页，人工确认形同虚设
  - 症状: NG 事件配了「需人工确认」，弹窗还没点，包装卡箱号已翻页、NG 箱已落账；工人点"重做"实际重做的是下一箱。
  - 根因: 检测层结算与包装层记账同步完成，人工确认定格只冻结检测线，包装账本不等确认结果。
  - 修复: NG+需确认时包装账本进入"箱账挂起"（不落账不翻页），确认弹窗给「认 NG 落账—进下一箱 / 重做本箱—不记 NG」二选一，后端 ack 接口直接解挂；超时自动确认按"重做"处置。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/source_event_trigger_mixin.py, backend/api/source_session_lifecycle_mixin.py, backend/api/source_routes.py, frontend/src/views/Monitor/index.vue, frontend/src/views/Monitor/PackagingFlowCard.vue

- [BUG-002] 工单收尾后信息全清空（含 NG 完结场景）
  - 症状: 最后一箱落账（哪怕是 NG）后，包装卡瞬间清空，工单号/箱明细/进度全没，操作员以为数据丢了。
  - 根因: 工单完成/作废即从在途表移除，前端轮询拿到空态。
  - 修复: 收尾时保留快照（完成/作废+最终结果+箱明细），展示态接口返回快照直到下一张工单开工自然顶掉；包装卡加绿/红收尾横幅。
  - 影响文件: backend/services/packaging_flow_coordinator.py, backend/api/packaging_flows.py, frontend/src/views/Monitor/PackagingFlowCard.vue

- [BUG-003] 「允许补数量」策略永不生效（死分支）
  - 症状: 开了补数量，少装滑块 NG 时从不给补做机会，直接落 NG 箱。
  - 根因: 少装必然导致整体判 NG，而补数量入口却要求"整体判 OK 才进"，条件自相矛盾。
  - 修复: 结算时把"步骤侧结论"与"数量侧结论"分开传递，步骤全对而数量不足时按补数量挂起。
  - 影响文件: backend/api/source_custom_mix.py, backend/api/source_session_lifecycle_mixin.py, backend/services/packaging_flow_coordinator.py

- [BUG-004] 补做处置后二次弹确认框（双重确认）
  - 症状: 工人在挂起弹窗点了"认 NG"，随后又弹一次确认框，要点两遍。
  - 根因: 认 NG 重发 NG 事件时又命中「需人工确认」入口，重新进定格。
  - 修复: 操作员已处置的重发一次性旁路定格；挂起超时落账同样不再二次进补做挂起（防无人值守无限等待链）。
  - 影响文件: backend/api/source_event_trigger_mixin.py, backend/api/source_settlement_mixin.py

- [BUG-005] 放托盘动作检测闪断，一次动作结算两次
  - 症状: 客户机（TensorRT FP32 旧权重）放一次托盘偶发记两盘，同套滑块被计两遍。
  - 根因: 动作标签检测闪断把一个物理动作劈成两个脉冲，动作确认状态机按两次结算。
  - 修复: 容器动作确认加不应期（默认 2 秒，可配 0 关闭），窗口内的重复脉冲吸收不再二次结算；出现/消失帧数与不应期三参数进前端跟踪配置 UI。
  - 影响文件: backend/api/source_custom_mix.py, frontend/src/views/Project/LogicConfigTab.vue, frontend/src/views/Project/index.vue
  - 关联: 已按同逻辑给 v3.43 客户机出过热补丁（仅后端时间窗版）。

- [BUG-006] 电子秤读数延迟 2~3 秒（萍乡百斯特"延迟高"根因）
  - 症状: 秤盘上加减料，软件数值条 2~3 秒才跟上，去皮/稳定判定慢。
  - 根因: 串口读取按"攒满固定字节数或等满超时"返回，连续输出的秤每帧十几字节被攒成约 1~2 秒一批；帧读取每次白等整个串口超时，采样被锁在约 1Hz。
  - 修复: 改"有多少收多少、见帧尾立即交货"，无分隔符帧以约 60ms 静默兜底；负重量直读符号位解析补齐。
  - 影响文件: backend/services/external_device_protocols.py, backend/services/external_device_pipeline.py

- [BUG-007] 数量门被"备盘凑数"骗过 + 结算余像误报
  - 症状: 真实录像回放发现两处：漏装第四盘就放油嘴包时数量门不拦（备盘区整盘被凑进总数"看起来已满"）；OK 结算瞬间封箱余像在新空周期上触发一次误报警甚至自开幽灵周期进挂起。
  - 根因: 数量门误用了 verdict 的"凑数口径"（含在位托盘）；数量门/挂起入口没有排除"周期未正经开始"的场景。
  - 修复: 数量门改用"已确认进箱"记账口径；空周期不做数量门判定；首步都缺的周期（幽灵周期）不进挂起，走原 NG 路径。
  - 影响文件: backend/api/source_custom_mix.py, backend/api/source_settlement_mixin.py

## 功能变更

- [FEAT-001] 收尾防呆：数量门 + 缺步挂起（上银 SY3 两段现场录像驱动）
  - 需求: 视频一（忘放油嘴包直接封箱）期望当场报警、补放后自动判合格；视频二（漏装第四盘就放油嘴包）期望收尾动作当场被拦报警、补盘后正常合格——全程不落错误 NG、不打断周期。
  - 实现: ①数量门——箱内已进数量未达目标时，配置的收尾步骤（放油嘴包/封箱）新出现直接拒收+节流报警，补够后自然放行；②缺步挂起——末步结算若"纯缺步骤"（无多余/重复）不判 NG，报警挂起等视觉补做，补齐按期望顺序重排自动判 OK，超时按原缺步 NG 落账（0=不限时）；挂起中吸收非缺失步骤余像防"重复步骤"死局。默认全关=行为零差异。
  - 验收: BDD 剧本 4 场景 + 两段真实录像真模型 UAT 全过（报警先于合格结算 7.6s/32.9s，不良零增）。
  - 影响文件: backend/api/source_settlement_mixin.py, backend/api/source_sequential_mixin.py, backend/api/source_events_check_mixin.py, backend/api/source_step_stats_mixin.py, backend/api/source_project_config_apply.py, backend/api/source_state_init.py, backend/api/source.py, backend/api/source_custom_mix.py

- [FEAT-002] NG 判定与处置统一配置模型（五代散装开关收敛）
  - 需求: v3.23 补做策略 / v3.32 违序提示 / v3.43 实时NG / v3.44 收尾防呆各自叠开关，逻辑设置页 6 张 NG 相关卡 + 事件页 3 个勾选互相隐性耦合，客户"开了没反应"。
  - 实现: 后端新增统一解析器（pipeline_config.ng_handling 块），四行语义——违规当场（不处理/当场提示/立即NG）、结算缺步骤（直接NG/定格弹窗可补步骤/挂起等补做）、结算少数量（直接NG/定格弹窗可补数量）、数量门（收尾步骤+提示事件）；老项目无新块自动从 legacy 键合成等价档位，行为零差异，状态机零改动。数量门与缺步挂起提示事件分离（话术可不同）。
  - UI: 逻辑设置 6 卡收敛为「NG 判定与处置」+「结算冷却」（防重复结算+NG 周期保护合并）两卡，一行一场景、档位不选高级参数不渲染；统一卡←→事件页双向联动明示（选定格弹窗档但 NG 事件没勾需确认→黄色警告；NG 事件页反向说明处置按钮来源与「确认后保留周期」被顶掉关系）。
  - 影响文件: backend/api/source_project_config_apply.py, backend/api/source_state_init.py, backend/api/source_settlement_mixin.py, frontend/src/views/Project/LogicConfigTab.vue, frontend/src/views/Project/index.vue, frontend/src/views/Project/EventsConfigTab.vue

- [FEAT-003] 人工确认弹窗包装挂账形态 + 处置结果文案按箱语义
  - 需求: 箱账挂起时工人要在弹窗一次完成处置，不再去包装卡二次操作。
  - 实现: 确认弹窗（大/小两处）显示在制箱明细（第几箱/已进箱/目标/挂起态），按钮二选一「认 NG 落账—进下一箱 / 重做本箱—不记 NG」；确认成功提示按箱语义明说落没落账；包装卡挂起横幅只提示引导不重复给按钮。
  - 影响文件: frontend/src/views/Monitor/index.vue, frontend/src/views/Monitor/PackagingFlowCard.vue, backend/api/source_routes.py
