# v2.7.9 (2026-04-21)

## Bug 修复

- [BUG-001] 集群汇总页「已连接副机」莫名其妙消失
  - 症状: 副机（机器标识 A）点一次「测试」后主机「已连接副机」列表显示出来，但主机切到其他页面再回集群汇总 → 副机又没了；数据也上不来。
  - 根因: v2.7.6 引入集群功能时，副机心跳**只在前端 ClusterPanel.vue 的 `setInterval(doHeartbeat, 10000)` 里发送**，仅在该页面挂载期间有效。副机一切页、关页或停留在其它页面 → 10s 心跳停 → 主机 `_slave_timeout=20s` 后把副机从 `_connected_slaves` 清掉。用户看到的「点测试按钮」其实是副机打开 ClusterPanel 时 `onMounted` 自动跑了一次 `doHeartbeat`，巧合而非测试触发。
  - 修复: 在 `ClusterCollector.start()` 里新起后台线程 `_heartbeat_sender_loop`（5s 间隔），**后端自主发送心跳**，不依赖前端页面状态。payload 从 `channel_manager` 实时取 `channel_count / detecting`，project 从任一 running 通道的 `project_config` 取，hostname 用 `socket.gethostname()`。HTTP 失败仅日志不崩，前端原 10s 心跳保留作双保险（`register_slave` 幂等）。
  - 影响文件: backend/services/cluster_collector.py

- [BUG-002] Windows 下串口连接 `PermissionError(13, '拒绝访问。')`
  - 症状: 工位 3 称重器接 COM20，「已连接」状态下显示红色错误「串口打开失败: PermissionError 13 拒绝访问」，设备用不了。
  - 根因: 两条并发/残留路径——(a) 上次连接或测试按钮关闭后 Windows 未完全释放端口（`ser.close()` 到系统真正释放有毫秒级延迟）；(b) 前端「测试」按钮的 `test_connection` 和连接线程 `_serial_loop / _serial_modbus_ascii_loop / _serial_continuous_loop` 短时间内先后开同一 port，后者被 OS 拒绝。首次打开失败后代码直接 `raise`，没有重试，导致整次连接作废。
  - 修复: 新增静态辅助 `ExternalDeviceService._open_serial_with_retry(port, baud, ..., timeout, max_retries=3, retry_delay=1.0)`，三个连接 loop 的 `serial.Serial(...)` 统一切到这个 helper。失败间隔 1s 再试最多 3 次；PermissionError 单独识别打日志；重试成功会打 `第 N 次重试打开成功`，便于运维诊断。测试按钮路径不加重试（短操作，稳态连接时测试失败本来就是预期行为）。
  - 影响文件: backend/services/external_device.py

## 已知问题

- 工位 3 称重器如果被外部程序（另一个串口工具、上一次软件实例未退出）真正占用，重试 3 次都失败，日志会清晰报出，但设备仍无法使用——属于预期行为，需关掉占用进程。
