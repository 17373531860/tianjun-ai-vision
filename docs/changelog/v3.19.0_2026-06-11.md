- [FEAT-002] NG 原因可解释性埋点（"一直 NG 能知道为什么"）
  - 需求: 某模式持续 NG 时现场无法定位原因（缺哪步、为什么不开周期、为什么步骤被拒收）。
  - 实现:
    - 逐件覆盖模式: 周期不开始原因（首步检出不足/数量不恒定/位置不稳定/严格等量未满足）、周期锁定与覆盖进度、结算时漏件明细，热路径 1 秒节流；调试面板新增 `backend.per_item` 分类。
    - 检测/跟踪模式: 步骤拒收原因（置信度低于阈值给出具体数值对比、检测框出 ROI），按标签 2 秒节流。
    - 顺序模式: 结算 NG 时输出缺失步骤清单（人话格式 `缺少=['step_b']`）、步骤被当上一周期残留跳过时留痕。
    - 超时强制 NG: 记录超时原因 + 当时已完成步骤。
  - 影响文件: backend/api/source_per_item_mixin.py, backend/api/source_settlement_mixin.py, backend/api/source_step_stats_mixin.py, backend/api/source_events_check_mixin.py, backend/api/source_session_lifecycle_mixin.py

## Bug 修复

- [BUG-001] 虚拟测试源最小项目配置缺步骤 ID 致周期静默丢弃
  - 症状: synthetic 剧本跑顺序模式 NG 场景，周期既不出 OK 也不出 NG 也无任何日志（孤儿周期）。
  - 根因: 测试运行时生成的最小项目配置步骤无 id 字段、流水线配置无序列定义，顺序结算路径在序列为空时直接丢弃周期且不留痕。
  - 修复: 最小项目配置补步骤 id + 序列定义 + 事件计数器配置；静默丢弃分支补调试日志。
  - 影响文件: backend/api/test_runtime_routes.py, backend/api/source_settlement_mixin.py

- [BUG-002] Windows 手动 cmd 启动日志乱码（彻底版）
  - 症状: 客户机 cmd 启动软件终端输出全乱码，排障需反复重启。
  - 根因: cmd 默认 GBK 码页，UTF-8 中文日志错解码；且日志只进终端不落盘。
  - 修复: Electron 主进程最早 `chcp 65001` + 主进程/后端日志全部 UTF-8 旋转落盘，应用内调试面板可直接看，不再依赖终端。
  - 影响文件: electron/main.js, electron/backend-manager.js
