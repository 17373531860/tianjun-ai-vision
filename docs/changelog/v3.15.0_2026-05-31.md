# v3.15.0 (2026-05-31)

> 把长期分支 `test/v3.12.0`（实际内容 = v3.13.1 已发 + v3.14.0 RFC11 + RFC12 平台能力）合入主干，并补 v3.12.1 客户反馈修复。同步把主程序版本号 bump 到 **3.15.0**，与福建金龙双工位插件 v1.1.8 声明的 `main_version_min=3.15.0` 对齐 —— 低于此版本会被插件版本校验**硬拒绝加载**。无破坏性改动，老配置 / DB / 接口、未装插件场景字节级零差异。

## 功能变更

- [FEAT-001] **RFC 12 `step_tick` 计时广播 hook（平台基础设施）**
  - 需求: 客户要"步骤耗时三档（未达最短 / 超警告 / 超最长）在步骤进行中当场报警 + 判 NG"，需要主程序在推理热路径里把"某步骤已计时多久"实时广播给插件。
  - 实现: 主程序对每个正在计时的步骤按 ~1Hz 节流 fire `step_tick`，ctx 携带 `elapsed_sec` + 步骤身份 + 主程序侧 `min/max_duration`（只读参考）。**只读 observe hook**，主程序不内嵌任何阈值策略；阈值判定 + 报警 + 经 `pre_cycle_end` 改写 NG 全在插件侧。
  - 影响文件: backend/api/source_step_stats_mixin.py, backend/plugin_system/hook_dispatch.py
- [FEAT-002] **前端 `host.api` 暴露已鉴权 axios 实例**
  - 需求: 插件前端要调自有后端路由（如三档耗时配置），不想自己拼登录 token / baseURL。
  - 实现: 宿主把已鉴权的 axios 实例通过 PluginHost 暴露给插件前端，复用主程序登录态。
  - 影响文件: frontend 插件加载层 + plugin_system registry
- [FEAT-003] **福建金龙双工位插件 v1.1.8 配套验证**
  - 需求: 客户现场专属双工位检测主页插件，依赖 RFC12 计时广播 + 库内权威统计重算。
  - 实现: 端到端验证插件安装（RSA 验签 + 客户绑定 HMAC + 版本校验）→ 激活 → 重启加载（注册 cycle_start / step_tick / step_change / pre_cycle_end 4 hook + 挂载自有后端路由）→ runtime loaded / health ok。前端 ESM 加载 + slot 注册 + theme 应用全通；布局覆盖按主程序设计仅双工位（channelCount===2）启用。
  - 影响文件: 无主程序代码改动（插件为客户专属包，不入主仓）
- [CHORE-001] **版本号 bump 3.14.0 → 3.15.0**
  - 需求: `electron/package.json` 是版本号唯一权威源，后端 `backend/_version.py` 运行时读取供插件 `main_version_min/max` 校验；不 bump 则福建金龙插件无法加载。
  - 影响文件: electron/package.json

## Bug 修复

- [BUG-001] **`.gitignore` 漏忽略插件安装副本目录**
  - 症状: 任何上传过 `.tjvplugin` 的开发机 / 客户机，`backend/plugins/` 下的运行时安装副本会被 git 当作待提交文件，可能误入版本库。
  - 根因: 合并 `test/v3.12.0` 时，收尾 commit 声称"backend/plugins 安装副本不入库"，但 `.gitignore` 实际没有这条规则。
  - 修复: `.gitignore` 补 `backend/plugins/` 忽略规则。
  - 影响文件: .gitignore
