# v3.15.4 (2026-06-01)

> 彻底根治插件系统现场连环事故并把所有热补丁固化进源码。修复打包后 `file://` 环境下前端插件代码动态加载失败（双工位定制 UI 等完全不生效、本地 http 不复现）的 P0；新增前端→后端诊断日志双通道（终端可见 + 落盘），插件加载全过程极致可观测——**现场排障无需开 DevTools、不再转发补丁、不再敲命令**；验签链路每步打期望值 vs 实际值；安装器覆盖安装清旧前端产物根治新旧 bundle 混叠。所有 v3.15.x 已发热补丁的修复确认已在源码，下次打包不再复发。

## Bug 修复

- [BUG-001] 打包后前端插件代码动态加载失败（`file://` 下 blob import 被拦）— **P0**
  - 症状: 客户机激活双工位定制插件并重启后，监控页 UI 与原版**一模一样**、插件加的功能全不生效；后端日志却显示 `startup_load OK`（后端 hooks/routes 已注册）；本地开发（`http://localhost`）完全正常、不复现
  - 根因: 打包后 Electron 主窗口走 `file://` 协议，Chromium 对 `file://` 源下 `import(blob:...)` 动态导入有安全限制 → 插件 ESM 静默加载失败 → 插件的 `register()` 根本没被调到 → slot / menu / route 全没注册 → 前端定制完全不生效。本地 dev 是 `http://localhost` 不触发该限制，所以开发机永远正常，bug 只在打包客户机暴露
  - 修复:
    1. 前端插件加载器 `import` 改为**三级数据驱动兜底**：`blob` → `data:URL` → 后端 `http` URL（主窗口 `webSecurity:false` 允许 `file://` 跨源 import `http://localhost:8001` 的 module），任一成功即用
    2. 把插槽注册内部的 `import('vue').then()` 异步动态导入改为顶部**静态 `import { markRaw }`**，消除 `file://` 下又一处动态 import 隐患（插件 `register` 已调到、slot 却永远设不上的元凶之二）
  - 影响文件: frontend/src/composables/usePluginLoader.js, frontend/src/store/usePluginThemeStore.js

## 新增

- [FEAT-001] 插件加载全链路诊断日志双通道（终端可见 + 落盘，**告别黑盒**）
  - 背景: 工业机开不了 F12、打包后浏览器 console 进不了启动终端 → 前端插件加载问题全程黑盒，只能靠现场转发补丁 + 敲命令整夜折腾
  - 实现:
    1. 新增后端接口 `POST /api/v1/plugins/client-log`，接收前端回传的诊断日志，统一打到 `tianjun.plugin` logger（进启动终端 `[Backend]` 行 + 落盘插件日志）
    2. 前端加载器**每一步**（拉 manifest / 拉 ESM / 三级 import 各策略成败 / `register` 各 slot·menu·route·tab 注册成败 / `register` 抛错）都双通道输出：`console` 带 `[⬛` 前缀 + POST 回传后端
    3. Electron renderer console 转发扩展：除 `[⬛` 外额外转发所有含 `Plugin` / `PluginLoader` / `RendererDiag` 的日志
  - 影响文件: backend/api/plugins.py, frontend/src/composables/usePluginLoader.js, electron/main.js

## 改进

- [IMP-001] 验签链路极致日志 — 每步打期望值 vs 实际值
  - `verify_extracted_plugin` 五步（manifest schema / 文件摘要 / RSA-PSS 验签 / 客户绑定 HMAC / license 客户码）逐步打日志：摘要不一致打**期望与实际两个哈希**；验签打公钥候选数·签名指纹·每个候选指纹是否命中·命中后验签是否通过；HMAC 不一致打期望与实际。任何 `PLUGIN_*_FAIL` 在后端日志一眼看出根因（密钥不符 / 包被篡改 / 缺 cryptography / 公钥不在白名单），不再靠猜
  - 插件加载器开头显式打**主程序生效版本号**（`0.0.0` 误拒事故的直接定位点）
  - 影响文件: backend/plugin_system/verifier.py, backend/plugin_system/manager.py

- [IMP-002] 双工位前提未满足时给可见提示
  - 症状: 客户装了双工位定制插件但工位数设成 1，监控页看不到任何变化，误判「插件像没装」
  - 修复: 监控页当检测到插件已注册定制监控界面（`layout.body` slot）但当前工位数不是 2 时，顶部显示明确橙色提示条引导去设置切换工位数为 2，杜绝静默无反应
  - 影响文件: frontend/src/views/Monitor/index.vue

- [IMP-003] 安装器覆盖安装前清旧前端产物 + 启动脚本密钥文件容错
  - 安装器: `installer.iss` 覆盖安装前 `DelTree` `app/dist` 旧前端目录。assets 用 content-hash 命名，升级后新文件名不同，Inno 的 `ignoreversion` 只覆盖同名文件 → 旧 hash 文件永久残留、新旧 bundle 混叠（现场出现 5/7 + 5/31 两批同存）。`app/dist` 纯静态、无用户数据，可安全重铺
  - 启动脚本: `start_backend.sh` 改成 `dev_keys/PLUGIN_SECRET.txt` 文件存在才 `export PLUGIN_SECRET_FILE`，不存在回退主程序内置统一密钥，从源头不污染环境变量
  - 影响文件: electron/build/installer.iss, start_backend.sh
