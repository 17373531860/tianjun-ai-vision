# v3.20.0 (2026-06-15)

> 外部 MES 双向打通：在原有「检测结果推送给外部 MES」之外，新增「主动去外部 MES 拉工单」能力（通用可配置，已对接上银 HIWIN 两层嵌套结构）+ 定时自动同步。现场扫码硬件扩展：USB 键盘式扫码枪即插即用（NT-1202W 等），归入扫码器面板统一管理，支持扫码拉工单 / 扫码绑工件。全链路接入 v3.19 调试中心。三层测试（单元 + BDD + 可见浏览器 UAT）全绿，141 BDD 零回归。

## 功能变更

- [FEAT-001] 新增: **外部 MES 工单主动拉取（通用可配置）**
  - 需求: 对接上银等外部 MES 时，对方不主动推工单本地就拿不到，产线无法开工
  - 实现: 新增 MESPuller 服务，复用 MESConnection 连接表。可配置拉取地址/方法/请求体模板/成功判定路径/数组路径/字段映射/导入模式；pull-test 自动识别返回结构（含上银 `response.resultData` 两层嵌套）；立即同步 / 试同步(dry_run) / 工单 upsert 幂等。前端 OrderPullPanel 面向小白点选式配置 + 高级参数
  - 影响文件: backend/services/mes_puller.py（新）, backend/api/mes_gateway.py, frontend OrderPullPanel.vue, MES/index.vue, gateway.js

- [FEAT-002] 新增: **工单拉取定时自动同步**
  - 需求: 不想每次人工点「立即同步」，要无人值守
  - 实现: PullScheduler 后台守护线程，按各拉取连接配置的间隔轮询拉取，相对独立、失败不影响主流程，随后端启停
  - 影响文件: backend/main.py, mes_puller.py

- [FEAT-003] 新增: **USB 键盘扫码枪（即插即用）**
  - 需求: 现场用 NT-1202W 等 USB 键盘式扫码枪，原扫码器体系只支持网络枪（LON/WMax）接不了
  - 实现: 做成扫码器设备的一种（device_type=usb_hid）。前端全局键盘捕获 + 速度启发式区分扫码与手输，按用途路由（拉工单 / 绑工件 / both）；后端跳过网络连接、跳过 IP:Port 唯一校验（多把枪不再撞 `:0`），仅作设备表记录。配置归入扫码器面板（UsbScanGunDialog），不再是独立子面板
  - 影响文件: frontend useScanGun.js（新）, UsbScanGunDialog.vue（新）, ScannerPanel.vue, layout/index.vue, backend/services/scanner.py, backend/api/scanner.py

- [FEAT-004] 新增: **工单拉取 + USB 扫码枪调试埋点**
  - 需求: 新功能现场排障要有日志
  - 实现: 新增 `backend.pull`（拉取发起/HTTP/解析/入库）与 `mes.pull`（测试连接/试同步/立即同步）调试分类，关开关零开销、开开关产出 job_no/url/HTTP状态/耗时/统计明细
  - 影响文件: debug_center.py, utils/debug.js, mes_puller.py, useScanGun.js, OrderPullPanel.vue

## Bug 修复

- [BUG-001] 修复: **外部 MES 返回非 2xx 时丢失返回体错误详情**
  - 症状: 拉取失败前端只看到「HTTP 500」，上银把真实原因（如某列字段有歧义）写在返回体里却被丢掉，现场无从排查
  - 根因: `_http_request` 非 2xx 分支只记 `HTTP {status}`，不读返回体
  - 修复: 非 2xx 时通用探测返回体常见错误字段（error.errorInfo / message / msg / detail，纯字符串则截断）拼进错误信息，不硬编码任何厂商；BDD 先红后绿验证
  - 影响文件: backend/services/mes_puller.py
