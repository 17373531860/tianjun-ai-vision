## 一、现场是什么（30 秒版）

上银（HIWIN）直线导轨滑块包装线。**俯视相机**看一张工作台：工人把滑块装箱发货。

一箱的标准作业（当前规格 96 滑块/箱，24 滑块/盘 × 4 盘）。
**工序顺序以此为准**（与项目配置的严格顺序链"贴标→套内袋→放油嘴包"一致；
视频里看到"封箱后出现贴标"是因为那次贴标贴的是**下一个空箱**，属于下一个周期）：

1. **贴标**（先给空箱贴箱面标签）
2. **套内袋**（箱内铺防潮袋）
3. **放油嘴包**（往箱里放一小袋亮晶晶的金属配件，每箱 1 包）
4. 从成品区端来**托盘**（上面码着 24 个独立包装的**滑块**），把整盘滑块倒/码进箱子
   —— 这个倒盘动作叫**放托盘**，每箱重复 4 次；托盘/滑块全程被逐帧跟踪计数
5. 如果这是工单的**最后一箱（尾箱）**，封箱前还要**放工单**（把纸质工单塞进箱子）
6. **封箱**（合上箱盖/胶带封口）
7. 箱子搬走 → 检测周期结算 → 系统自动开始数下一箱

（放托盘/封箱在系统里不卡先后次序；卡序的只有 贴标→套内袋→放油嘴包 这条链，违序只报"提前出现"。）

上层业务：工人先用扫码枪扫纸质工单 → 系统从客户 MES 拉"排产量"（如 250 个滑块）→
自动算出 3 箱（96+96+58，最后一箱 58 叫尾箱余数）→ 之后全靠视觉逐箱结算，扫码只用于开单/换单。

## 二、9 个标签在系统里的角色（重点！每个类的"用途"决定它的标注与验收标准）

系统不是"检出来给人看"，每个标签接进了不同的逻辑机器。分三种角色：

### 角色 A：实体·持续跟踪类（要求：在位期间**每一帧都稳定检出**，不能闪断）

| 标签 | 系统怎么用 |
|---|---|
| **托盘** | 「容器累加器」的容器：系统按 IoU 逐帧跟踪每一个托盘实体，记录"这盘曾同框的滑块峰值数"。托盘消失满 20 帧（或确认动作触发）→ 这盘的滑块数"进箱"累加。**检出闪断会导致托盘被误判消失→提前进箱→数量错**。 |
| **滑块** | 「容器累加器」的计数物品：逐帧数"当前托盘上有几个滑块"，取峰值。一盘 24 个独立包装并排码放，**要求同框 24 个目标全部检出**（漏检直接少数）。 |
| **箱子** | 目前仅作辅助显示/未参与结算（步骤未启用）。优先级最低。 |

### 角色 B：工序步骤类（要求：动作发生的 1~3 秒内**连续检出若干帧**即可，动作没发生时**绝不能出现**）

这些标签接的是"步骤完成判定"：置信度过阈值 + 连续出现满最短帧数 → 步骤打勾；
周期结束时缺任何一个必做步骤 → 这一箱判 NG。**误检一次 = 步骤被错误打勾 = 漏检真实违规**。

| 标签 | 语义（正样本的准确定义） | 特别用途 |
|---|---|---|
| **套内袋** | 手把防潮内袋铺进空箱的过程 | 必做步骤 |
| **封箱** | 合箱盖/封胶带的过程 | 必做步骤，且是周期收尾信号之一 |
| **贴标** | 手持标签贴到箱面的过程 | 必做步骤 |
| **放油嘴包** | **手中可见油嘴包**且伸到箱口内的瞬间 | 必做步骤 + 包装结算层"每箱必须放油嘴" gate 复查 |
| **放工单** | **手持纸质工单**悬在箱口上方/塞进箱内的瞬间 | 尾箱专属：包装结算层"尾箱必须塞工单" gate 靠它探测；不是每箱必做步骤 |
| **放托盘** | 整盘滑块被端到**箱口正上方**倒入的瞬间 | 双重用途：普通步骤 + 「容器累加器」的**进箱确认动作**（配置里"标签动作确认"选的就是它）。误检会提前锁盘/错位进箱，直接把滑块计数搞错 |

### 角色 C：没有的类不要发明

新模型类别集合 = 上面 9 个，顺序无所谓但**名字必须一字不差**（系统按标签名字符串对接）：
`托盘 箱子 贴标 套内袋 滑块 放油嘴包 封箱 放工单 放托盘`

## 三、系统逻辑机器（懂这个才懂"为什么误检比漏检更致命"）

1. **周期 = 一箱**：自定义混合模式（custom + tracking 容器累加器）。托盘是容器、滑块是物品，
   目标 96/箱（尾箱由包装结算层反向下发余数目标，如 58）。周期结算时判：
   进箱滑块总数 == 目标 且 所有必做步骤完成 → OK，否则 NG（原因逐条列出）。
2. **进箱确认方式**（托盘的滑块何时"落账"）三选一/可组合：
   - 消失满帧：托盘从画面消失连续 20 帧 → 进箱（老机制，只依赖"托盘"类的稳定性）；
   - 标签动作确认：检出"放托盘"步骤完成 → 进箱（**当前 SY 配置只开了这个**，所以放托盘误检=计数灾难）；
   - 两者 OR/AND。动作进行中有"屏蔽窗口"：锁定当前主托盘、不数下一盘的滑块，防串算。
3. **步骤判定参数**（当前 SY 各步骤基本都是默认值）：置信度阈值 50%、最短出现帧数默认、
   消失确认延时个别步骤配了（封箱 3s、放托盘 0.8s+最短持续 0.3s）。重训后这些都可再调。
4. **包装结算层**（工单→箱→滑块三层）：扫工单开单 → 算箱数/尾箱 → 每个检测周期=一箱落账；
   两个视觉 gate 复查步骤集：「每箱必须放油嘴」（每箱查"放油嘴包"）、「尾箱必须塞工单」（只尾箱查"放工单"，
   支持"放工单=收尾动作"模式：装满被拦→挂起快照→之后探到放工单才收箱，一直没放就扫新单判 NG）。
   **gate 的探测源就是步骤检出**，所以"放工单检不出"会让整个尾箱闭环失效。

## 四、旧模型 `best(7).pt` 实测烂在哪（重训就是为了修这些）

合格作业视频（应全 OK）全帧推理统计，阈值 50%：

| 标签 | 检出帧数/6656 | 置信度中位 | 最长连续段 | 结论 |
|---|---|---|---|---|
| 托盘 | 5540 | 0.98 | 1461 | 稳 |
| 滑块 | 5765 | 0.97 | 1386 | 稳 |
| 箱子 | 749 | 0.70 | 132 | 够用 |
| 贴标 | 119 | 0.84 | 34 | 够用 |
| 套内袋 | 102 | 0.81 | 31 | 够用 |
| 封箱 | 221 | 0.88 | 74 | 够用 |
| 放托盘 | **558** | 0.94 | 85 | **严重过检**：真动作约 10 次却连烧 3~4 秒；峰值帧=整盘被端着走就触发 |
| 放油嘴包 | **42** | 0.58 | 16 | **弱+飘**：真动作只闪 1~4 帧；峰值帧=油嘴包拿在手里在箱外 |
| 放工单 | **8** | 0.22 | 3 | **基本死亡**：峰值帧误检在手套上；真放纸动作检不出 |

现场四个反馈（与统计吻合）：
1. 桌面多放了别的东西（视角没动）→ 所有类全检不出 → **背景过拟合**，训练集场景太单一；
2. 手碰一下托盘就触发"放托盘" → 模型学的是"手+托盘同框"不是"倒盘入箱"；
3. "放工单"基本检不出 → 俯视下手中工单纸与桌面常驻的白纸无区分度、样本量不足；
4. "放油嘴包"伸手就误触、真放有时漏 → "空手伸箱"与"持包伸箱"单帧太像，缺难负样本。

## 五、重训要求（数据侧）

1. **正样本定义收紧**（动作三兄弟是重灾区）：
   - 放托盘：只标"托盘位于箱口正上方、倾倒/下放姿态"的帧；端着走、手搭在盘上、盘在成品区 → 不标；
   - 放油嘴包：只标"手中可见油嘴包 且 手已进箱口范围"的帧；持包在箱外走动 → 不标；
   - 放工单：只标"手持工单纸悬于箱口/塞入箱内"的帧；桌面摊着的纸、拿着纸走 → 不标。
2. **难负样本必采**：空手伸箱（治放油嘴包）、手碰/挪托盘但不倒盘（治放托盘）、桌面各种纸（治放工单）、
   桌面堆杂物但无任何目标的空景帧（治背景过拟合）。
3. **场景多样性**：不同班次光照、不同工人（手套颜色）、桌面有/无杂物、箱子不同位置；
   训练增强开满（马赛克、复制粘贴、HSV 抖动）。
4. **样本量参考**：动作类每类 ≥300~500 个正例（来自 ≥30 个不同作业周期），实体类维持现有量级即可
   （托盘/滑块旧模型已很稳，别把它们练退步了——保留旧训练集的这部分）。
5. 现场素材：可用系统"数据中心"导出的周期录像回放逐帧截图；标注规范参考仓库
   `docs/` 下标注规范 v1.1（有正/负样本示例图的那份）。

## 六、重训验收标准（拿同一段合格视频回放测，阈值 50%）

| 类 | 通过线 |
|---|---|
| 托盘/滑块 | 不低于旧模型（在位期间检出率 ≥95%，滑块同框 24 个全检出） |
| 贴标/套内袋/封箱 | 每次真动作连续检出 ≥15 帧；全片误检段 0 |
| 放托盘 | 每次真实倒盘连续检出 ≥10 帧；"端盘走动/手碰托盘"段落检出 0 |
| 放油嘴包 | 每次真放连续检出 ≥8 帧；"空手伸箱"检出 0 |
| 放工单 | 尾箱真放连续检出 ≥8 帧；桌面摊纸全片检出 0 |

验收方法：本仓库有现成脚本思路——全帧推理存时间线 JSON，按 10 秒段统计各类检出帧数，
与人工标注的"动作发生时刻表"比对（做法见本次分析，可复用 `/tmp/sy_best7_timeline.json` 的生成逻辑）。

## 七、如果新模型仍然救不了动作类

备选架构（系统已内建，不用开发）：**区域事件模式**（v3.32 第 6 种逻辑模式）——模型只认实体
（托盘/油嘴包/工单纸），由规则引擎用"实体位移进入箱口区域+消失"判动作。让检测干检测擅长的事，
把"动作语义"交给规则。届时找主会话改 SY 项目配置即可。
