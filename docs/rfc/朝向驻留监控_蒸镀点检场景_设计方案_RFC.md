# RFC：朝向驻留监控（orientation dwell）— 蒸镀点检合规场景

> 状态：**方案保留，待排期开发**（2026-09-08 与用户口头定稿）
> 背景客户场景：ULVAC ULFARAD-600 真空蒸镀机点检监控（机器长 13 米/开箱后，高 3.2 米，车间高 5~6 米）
> 素材：《镀膜过程监控要求.docx》+ 工程师现场 6 段视频 + 工位整体照片（微信文件，已阅）

---

## 一、场景与需求

蒸镀点检是**时间驱动的巡检合规**：

| 客户要求（文档原文） | 监控语义 |
|---|---|
| 蒸镀中每 5 分钟确认工艺参数 | 周期性出现在点位 + 面向仪表 + 驻留 |
| 每 6 分钟确认膜面 / 每 7 分钟确认留边 / 每 10 分钟确认铝舟铝线 | 同上，各点位周期不同 |
| 每班/每周开卷绕小车门进入点检油量、润滑 | 低频定时点检，要台账 |
| 每次开箱 4 项清洁确认 | 事件触发的 SOP 序列 |

**关键约束（用户两条否决意见，方案由此定型）**：
1. 出现的操作员每次不同 → 方案必须与人的身份/外观无关（识别几何而非识别人）。
2. **多台仪表在空间上挨在一起**：人站同一位置，只是转身朝向不同就在看不同的仪表 → 纯 ROI 驻留无法区分"在看哪台"，**必须有连续角度的朝向估计**，4 类粗分类也不够。

## 二、方案设计（已定稿保留）

### 推理管线（全程零训练、商用许可干净）

1. **人体检测 + 跟踪**：已有（预置行人模型 + ByteTrack）。
2. **裁剪放大 → 姿态关键点**：两段式（先检测框裁剪再跑 pose，对抗 5~6 米俯视机位下人太小）。
   - 首选 **YOLO11-pose**（Ultralytics Enterprise 授权已购，商用干净，COCO-pose 训练）。
   - 备选 **MediaPipe Pose**（Apache 2.0，系统 v3.32 起已内置骨架叠加），33 关键点含双肩双髋鼻双耳 + z 深度。
3. **朝向角计算**（几何，换人天然泛化）：
   - 躯干 yaw：双肩连线法向量给朝向轴；鼻/耳可见性与相对位置消除 180° 歧义。
   - 头部 yaw：鼻相对双耳/双眼的偏移单独算头的偏航角——**仪表挨得近时头的朝向比身体更准**。
   - 逐帧平滑输出 0~360° 连续角。

### 配置方式（好用的关键）

不配抽象角度数字，而是在画面上**点标每个仪表的位置点**（instrument point）。判定：

> 人的朝向向量 与 人→仪表点连线 的夹角 < 容差（默认 ±30°），持续 ≥ N 秒 → 记一次"确认了该仪表"。

夹角相对人的实时站位计算，站位偏移不影响；同一站位转身看哪台就计哪台的时长。

### 接入现有体系

- 区域事件引擎新规则类型 `facing_dwell`，复用 episode 计时/落库/导出/MES 推送骨架。
- "每 6 分钟必须确认膜面" = 监控规则反向用：膜面仪表点 360 秒内无任何 facing episode → 告警（同 `region_empty` 语义）。
- 前端：仪表点标注 UI（复用 ROI 画布）、容差/时长参数、监控模板。
- 已知小缺口：前端确认时长输入上限 30 秒（`LogicConfigTab.vue` `:max="30"`），巡检需 300~600 秒，后端无上限，放宽即可。

### 风险与退路

- 远距离小人关键点弱 → 两段式裁剪缓解；仍不够时由 YoloVision 平台侧用**自有现场数据**训 MEBOW 式连续朝向回归模型（任务定义借鉴 MEBOW，数据自标，接口不变）。

## 三、三条公开路线核查结论（2026-09-08）

| 路线 | 代码许可 | 预训练权重可否商用 | 结论 |
|---|---|---|---|
| 头部姿态（6DRepNet/6DRepNet360、WHENet、FSA-Net） | MIT / BSD-3 / Apache（均可商用） | ❌ 训练数据被卡死：300W-LP 含 BFM/LFPW（明确禁商用）；全角度版（6DRepNet360 Full、WHENet）依赖 CMU Panoptic（仅限科研，禁商用禁再分发） | 思路采纳（头 yaw 精分相邻仪表），权重不可直接进产品；头 yaw 改用 pose 关键点几何实现 |
| 关键点 + PnP（MediaPipe Face Mesh + solvePnP） | Apache 2.0，商用干净，已内置 | ✅ | 有用但只能当**辅助**：背对相机失效，而本场景操作员大部分时间背对相机面向设备。作为"脸可见时的精化信号"接入 |
| 人体朝向（MEBOW） | 代码可用 | ❌ 数据集官网明示 "Commercial use is not allowed"，企业获取需签非商用承诺函，权重同受限 | 数据与权重不可用；**任务定义（连续 0~360° 躯干朝向回归）借鉴**，二期用自有数据自训同任务模型 |

> 核查依据：Ascend-Research/HeadPoseEstimation-WHENet（BSD-3 但训练标签取自 panoptic dataset）；thohemp/6DRepNet360（MIT，权重 fine-tuned on 300W-LP + Panoptic）；BFM/LFPW 非商用条款；chenyanwu.github.io/MEBOW 官网非商用声明。

**总结论**：三条公开路线的预训练权重全部不可直接商用，反而验证了主方案（Enterprise 授权的 YOLO11-pose / Apache 的 MediaPipe Pose → 关键点几何算朝向，零训练）是唯一许可干净且离线可装的落地路径。

### 补充结论（2026-09-08 用户追问）："功能免费开放"能否绕开非商用限制？

**不能**，三个原因：
1. 非商用条款限制的是**用途**而非收费与否。BFM 原文禁止"直接或间接盈利"——免费功能给商业产品增加卖点/助力谈单即属间接盈利。
2. 终端客户在工厂产线上使用即客户侧商业使用，风险落我们和客户两头。
3. CMU Panoptic 额外**禁止再分发**：把权重打进安装包这个动作本身违规，与是否免费无关。
4. 连销售演示都不行（BFM "间接盈利"覆盖 demo 场景）；仅内部研发评估/跑基线可用公开权重。

**正规路径（路线一、三殊途同归）**：代码/架构是 MIT/BSD 可商用，被卡死的只是权重（训练数据脏）→ **换血自训**：
- 头部姿态：6DRepNet 架构（MIT）+ 授权模型伪标签（YOLO11-pose Enterprise / RTMPose Apache，鼻耳眼关键点几何推 yaw）+ 人工抽检修正。
- 躯干朝向：MEBOW 任务定义/代码照搬，标签自标（朝向标注成本极低，几千条现场数据够单场景族）+ 双肩关键点几何伪标签预填。
- 数据来源即 YoloVision 互连闭环：现场采样回流 → 平台标注训练 → `.yvmodel` 推回天军。训出权重权利完整，内置/免费/售卖均可。
- BFM 虽有巴塞尔大学官方商业授权可谈，但全角度版依赖的 CMU Panoptic 无商业通道，花钱只能买到正面头姿，不推荐。

## 三·五、复杂现场增强：多信号融合架构（2026-09-08 二轮扩展）

用户判断单一 2D 关键点几何在复杂现场不够用——认同。核心思路转为**多信号分层融合**，
利用点检合规"驻留数十秒、上千帧"的特性做时间积分，不追求逐帧准确：

### 信号层（从便宜到贵）
1. **轨迹朝向先验**（零成本）：行进方向作身体朝向强先验，站定后 Kalman 保持航向。
2. **2D 关键点几何**：已定稿主干（YOLO11-pose 双肩/鼻耳）。
3. **多相机三角化**（复杂现场最大增益）：六方向本就多相机覆盖，重叠视野两路 2D 关键点
   三角化出 3D 骨架 → 躯干平面法向量 = 真三维朝向，免疫单视角透视歧义/遮挡/人小。
   代价仅装机时棋盘格标定一次。全程自有 pose 模型，零许可依赖。
4. **俯视专用 YOLO11-obb**（Enterprise 已购）：俯视机位旋转框角度即身体航向，
   单阶段极快、自有数据标旋转框成本低。俯视位可作主信号。

### 语义层
5. **本地 VLM 审计：Qwen2.5-VL-7B（已核查 Apache 2.0 可商用可离线内置；
   注意 3B 版非商用、72B 版有 1 亿 MAU 门槛条款，选型钉死 7B）**。
   点检是分钟级低频事件，几何层判到疑似确认动作时抽关键帧问 VLM
   （面向哪块面板/是否在点检）。量化后 8GB 显存可跑。白送两个能力：
   审计文本自动生成（进点检台账）+ 泛化到未建模脏情况（门开没开/拿没拿点检表）。

### 训练弹药层
6. **合成数据引擎**：Blender + MakeHuman（CC0）+ Mixamo 动画渲染数字孪生车间
   （蓝工装/帽），朝向真值零标注成本，合成预训练 + 少量现场微调。
   ⚠️ 避开 SMPL（禁商用）。

### 融合判定
信号加权投票 + 时间平滑 + SOP 顺序上下文（维特比式约束）；单信号翻车由其余信号
与时间积分兜底。

### 已排除路线（同许可坑）
视线估计 Gaze360/L2CS-Net：数据集条款"研究专用、禁商用、禁再分发"，
明文覆盖"models trained on dataset"及衍生物；且远距离脸小时 gaze 本不可用。

## 三·九、客户素材落地与固定机位离线验证（2026-09-11）

客户发来正式素材：《镀膜过程监控要求》定稿 + **Camera 01 固定机位视频**（960×544@20fps，
13 分钟，正对 ULVAC ULFARAD-600，画面覆盖工艺参数控制屏/膜面区/卷绕区）+ 监控室实拍
（NVR 多画面在手，取流无障碍）。文档内时间戳即该视频内的示范段。

**离线验证结论（`tests/uat/duamo_cctv_facing_validation.py`，两段式生产同构管线）**：
- 人检出 121/121 抽帧、朝向输出 268 人次——固定广角机位下管线可用；
- 以控制屏为仪表点（归一化 (0.465, 0.36)，画面实测），文档示范段（0:50-0:59 工艺参数
  确认）命中驻留 episode（40-51s 等三段），且"谁在面向屏"判得对人：控制屏前操作员
  对准夹角 8°命中、旁边背对的外协人员 179°正确不命中；
- 已知限制：单机位遮挡（两人重叠时后者漏检个别帧，episode 靠时间积分兜住）；
  验证脚本 overlay 中文标注为 cv2.putText 乱码（纯脚本层示意，主程序前端无此问题）。

**需求→系统配置映射**：
| 文档要求 | 落法 |
|---|---|
| 每 5/6/7/10 分钟确认工艺参数/膜面/留边/铝舟 | region_events 项目，每项两条独立 facing_dwell（2026-09-13 工程师口径：四项独立计时，确认 A 不重置 B）：①确认台账（min_seconds 2~3）②超时哨兵（alert_on_absent，300/360/420/600）。规则开 require_operator（只认蓝工装；黄背心外协即使走进站位、面向仪表也不打卡）。无蒸镀开始/结束信号——始终像目标检测一样在跑，不配开始动作。仪表点按 Camera 01 装机标定：控制屏 (0.30,0.39) / 舱口膜面 (0.18,0.36) / 卷绕膜卷 (0.72,0.28) / 平台上方铝舟 (0.60,0.08)；装机用模型仓库试一试「读通道当前画面」复核 |
| 每班/每周开卷绕小车门点检 | region_enter（小车门区域）记台账；"每班/每周六"的日历核对走每日短信日报/自定义导出，不塞进秒级引擎 |
| 开箱作业 4 项 SOP | 需识别开箱状态/清洁动作等目标，预置行人模型不够——走 YoloVision 采样回流训模型后再立项（本 RFC 三期弹药）；先用 region_enter(开箱区) 记"开箱发生"台账 |
| 双面镀工艺参数设定（留边/油温等） | 非视觉监控项不处理；可选延伸：控制屏数值 OCR 读屏（/ocr/read-frame 现场可试） |

### 三·九·一、端到端演示项目结论（2026-09-13，主程序真管线）

「蒸镀点检演示」项目（logic_mode=region_events + COCO yolo11n 检人 + v3 现场视频文件源）
六条规则全链路跑通：四项周期确认（站位驻留 region_count）+ 进小车门（region_enter）+
超时哨兵（region_empty 60s），确认事件与视频示范段对齐。两个关键工程发现：

1. **region_events 项目的 steps_config 必须含模型类别行**（如 person）：检测出口有
   "启用步骤标签"白名单过滤（`_get_enabled_labels`），步骤表只写事件名会把模型输出
   全部丢弃（100% 空结果）。CI synthetic 用例绕过模型出口测不出此坑。配置口诀：
   步骤表 = 模型类别行 + 事件名行。
2. **朝向层的分辨率门槛**：微信压缩子码流 960×544 下远位人体约 110px、头部 <20px，
   头姿输出振荡不可用（v2 近构图 190px 人体时 8° 精准命中）。部署必须取主码流
   （≥1080p），朝向层在装机标定时按实际人体像素高（建议 ≥180px）决定启用；
   现阶段站位驻留语义已可支撑台账+超时告警。铝舟观察位与卷绕日常作业区重叠，
   站位驻留会多报——该点位是朝向层的刚需场景（或主码流后精化站位区）。

## 四、分期

- **一期 ✅ 已完成（2026-09-08）**：前端 min_seconds 上限 30→3600（`LogicConfigTab.vue` 输入框 + `index.vue` 序列化钳制两处）；新增「巡检超时未检」监控模板（region_empty，人，默认 360 秒）；e2e 六模板用例守门 360 秒原样落库。
- **二期 ✅ 已完成（2026-09，ai-modes 批次合入主干）**：`facing_dwell` 规则 + pose 朝向计算模块（`services/person_orientation`）+ 仪表点标注 UI + 监控模板；用工程师 6 段真实视频做验证素材（`tests/uat/facing_dwell_video_validation.py`）。
- **二·五期 ✅ 已完成（2026-09-10，多后端统一批次）**：用户取得模型授权后"全部加进去"——`person_orientation` 收编为三层多后端（YOLO11-pose COCO-17 首选 / MediaPipe Pose 33 点兜底，`TIANJUN_ORIENTATION_BACKEND` 可显式指定；头姿 ONNX 精化槽位 `backend/data/models/headpose.onnx` 或 `TIANJUN_HEADPOSE_MODEL`，兼容 6DRepNet 旋转矩阵/6D 表示/欧拉角/WHENet-HopeNet 分箱四种导出形态，放权重文件即热生效）；`yolo11n-pose.pt` 权重随包落位；孤儿 `orientation_engine.py`（合并遗留零引用）吸收后删除；新增 `/api/v1/orientation/*` 试用端点（status/estimate/estimate-frame）+ 朝向估计试用 UI（装机标定实测角度入口；初落 AI 能力试用页，2026-09-13 该页下线后迁入模型仓库「试一试」抽屉，支持传图与读通道当前画面）。
- **二·六期 ✅ 已完成（2026-09-11，公开权重占位）**：用户决策"先把公开的用上，授权版到手再替换"——头姿槽位灌入公开 6DRepNet360 全角度版（PINTO model zoo 导出 `sixdrepnet360_1x3x224x224_full.onnx`，300W-LP+Panoptic，90MB，输出 `yaw_pitch_roll` 度）。符号/映射已实证（zidane 扭头朝画面左 → 模型 yaw −57.7 → 图像平面 147.7° ✓）。⚠️ 许可现状：该权重训练数据含 CMU Panoptic（非商用），当前为**占位试用**，用户正在谈授权，出厂发版前必须替换为授权版（同名文件热替换，解码器四形态兼容，`TIANJUN_HEADPOSE_UNITS` 可调单位）。
- **三期（按需）**：脸可见时 Face Mesh PnP 精化头部朝向（headpose 槽位已被 ONNX 模型覆盖，此项仅在授权版权重不可得时再启动）；远机位平台侧自训 MEBOW 式朝向回归模型（训出后同样灌 headpose 槽位）。
