## 二件：MES 推送自动熔断（对不可达连接自动停手）

**改动**
- `backend/services/mes_gateway.py`：每连接失败计数；连续失败达阈值（默认 5）→ 熔断打开，冷却期（默认 30s）内跳过推送；冷却到点放一发探针（半开），成功即恢复、失败再熔断。手动"测试连接"成功 / 修改连接配置会人工复位熔断。
- `backend/api/mes_gateway.py`：连接序列化暴露熔断状态，前端可见。

| 风险 | 等级 | 处置 | 验证 |
|---|---|---|---|
| 误熔断把正常推送拦掉 | 中 | 阈值按"连续"失败计，任一成功即清零；半开探针自动恢复；可配置关闭（`cb_enabled: false`） | 单测 B1（未达阈值不拦）/ B4（探针成功恢复） |
| 熔断期数据丢失 | 中 | 熔断只是跳过实时推送，通信日志照记；恢复后新事件照推（与推送失败重试语义一致，本就不做补推） | 单测 B2 + 与既有失败语义对齐审查 |
| 状态跨连接串扰 | 低 | 熔断状态按连接 id 隔离的字典 | 单测覆盖多状态互不影响 |

单测：`tests/test_mes_gateway_circuit_breaker.py` 7 例全绿 + 既有网关锁释放/隔离测试回归绿。

## 三件：RFC 落地 — 收尾持久化出推理线程（治本刀）

**改动**（细节见 RFC 文档"七、落地实录"）
- 新增 `backend/api/source_persist_worker.py`：每通道 FIFO 落库线程。
- `source_session_lifecycle_mixin.py`：周期建行 / 步骤记录 / 对账 / 周期结束 / 空周期作废全部改为"同步段只做内存决策 + 值快照打包进落库作业"。
- `source_recording_api_mixin.py`：录像元数据写库进落库线程。
- "周期进行中"守门全面改用周期 uuid（id 由落库作业提交后回填）：容器 settle_dedup、checklist、NG 补做 gate、scan_pair 建行守门、关机流程、custom_mix 状态暴露。
- `_backfill_step_records` 改读本地缓存（不再查库判断已记录步骤）。
- `end_session` 统计前等本通道落库队列排空（15s 上限）。
- 兜底：`TIANJUN_SYNC_PERSIST=1` 环境变量一键回退全同步（现场急救开关）。

### 残余风险（如实登记）

1. 通道被删除时该通道落库线程不主动退出（守护线程挂空队列）。通道增删是配置期低频操作，泄漏量 = 一条空闲线程/次；后续可在 remove_channel 挂 flush+stop。
2. 数据页"最近一条周期"可见性有毫秒级延迟（落库异步）。人眼不可感；测试如需强一致可用 `TIANJUN_SYNC_PERSIST=1`。
3. 队列打满（2000 件积压，约对应写锁被外部握住数十分钟）时退化为同步 = 回到老版行为并留痕，属于有意识的保底而非缺陷。
