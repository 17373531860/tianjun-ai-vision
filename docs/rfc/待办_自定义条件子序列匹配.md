# 待办：自定义条件子序列匹配

## 问题描述

当前"基于顺序模式的自定义检测"存在限制：**条件必须以基础顺序的第一步开头**，否则无法正确匹配。

### 示例

```
基础顺序：A → B → C → D → E
条件1：B-C-A-B-C-E → 事件1（以B开头，不以A开头）
条件2：A-B-A-B-C-D-E → 事件2（以A开头，正常工作）
```

检测序列：`A-B-C-A-B-C-E`

**当前行为**：
1. `A` 出现 → 周期开始，序列 `[A]`
2. `B, C` 出现 → 序列 `[A,B,C]`
3. `A` 重新出现 → **触发结算**，序列被截断
4. 新周期开始，序列 `[A]`
5. 最终无法匹配条件1 `[B,C,A,B,C,E]`

**期望行为**：
- 序列应该继续累积为 `[A,B,C,A,B,C,E]`
- 在最后一步消失时，检查是否包含匹配条件的**子序列**
- 发现 `[B,C,A,B,C,E]` 是 `[A,B,C,A,B,C,E]` 的子序列 → 匹配条件1

---

## 根本原因

`_is_condition_prefix` 函数在第一步重新出现时会检查前缀匹配，如果不匹配则触发 `_settle_custom_cycle` 结算当前周期。

相关代码位置：
- `_update_step_stats` 中调用 `_is_condition_prefix`（约1710行）
- `_settle_custom_cycle`（约1410行）
- `_check_custom_sequential_mode`（约1980行）

---

## 解决方案

### 核心改动

1. **取消"第一步重新出现时结算"**
   - 让序列继续累积，不提前截断

2. **改用子序列匹配**
   - 在最后一步消失判定时，搜索 `current_cycle_steps` 中是否包含匹配条件的连续子序列
   - 按优先级顺序检查，第一个匹配的触发事件

3. **保留兜底机制**
   - 所有条件都不匹配时，回退到基础顺序判定

### 需要修改的函数

1. `_update_step_stats`：移除第一步重新出现时的结算逻辑
2. `_check_custom_sequential_mode`：改用子序列匹配算法
3. 可选：`_settle_custom_cycle` 可能需要调整或移除

### 子序列匹配算法示例

```python
def _find_matching_condition(self, sequence, conditions):
    """在序列中搜索匹配的条件（子序列匹配）"""
    # 按优先级排序
    sorted_conditions = sorted(conditions, key=lambda c: c.get('priority', 999))
    
    for cond in sorted_conditions:
        cond_labels = cond['labels']
        cond_len = len(cond_labels)
        
        # 从后向前搜索（优先匹配最近的）
        for start in range(len(sequence) - cond_len, -1, -1):
            if sequence[start:start+cond_len] == cond_labels:
                return cond  # 找到匹配
    
    return None  # 无匹配
```

---

## 注意事项

1. **优先级已实现**：代码中已有 `priority` 字段排序逻辑，子序列匹配时继续使用
2. **序列长度**：取消提前结算可能导致序列变长，但最后一步消失时仍会判定+重置
3. **兼容性**：以第一步开头的条件不受影响，行为保持一致
