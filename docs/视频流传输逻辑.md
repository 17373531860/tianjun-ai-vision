# 视频流传输逻辑说明

## 整体架构

```
[输入源] → [后端采集/检测线程] → current_frame → [MJPEG 生成器] → HTTP 流 → [前端 <img>]
     ↑                              ↑
  摄像头/视频/图片              get_frame() 读取
```

---

## 1. 数据源（输入源）

- **摄像头**：`cv2.VideoCapture(device_index)` 持续 `read()` 帧
- **视频文件**：同上，按帧率或倍速读取
- **图片**：单帧，不更新

采集和检测在 **同一个线程** `_capture_loop()` 中完成：
- 从输入源取一帧
- 若开启检测，调用 `_detect_only()` 做 YOLO 推理，结果写入 `current_detections`
- 把**原始帧**（不画框）写入 `current_frame`
- 若开启录制，把帧放入**异步写入队列**（另一线程写 AVI）

---

## 2. 后端：MJPEG 流生成

**入口**：`GET /video_feed`（在 `backend/main.py`）

- 若 `video_manager.is_running == True`：  
  使用 `video_manager.generate_mjpeg()` 作为流内容
- 否则：用默认摄像头的 `generate_frames()` 作为后备

**`generate_mjpeg()`**（`backend/api/source.py`）：

```python
def generate_mjpeg(self):
    while self.is_running:
        frame = self.get_frame()   # 从 frame_lock 里读 current_frame 的拷贝
        if frame is not None:
            ret, buffer = cv2.imencode('.jpg', frame, [cv2.IMWRITE_JPEG_QUALITY, 85])
            if ret:
                yield (b'--frame\r\n'
                       b'Content-Type: image/jpeg\r\n\r\n' + buffer.tobytes() + b'\r\n')
        time.sleep(1.0 / max(self.fps, 1))   # 按配置的 fps 控制推送间隔
```

- **数据来源**：始终是**当前最新的一帧**（`get_frame()` 里对 `current_frame` 加锁并 copy）
- **格式**：每帧一张 JPEG，用 HTTP **multipart/x-mixed-replace; boundary=frame** 流式推送
- **节奏**：用 `time.sleep(1/fps)` 控制大致帧率（如 30fps ≈ 33ms 一帧）

也就是说：**谁在消费 `/video_feed`，谁就拿到“当前最新画面”的 JPEG 序列**，而不是“每一帧都必传一次”的严格队列。

---

## 3. HTTP 协议

- **Content-Type**：`multipart/x-mixed-replace; boundary=frame`
- 每个 part 是一帧 JPEG：
  - 分隔符：`--frame\r\n`
  - 头：`Content-Type: image/jpeg\r\n\r\n`
  - 体：JPEG 二进制
  - 结尾：`\r\n`

浏览器会按顺序用新 part 替换前一个，形成“连续视频”的视觉效果。

---

## 4. 前端消费方式

**监控页**（`frontend/src/views/Monitor/index.vue`）：

- 视频画面：`<img :src="streamUrl">`
- `streamUrl`：`${getBackendHost()}/video_feed?t=${streamTimestamp.value}`
- 即：**一张长连接的图片**，地址指向后端的 MJPEG 流；浏览器会持续用新 JPEG 替换同一张图，实现“实时画面”。

**检测框**：

- 检测结果通过**轮询**从 `/api/v1/source/status` 等接口拿 `current_detections`
- 前端在 Canvas 上叠加绘制框，和 `<img>` 的视频层合成显示

所以：**视频流 = 后端不断把“当前帧”编码成 JPEG 推给 `/video_feed`；前端用一张 `<img src="/video_feed">` 显示。**

---

## 5. 流程小结

| 步骤 | 位置 | 说明 |
|------|------|------|
| 1 | 后端 `_capture_loop()` | 从摄像头/视频取帧 → 检测（可选）→ 更新 `current_frame` |
| 2 | 后端 `generate_mjpeg()` | 循环：`get_frame()` → JPEG 编码 → yield 一个 part |
| 3 | main.py `GET /video_feed` | 用 `StreamingResponse(generate_mjpeg(), multipart/...)` 把生成器作为响应体 |
| 4 | 前端 `<img src=".../video_feed">` | 浏览器请求该 URL，持续接收 multipart，用新 JPEG 替换显示 |
| 5 | 前端轮询 | 请求 `/source/status` 等拿 `current_detections`，在 Canvas 上画框 |

**延迟来源**：  
- 采集到写入 `current_frame` 的间隔  
- `generate_mjpeg()` 的 `sleep(1/fps)`  
- JPEG 编码时间  
- 网络传输  
- 浏览器渲染  

因此会出现“帧率稳定在 29–31，但延迟有时几 ms、有时几百 ms”的现象；连真实摄像头时逻辑相同，只是输入源从虚拟摄像头换成物理摄像头。
