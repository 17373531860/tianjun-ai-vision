# 包装检测系统 现场部署手册（三工位 / 双软件 / 集群汇总 → MES）

## 适用版本与目标场景

- 软件版本：v2.7.5+（v2.7.5b 已修扫码器 LON 联动；v2.7.4 已支持隐藏标注框、堆叠模式、最大识别数）
- 场景：**三工位流水线，两台软件**
  - 工位 1：1 台电脑 + 1 摄像头 + 1 扫码器，检测箱子第一层
  - 工位 2：1 台电脑 + 2 摄像头（双工位检大件 / 小件）+ 2 扫码器（自己 1 把 + 工位 3 那把），检测箱子第二层
  - 工位 3：**没有电脑**，只有称重器 + 扫码器，物理上接在工位 2 电脑的交换机上
- 数据走向：工位 1（副机） + 工位 2 双通道（B-0 / B-1） + 工位 3（称重器 + 扫码器）→ 全部汇总到工位 2 主机 → 推客户 MES

---

## 第一步：先做 IP 规划（纸上画完再动手，10 分钟）

### 1.1 IP / 端口表（同事先填实际值，确认可 ping 通再继续）

| 设备 | 角色 | IP | 端口 | 物理接哪台机器 |
|---|---|---|---|---|
| 工位 1 电脑 | 副机 | `192.168.X.A1` | 8001（后端） | — |
| 工位 2 电脑 | 主机 | `192.168.X.A2` | 8001（后端） | — |
| 扫码器 1 | LON 文本扫码（工位 1 用） | `192.168.X.S1` | 55256 | 工位 1 网络 |
| 扫码器 2 | LON 文本扫码（工位 2 大件用） | `192.168.X.S2` | 55256 | 工位 2 网络 |
| 扫码器 3 | LON 文本扫码（工位 3 用） | `192.168.X.S3` | 55256 | **工位 2 网络** |
| 称重器 | Modbus / 串口（工位 3 用） | 视协议 | 视协议 | **工位 2，USB 转串口** |
| 摄像头 1 | 工位 1 主摄 | — | RTSP / USB | 工位 1 |
| 摄像头 2 | 工位 2 大件 | — | RTSP / USB | 工位 2 |
| 摄像头 3 | 工位 2 小件 | — | RTSP / USB | 工位 2 |

> ⚠️ **扫码器换 IP 必须先做**：去扫码器自带的 PC 配置工具里把新 IP 写进固件并断电重启，确认两台电脑都能 `ping` 通这三个新 IP，**再**回软件配。否则后面任何"连接失败"都没法判断到底是网络问题还是软件问题。

### 1.2 集群 station_id 命名规则（必背）

```
工位 1 (副机, 整机一个)        → station_id = A
工位 2 (主机) 摄像头 0（大件） → station_id = B-0   ← 双工位模式自动加后缀
工位 2 (主机) 摄像头 1（小件） → station_id = B-1
工位 3 (无电脑, 接主机)        → station_id = C
```

主机汇总等待集合 = `[A, B-0, B-1, C]`，**少一个 MES 不会推**。

### 1.3 设备分组号命名规则（防漏的关键）

「设备分组号」（`pairing_group`）是**扫码器和外部设备配对的纽带**，让扫到的条码自动注入下一笔称重读数。和"绑定工位"完全无关。

本场景下用一组：

```
工位 3 扫码器  设备分组号 = scale-c
工位 3 称重器  设备分组号 = scale-c     ← 必须一字不差
```

**两端必须填一模一样的字符串**，大小写都不能差。叫什么无所谓（`scale-c`、`pair-3`、`abc123` 都行）。

## 第二步：工位 1 电脑（副机）配置

**目标**：单工位 + 1 个扫码器 + 把检测结果上报给工位 2 主机。

### 2.1 启动软件
开机、双击桌面图标、等启动完成。如果是首次启动可能需要激活，激活码找上一任工程师要。

### 2.2 视频源（左侧菜单 → 源设置 / Source）

1. 顶部「工位数」选择 **1**（如果之前是 2 或 4，先改成 1，会重启视频管线，等几秒）
2. 工位 1 这一行：
   - 类型：摄像头实际接法（USB / RTSP / 海康 SDK / 工业相机）
   - 填参数（IP / 端口 / 用户名 / 密码 / 路径）
3. 点 **启动** → 画面出图就 OK

### 2.3 项目（左侧菜单 → 项目 / Project）

1. 选已经做好的"包装第一层"项目，点 **激活到工位 1**
2. 没有的话先按以下步骤建：
   - 新建项目，模型选对应训练好的 .pt
   - 添加步骤（按实际工序，每步一个 label）
   - 检测模式选 **顺序模式（sequential）**——这是包装场景必须的
   - 在传动杆步骤勾 **`step_conf_thresholds = 0.55`**（已知 class 5 在 v2.7.5+ 默认开 sequential 时序硬约束 + companion gate 双层过滤）
   - 把箱子、泡沫槽这类辅助类的步骤勾 **「隐藏标注框」**（v2.7.4 字段 `hide_in_view`）
3. 保存激活

### 2.4 扫码器（左侧菜单 → 外部对接 → 扫码器面板）

点 **新建** 或 编辑已有那台：

| 字段 | 填什么 |
|---|---|
| 名称 | `工位1-扫码器` |
| 类型 | **LON 文本** |
| IP | `192.168.X.S1`（实际新 IP） |
| 端口 | `55256` |
| 绑定工位 | **0** |
| 广播工位 | 留空 |
| station_id | 留空（副机不需要） |
| 设备分组号 | 留空 |

**7 个开关如何设置：**

| 开关 | 字段 | 工位 1 建议 | 含义 |
|---|---|---|---|
| 启用 | `enabled` | ✅ 开 | 关掉就不工作 |
| 先扫后检 | `scan_required` | ✅ 开 | 没扫码不开始周期 |
| 无码告警 | `warn_no_barcode` | ❌ 关 | 已开"先扫后检"则不必再提醒 |
| 自动建工件 | `auto_create_workpiece` | ✅ 开 | 扫到新码自动建工件记录 |
| 关联工单 | `auto_link_order` | 看是否用工单 | 用就开 |
| 扫码提示框 | `toasts.scan.enabled` | ✅ 开 | Monitor 右上角弹"已扫 XXX" |
| 只喂外部设备 | `external_only` | ❌ 关 | 工位 1 扫码器要触发检测，**不能开** |

保存 → 状态应变成 **已连接（绿）**。如果黄/红：先 `ping` 这个 IP，再检查扫码器自己的网口指示灯。

### 2.5 集群配置（左侧菜单 → 外部对接 → 集群面板）

| 字段 | 填什么 |
|---|---|
| 角色 | **副机（Slave）** |
| 本机工位标识 | `A` |
| 主机地址 | `http://192.168.X.A2:8001` |
| 同步模式 | 等齐再推（默认） |

点 **测试连接** → 显示绿色"主机可达" → 点 **保存并启用**。

如果"主机可达"测不通：
- 主机后端起没起？任务栏图标是否绿
- 主机防火墙 8001 是不是放行
- 两台机器是不是同网段

### 2.6 副机不用配的东西

- ❌ MES 网关（副机不直推 MES，主机统一推）
- ❌ 外部设备（称重器在工位 2）
- 报警按现场需要：如果工位 1 现场有声光柱，就配；没有就跳过

### 2.7 副机自检

回 Monitor 页 → 点 **开始检测**：

- 扫一次条码 → 画面应当触发一次周期
- 周期结束日志里会出现：
  ```
  [Scanner] 工位1-扫码器 LON 已发送 (开始扫码)
  [Cluster] 上报 station=A box_serial=xxx → 主机 192.168.X.A2:8001  OK
  ```
- 看不到 `[Cluster] 上报` → 回 2.5 重检集群配置
- 看不到 `LON 已发送` → 回 2.4 检查扫码器配置和绑定工位是否填了 0

最复杂，按子节序 3.1 → 3.7 一项一项做，**每一项做完先验证再继续**。

### 3.1 视频源 → 双工位

1. 左侧菜单 → 源设置
2. 顶部「工位数」选 **2**（保存后会重启视频管线，等几秒）
3. 工位 1 行：摄像头 2（**大件**），启动
4. 工位 2 行：摄像头 3（**小件**），启动

### 3.2 项目（双通道各激活一个）

### 3.3 扫码器 2（工位 2 自己的，扫大件 + 小件那把）

左侧菜单 → 外部对接 → 扫码器面板 → 新建：

| 字段 | 填什么 |
|---|---|
| 名称 | `工位2-扫码器` |
| 类型 | LON 文本 |
| IP | `192.168.X.S2` |
| 端口 | `55256` |
| 绑定工位 | **0** |
| **广播工位** | **`0,1`** ← 关键：同一个码同时给两路（大件 + 小件看的是同一个箱子） |
| station_id | 留空 |

### 3.4 扫码器 3（工位 3 那把，物理接在工位 2，仅给称重器配条码）

继续在扫码器面板新建：

| 字段 | 填什么 |
|---|---|
| 名称 | `工位3-扫码器` |
| 类型 | LON 文本 |
| IP | `192.168.X.S3` |
| 端口 | `55256` |
| 绑定工位 | 留默认（不重要，下面 only 模式会接管） |
| 广播工位 | 留空 |
| station_id | 留空 |
| **设备分组号** | **`scale-c`** ← **关键**：与称重器配对 |

7 个开关重点：

| 开关 | 工位 3 扫码器 |
|---|---|
| 启用 | ✅ 开 |
| 先扫后检 | ❌ 关（这把扫码器不触发检测） |
| 无码告警 | ❌ 关 |
| 自动建工件 | ❌ 关 |
| 关联工单 | ❌ 关 |
| 扫码提示框 | 看你要不要看到 |
| **只喂外部设备（不触发视觉检测）** | **✅ 开** ← **关键** |

保存 → 状态绿。

### 3.5 称重器（左侧菜单 → 外部对接 → 外部设备面板）

#### 3.5.1 推荐:直接用「称重器（Modbus）」预设

新建对话框上方有 **「应用预设」** 按钮 → 选 **`称重器（Modbus）`**，软件会自动填好下面这些值：

```
设备角色:    称重器 (weight)
协议:        串口 Modbus ASCII (serial_modbus_ascii)
波特率:      9600
数据位:      8 / 校验:无 / 停止位:1
从站地址:    1
寄存器地址:  41203
寄存器数量:  2
字节序:      H4H3L2L1（大端）
比例系数:    0.01      ← 关键的换算系数
轮询间隔:    0.5s
解析模式:    直接取值 (direct)
```

#### 3.5.2 同事还需要补这 4 个字段

| 字段 | 填什么 |
|---|---|
| 名称 | `工位3-称重器` |
| **串口号** | Linux：`/dev/ttyUSB0`（多个串口看 `ls /dev/ttyUSB*`）<br>Windows：`COM3`（设备管理器查实际编号） |
| 数据流向 | **集群汇总 (cluster)**（如果同时也想出现在 MES extra 字段里就选"两者都发"） |
| **工位标识 (station_id)** | **`C`** |
| **设备分组号 (pairing_group)** | **`scale-c`** ← 必须和扫码器 3 一字不差 |

#### 3.5.3 比例系数（换算）怎么算

**比例系数 = 真实重量 ÷ 称重器原始读数**

| 称重器发送 | 实际重量 | 比例系数填 |
|---|---|---|
| `40` | 0.40 kg | `0.01`（预设值） |
| `40` | 4.0 kg | `0.1` |
| `40` | 40 kg | `1.0`（不换算） |
| `400` | 0.40 kg | `0.001` |

**调试方法**：放一个已知重量的物体上秤（比如标准 1kg 砝码），看软件读出多少。
- 显示 `1.00` → 正确
- 显示 `100.00` → 比例系数从 `0.01` 改成 `0.0001`
- 显示 `0.01` → 比例系数从 `0.01` 改成 `1.0`

> ⚠️ **「比例系数」字段只在协议为 `串口 Modbus ASCII` 或 `串口连续接收` 时才显示**。如果同事不小心选了 Modbus TCP / HTTP 轮询 / 纯串口，这个框就消失了——这种情况下要么换协议，要么找开发补一个通用 `data_scale`（这是已知 UI 缺口）。

#### 3.5.4 范围校验（强烈建议开）

下方「重量范围校验」面板：
- 最小：填一个略小于"空盒+最小内容"的值，例如 `0.30` kg
- 最大：填一个略大于"满盒+最大内容"的值，例如 `5.00` kg
- 超出范围会自动标 NG

#### 3.5.5 稳定值判定（强烈建议开）

下方「稳定值判定」面板，开启开关后：
- 稳定波动 ±Δ：`0.02` kg（连续读数的最大差小于这个就算稳定）
- 连续稳定次数：`5`
- 空载阈值：`0.05` kg（小于这个值视为空载，会清空已绑定的条码）

> 这个面板的作用：过滤称重器抖动数据。没开会把每个抖动值都上报，集群和 MES 会被刷屏。

#### 3.5.6 有重无码告警（按需）

如果场景是"称上有重物但没扫码 = 操作员忘扫码"，开此项：
- 超时时间：`30` 秒（实际看流程节奏调）
- 触发后会派发 `weight_no_barcode` 事件 + 报警灯

#### 3.5.7 测试

点 **测试连接** → 应能拿到一次实时重量值（在称上放东西看读数变化）。

#### 3.5.8 协议不是 Modbus ASCII 的备用方案

如果客户那台称重器只支持其它协议：

| 协议 | 怎么填 |
|---|---|
| **Modbus TCP** | 协议选 Modbus TCP；IP+端口 502；从站地址、寄存器同上；**比例系数当前没框**，要么换协议，要么找开发加 |
| **串口纯文本（设备主动推）** | 协议选「串口连续接收」，数据格式选「纯文本 ASCII」，分隔符 `\r\n`，比例系数有 |
| **串口纯文本（命令-响应）** | 协议选「纯串口」，解析模式选「正则提取」，正则按设备协议手册写 |
| **HTTP 轮询** | 协议选「HTTP 轮询」，URL 填 `http://设备IP/api/weight`，解析模式选「JSON 字段」 |

### 3.6 集群汇总（主机这一侧）

左侧菜单 → 外部对接 → 集群面板：

| 字段 | 填什么 |
|---|---|
| 角色 | **主机（Master）** |
| 本机工位标识 | **`B`**（**只填 B，不要自己加 -0/-1，软件会自动加**） |
| 监听端口 | `8001`（默认；和后端端口一致） |
| **汇总需要的工位** | **`A,B-0,B-1,C`**（4 个，缺一个不推 MES） |
| 同步模式 | **等齐再推** |
| 超时（秒） | `600`（10 分钟，按你流水线最慢工位间隔的 2 倍设） |
| 超时仍推送 | ✅ 建议开（result 会标 `TIMEOUT` 让 MES 自己判断） |

保存。

### 3.7 MES 推送（左侧菜单 → 外部对接 → MES 网关）

新建一条 MES 连接：

| 字段 | 填什么 |
|---|---|
| 名称 | `客户MES-包装线` |
| 协议 | HTTP POST / HTTPS / TCP（按客户接口文档） |
| 地址 | 客户给的接口 URL |
| **触发事件** | **勾 `box_complete`**（集群齐了就推） + 视情况勾 `box_timeout` |
| 绑定工位 | **留空**（汇总后是整箱数据，不属于哪一路） |
| 模板 | 用 `{字段路径}` 占位符按客户接口要求填，示例见下方 |
| 响应判断 | 填客户的成功标识（如 `code=0` 或 `success=true`） |

#### 模板示例（客户要 form-data）

```json
{
  "barcode":         "{workpiece.serial_no}",
  "result":          "{cycle.result}",
  "weight":          "{extra.weight}",
  "stationA_ok":     "{stations.A.is_good}",
  "stationB0_ok":    "{stations.B-0.is_good}",
  "stationB1_ok":    "{stations.B-1.is_good}",
  "stationC_weight": "{stations.C.extra.weight}",
  "timestamp":       "{timestamp}"
}
```

保存 → 点 **测试推送**：发一笔假数据看客户 MES 那边日志能不能收到。

### 3.8 报警（按现场需要）

左侧菜单 → 报警 → 配置串口/TCP 灯塔：
- **绑定通道 0** 一条灯塔
- **绑定通道 1** 一条灯塔
- 两个工位各自有自己的 OK / NG / 待机指示

## 第四步：启动顺序（按这个开机能少踩 80% 的坑）

每次断电重启或换配置后按这个顺序：

1. **先开工位 2（主机）**
   - 等后端起完（任务栏图标变绿）

2. **再开工位 1（副机）**

## 第五步：端到端验证清单（一项一项打勾）

| # | 操作 | 预期 | 失败往回查 |
|---|---|---|---|
| 1 | 工位 1 扫码器扫一次条码 | 工位 1 画面触发周期，扫码器 LED 闪 | 2.4 IP / 绑定工位 |
| 2 | 工位 2 扫码器 2 扫一次条码 | **两个画面同时**触发周期 | 3.3 广播工位是不是 `0,1` |
| 3 | 工位 3 扫码器扫一次条码 | 工位 2 软件**不触发摄像头检测**，但记录条码 | 3.4 是不是勾了"只喂外部设备" |
| 4 | 工位 3 称重器放上重物 | 外部设备面板出现一笔新记录，**带刚才扫的条码** | 5.1 二者「设备分组号」是不是都填了 `scale-c` |
| 5 | 同一箱子完整流程过一遍 | 工位 2 集群面板出现 1 个完整 box，4 个 station 全 ✓ | 看哪个 station 是 ✗ 就回去查 |
| 6 | 第 5 步成功后看 MES 网关日志 | 出现一条 push 成功 | 模板字段是否对、客户接口是否能收 |

## 第六步：常见坑速查表（同事问到时直接对答案）

| 现象 | 可能原因 | 解决 |
|---|---|---|
| 扫码器状态绿但扫码不触发周期 | 绑定工位填错；或软件待机后再开始时旧版本不发 LON | 检查绑定工位；确认在线版本 ≥ v2.7.5b |
| 工位 3 扫码后称重器读数没绑上条码 | 扫码器和称重器「设备分组号」不一致 | 二者都改成 `scale-c`，大小写都不能差 |
| 工位 3 扫码后摄像头莫名其妙触发了一次检测 | 扫码器 3 没勾"只喂外部设备" | 勾上，并补「设备分组号」 |
| MES 永远不推 | 集群"汇总需要的工位"少写了一个；或 station_id 大小写不对 | 必须 `B-0` 不能 `b-0`；4 个全列齐 |
| 双工位计数器互相覆盖 | 两个通道用了同一个 project_id | 复制一份项目改名，每路用独立项目 |
| 副机 → 主机报 connection refused | 主机后端没启 / 防火墙 8001 没放行 / 不同网段 | 按这三条排 |
| 称重器接 USB 转 RS232 在 Windows 找不到 COM 口 | 缺驱动 | 装 CH340 或 FTDI 驱动 |
| MJPEG 视频明显卡顿 | 工位 2 双摄 + 双检测 CPU 不够 | 设置页把目标推流帧率从 30 调到 15 |
| 称重器读数是真实值的 100 倍 / 100 分之一 | 比例系数没对 | 用 1kg 砝码标定，读数 ÷ 比例系数 = 真实值 |
| 称重器读数抖动严重，MES 被刷屏 | 没开稳定值判定 | 开稳定值判定（3.5.5） |
| 传动杆误报漏检 | 项目没开 sequential 时序硬约束 | 在项目→检测模式选"顺序模式"，传动杆步骤填 conf=0.55 |
| Monitor 画面出现箱子 / 泡沫槽的框很乱 | 没开「隐藏标注框」 | 项目页那两个步骤勾 `hide_in_view` |
