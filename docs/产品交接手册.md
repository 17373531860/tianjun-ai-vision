## 十九、关键业务流程

### 19.1 检测运行时数据流

```
用户点击"开始" (Monitor L635)
  → startDetection() (Monitor L2098)
    → syncProjectConfig() (L2074) → POST /detection/project-config
    → apiStartDetection() (detection.js L3) → POST /detection/start
      → backend/api/detection.py → VideoSourceManager.start_detection()
        → backend/api/source.py：加载模型 → 启动推理线程 → 开始采集帧
    → startPolling() (Monitor L2228, setInterval 150ms)
      → getDetectionResults() (detection.js L21) → GET /detection/results
        → backend返回 {detections, counters, steps, events, fps, latency, ...}
      → 更新前端状态：
        drawDetections() (L1760)   → Canvas绘制检测框
        updateStepsFromBackend() (L2364) → 更新SOP卡片+表格
        updateCharts() (L2065)     → 更新ECharts
        showToastById() (L1441)    → 触发Toast
        speak() (L1427)            → 语音播报
```

### 19.2 项目配置保存数据流

```
用户在 Project 页编辑步骤/事件/计数器
  → handleUpdateProject() (Project L1230)
    → updateProject(id, payload) → PUT /projects/${id}
      → backend/api/projects.py → 更新DB projects表
    → 若是激活项目：
      → getProjectDetail(id) → GET /projects/${id}
      → projectStore.setCurrentProject(detail)
    → 返回Monitor页时：
      → syncProjectConfig() (Monitor L2074) → POST /detection/project-config
        → backend/api/detection.py → VideoSourceManager.set_project_config()
          → source.py：重建steps状态机、events触发器、counters
```

### 19.3 报警触发数据流

```
source.py 检测到事件 (step_ok/step_ng/cycle_ok/cycle_ng)
  → alarm_manager.trigger(event_type, data)
    → backend/api/alarm.py AlarmManager
      → 查询alarm_config.rules匹配事件
      → 串口发送Modbus指令（红灯/黄灯/绿灯/蜂鸣器）
  → 事件加入 recent_events 队列
  → 前端轮询 getDetectionResults() 获取
    → showToastById() 前端Toast
    → speak() 前端语音播报
```

### 19.4 MES联动数据流

```
source.py 周期完成
  → services/mes_hooks.py → on_cycle_complete(cycle)
    → 更新 workpiece 检测计数
    → 若NG → 创建 defect 记录
    → 推送至 gateway_connections (services/mes_gateway.py)
      → 遍历启用的gateway → 按适配器类型发送HTTP请求
      → 记录 gateway_push_log
```
