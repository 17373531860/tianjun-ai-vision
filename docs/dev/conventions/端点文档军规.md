# 端点文档军规（一页纸）

> **类型**：军规（参考象限）
> **本文不讲**：怎么新增端点（见 `add-api-endpoint` skill）、docstring 通用规范（见 [docstring军规.md](docstring军规.md)）。
> **执行机制**：`scripts/ci/check_doc_endpoints.py` 基线法门禁——存量欠账记在基线文件里，**新增/被改动的端点缺文档直接 CI 红**。

---

## 一、每个端点的最低配置（四件套）

```python
@router.post(
    "/orders/{order_id}/close",
    summary="关闭工单",                       # ① 必填：动宾短语，出现在 /docs 列表页
    response_model=OrderOut,                  # ② 必填：有响应体就必须声明（None 也要显式写）
)
def close_order(
    order_id: int,
    payload: CloseOrderIn,                    # ③ 请求体必须是 Pydantic 模型，禁止裸 dict
):
    """关闭工单并触发收尾结算。

    - 已关闭的工单重复关闭返回 409。            # ④ docstring：语义+错误行为，进 /docs 详情页
    - 关闭会级联冻结未结算工件（不删除）。
    """
```

1. **summary**：≤12 字动宾短语。没有 summary 的端点在 /docs 里只剩函数名，客户 IT 无法对接。
2. **response_model**：让 OpenAPI 长出响应 schema。确实无响应体写 `status_code=204`。
3. **请求体 Pydantic 化**：裸 `dict`/`Body(...)` 会让参数表变黑洞。历史存量裸 dict 记基线不追责，**新端点禁止**。
4. **docstring 写"语义+错误"**：正常行为一句话；每个非 200 出口一行（什么条件→什么码）。

## 二、Pydantic 字段必须带 description

```python
class CloseOrderIn(BaseModel):
    reason: str = Field(..., description="关闭原因，进审计日志")
    force: bool = Field(False, description="强制关闭：跳过在途工件检查")
```

无 description 的字段在 OpenAPI 里只有类型没有含义——等于没写。枚举值逐个解释（写在 description 或 Enum 注释）。

## 三、废弃与内部端点的标注

- 废弃端点：`deprecated=True` + docstring 首行写替代端点（参照 `/operators/*` 410 处理）。
- 仅供前端内部/调试用、不承诺给插件或客户 IT 的端点：docstring 首行标 `[内部端点]`——这是"内部 API 遮蔽"制度的 API 层落点（详见 `reference/plugin-sdk.md` 白名单）。
- 开发 mock 端点：必须守 `ENABLE_DEV_MOCKS` 环境变量门（出厂版保持关闭）。

## 四、基线法门禁怎么运作

1. `scripts/ci/check_doc_endpoints.py` 遍历路由登记处（`backend/api/router_manifest.py`）挂载的全部路由，检查四件套。
2. 存量欠账固化在 `scripts/ci/doc_endpoint_baseline.json`——这些**不报错**，但清一条从基线里删一条，基线只许缩不许涨。
3. 新端点（不在基线里）缺任一件 → CI 红。
4. 想给存量还账：改到哪个文件就顺手清那个文件的基线项，禁止一次性大爆改。
