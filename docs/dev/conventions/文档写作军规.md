# 文档写作军规（一页纸）

> **类型**：军规（参考象限）
> **本文不讲**：代码注释（见 [docstring军规.md](docstring军规.md)）、端点文档（见 [端点文档军规.md](端点文档军规.md)）。
> **适用范围**：`docs/dev/`、`.claude/skills/`、`AGENTS.md`、`docs/plugin-system/` 的一切 Markdown。

---

## 一、每篇头部三行元信息（强制）

```markdown
> **类型**：tutorial / how-to / reference / explanation / ADR / 军规（六选一）
> **本文不讲**：X（去看 Y）、Z（去看 W）
> **与代码冲突时**：以代码为准，发现请顺手修本文或告知主作者
```

第二行是最便宜的路由器——AI agent 和人拿错文档类型时靠它一步跳转。生成物（reference/ 下脚本产出）改为标注"生成物勿手改 + 生成命令"。

## 二、四象限写作纪律（Diátaxis）

| 类型 | 铁律 | 最常见的病 |
|---|---|---|
| tutorial | 100% 可复现；狠心砍解释（给链接就走）；早出结果 | 教程里塞原理导致心流断裂 |
| how-to（skills） | 围绕真实问题组织；标题直说解决什么；不求完整求好用 | 塞参考大全把干活的人淹没 |
| reference | 格式高度一致；中立描述不发表意见；能生成就生成 | 混进"建议你…"类观点 |
| explanation | 讲为什么/权衡/历史；允许观点；标题能默补"关于"二字 | 吸收操作步骤（那是 how-to 的家） |

发现混装：**就地拆分搬家**，不要原地扩写。

## 三、防腐四则

1. **概念必配指针**：每讲一个机制，落一行"代码位置：文件 → 类/函数"。指针比代码摘录抗腐化，且路径会被 CI 校验（`scripts/ci/check_doc_paths.py`）。
2. **一句一行**：Markdown 源文件尽量按句断行，让 PR diff 只显示真正改动的句子。
3. **版本注记自包含**：`> v3.31 起：...` 写成独立引用块，不揉进正文句子；保留两个大版本后整块删。
4. **数字禁止手抄**：表数、字段数、端点数这类会变的数字，要么从生成物引用，要么写"约 N"，要么写"以 X 为准"。历史教训：308 字段、37 张表都曾在多处漂移。

## 四、文风（借 Google/微软风格指南）

- 禁用词：**"很简单"、"轻松地"、"只需"**——用户卡住时这些词加倍羞辱人。
- 不写占位句（"请注意"、"值得一提的是"）；结论先行。
- 代码示例前必有一句引导语；省略代码用该语言注释表达（`# ... 省略参数校验 ...`），不用裸省略号。
- 叙述文字用业务语义中文，标识符出现在代码块和"代码位置"行里。

## 五、生命周期规则

- **实现状态决定归属**（抄 Chromium）：RFC/设计稿在功能落地后**必须**盖归档戳：
  `> ⚠️ 本文已归档（vX.Y 落地）。现状以 <指针> 为准，本文仅供决策考古。`
- 删除测试法维护 AGENTS.md/skills：agent 反复犯错→加一条；从不犯错的条目→删；规则被忽视先怀疑文件太长。
- 文档改动与代码同一次提交；碰模块不改对应文档 = T1 影响分析不合格。
