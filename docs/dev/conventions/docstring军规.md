# docstring 与注释军规（一页纸）

> **类型**：军规（参考象限）
> **本文不讲**：端点文档怎么写（见 [端点文档军规.md](端点文档军规.md)）、Markdown 文档怎么写（见 [文档写作军规.md](文档写作军规.md)）。
> **与代码冲突时**：以本军规为准修代码注释——军规本身要改，先过主作者。

---

## 一、什么必须写 docstring

| 对象 | 是否强制 | 最低内容 |
|---|---|---|
| 进入多线程热路径的函数/方法（帧循环、hook 回调、队列消费者、定时器） | **强制** | 一句话职责 + **Context 段** |
| 对外承诺的插件能力面（hook、PluginHost 方法） | **强制** | 职责 + 参数语义 + 失败行为 |
| 服务层公开方法（被 api 层调用的） | 强制 | 一句话职责；非显然时补参数/返回 |
| ORM 模型类 / JSON 配置键的解析函数 | 强制 | 字段含义写在字段行注释 |
| 私有工具函数、一眼能懂的 getter | 不强制 | 命名说清即可，别写废话 |

## 二、Context 段（本项目最重要的一段，抄自 Linux kernel-doc）

多线程串扰是本项目历史重灾区。凡被非主线程调用、或持锁、或不能阻塞的函数，docstring 里**必须**有：

```python
def on_cycle_end(self, channel_id: int, payload: dict) -> None:
    """周期结束时把结算任务入队给 MES 推送线程。

    Context: 在检测帧循环线程内被调用；持有 channel 状态锁；
             禁止阻塞（队列满走 spill 落盘，不许 put(timeout)）。
    """
```

Context 段三问（答不上来就去读调用方再写）：
1. **在哪个线程被调**（主线程 / 帧循环 / MES 队列消费者 / 定时器 / uvicorn worker）？
2. **持有什么锁**（或要求调用方持有什么锁）？
3. **能否阻塞**（能睡多久；不能阻塞时失败路径是什么）？

## 三、三禁令（抄自 LLVM，与"注释最少化"守则合并执行）

1. **不在注释里重复函数名**——"``foo()`` 计算 foo"是废话，直接写它做什么。
2. **接口说明只写一份**——写在定义处（服务层方法本体），api 层薄封装不复写，用"见 XxxService.foo"指过去。
3. **能靠命名说清的不写注释**——先改名，改不动再注释。

补充：布尔实参必须带语义注释：`do_settle(force=True)` 写成 `do_settle(force=True)  # 强制结算，跳过守门`，或改用关键字参数。

## 四、格式约定

- 中文为主，技术术语/标识符保留英文；现在时第三人称（"返回 X"，不写"将会返回"）。
- 首行一句话职责，句号结尾；需要展开时空一行再写。
- 示例输出统一 `# =>` 前缀；边界行为必须写（入参为空/None 时返回什么）。
- 历史教训注释保留出处：`# v3.1.3 关键修复: ...`——这类注释**永远不许在重构时顺手删**。
- 版本注记写成独立行（`# v3.31+: ...`），不揉进长句，方便两个大版本后整行清理。

## 五、审查口径（进 T1/T2 自检）

改动碰到"第一节强制表"里的对象而没有合格 docstring → 视为 lint 不过，本次改动内补齐。
只补被你碰到的函数，**不要求顺手补全文件**（避免 diff 污染）。
