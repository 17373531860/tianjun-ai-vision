# 分层依赖规则

> **类型**：explanation（架构 · 借鉴 VS Code Source Code Organization）
> **本文不讲**：具体模块详解（→ [internals/](../internals/) 与各 skill）
> **与代码冲突时**：以代码为准。

## 后端分层（谁可以 import 谁）

```
routes (backend/api/*.py)
    ↓ 可以 import
services (backend/services/*.py)
    ↓ 可以 import
models + db (backend/models/, backend/db/)
    ↓ 可以 import
core (backend/core/config.py 等)

禁止反向：models/services 不得 import routes（避免 HTTP 层污染领域逻辑）
禁止横向穿越热路径：source.py 主类改前必读 modify-source skill（has-a 兼容层）
```

| 层 | 目录 | 允许依赖 | 禁止 |
|---|---|---|---|
| 路由层 | `backend/api/` | services, models, db, core, plugin_system | 在路由里写大段业务（>50 行应下沉 service） |
| 服务层 | `backend/services/` | models, db, core | import 具体 router |
| 模型层 | `backend/models/` | db.Base | import api/services |
| 插件平台 | `backend/plugin_system/` | db, models（审计） | 被插件反向 import 主程序内部 ORM（插件走 PluginHost facade） |

**新代码放哪的判定**：

- 对外 HTTP 端点 → `backend/api/<域>.py`，登记 `router_manifest.py`
- 跨端点复用的业务 → `backend/services/<域>.py`
- 持久化结构 → `backend/models/` + 新建 migration
- 插件能力面扩展 → `plugin_system/` + `docs/plugin-system/`

## 前端分层

```
views (frontend/src/views/)
    ↓ 可以 import
store (frontend/src/store/) + composables
    ↓ 可以 import
api (frontend/src/api/)
    ↓ HTTP
后端 /api/v1

views 不应直接拼 axios URL（走 api 层）；store 之间尽量避免循环 import
```

| 层 | 目录 | 职责 |
|---|---|---|
| 视图 | `views/` | 页面与业务 UI；大视图已拆子组件（Monitor/Project 子目录） |
| 状态 | `store/` | Pinia：检测状态、系统配置、鉴权、插件主题 |
| API | `api/` | axios 封装，路径不含 `/api/v1`（baseURL 已含） |
| 组合逻辑 | `composables/` | 插件加载三级兜底等跨视图逻辑 |

## Electron 壳

- `electron/main.js`：窗口、License、启停后端
- `electron/backend-manager.js`：spawn python、健康检查、8 步关机 API 序列
- **禁止** Electron 主进程直接操作 DB；一切经后端 HTTP

## 插件边界

- 插件 Python：`backend/plugins/<customer>/` 或安装目录解压
- 插件前端：动态加载 ESM（blob → data:URL → http 三级兜底，`usePluginLoader.js`）
- 插件**不得**依赖主程序未在 PluginHost / hook 契约中承诺的 internal API

## 代码位置

- 路由登记：`backend/api/router_manifest.py`
- 前端路由表：`frontend/src/router/index.js`
- PluginHost 契约：`backend/plugin_system/registry.py` L297+
