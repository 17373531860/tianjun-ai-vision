# 捷昌 B 站双工位 · v3.51.0 升级后现场操作清单

> 装完 v3.51.0 正式版后，**按顺序**做完下面 6 步，五个问题才能全部闭环。
> 背景：五个问题里有两个是纯软件 bug（黑屏、删记录仍拒码），升级即修；
> 另外三个（项目互踩、统一报合格、扫码前计数）**修复已就位但需要现场配置**，不配等于没开。

---

## 第 1 步：把工位 0 的项目绑定改回来（必做，一次性）

历史 bug 把工位 0 的项目绑定写坏成了小件项目（这就是"删个标签，两个工位都变小件"的病根之一）。升级后**先修数据**：

1. 进 **源设置** 页，切到 **工位 0**；
2. 在"绑定项目"下拉里选回 **大件项目**，保存；
3. 切到 **工位 1** 确认绑定仍是 **小件项目**（工位2 的项目）。

## 第 2 步：关掉「自动接管未绑定工位」（必做，防复发）

**系统设置 → 显示设置页 → 「启用项目时自动接管未绑定工位」→ 关**。

关掉后，任何一次"启用项目"（包括删标签后保存项目触发的重载）都**只影响明确绑定该项目的工位**，两个工位再也不会互相踩。

## 第 3 步：开「扫码后才计数」（要"扫码前检测不算数"就必开）

A 站能"扫码前不算数"是因为 A 站项目开了这个开关，B 站项目**没开**：

1. 进 **项目管理**，打开 **大件项目** → 逻辑设置 → 跟踪配置 → **「扫码后才计数」开**，保存；
2. **小件项目**同样操作；
3. 确认两个工位的扫码器在 MES → 扫码器面板里勾了 **「先扫后检」**（扫描模式选 **E 码-合格-码** 的可跳过——E 模式自动强制先扫后检）。

## 第 4 步：建工位组 + 开「统一播报」（要"两个都合格才一起报"就必做）

**系统设置 → 「工位组互通」标签页 → 新建工位组**：

| 配置项 | 填什么 |
|---|---|
| 组名 | 例：B站双工位 |
| 成员工位 | 0, 1 |
| 联动策略 | **全部工位 OK 才算合格**（synchronized_all_ok） |
| 统一播报 | **开**（选上面策略后才出现这个开关） |
| 等待超时 | **≥ 单件最长检测时长**（建议先设 120000 毫秒=2 分钟，跑顺了再收紧） |
| 启用 | 开 |

效果：一个工位先合格 → 不亮灯不语音不弹框（计数照常）；两个都合格 → 一起报一次合格；任一 NG → 立即报。

> ⚠️ 等待超时设太短会退化成各报各的（超时后已合格工位补报自己的合格），所以宁大勿小。

## 第 5 步：修第二把扫码器（硬件问题，软件替代不了）

日志里 **192.168.0.2 扫码器全程连接超时**，且它配置的"绑定工位=2"是不存在的工位（本机只有工位 0/1）：

1. 查网线/交换机口，工控机上 `ping 192.168.0.2` 通了再进下一步；
2. MES → 扫码器面板：把该设备的**绑定工位改成实际工位**（0 或 1）；
3. 广播枪（一把枪管两个工位）则只留一台设备、绑定工位按现场实际。

## 第 6 步：验收（10 分钟走一遍）

1. **重启工控机** → 软件自动起 → 监控页**两个工位都有画面**（黑屏修复验证；若有一个没画面等 10 秒会自动补拉）；
2. 不扫码，往视野里放东西 → **物品清单不动**（第 3 步验证）；
3. 扫码 → 两个工位开始计数；先合格的工位**安静**，第二个也合格时**一起报合格 + 扫码枪重新亮灯**（第 4 步验证）；
4. 项目管理里随便改一下小件项目（比如改个描述）并启用 → 回监控页确认**工位 0 还是大件项目**（第 1/2 步验证）;
5. 数据页删掉刚才那个码的记录 → 重扫同一个码 → **能正常登记**不再提示"已合格拒绝"（删记录解封验证）。

## 常见问题速答

- **问：升级后还需要打 v3.50.0a 补丁吗？** 不需要，17 条补丁内容已全部随 v3.51.0 出厂，`hotfix.py` 不再依赖。
- **问：「统一播报」开了，NG 会不会也等？** 不会，NG 永远立即报（安全优先）。
- **问：只有一个工位在检测时会不会等死？** 不会，没在检测的工位不进分母；等待超时也兜底。
- **问：删记录解封只对新版生效吗？** 是。老版本删记录不动工件状态；v3.51.0 起删除时自动把已合格工件解封回"已登记"。
