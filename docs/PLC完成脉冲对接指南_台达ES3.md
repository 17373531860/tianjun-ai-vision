# PLC 完成脉冲对接指南（台达 DVP32ES3）

> **类型**：how-to
> **本文不讲**：逐件覆盖（打螺丝）本身怎么调参（见 `.claude/skills/debug-per-item/SKILL.md`）、MES 网关往 Modbus 寄存器推检测结果（那是另一条独立通路，见 `.claude/skills/debug-mes/SKILL.md`）
> **与代码冲突时**：以代码为准，发现请顺手修本文或告知主作者

## 一、这个功能解决什么

工人把一块板上的螺丝全部打完，系统判合格之后，需要给 PLC 一个信号，让 PLC 去控气阀（吹气/推料/放行）。

系统走的是「外部设备」这条通路，和接电子秤是同一套配置界面：

```
工人打完最后一颗螺丝
      ↓
逐件覆盖状态机判定本周期合格（落账 OK 事件）
      ↓
把「发脉冲」请求塞进这台外设的队列（推理线程到此结束，不等 PLC）
      ↓
外设自己的线程写 Modbus：线圈 ON → 等 300ms → 线圈 OFF
      ↓
PLC 程序检测到 M100 的上升沿 → 控气阀
```

**推理线程不等 PLC**：PLC 断电、网线拔了、IP 填错，都只会让这台设备卡红并记一条错误，检测帧率不受影响、周期不会卡住。

## 二、配置步骤（不需要懂 PLC 也能照做）

> **不用 MES 也能用这个功能。**「外部设备」页面挂在 MES 菜单下面只是历史原因（电子秤、扫码器都在那），
> 气阀脉冲这条通路和工单、工件追溯、MES 数据回传**完全无关**：触发时只查「绑定的工位」和「外部设备」，
> 不查工单、不需要开 MES 网关。没上 MES 的项目直接进「MES → 外部设备」加设备即可。

先跟电气/PLC 工程师问清三件事，填在便签上：

1. **PLC 的 IP 地址**（例：`192.168.1.10`）和 **Modbus 端口**（台达一般是 `502`）
2. **PLC 站号**（Modbus 从站号，一般是 `1`）
3. **用哪个点位当"完成信号"**（例：`M100`）

然后：

1. 打开 **MES → 外部设备**，右上角点「预设模板 ▼ → 台达 PLC - 完成脉冲 (气阀)」。这一步会把除 IP 以外的参数全部填成默认值。
2. 填 **名称**（随便起，例：`工位1气阀`）。
3. 填 **IP 地址** 和 **端口**（PLC 的 IP + `502`）。
4. **地址填写方式** 保持「台达 M 编号」，**地址** 填 `100`（就是 M100，系统自动换算成 Modbus 的 2148，界面下方会显示换算结果）。
5. **触发时机** 保持「周期判合格时」。
6. **绑定工位** 选这台 PLC 管的那个工位。⚠️ **不选工位的设备永远不会被自动触发**。
7. 点「保存」。
8. 点设备卡片上的「**测试**」——只连不写，确认网络通。
9. 点设备卡片上的「**试发脉冲**」——真的给 PLC 发一次。让 PLC 工程师在旁边看 M100 有没有闪一下、气阀有没有动。**这一步通了，整条链路就通了。**

配好之后，卡片上会显示 `完成脉冲: M100 · 300ms · 判合格时`，右侧「数据日志」每发一次都会记一条 `PULSE coil@2148 ...`。

## 三、参数逐条说明

| 界面字段 | 默认值 | 说明 |
|---|---|---|
| 连接方式 | Modbus TCP (网线) | 台达 ES3 走网口就选 TCP；只有 485 口就选 RTU，然后填串口号和波特率 |
| 从站号 (PLC 站号) | 1 | PLC 侧设定的 Modbus 站号 |
| 写入类型 | 线圈 M/Y (推荐) | 写线圈用功能码 05；选「保持寄存器 D」则用功能码 06 |
| 地址填写方式 | 台达 M 编号 | 填 `100` 即 M100，系统自动 +2048。不确定换算关系时选「Modbus 原始地址」，直接填 PLC 工程师给的数字 |
| 地址 | 100 | 配合上一项 |
| 脉冲宽度 (毫秒) | **300** | ON 保持多久再复位。填 `0` = 只写 ON 不复位，由 PLC 程序自己清零 |
| 有效值 (ON) / 复位值 (OFF) | 1 / 0 | 常闭型执行机构要反逻辑就填 `0` / `1` |
| 通讯超时 (秒) | 3 | 单次连接/读写的超时 |
| 逐件覆盖（打螺丝）完成时自动发脉冲 | 开 | 关掉 = 只保留「试发脉冲」手动按钮，不自动发 |
| 触发时机 | **周期判合格时** | 见下一节 |
| 最短触发间隔 (毫秒) | 1000 | 两次自动脉冲之间的最小间隔，防抖。手动「试发脉冲」不受此限制 |

## 四、两种触发时机怎么选

| 触发时机 | 什么时候发 | 适合 |
|---|---|---|
| **周期判合格时**（`cycle_ok`，默认，更稳） | 本周期判定**合格并落账**那一刻发。NG、周期超时强制结算、空闲超时强制结算**都不发** | 绝大多数场景。气阀只放行合格件，不合格件不给放行信号 |
| **全部覆盖完成时**（`all_covered`，更快） | 本周期所有工序**首次全部覆盖完成**那一帧就发，不等收尾动作、不等结算。同一周期只发一次 | 现场要求"打完立刻吹气"、不能等收尾标签的节拍型工位 |

两种模式都做了**同周期只发一次**的边沿锁；再叠一道「最短触发间隔」兜底，即使模型抖动也不会连发。

> 一台设备只能选一种。要"打完先吹一次、判合格再吹一次"就配两台设备，分别选不同触发时机（可以指向不同 M 点位）。

## 五、与 PLC 的点表对照（台达 DVP 系列，含 DVP32ES3）

台达 M 继电器的 Modbus 地址换算（**M0 → 0x0800 → 十进制 2048**）：

| PLC 点位 | 台达内部地址 (Hex) | Modbus 0 基地址（本系统「原始地址」填这个） | 1 基文档编号（部分手册/上位机软件写这个） |
|---|---|---|---|
| M0 | 0x0800 | 2048 | 002049 |
| **M100（推荐当完成脉冲）** | **0x0864** | **2148** | **002149** |
| M101 | 0x0865 | 2149 | 002150 |
| M200 | 0x08C8 | 2248 | 002249 |
| Y0 | 0x0500 | 1280 | 001281 |
| X0 | 0x0400 | 1024 | 101025（只读） |
| D0 | 0x1000 | 4096 | 404097 |

换算公式：**M*m* 的 Modbus 0 基地址 = 2048 + m**。选界面上的「台达 M 编号」就不用自己算。

功能码：位设备（M/Y）用 **05 写单个线圈**；字设备（D）用 **06 写单个寄存器**。

> ⚠️ **以台达手册的 Modbus 对应表为准，现场必须核对一次。**
> 两个常见偏差：① 部分手册/上位机按 1 基编号写作 002149，比本系统的「原始地址」大 1；② 不同型号/网关的映射区间可能不同（M1536 起在 DVP 老系列跳到 0xB000 段）。
> 拿不准就让 PLC 工程师直接给一个数字，界面上「地址填写方式」选「Modbus 原始地址 (0 基)」原样填进去，再点「试发脉冲」验证。

### PLC 侧程序建议

系统发的是**点动信号**（ON 300ms 后自动 OFF），PLC 侧建议按**上升沿**取信号再自锁，不要直接把 M100 当气阀输出：

```
M100 上升沿 → 置位「放行请求」 → 气阀输出 + 定时器 → 定时到 → 复位「放行请求」
```

这样即使网络抖动导致复位帧丢了，也不会把气阀一直吹住。若把「脉冲宽度」设为 0（只发 ON），则**必须**由 PLC 程序自己清 M100。

> 现场没有电工、要自己装 PLC 的，看 [附录 A：PLC 侧程序与操作](PLC完成脉冲对接指南_台达ES3_附录A_PLC侧程序与操作.md)——
> 里面有可直接照抄的 3 条梯级、ISPSoft/COMMGR 安装与下载步骤、接线检查清单和 10 条排查。

## 六、排查清单

| 现象 | 先看这里 |
|---|---|
| 点「测试」就失败 | PLC 的 IP/端口对不对、工控机和 PLC 是否同网段（`ping` 一下）、PLC 侧 Modbus TCP 从站功能是否开启 |
| 「测试」通了但「试发脉冲」失败 | 站号（从站号）对不对、写入类型选错（把 D 寄存器当线圈写）、地址超出 PLC 支持范围 |
| 「试发脉冲」成功但气阀不动 | 地址换算错（问 PLC 工程师核对点表，见第五节 ⚠️）、PLC 程序没接这个点位、脉冲太短 PLC 没扫到（把脉冲宽度从 300 加到 500） |
| 手动能发、打完螺丝不自动发 | ① 有没有**绑定工位**，绑的是不是当前工位 ② 「逐件覆盖（打螺丝）完成时自动发脉冲」开关是否开着 ③ 触发时机选的是「周期判合格时」而这一轮判了 NG（NG 本来就不发）④ 「最短触发间隔」是否设得比生产节拍还长 |
| 一个周期发了好几次 | 正常情况下不会（有同周期边沿锁）。若真出现，检查是不是配了多台设备都绑同一工位 |
| 设备卡片一直红/错误 | 看卡片上的错误文字和右侧「数据日志」；PLC 未上电时就是这个状态，上电后下一次发脉冲会自动恢复 |

日志关键字：后端日志搜 `完成脉冲`、数据日志搜 `PULSE`。
