# 传感器清洁工序插件（sensor-clean）

> Tier 3 全栈插件 · customer_code = `sensor-clean`
>
> 把「传感器清洁」双视角检测 + 棉签寿命约束接入天军主程序。**检测推理复用主程序引擎；产品计数由插件挂帧级钩子按客户真值标定的轨迹算法逐帧计算**。v1.4.3 三段真值回放结果：视角1正常 38 件、小幅移动 2 件，视角2有效换棉签 16 次。

---

## 一、业务背景

计数逻辑以 `detect9.py` 的业务语义为基础，并用客户真值视频重新标定：

- **视角1**：检测「查看产品有无脏污 / 擦拭产品」两个动作。锚动作（查看脏污）出现后开始跟踪，**只要移动够远 + 连续几帧确认就立刻计一件**（不等离开），计数后强制锁定若干帧防重复。
- **视角2**：检测「更换棉签」动作。
- **耗材约束**：一根棉签默认允许擦 11 件；**第 11 件仍为 OK，第 12 件起逐件判 NG**。视角2 检出一次有效换棉签动作后，当前棉签用量清零。

## 二、架构（帧级复刻式）

```
主程序（推理引擎，不改业务逻辑）            本插件（挂帧级钩子）
┌────────────────────────────┐          ┌──────────────────────────┐
│ 视角1 通道：YOLO 逐帧推理     │ 每帧检测框 │ detection_frame 钩子      │
│   查看脏污 / 擦拭产品         │ ───────► │  轨迹移动确认 + 时间制去重  │
│                            │          │  → 计 1 件 + 棉签 +1       │
│ 视角2 通道：YOLO 逐帧推理     │ 每帧检测框 │  → 达 K 锁定 + 报警提示    │
│   更换棉签                  │ ───────► │  → 每个动作段只计 1 次更换 │
└────────────────────────────┘          └──────────────────────────┘
                                          + 双视角监控面板（前端）
                                          + 一键应用客户真值标定配置
```

- **检测**：复用主程序引擎（多通道 + 模型加载 + YOLO 推理），插件不写任何 `source_*_mixin`、不碰推理实现。
- **计数**：由插件接管。主程序推理循环每帧通过 `detection_frame` 广播检测框，插件按视频时间戳跟踪锚动作：移动够远 + 连续确认计一件，计数后按真实秒数强锁并等待产品离场。换棉签采用“出现—持续—离场”的动作段状态机，同一连续动作无论持续多久只命中一次。
- **错误隔离**：钩子与接口全程 try/except 兜底，插件异常不影响主程序检测。

### 对未启用本插件的主程序：零影响

- `detection_frame` 是 observe-only 钩子，返回值不在可写白名单、会被丢弃，**不能改主程序检测/计数/录像/状态机**。
- 没有 active 插件时，钩子分发在「插件注册表为空」处立即返回，根本不进入插件代码；每帧仅多出微秒级的空判断开销，对帧率无实质影响（与主程序既有的步骤计时广播钩子同款写法）。
- 跟踪（tracking）模式不触发本钩子。

## 四、配置项

系统配置键 `plugin_sensor_clean_config`（不配则用 v1.4.3 客户真值标定默认）：

| 字段 | 默认 | 含义 |
|---|---|---|
| `count_channels` | `[0]` | 视角1 计数通道列表 |
| `count_anchor_label` | `查看产品有无脏污` | 视角1 锚动作标签（detect9 cls0） |
| `count_require_label` | `"擦拭产品"` | v1.4.0 计数许可标签（detect9(1) 语义）：非空时该标签出现过即解锁计数（不必与锚框同帧，两类交替出现也能计）；计到一件/锚跟踪销毁重置许可，下一件需再见它；空=不启用、行为同 v1.2.0。v1.4.2 起默认开启 |
| `label_rois` | `{}` | v1.4.0 按标签 ROI（归一化多边形 `[[x,y],...]`，中心点在内才算数；空/少于3点=不限制）。key: `count_anchor` / `count_require` / `swap` / `fake_wipe`，配置 Tab 有画面快照绘制器 |
| `swap_channel` | `1` | 视角2 换棉签通道 |
| `swap_label` | `更换棉签` | 视角2 换棉签动作标签 |
| `max_uses_per_swab` | `11` | 单根棉签合格上限 K；第 K 件 OK，第 K+1 件起 NG |
| `swab_lock_time` | `0.25` | 相邻独立换棉签动作最小间隔；连续动作去重由动作段状态机保证 |
| `swab_min_sustain_sec` | `0.12` | 换棉签动作最短持续时间，过滤瞬时误检 |
| `swab_gap_sec` | `0.2` | 动作内允许的短时丢框；连续缺框超过此值才重新武装 |
| `alarm_event` | `""` | 锁定时触发的报警事件类型（空=不报警） |
| `move_threshold` | `0.02083` | 移动判定阈值（归一化 = 20px / 960） |
| `lock_spatial` | `0.02604` | 位置锁范围（归一化 = 25px / 960） |
| `lock_time` | `3.0` | 位置锁 / 计数冷却（秒，detect9） |
| `move_confirm_frames` | `3` | 连续 N 帧位移超阈值才确认移动（防抖动） |
| `lost_frame_thresh` | `5` | 连续丢失 N 帧确认产品离开 |
| `force_lock_frames` | `40` | 计数后强制锁定帧数（防漏检重建跟踪重复计数） |
| `lost_gone_sec` | `0.15` | 锚缺席 ≥ N 秒确认产品离场（>0 时替代 `lost_frame_thresh`） |
| `force_lock_sec` | `1.4` | 计数后按真实时间强锁 N 秒（>0 时替代 `force_lock_frames`） |
| `min_confidence` | `0.7` | v1.4.1 插件内置信度地板（detect9(1) CONF_THRES）：低于此值的检出不进计数/许可/换棉签判定；0=跟随监控页滑条 |

> `move_threshold` / `lock_spatial` 是归一化阈值（= detect9 像素阈值 / 960px 显示宽度）。换模型或缩放策略后需重新按真值标定。
>
> **为什么要时间制**：主程序是实时推理（如 30fps 源 23fps 推理会丢帧），帧数制的"连续丢 5 帧算离开"覆盖的真实时长被拉长，跟踪器存活过久 → 短暂离场没确认、位移跨段累积 → 小幅度移动视频多计（真值 2、实测 4~5）。时间制按真实缺席时长判定，跨帧率语义一致；两个时间参数填 0 可回退帧数制老行为。
>
> v1.4.3 默认启用 `lost_gone_sec` / `force_lock_sec`，因此核心去重语义按视频真实时间计算，不再依赖推理实际处理了多少帧。旧 v1.4.2 已落盘的出厂值会一次性迁移；迁移后的显式人工配置仍会保留。

改配置后调 `POST /swab/reload-config` 生效（一键应用端点会自动热加载）。

## 五、接口

挂在 `/api/v1/plugins/sensor-clean/swab/` 下：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/state` | 棉签状态：已用 / 上限 / 剩余 / 是否锁定（前端轮询） |
| POST | `/reset` | 手动更换棉签（清零解锁） |
| POST | `/reload-config` | 重新加载插件配置 |
| GET | `/templates` | 取客户双视角项目/模型模板 + 真值标定配置 |
| POST | `/apply-preset` | **一键应用**：把真值标定的计数/耗材参数写库持久化 + 热加载，并返回视角1/视角2 的项目+模型配置 |

## 六、一键应用 + 项目配置

插件激活后，计数/耗材参数即为三段客户真值共同标定的默认值（见第四节），无需手工配置。前端面板点「一键应用客户标定配置」会：

1. 把最优参数写入系统配置并热加载（持久化，可后续再改）；
2. 返回视角1/视角2 的项目名 + 默认模型路径，提示你到「项目」页用这两个模型新建项目，分别激活到视角1 / 视角2 通道。

> ⚠️ `preset.py` 里的默认模型路径指向本次客户素材目录，迁移到其他工控机时需在「项目」页重新指定现场权重路径。

项目侧只需让模型识别出对应动作标签即可（无序检测模式，置信度沿用 detect9 的 0.7）；**计数精度全在插件侧的逐帧参数里**，与主程序的周期结算无关。

### 一致性验证

- `视角1-正常.mp4`（1728×1080 @60fps）：真值 **38 件**，插件真实模型回放 **38 件**。
- `视角1-正常(小幅度移动不计数).mp4`（1280×720 @30fps）：真值 **2 件**，插件真实模型回放 **2 件**。
- `视角2-正常.avi`（2448×2048 @60.039fps）：真值 **16 次有效换棉签**，插件真实模型回放 **16 次**。
- 规则回归：第 **11** 件触发 OK，第 **12** 件起触发 NG。

## 七、本地 dev 加载

```bash
export DEBUG_MODE=1
export PLUGIN_DEV_MODE=1
python scripts/plugin/dev-plugin.py --src ./plugins-examples/sensor-clean --activate
# 然后用 tianjun conda 环境启动后端，插件即被加载（dev 模式跳过验签）
```

- 改后端 Python 代码需重启后端；改前端面板（手写 `dist/index.esm.js`）刷新页面即可。
- 正式分发：打包成 `.tjvplugin`（ZIP）→ 主作者用私钥签名 → 公钥验签与安装 dry-run 均通过后，再交付客户在「设置」页上传安装。
