# 客户老胡 ▸ 自定义导出步骤说明

> 验证日期: 2026-05-12 凌晨
> 验证环境: v3.7.0 + Playwright 真开浏览器 + 灌入 8 个周期的虚拟 session
> 验证结果: 下载 CSV 11/11 项断言全过 (verdict.json)

---

## 一、客户做之前要确认的两件事

1. **客户机已升级到 v3.7.0 以上**
   方法: 打开软件 → 右上角看版本号. 如果不是 `v3.7.0` 或更高, 先升级 (旧版本步骤数据不会写进导出).

2. **平时跑产线时, 步骤要正常跑完**
   也就是 cycle 里要有 `StepRecord` 数据. 检测页跑出来的"拿取/正面涂黑/翻转/反面涂黑/放置" 必须是项目里实际配置过的步骤名, 否则导出表里"该步骤"那列会是 0.

---

## 二、导出操作 (按顺序点)

### 第 1 步: 打开"数据管理"页

主菜单点 **数据管理**.

### 第 2 步: 右上角点 **自定义导出 / 客户模板**

这是一个绿色按钮, 旁边有个魔法棒图标.

### 第 3 步: 左边一列「数据范围」, 选「单 session (按 ID)」

下面会出现一个"会话"下拉框, 在下拉框里:

- 拉到要导的那次 session, 点中它.
- 如果记得 session ID, 直接打数字也行.

> 注: 不需要勾「包含 cycle 明细」—— 选 session 模式时, 系统默认就会把每个 cycle
> 连同它下面的步骤一起拼到导出文件里.

### 第 4 步: 中间一列「模板」, 把下面这段贴到「模板内容」编辑框

(看下方 **三、改好的客户模板** 那一段, 整段复制粘贴)

### 第 5 步: 右下角点 **立即下载**

浏览器会弹下载, 默认文件名是 `session_<id>_<时间戳>.csv`.

## 三、改好的客户模板 (相比客户原版的改动 + 原因)

```jinja2
会话信息
会话ID,{{ session.id }}
开始时间,{{ session.start_time or '' }}
结束时间,{{ session.end_time or '' }}
总周期数,{{ stats.cycles|length }}
合格数,{{ stats.good_cycles or 0 }}
不良数,{{ stats.ng_cycles or 0 }}
平均周期时间(秒),{{ '%.2f' % (stats.avg_cycle_time or 0) }}

计数器统计
计数器名称,数值
合格总数,{{ stats.good_cycles or 0 }}
不良总数,{{ stats.ng_cycles or 0 }}
总产量,{{ stats.total_cycles or 0 }}

周期序号,开始时间,结束时间,耗时(秒),周期间隔(秒),结果,事件,步骤序列,拿取,正面涂黑,翻转,反面涂黑,放置
{% for cycle in stats.cycles -%}
{% set step_by_label = {} -%}
{% for s in cycle.steps -%}
{% set _ = step_by_label.update({s.label: s}) -%}
{% endfor -%}
{{ cycle.cycle_number }},{{ cycle.start_time or '' }},{{ cycle.end_time or '' }},{{ '%.2f' % (cycle.duration or 0) }},{{ '%.2f' % (cycle.interval or 0) if cycle.interval else '' }},{{ '合格' if cycle.is_good else '不良' }},{{ cycle.event or '' }},{{ cycle.steps|map(attribute='label')|join(' -> ') }},{{ '%.2f' % (step_by_label['拿取'].duration if '拿取' in step_by_label else 0) }},{{ '%.2f' % (step_by_label['正面涂黑'].duration if '正面涂黑' in step_by_label else 0) }},{{ '%.2f' % (step_by_label['翻转'].duration if '翻转' in step_by_label else 0) }},{{ '%.2f' % (step_by_label['反面涂黑'].duration if '反面涂黑' in step_by_label else 0) }},{{ '%.2f' % (step_by_label['放置'].duration if '放置' in step_by_label else 0) }}
{% endfor %}
```

### 跟客户原版的 4 处差别 (用大白话, 不讲变量名)

| 改动点 | 客户原版 | 改好后 | 为什么 |
|---|---|---|---|
| 总数字段 | `合格数,{{ stats.good_count\|default('') }}` | `合格数,{{ stats.good_cycles or 0 }}` | 系统里这个数叫"合格周期数", 不是"合格数". 写错名字就空白. |
| 总产量 | `stats.total_count` | `stats.total_cycles` | 同上, 字段名要对得上系统. |
| 平均周期时间 | `stats.avg_duration` | `stats.avg_cycle_time`, 而且 `'%.2f' %` 保留两位小数 | 否则会出现 `5.239999999999999` 这种丑数字. |
| 没值的字段 | `\|default('')` | `or ''` | 系统里"没事件"是写成 None, 用 default 还是会显示成字符串 "None"; 用 or 才会变空白. |

### 模板里"步骤名"客户要按实际改

模板末尾几列写的是 `拿取/正面涂黑/翻转/反面涂黑/放置`, 这些是老胡产线的 5 步.

**别的客户用时**, 直接把"拿取"这几个词换成自己产线的步骤名即可, 两处都要改:
- 表头那行 (`周期序号,...,拿取,正面涂黑,...`)
- for 循环最后一行那 5 个 `step_by_label['拿取']` 等

## 四、客户拿到 CSV 应该是啥样

打开下载的 csv (实测样本见 `downloaded.csv`), 用 Excel 打开是这样:

```
会话信息
会话ID                 843
开始时间               2026-05-12T01:30:16.095144
结束时间               2026-05-12T01:40:16.095144
总周期数               8
合格数                 7
不良数                 1
平均周期时间(秒)        5.24

计数器统计
计数器名称              数值
合格总数               7
不良总数               1
总产量                 8

周期序号  开始时间                       ...  结果   事件        步骤序列                                       拿取  正面涂黑 翻转 反面涂黑 放置
1        2026-05-12T01:30:16.095144   ...  合格              拿取 -> 正面涂黑 -> 翻转 -> 反面涂黑 -> 放置  0.22 2.01   0.61 1.89   0.51
2        ...                          ...  合格              拿取 -> 正面涂黑 -> 翻转 -> 反面涂黑 -> 放置  0.22 2.01   0.61 1.89   0.51
3        ...                          ...  合格              拿取 -> 正面涂黑 -> 翻转 -> 反面涂黑 -> 放置  0.22 2.01   0.61 1.89   0.51
4        ...                          ...  不良  缺步骤NG    拿取 -> 正面涂黑                              0.22 2.01   0.00 0.00   0.00
5-8                                       (后面同样)
```

**重点验证三件事**:
1. "步骤序列" 这一列有箭头 `->` 串起来的 5 个步骤名 → 客户原本说"步骤序列都没获取到", 这里有.
2. 后面 5 列 (拿取/正面涂黑/翻转/反面涂黑/放置) 每个都有秒数 → 客户原本说"拿取这些字段都没获取到", 这里有.
3. NG 周期 (第 4 行) 步骤序列短、缺的几步显示 0.00、"事件" 列显示触发原因 → 出问题时一眼能看到是哪步丢了.

## 五、客户如果还是导出来空白, 排查清单

按这个顺序排查 (按这个顺序排, 80% 问题在前 3 条):

1. **版本不到 3.7.0**: 看右上角版本号, 必须是 3.7.0 或更高.
2. **范围选错了**: 必须是"单 session", 不是"日期范围"也不是"系统级".
3. **session 选错了**: 选的是"今天没跑过产线"的 session, 当然没 cycle.
4. **项目里步骤名跟模板里对不上**: 比如客户产线步骤实际叫"取料", 但模板里写"拿取" → 这一列就是 0.00.
   - 排查办法: 检测页项目设置 → 步骤定义那里, 看实际的中文名是啥, 把模板里 5 个 `step_by_label['拿取']` 改成实际的名字.
5. **如果出现了 `None` 字面量**: 说明用了 `|default('')` 而不是 `or ''`. 按上面给的模板照抄就行.
6. **如果出现 `5.23999999...` 这种丑数字**: 没用 `'%.2f' %` 格式化. 按上面给的模板照抄就行.
